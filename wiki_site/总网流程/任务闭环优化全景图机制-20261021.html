任务闭环优化全景图机制（大模块·小步骤）

用户要求（2026-10-21）：每做完一个任务就闭环优化全景图/进度图，下次照着接着干，且下个 RAG 项目能全部复用。

核心命题：全景图不是汇报材料，是"任务闭环的单一事实源"。做完任务必须回写全景图（进度图+缺口图），否则下次从头问、下个项目从头摸。本机制把它固化成可照跑的规则，跨 RAG 项目复用。

3. 回写规则（每单交付时强制，缺一不收口）3 个重点▾ 点开看本章重点
本章重点
  • 1. 进度图必回写：状态 ✅/🔄/⏳ + 产物路径 + 验收凭据（receipt verify 绿 / 评测数字）
  • 3. 坑图必修正：踩的坑写根因+修复+指纹，同步 「error-ledger」

2

铁律：任务交付 = 产出物 + 验收凭据 + 全景图回写。只交产出物不回写 = 任务未完成。

  1. 进度图必回写：状态 ✅/🔄/⏳ + 产物路径 + 验收凭据（receipt verify 绿 / 评测数字）。
  2. 缺口图必补：本任务暴露的缺口当场登记（"我做 X 时发现还缺 Y"），标 P0/P1/P2。
  3. 坑图必修正：踩的坑写根因+修复+指纹，同步 error-ledger。
  4. 总地图必挂：新资产挂对应 N 节点（orphan-asset-check.py exit=0）。
  5. 口径标注：数字附命令+口径（如"234 txt（find raw/courseware -iname '*.txt'）"），不裸写数字。

新项目启动时：
1. 复制机制骨架（本文 §2 三图五模块）到 <新项目>/wiki/总网流程/任务闭环全景图机制.md。
2. 建 <新项目>/raw/_task_orders/全景图-<项目>-<日期>.md，填三图初始态（进度图=全⏳，缺口图=启动缺口，坑图=空）。
3. 每单交付走模块 A→B→C，回写三图。
4. 新会话开局走模块 D，照进度图/缺口图接着干。

复用判据：换项目时，本机制的字段/命名/规则一字不改能用，只替换项目特定内容 = 复用成功。若发现规则要改 → 改本机制（回流），不是在新项目另写一套。

2
