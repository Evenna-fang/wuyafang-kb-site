二、三层上下文体系（AGENT-HANDBOOK）

3

核心原则：Agent 应当恰好获得当前任务所需的上下文——不多不少。做法是分层加载 + 渐进式披露（常驻最小集，按需拉取更多）。

层级 加载时机 内容 占用
Tier 1 会话常驻 每次会话自动注入 行为准则、工具路由、手册 最小
Tier 2 按需加载 技能被调用时 专业流程、领域知识（SKILL.md） 中等
Tier 3 持久化知识库 Agent 主动查询时 错误台账、项目笔记、历史会话 按需

判断法则：每次任务都要遵守 → Tier1；特定场景才用 → Tier2（做成技能）；只在排查/回顾时才查 → Tier3（做成台账/笔记）。Tier2 加载方式因 Agent 而异：Hermes 有 skill_view(name)/skills_list() 工具直接调用；其他 Agent（DSH/Claude Code/Codex/OpenClaw）无内置技能工具，通过读 ~/shared-skills/<name>/SKILL.md获取（本质是 Tier3 的文件读取）。

知识库索引（Tier3）三处：错误台账 error-ledger/ledger.tsv（报错第一步查、修复后写回）；技能库 ~/shared-skills/；决策与审计记录（skill-governance.sh / evolution-monitor.sh / session_search）。

五、agent 脚本设计模式（非交互式适配）3 个重点▾ 点开看本节重点
本节重点
  • 核心问题：agent 运行脚本时是非交互式终端，「read -p」 等交互命令会直接跳过
  • agent 调用流程：① 「source script.sh --list 」 显示列表 → ② 把列表给用户问"选哪个" → ③ 「source script.sh 」 执行
  • 复用场景：模型切换脚本、配置切换、工具选择、环境切换（2026-09-06 模型切换系统构建实战沉淀）
3

核心问题：agent 运行脚本时是非交互式终端，read -p 等交互命令会直接跳过。 解决——--list 模式 + 编号切换：script.sh --list <选项>（仅显示列表，agent 用）；script.sh <选项> <编号>（直接执行，agent 用）；script.sh <选项>（交互式选择，终端用）。agent 调用流程：① source script.sh --list <选项> 显示列表 → ② 把列表给用户问"选哪个" → ③ source script.sh <选项> <编号> 执行。

避坑三点：--list 不带参数要加参数检查与用法提示（否则报错）；配置文件读取加 try-except（文件可能不存在）；多智能体同步用共享技能库 + 各 Agent skills 目录（cp 到 ~/.claude/~/.codex/~/.openclaw/~/.hermes）。复用场景：模型切换脚本、配置切换、工具选择、环境切换（2026-09-06 模型切换系统构建实战沉淀）。
