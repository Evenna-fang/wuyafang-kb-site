一、完成凭据铁律：下游未归档 → 上游无法标记完成3 个重点▾ 点开看本节重点
本节重点
  • 这是本套规范的最高优先级
  • 为什么非要这样：只要验证者还是执行者自己，写多少规则都防不住"过早胜利"
  • 声称"完成／修好／通过"之前，必须用可执行命令产出凭据——"我测过了"这类自证一律不采信
3

这是本套规范的最高优先级。声称"完成／修好／通过"之前，必须用可执行命令产出凭据——"我测过了"这类自证一律不采信。

  • 命令链：python3 ~/.hermes/scripts/receipt.py declare --task "..." --check "<命令>"，再 receipt.py verify，全绿才允许说完成。
  • verify 内置台账门禁：若错误日志比台账新（>5 分钟）则判失败，强制先写回台账。这就是"真反压"——下游没归档，上游就没法标记完成，无法绕过。
  • 为什么非要这样：只要验证者还是执行者自己，写多少规则都防不住"过早胜利"。 历史教训：曾宣称"6 场景全通"，实际只测了正例，被独立审查查出 4 条 fallback 悬空。

三条配套纪律互为加固：

纪律 要求
PDCA 闭环 执行类任务（修/改/部署/同步/配置）必须走 Plan→Do→Check→Act；修了≠完成，验证了=完成，"全部完成"必须附 Check 输出
功能清单对抗早宣布胜利 任务开始用 todo 建完整功能清单，结尾逐项 Check；未完成标 pending 不删除，全部 completed 才算完成
禁止无 E2E 验证标记完成 curl／单元测试通过 ≠ 真正能用；关键功能必须跑通完整用户流程（端到端）才算 done

二、记忆 vs 技能：按"我是谁／怎么做"分家（防覆盖的根本手段）

3

互相覆盖的根因是"什么都往一个文件堆"。规范用内容类型决定归宿：

  • 记忆只放"我是谁"：行为准则、环境事实、触发提醒，≤15 条（硬上限）。
  • 技能放"怎么做"：操作流程、模板、数据、规范，必须有 triggers（触发词）才能被召回。

判断标准很直白：一条新内容如果回答的是"当前这条规则/环境是什么"，进记忆层；如果回答的是"遇到某场景该按什么步骤做"，进技能层。归属一确定，覆盖问题就消掉大半——因为不同 Agent 写的是不同层，不争同一个位置。

三、技能价值四维评估：决定"留谁、删谁"2 个重点▾ 点开看本节重点
本节重点
  • 权重 3/2/2/1 是刻意的不对称：不可替代性最贵（省不掉的那部分），折旧率取补——越易过时，该项扣得越狠
  • 用法：定期对技能库打分排序，尾部的合并或下线，避免"只增不减"撑爆召回
3

记忆与技能不能只进不出。团队用一条可计算的公式给技能打分，低分自然淘汰：

价值 = 不可替代性 × 3 + 组合价值 × 2 + 触发可达性 × 2 + (1 − 折旧率) × 1

  • 权重 3/2/2/1 是刻意的不对称：不可替代性最贵（省不掉的那部分），折旧率取补——越易过时，该项扣得越狠。
  • 用法：定期对技能库打分排序，尾部的合并或下线，避免"只增不减"撑爆召回。

四、风险分级门禁：风险词触发 + 四级响应

3
  • 检测到风险词（删除／修改／上线／生产／重启／报错／故障）→ 自动触发检查门禁，不靠人记得。
  • 四级响应按影响面升级：一级=自检 | 二级=决策树 + 多 Agent | 三级=双 Agent 复核 | 四级=PDCA 复盘。

总纲：全面的信息 + 正确的逻辑 + 场景下的专家验证。两条配套要求：审查要交完整思路（把怎么想、怎么规划、怎么实施全给审查者，不是只给代码，且讨论后再改而非改完才审）；发现任一智能体的配置/能力/可用性问题必须当场实测确认并明确告知用户，不得静默修复或跳过。

六、谁在什么时候写、写到哪一层、怎么保鲜

3
维度 规则
谁写 Hermes 是共享文件（shared-memory.md / AGENT-HANDBOOK.md）的唯一管理者；各 Agent 共享同一套，不各自建副本
何时写 任务收尾前跑沉淀三问（有新来源？踩过坑？流程可优化？）；另有两类定时任务：每日 09:00 共享技能库更新检测，每周日 13:00 大扫除（记忆瘦身 + 技能库整理）
写到哪层 记忆层（我是谁，≤15 条）／技能层（怎么做，带 triggers）／环境避坑区（环境事实）
防覆盖 单一管理者 + 内容类型分家 + 技能四维评估淘汰；三把锁叠加
保鲜 每周大扫除做记忆瘦身（超 15 条先删再进）；技能用四维公式按折旧率淘汰
冲突处理 与现有规则冲突时不写，在原位置追加 ⚠️冲突: <现有规则#>，下次周复盘一并提案（落地门细则见 AGENTS规范实战 第五节）

环境事实沉淀范例（属记忆层，示范"具体、可验证"的写法）：检测 Docker 状态用 docker version（显示 Client+Server），不要用 which docker；Python 3.14 装包用 --break-system-packages；不自建 apt 源，避免 sudo，装到 ~/.local/bin。用户偏好固定两条：最小化安装 + 密码不存储 + 先查后装。这类"环境事实"越具体越有用，且随环境变化需要保鲜——原始共享记忆里同一兜底链出现过 MiMo V2.6 Pro 与 V2.5 Pro 两个版本，正是旧版本信息漂移的实例，说明模型版本类内容应定期重验而非长期外推。

八、思维方法路由：按场景选推理方法（不靠默认一把梭）

3

收到任务先判场景，自动匹配推理方法，而不是所有问题都用同一种思路：

方法 场景 触发信号
CoT 链式思考 逻辑推理、因果分析 为什么、推理、分析
ToT 树式思考 多方案决策、对比评估 哪个方案、对比、选择
GoT 图式思考 系统性分析、根因分析 关系、依赖、根因
PDCA 执行闭环 修/改/部署/同步/配置 任何执行类任务
ReAct 推理+行动 需反复"想一步做一步"（默认模式） 探索型任务
Reflexion 失败反思 失败后反思重试 报错、重试
PoT 程序化思考 数值 / 计算密集 算数、统计
SoT 骨架化思考 大型规划 先搭骨架再并行展开
Multi-Agent Debate 关键决策交叉验证 高风险选型/架构

选型逻辑：能一步推出答案的用 CoT；多岔路选 ToT；纠缠成网用 GoT；要动手就叠 PDCA；关键且不可逆的决策才上 Debate——它是成本最高的一档，别日常滥用。
