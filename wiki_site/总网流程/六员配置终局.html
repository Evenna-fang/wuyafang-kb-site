按任务的"思考深度"选模型档位，而不是整任务锁一个模型。用 AFP 系数（价格/能力倍数）量化每档成本——写对比结论时必须报数字，不能只说"贵/便宜"。

模型 档位 AFP 适用任务 token 范围
doubao-seed-2.0-mini 轻量 0.5 格式化/摘要/分类 2k–8k
doubao-seed-2.1-lite 通用 1 通用问答/普通推理 4k–16k
doubao-seed-2.1-pro 强力 5 复杂推理/代码/规划 8k–32k
kimi-k2.7-code 顶级 9 长代码/深度重构（慎用） 16k–64k

步级路由规则：

  • planning / 规划 → pro（AFP 5，值得长链推理投入）
  • formatting / 格式化 → mini（AFP 0.5，模板化轻量即可）
  • 通用对话 → lite（AFP 1，默认性价比）
  • 代码工程 → pro（不切 kimi，省成本）

依据：AgentRouter（arXiv:2609.22951）步级路由思路，已落地为本矩阵。

三、token 预算三档（Low / Mid / High）

2

不同角色的 token 上限不该一刀切。task-dispatcher 派单时按承接者档位自动定 token 上限，同一任务跨档时以最终承接者为准。派单前门禁与派单后监督细则详见 六员通道与派单监督-一手篇。不按任务字数硬算（此方案曾被打回 R2），保持 adaptive 停止。

档 角色 适用任务 token 上限策略
Low QwenCode（小运维）、DSH（批量吞吐） 脚本执行、批量命令、简单查询 低上限，快速返回
Mid Hermes（规划编排）、DSH（执行） 任务拆解、多步编排、中等复杂度 中上限
High Claude Code（工程）、Codex（原型）、OpenClaw（审查） 代码工程、原型生成、独立审查 高上限，允许长推理

派单示例：

  • "写个清理脚本" → Low（QwenCode/DSH）
  • "规划多步重构" → Mid（Hermes）
  • "独立审查这份方案" → High（OpenClaw）

① 技能按需加载（Skills on-Demand Loading）

3
  • 问题：200+ 技能全量塞 system prompt，光 skills 块就 ~43k chars，每轮都烧。
  • 方案：按 query 关键词只加载 3–5 个最相关技能。
  • 落地：build_skill_index.py（倒排索引）+ skill_matcher.py（query→top-N）；prompt_builder.py 只塞命中技能。
  • 效果：每轮加载技能 200+ → 3–5（-97.5%）。
