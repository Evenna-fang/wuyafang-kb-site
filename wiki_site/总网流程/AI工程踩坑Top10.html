Top2 · 密钥字段名混乱 + 掩码占位符

2
  • 踩坑: .env 用 XIAOMI_API_KEY 但 Claude/DSH 要 XIAOMIMIMO_API_KEY；secrets.env 里存的是字面掩码 sk-... 而非真 key；settings.json 里 token 是含 U+2026 省略号的占位符 → 401/402 且不报错，难定位。
  • 根因: 多 Agent 各自维护 key 字段名；统一改造时把"记忆里的掩码记法"当真值写回；read_file 读敏感文件返回 «redacted»，write_file 写回时把真值覆盖成占位符。
  • 怎么避免: ① 敏感文件禁 read_file → write_file 往返，一律用 python 直接读写；② check 脚本固化"值必须 sk- 开头且不含字面 …"门禁；③ 改 key 必跑一次全量校验脚本，一次暴露所有字段名问题。

Top4 · 配置并发写 + 多副本漂移

2
  • 踩坑: 同批 6 个文件的切模型/同步/换 key 并发写，改一处漏一处；模型配置在 6 处 / 5 个文件重复定义，改一处另一处陈旧。
  • 根因: 多 Agent 同时改同一批配置文件无串行锁；同一逻辑多处各自定义。
  • 怎么避免: ① 配置类操作全局串行，同批文件禁并发；② 抽共享模块做单一事实来源，两处 import 同一份；③ 只读校验器交叉核对每个引用。

2
  • 踩坑: 对文件 chmod 600 返回 0 但权限仍 777（软链指向 /mnt/c，9p 无 metadata 挂载，Linux chmod 在 9p 上是静默空操作）；WSL interop 启动 Windows exe 时 Linux env 全不过边界；从 WSL 用 powershell Start-Process 拉 IDE 触发崩溃。
  • 根因: 路径勘察只看路径名和 ls，没做 readlink -f / df -T / stat；想当然假设文件都在 ext4。
  • 怎么避免: ① 路径/权限勘察必做三件套 readlink -f + df -T + stat；② 对 chmod/cp/sed -i 等可能静默成功的命令，读回环境状态而非只看退出码；③ IDE 从 Windows 侧启动。

Top6 · 批量替换模型名子串污染

2
  • 踩坑: 批量替换 mimo-v2.5 → mimo-v2.6 时无顺序 → 产出 mimo-v2.6-flash-pro；无负向前瞻 → 语音模型 mimo-v2.5-asr/tts 被毁成无效 id → API 404 全线回退。
  • 根因: 正则替换没考虑子串包含关系 + 没保留特例。
  • 怎么避免: ① 两遍法：先替换长名，再用 mimo-v2\.5(?![-a-z0-9]) 负向前瞻替换短名；② 替换前后必跑正负例：pro/base 改对 + asr/tts 保留。

Top8 · 百炼 / Ollama 端点与免费档误判

2
  • 踩坑: sk-sp- 前缀的百炼套餐 key 只能在专属端点生效，用标准 dashscope 端点测试返回 401，误判 key 失效；Ollama 云端列 20 个模型但仅 5 个真免费，其余 15 个调用即 402。

Top10 · 正则重排 markdown 误伤

2
  • 踩坑: 用正则重排 markdown 段落时匹配范围过宽，整段核心准则被删，三份手册受损；向文件开头插入以 --- 开头的块，制造 YAML frontmatter 污染，内容被解析器吞掉。
  • 根因: 宽正则无边界；插入块首没确认目标文件首行结构。
  • 怎么避免: ① 重排段落不用宽正则，先备份，改后立即 grep 关键段计数验证；② 插入块首不要用 ---，插入后 head -1 验证。
