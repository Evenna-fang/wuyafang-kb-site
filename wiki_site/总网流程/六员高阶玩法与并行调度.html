六员体系除了"角色 + 模型路由"，还有一套可组合的高阶编排原语与并行调度引擎。核心分层是六个角色各占一层——Hermes=战略规划层 / DSH=战术执行层（新增，Hermes 的直接执行臂）/ Claude Code=工程设计层 / Codex=快速原型层 / OpenClaw=多模态外联层 / QwenCode=补岗/小运维层（后补入六员），Hermes 直接指挥全部六个 Agent（去掉 OpenClaw 中间调度）。并行调度引擎提供 4 种策略（independent / pipeline / race / scatter-gather），max_concurrency: 3，错误按 L1–L4 分级。高阶玩法手册给出 10 类能力（Kanban Swarm / Persistent Goals / Recurring Loops / MoA / Computer Use / Browser / Voice / Holographic / 协作模式 / 自进化），每类都有可复制的命令与"何时用"判据。配套一条团队硬纪律：任务完成后必须删过程垃圾。

二、并行调度引擎 v2

3

派单前门禁、通道实测与派单后监督细则详见 六员通道与派单监督-一手篇（本节只讲引擎策略本身）。

任务类型 并行策略 示例
独立任务 完全并行，无依赖 同时写前端 + 后端 + 文档
流水线任务 阶段并行，流水线执行 A 完成后 B 开始，同时 C 也在进行
竞争任务 多 Agent 同时尝试取最优 Codex 和 Claude 各写一版选优
聚合任务 分片并行最终合并 多文件同时改，最后合并

task_batch 格式：parallel_strategy（independent/pipeline/race/scatter-gather）、max_concurrency: 3、每个 task 带 agent/description/dependencies/timeout/retry。错误分级：L1 可自愈（Agent 自行重试 ≤ 2 次）/ L2 需协助（上报 Hermes）/ L3 需切换（Hermes 重新分配）/ L4 阻塞（暂停整批等人）。性能指标：并行效率目标 > 0.6、一次通过率 > 0.8、返工率 < 0.15。

三、Kanban Swarm（持久化 SQLite 任务板）3 个重点▾ 点开看本节重点
本节重点
  • 把大任务拆为并行 Worker → Verifier → Synthesizer，用依赖链自动编排
  • 避坑：不要把 support card 链回它要解阻塞的父任务（死锁）
  • Worker 通过 「kanban_*」 工具驱动（「kanban_show/comment/block/complete/request_review」），不是 CLI
3

把大任务拆为并行 Worker → Verifier → Synthesizer，用依赖链自动编排。组件：Board（独立 SQLite DB + 调度器循环）、Task（状态机 triage→todo→ready→running→blocked→review→done→archived）、Link（parent→child 依赖，所有 parent 完成时 todo 自动→ready）、Dispatcher（长驻循环，每 60 秒回收过期、提升 ready、原子 claim、spawn worker）。Worker 通过 kanban_* 工具驱动（kanban_show/comment/block/complete/request_review），不是 CLI。工作空间 scratch（默认，完成后删除，artifacts 先复制）/ dir:<path>（保留）/ worktree（保留）。避坑：不要把 support card 链回它要解阻塞的父任务（死锁）。

四、Persistent Goals（完成契约）

3

/goal 设目标，Judge 模型判完成、未完成自动继续。完成契约五字段：outcome（单一状态，必须为真）/ verification（可运行的测试/命令/产物）/ constraints（不能回归的内容）/ boundaries（范围内文件/目录/工具）/ stop_when（停止并请求输入的条件）。质量门禁：/goal gate add "pytest tests/ -x"、"ruff check src/"、"mypy src/ --strict"（至少含测试 + lint 两个门禁）。

五、Recurring Loops（会话内定时循环）2 个重点▾ 点开看本节重点
本节重点
  • 两模式：固定间隔（「/loop 5m ...」，精确执行）与自适应节奏（省略间隔，Agent 按状态自决）
  • 最佳实践：短间隔 + 次数限制；条件停止优于手动停止；自适应适合不确定时长任务（如迁移）
3

两模式：固定间隔（/loop 5m ...，精确执行）与自适应节奏（省略间隔，Agent 按状态自决）。停止条件：LOOP_COMPLETE 标记 / --times N / --until <证据条件> / /loop stop / loops.max_ticks（默认 100 次）。最佳实践：短间隔 + 次数限制；条件停止优于手动停止；自适应适合不确定时长任务（如迁移）。

六、MoA 多模型协作（专家委员会）

3

多个参考模型先独立分析 → 聚合模型综合输出。预设：coding（2 参考 + 1 聚合：mimo-v2.6-pro + deepseek-v4-pro / 聚合 mimo-v2.6-pro）；reasoning（3 参考 + 1 聚合，加 qwen3.8-max）。/moa <问题> 一次性使用。成本警告：MoA 的 token 消耗是单模型的 N 倍（N=参考模型数）——复杂决策（架构/选型/安全）才用，简单任务用单模型。

八、自进化机制（curator）

3

技能沉淀触发条件：同类任务出现 3 次以上 / 解决非平凡问题（耗时 > 10 分钟）/ 发现通用避坑方法 / 用户主动要求"记住"。自动维护：30 天未使用→标 stale；90 天未使用→归档 .archive/；LLM 合并建议（opt-in）。Curator 配置：interval_hours: 168（7 天）、stale_after_days: 30、archive_after_days: 90、consolidate: false。记忆同步：会话结束触发 提取事实 → 分类存储 → 同步到 ~/shared-skills；手动 ~/shared-skills/sync-memory.sh -a。

九、团队行为纪律（agent-team-conventions · 4 Agent 共享）3 个重点▾ 点开看本节重点
本节重点
  • 1. 每次沟通/跑完项目后必须删除过程垃圾：临时脚本（「/tmp/*.py」）、测试产物、备份残留、无价值中间产物；任务收尾立即清，不留到下次
  • 2. 节约 Token 准则：优先结构化记忆不重复解释；复用技能不重复造轮子；长日志落盘只回传结论/摘要；结论先行；一次性批量执行；长会话定期归档
  • 区分：⚠️垃圾（临时脚本/测试副产品/诊断中间文件/无用途备份）vs ✅保留（正式成果/记忆/技能/配置/有价值日志）
3
  1. 每次沟通/跑完项目后必须删除过程垃圾：临时脚本（/tmp/*.py）、测试产物、备份残留、无价值中间产物；任务收尾立即清，不留到下次。区分：⚠️垃圾（临时脚本/测试副产品/诊断中间文件/无用途备份）vs ✅保留（正式成果/记忆/技能/配置/有价值日志）。有疑问先列清单确认再删。
  2. 节约 Token 准则：优先结构化记忆不重复解释；复用技能不重复造轮子；长日志落盘只回传结论/摘要；结论先行；一次性批量执行；长会话定期归档。
  3. 配置类任务铁律（2026-09-18 复盘）：配置完必须立即验证（调用工具/API/端口测试）；禁止"配置存在=功能可用"；验证阶段不深入分析（先直接测，失败再查日志）；验证失败优先级 重启→重配→查日志→分析代码；单个验证 ≤ 2 次 tool call，超 3 次修复仍失败才进深入分析。
