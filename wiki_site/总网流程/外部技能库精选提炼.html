把生产级 RAG 拆成十个必查模块，建系统时逐项过一遍：

  1. 切块：固定尺寸（加 10-20% 重叠）/句子/段落/语义/递归/文档感知六种策略，按体裁选——叙事文用句子级、技术文档用段落级、混合内容用递归。最常见的病就是"句子中间切断"，解法是边界感知 + 重叠。
  2. 嵌入模型：按维度分层——384 维快查、768 维均衡、1536 维高质量；代码用 CodeBERT、中文多语用 multilingual-e5。
  3. 向量库：原型用 Chroma、已有 PG 用 pgvector、高性能用 Qdrant、要托管用 Pinecone。
  4. 检索：稠密（语义）+ 稀疏（BM25 关键词）混合检索（RRF 融合），再上重排序（cross-encoder）提精度。
  5. 查询变换：查询与文档风格不一致用 HyDE（先生成假想答案再嵌入它）；召回不足用 Multi-Query（生成 3-5 个变体去重合并）；具体问题缺背景用 Step-Back（先泛化再检索）。
  6. 上下文组装：相关度优先排序、去冗余、摘要先行，硬管 token 预算。
  7. 评估：生产门槛量化——忠实度 >90%、上下文相关 >0.8、答案相关 >0.85，指标用 Precision@K / Recall@K / MRR / RAGAS。
  8. 生产模式：查询级/语义级缓存、流式检索、失败降级（缓存兜底 + 备用库）。
  9. 成本：批量嵌入、只重嵌变更文档、量化压缩索引、简单查询路由到便宜通道。
  10. 护栏：注入防护、PII 过滤、幻觉检测、答案必须带出处。

排错速查：检索不相关 → 换嵌入模型 + 加重排 + 调阈值；延迟高 → 优化索引 + 缓存 + 换快模型；质量不稳 → 先把评估体系建起来再调参。总原则：从最简单方案起步，靠评估数据决定何时加复杂度。

重点展开二：agent-protocol 的协议设计要点

2

这是给"C 套高管代理团队"定的通信协议，四块设计可直接迁移到任何多角色体系：

  • 调用语法：[INVOKE:role|question] 发问，被调方用固定四段式回答——一句话结论 + 3 条支撑数据 + 置信度（高/中/低） + 一行 caveat。回答模板本身就是质量约束。
  • 防环四硬规则（无条件执行）：① 禁自调用；② 链深上限 = 2（A→B→C 即止）；③ 同链禁回环（B 不能回调 A）；④ 每次调用携带 [CHAIN: a→b→c] 供下游自查。被阻断时必须显式声明所依赖的假设（[ASSUMPTION: ...]）而不是含糊带过。
  • 何时调用 vs 何时假设：需要域内数据且错了会实质影响结论 → 调用；方向已明确精度不关键、或已在深度 2 → 假设并声明。两个代理结论冲突时禁止悄悄二选一，必须 [CONFLICT: ...] 上浮给用户，并给出保守/概率/升级三种处置。
  • 按赌注分级质检：低赌注只做自查（来源标注、假设审计、置信打分、"So What"测试）；中赌注加跨域互检（涉及钱的 CFO 核、涉及可行性的 CTO 核）；高赌注/不可逆决策加批评者预审（最弱点/盲区/量化代价/放行结论）。对人的输出永远结论先行：每节最多 5 条、行动必须带负责人和期限、"我们或许应该"被明令禁止、没内容可报就保持沉默。

铁律只有一句：没完成根因调查，不许提出任何修复——症状修复即失败。四阶段强制串行：

  1. 根因调查：逐字读报错（常含答案）→ 稳定复现 → 查最近变更（git diff）→ 多组件系统先在各组件边界记录进出数据，定位坏在哪层再深入 → 沿调用栈向上追坏值源头。
  2. 模式比对：找同库正常工作的相似代码，逐条列差异（不许预设"这个不可能有影响"），参照实现要整篇读完而不是扫一眼。
  3. 假设与最小验证：一次只提出一个具体假设，做最小改动验证，一次只动一个变量；没效就换新假设，不许往上再叠修复。
  4. 实施：先写最简失败测试用例 → 只修根因一处（禁止"顺手优化"）→ 验证测试转绿且无回归。

止损机制：失败修复 ≥3 次 = 架构问题的信号，必须停下质疑架构本身（"是不是仅凭惯性在硬撑？"），与人讨论后决定重构还是继续。作者还配了一张"借口 vs 现实"对照表专治合理化："紧急没时间走流程"→系统化比乱试更快；"我看出问题了直接修"→看到症状 ≠ 懂根因；95% 的"查无根因"其实是查得不彻底。

重点展开四：senior-prompt-engineer 的提示词工程要点

2
  • 问题→模式对照表：输出含糊 → 加显式格式规范；太啰嗦 → 抽成 few-shot 示例；结果不稳定 → 加角色框架；缺边界情况 → 加约束边界。
  • Few-shot 设计：选 3-5 个多样化示例——简单例、边界例、复杂例、反例（什么不该输出），格式前后一致，最后用保留用例验证泛化。
  • 结构化输出四步：定 JSON schema → schema 写进 prompt → 加硬性格式指令（"只回 JSON，以 { 开头 } 结尾"）→ 机器校验输出。
  • 五大模式速查：zero-shot（简单任务）/ few-shot（要格式一致）/ CoT（推理多步）/ 角色扮演（要专业视角）/ 结构化输出（要可解析）。
  • 配套三脚本：prompt_optimizer（token 清点 + 清晰度打分 + 冗余定位）、rag_evaluator（忠实度/覆盖率报告）、agent_orchestrator（YAML 定义校验 + 流程图可视化 + token 估算）。
