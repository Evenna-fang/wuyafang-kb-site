节点 做什么 门禁 / 关键约束
N1 分诊 定 A/B/C 档 碰 secrets/不可逆删除 → 强制升 C；改流程资产/门禁脚本本身（dispatch-guard/index-guard/AGENTS/总地图）→ 升 C（治"主对话亲手改 guard"的缝隙）；自动更新检测仅每周五执行，非周五静默跳过
N2 规划 先学再画：查本地 RAG → 不够搜一手源 → 画全景图 → Clarify 查 rag/query.py "问题"；禁被动模式；返工 > 1 次回 N2；plan_hash_guard.py（计划被篡改）
N3 派单 3 问：性质→谁干(查 guard 路由)→通道活着吗(guard 实测) GATE：python3 ~/.hermes/scripts/dispatch-guard.py --task "关键词"（exit=1 拦）；派单后监督 5min/10min；guard 拒绝→补派单卡 4 核后回 N3（4 核必填拦死，5 个建议字段只提示不拦）
N4 执行 按派单卡执行，白名单"只这 N 件"，单卡单目标，DSH 批量 N=5 停手规则：撞新门/同错 3 次/空转 5 轮/超预算 2 倍；审查链 OC→DSH→Claude→Codex，轮 ≤ 2；【不免凭据】单必带 trace_hash=sha256；每 N 任务/30–60 分钟暂停，用户定 continue/rewind
N5 验收 两层验收 + E2E，自报不采信 第一层确定性（grep/schema/单测/预埋 check 复跑）+ 第二层 LLM-judge（rubric 3–5 维×1–5 分，温度 0.2，关键判 3 次）；GATE：receipt.py declare→receipt.py verify（全绿才完）；E2E 正负例 ≥ 5；探测纪律 G1–G5
N6 收口 四问 + 沉淀回流 四问（派 QwenCode）：产物落位/旧备份清/踩坑记台账/进程清（内存 < 1.5G 强清）；新规则/新资产/新坑必须当场挂进总地图对应节点

A/B/C 档回边（B8 补充，防 80% 主流量绕验收+沉淀）：A 档直出不派单（N3 跳过），但仍过 N5 最小验收（命令真跑 + 结果核对）+ N6 收口，不允许"答完就走"；B 档完整走 N3–N6；C 档走 OC 审 + E2E + receipt verify G0–G9。
