FDE（Forward Deployed Engineer，前沿部署工程师）是 Palantir 起源的角色，2026 年 Anthropic/OpenAI/AWS/微软/Google Cloud 都设了 FDE 部门。它和"售前对方案负责、咨询对建议负责"的关键区别是——FDE 对生产环境里真实发生的业务结果负责。FDE 主干要把"怎么交付一个 AI 项目"讲成一套可复用的骨架：从发现需求到设计、部署、复盘，加上定价和商业模式。这一篇是整个 L8-FDE 子域的总入口。

每阶段有明确的入口条件、关键动作、出口产物、出口检查。最常见翻车：Discover 没做完就 Deploy，以及没有 Eval 计划就不算 Design 完成。

关键规则：
- Discover 1-2 周、窄 Pilot 2-6 周是常见时间盒。
- Design 阶段方案至少 2 个，含"不做 LLM"选项。
- Deploy 要分阶段 rollout（影子模式 → 建议模式 → 自动模式）。
- Review 必须把知识沉淀到 Playbook，不能只停在 FDE 个人笔记本。

2. FDE Loop 五步闭环（OpenFDE 一手）

3

DDDR 是项目级流程；FDE Loop 是判断力沉淀的微观循环，每个阶段内部都在跑：

DEPLOY 面（驻场：连接器 · 授权 · 审计）
① OBSERVE 看 → ② ELICIT 问 → ③ INDUCE 学 → ④ ACT 做 → ⑤ EVOLVE 长
ATTRIBUTION 面（归因：哪一次判断推动了真实结果？）
  • OBSERVE：坐专家旁边看真实工作流（观察告诉你 what）。
  • ELICIT：关键时刻追问"你刚才为什么这么判断、看了什么、什么情况下会不这么做"（引出 why）。
  • INDUCE：归纳成判断单元（Judgment Unit）——触发信号、决策、理由、被放弃的备选、反转条件（只存在于专家脑子里，主动引出才拿得到）、渐进自主度（suggest→approve→auto）。
  • ACT：编译成内建治理的 Agent 配置，写操作强制审批。
  • EVOLVE：信任是挣来的——真实结果归因 +1 后才从 suggest 提升到 approve。

4. 实战提炼：智能客服端到端三原则

3

来自一个完整 RAG 项目复盘，最可迁移的三条：
1. 先上线再优化，但边界先划死：真实 query 分布只有上线后才暴露；但"什么必须转人工"第一天就要硬编码。
2. 评测集 > 模型选型：纠结"哪个模型更好"不如建一个 500 条真实 query 标注集，每次改动回归跑一遍。准确率是磨出来的，不是换出来的。
3. 架构里埋省钱设计：模型路由和语义缓存不是事后补丁，是第一天默认设计。单个本地项目复盘的口径是：月活 1 万时，全量大模型 9360 元/月 → 加模型路由（75% 走小模型）→ 加语义缓存 → 最终 2400 元/月，省 74%。本库未独立复测，不能外推为其他项目收益承诺；正式报价须重算模型单价、命中率、流量和人工复核成本。

“幻觉根因 80% 在检索层”也只是该素材的项目复盘经验，不是通用统计结论。可迁移动作是先查召回（top-k 里有没有正确答案），再分诊模型、上下文与生成；召回漏了，模型再强也可能拿错误上下文编造。

5. 定价：按成果价值，不按工时3 个重点▾ 点开看本节重点
本节重点
  • FDE 定价不是"我做了多少事你就付多少钱"，而是按客户能感知到的成果价值算
  • 核心原则（《赢利》）：价是本，量是末——你收多少钱决定利润正负，做多少单只决定规模大小
  • 报价时把准确率拆成阶段：第一版 80% 解决 80% 场景，后续迭代到 90%

FDE 定价不是"我做了多少事你就付多少钱"，而是按客户能感知到的成果价值算。核心原则（《赢利》）：价是本，量是末——你收多少钱决定利润正负，做多少单只决定规模大小。

素材转述的制造业设备维修知识库例子称：维修工每单查历史故障 20 分钟、日耗 140 小时，AI 上线后变成“看一眼 AI 提取结果、重点复核标黄项”，并给出“一年省 200 万人力”的测算。这些数字未由本库独立核验，只能演示价值定价的计算方式，不是客户案例实证或收益承诺。若按 3 天工时报价收 2 万，说明报价可能被工时锚定；真实项目必须由客户确认基线、分子分母与可实现价值后再定价。

三种模型：
| 模型 | 适用场景 | 参考逻辑 |
|------|---------|---------|
| 按成果定价 | 客户能算清省了多少人力/时间 | 节省人力 × 3-6 个月 |
| 按项目定价 | 交付物明确（知识库搭建、流程改造） | 行业基准 + 复杂度系数 |
| 按 retainer 定价 | 持续优化、上线后迭代 | 月度固定费 + 超量按次 |

实操要点：
- 第一次合作可用“小额收费 Demo + 后续转化”模式验证双方投入；5000—10000 元只是原素材示例，不是市场报价依据，价格须按范围、风险与成果另算。
- 报价时把准确率拆成阶段；80%、83%、90% 均为教学示例，不是推荐阈值。实际每阶段门槛要由基线、任务难度、错误代价与冻结 Eval 决定，不能用“超预期”替代书面验收。
- 中小微客户要把服务拆成标准化小模块卖——知识库梳理一次固定价、流程诊断一次固定价、月度维护月度固定费。不要给小客户报"整体 AI 改造方案"，他们会被价格吓跑。

6. Anthropic 工程共识（2025）

3
  • 《Building Effective Agents》："most successful implementations use simple, composable patterns rather than complex frameworks"——方案阶段先选最简单可组合的模式（prompt chaining / routing / parallelization / orchestrator-workers / evaluator-optimizer），复杂度只在被证明必要时增加。
  • 《Effective Context Engineering》："good context engineering means finding the smallest possible set of high-signal tokens"——工具要"最小可用集"，如果人类工程师都不能明确说什么场景用哪个工具，AI agent 也不行。
