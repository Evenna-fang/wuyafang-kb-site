1. 客户的真实场景触发词

3
  • 制造业：产线 SOP 是 JPG/截图，质检报告是扫描件，设备报警带照片。纯文本 RAG 检索不到「第 3 张图里那个红色按钮」。
  • 金融 / 法务：合同 PDF 里有大量印章、手写批注、扫描表格，OCR 一遍出来结构全丢。
  • 客服 / 呼叫中心：每天几万通电话，文本 RAG 处理不了 wav/mp3。
  • 医疗 / 教育：病历单、试卷、板书——天生非文本。
  • 现场作业：工人戴手套、不能拿手机打字，需要语音输入 + 语音播报。

4. 多模态 RAG 新范式3 个重点▾ 点开看本节重点
本节重点
  • 传统做法：「OCR → 切文本 → embedding → 文本向量库」
  • ColPali：把每一页 PDF 渲染成图，用 VLM 直接对「页面图」提取 patch embedding，存进向量库
  • 查询时直接检索「最像这张图的页面」，把原图 + 问题一起喂给 VLM 生成答案
3

传统做法：OCR → 切文本 → embedding → 文本向量库。
2025-2026 新做法（ColPali / VisRAG / Qwen3-VL-Embedding）：
- ColPali：把每一页 PDF 渲染成图，用 VLM 直接对「页面图」提取 patch embedding，存进向量库。查询时直接检索「最像这张图的页面」，把原图 + 问题一起喂给 VLM 生成答案。
- Qwen3-VL-Embedding / Reranker（2026.02 发布）：官方开源的多模态 embedding 模型，把文本、图、视频统一到同一向量空间。
- 优势：不丢版面——表格、印章、批注、图表全部保留视觉语义。
- 代价：向量体积比纯文本大 5-10×，需要 Qdrant / LanceDB 支持多向量索引。

# multimodal_demo.py —— 语音进 → VLM 理解图 → 语音出
from funasr import AutoModel
from openai import OpenAI

# 1. ASR：录音转文字
asr = AutoModel(model="iic/SenseVoiceSmall", vad_model="fsmn-vad", device="cuda:0")
query_text = asr.generate(input="/data/worker_voice.wav", language="zh", use_itn=True)[0]["text"]
print("工人说：", query_text)

# 2. VLM：读图回答（Qwen2.5-VL via vLLM OpenAI 兼容 API）
vlm = OpenAI(base_url="http://127.0.0.1:8000/v1", api_key="EMPTY")
response = vlm.chat.completions.create(
    model="qwen2.5-vl",
    messages=[{
        "role": "user",
        "content": [
            {"type": "image_url", "image_url": {"url": "file:///data/sop_page_03.jpg"}},
            {"type": "text", "text": query_text},
        ],
    }],
    temperature=0.1,
)
answer = response.choices[0].message.content
print("答案：", answer)

# 3. TTS：文字转语音（CosyVoice3 零样本克隆）
from cosyvoice.cli.cosyvoice import CosyVoice3
cosy = CosyVoice3("iic/CosyVoice-300M")
for out in cosy.inference_zero_shot(
    text=answer,
    prompt_speech_16k=load_wav("/ref/operator_voice.wav"),
    prompt_text="参考音频原文转写",
):
    save_wav("/out/reply.wav", out["tts_speech"])

from funasr import AutoModel
from funasr.utils.postprocess_utils import rich_transcription_postprocess

model = AutoModel(
    model="/models/sensevoice-small",
    vad_model="fsmn-vad",
    punc_model="ct-punc",
    device="cuda:0",
)

def transcribe(path: str, language="zh") -> str:
    res = model.generate(
        input=path,
        language=language,
        use_itn=True,
        batch_size_s=60,
    )
    return rich_transcription_postprocess(res[0]["text"])

# index_pdf.py —— 每页 PDF 当一张图
import fitz  # PyMuPDF
import qdrant_client
from qdrant_client.models import Distance, VectorParams, PointStruct
from colpali_engine.models import ColQwen2Processor, ColQwen2

# 1. 加载 ColPali（或换成 Qwen3-VL-Embedding）
processor = ColQwen2Processor.from_pretrained("/models/colqwen2")
model = ColQwen2.from_pretrained("/models/colqwen2").cuda().eval()

# 2. 初始化 Qdrant（支持多向量 MAX_SIM 度量）
client = qdrant_client.QdrantClient(path="/data/qdrant")
client.recreate_collection(
    collection_name="pages",
    vectors_config=VectorParams(size=128, distance=Distance.COSISM),
)

# 3. PDF 每页渲染成图 → 提取 patch embedding
doc = fitz.open("/data/contract.pdf")
for page_no, page in enumerate(doc):
    pix = page.get_pixmap(dpi=150)
    img = Image.frombytes("RGB", (pix.width, pix.height), pix.samples)
    inputs = processor.process_images([img]).to("cuda")
    with torch.no_grad():
        patch_emb = model(**inputs).cpu().numpy()[0]  # shape: [num_patches, dim]
    # ColPali 每页是一个 multi-vector（num_patches 个向量）
    client.upsert(
        collection_name="pages",
        points=[PointStruct(id=hash((doc.name, page_no)) & 0x7fffffff,
                            vector=patch_emb.tolist(),
                            payload={"doc": doc.name, "page": page_no})]
    )

步骤 5：查询时多模态检索 + VLM 生成

3 
def multimodal_ask(question: str, top_k=3):
    # 1. 用同模型编码 query（multi-vector）
    q_inputs = processor.process_queries([question]).to("cuda")
    with torch.no_grad():
        q_vec = model(**q_inputs).cpu().numpy()[0]

    # 2. Qdrant 多向量检索（MaxSim）
    hits = client.search("pages", query_vector=q_vec, limit=top_k)

    # 3. 取回对应页面图
    pages_imgs = []
    for h in hits:
        pdf = fitz.open(h.payload["doc"])
        pix = pdf[h.payload["page"]].get_pixmap(dpi=150)
        pages_imgs.append(Image.frombytes("RGB", (pix.width, pix.height)))

    # 4. 把页面图 + 问题喂给 Qwen2.5-VL
    return vlm_chat(images=pages_imgs, question=question)

常见坑

2
  1. VLM 显存算错：只算了 LLM 权重，忘了 ViT + KV cache。→ 预留 30% 余量。
  2. ColPali 索引体积爆炸：每页几百个 patch 向量，1 万页 PDF ≈ 几亿向量。→ 限制 top-k，用 Qdrant on-disk HNSW，别全入内存。
  3. ASR 热词没定制：产品名、型号、人名识别错。→ SenseVoice 支持 hotword 参数，上线前必须跑一轮热词表。
  4. TTS 克隆音色侵权：直接克隆员工/客户声音有合规风险。→ 合同里明确录音授权，或用预置音色库。
  5. 多模态 RAG 还是走 OCR 老路：切完图再 OCR 再 embedding，等于没做多模态。→ 要么上 ColPali，要么至少把图本身挂到 chunk 上让 VLM 现场读。

本库真实落地（源码核对，2026-11-04）

  • 多模态交付在本库的真实边界：文档形态多、模态只有文本（rag/ingest.py L67 EXCLUDE_DIRS，grep 可验）：
    python EXCLUDE_DIRS = ( "node_modules", ".git", "dist", "build", "__pycache__", ".venv", "venv", "site-packages", "__MACOSX", ) # 路径子串匹配: 备份/历史归档不应进正文库 EXCLUDE_PATH_PARTS = ( "books.bak-", # raw/weread/books.bak-*/ 书籍备份 "plans-历史方案", # raw/practice/plans-历史方案/ 历史方案副本 "/archive/", # raw/_task_orders/archive/ 流程历史版本 )
    入库覆盖面：Markdown 与 Python 等文本类 + 结构文件；图片/PDF 扫描件/视频没有解析路径。多模态交付=客户材料五花八门时，本库的答案是"先把材料转成 md 再入库"，而不是在管线里塞一堆解析器。单文件上限 150 万字符（MAX_FILE_CHARS，注释里记录了"1.02 亿字符的语料撑爆入库导致后续 192 个课件没进库"的真实事故）。
  • 表格与代码块的保护（rag/ingest.py L397 _split_table_segments() / L434 _split_table_block()）：表格整块保留（表头+数据行必须同 chunk），代码围栏整段保留——多模态材料里最常见的"结构化片段被切散"在这里被处理。
  • 和课件讲法的差异：课件多模态常用 MinerU/Docling 做版面解析 + VLM 抽图注；本库暂无 PDF/图片解析。若客户交付材料以 PDF 为主，需按课件补解析器，并把 chunk_type 细分为 prose/table/code/ocr（本库现只有 raw/skill/note/decision/error 五类）。
