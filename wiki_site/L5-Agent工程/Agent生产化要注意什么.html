Agent 生产化要注意什么：错误处理、重试、观测、安全

← 返回总入口

这个问题的答案是什么

一句话：demo 和生产的差距不在"能不能跑"，在"跑挂了怎么办"——7 本书里只有《Building Agentic AI Systems》系统讲了这件事，其他 6 本基本只教怎么搭，不教怎么修。

生产化必备 4 件事： 1. 错误处理 & 重试：LLM 会幻觉、API 会超时、工具会报错——不处理就是裸奔。 2. 观测 & 日志：出问题时能回答"哪一步、哪个 prompt、哪个工具调用出了错"。 3. 安全 & 权限：高风险操作必须有人审，不能让 Agent 自己转账自己删库。 4. 状态检查点：长任务跑了 30 步挂了，能不能从第 25 步续跑，而不是从头再来。

详细内容

一、错误处理：LLM 不是可靠软件

常见错误源（7 本书汇总）： - 幻觉：模型编造不存在的 API 返回、编造数据库记录。《动手做》划线上有名言："如果你没有这方面的知识，一定不要胡说，要查阅相关的资料"——这是给模型的提示，但人也得防。 - 数字/数学短板：《零基础搭建》第 3 章专门讲"为什么 AI 无法准确识别数字、为什么有数学逻辑短板"——涉及金额、数量的必须外挂代码执行，不让模型心算。 - 工具调用失败：FC 传错参数、API 返回 500、超时。 - 循环失控：ReAct 跑到 max_iterations 还没结束。

对策： - 每个工具调用包 try/except，失败后让 LLM 决定是"换工具"还是"问用户"。 - 设 max_iterations 硬上限（一般 10-20 步）。 - 高风险操作（写库、发邮件、删文件）必须人工确认——MCP 原生支持这个弹窗（《MCP 原理与实战》2.4 节）。

二、观测 & 日志：没有日志就没有生产

《零基础搭建》划线上第 15 条（1777 人划）讲得最实在："LangChain 提供了多种内置回调处理器……每次用户提问、链的运行状态、模型的输出结果都被详细记录到日志文件中，若出现用户反馈'回复异常'，就能通过日志快速定位问题所在。"

生产环境的日志最少要记什么： - 输入 prompt（完整版，含工具描述）。 - 每一步的工具调用：工具名、参数、返回结果、耗时。 - 最终输出和用户反馈（好/坏）。 - 异常堆栈。

《Building Agentic AI Systems》强调：要能"清晰地解释自身的决策方式"——这是信任的基础，不只是 debug 用。

三、安全 & 权限：Agent 是有权限的程序

《MCP 原理与实战》2.4 节是 7 本里讲得最细的： - OAuth 授权：第三方服务调用走标准 OAuth，不暴露用户名密码。 - 令牌传递：通信过程用 token，不用原始凭证。 - 高风险操作确认弹窗："大模型想执行删除操作，是否允许？"——用户同意才放行。 - 工具描述标注影响等级：只读 vs 写操作必须在 schema 里说清，主机端才能分级管控。

《Building Agentic AI Systems》从企业视角补充： - 数据隐私：要"超越传统生成式 AI 保障的增强方法"。 - 偏见：用有代表性的多样训练数据、定期监控、收集利益相关者反馈。 - 自主决策的边界："AI 的自主性涉及系统根据内部程序自主决策的能力"——但企业级场景必须有人类最终否决权。

四、状态检查点：长任务能断点续跑

《Building Agentic AI Systems》明确说："对决策状态进行版本控制，并结合检查点机制，可以在检测到异常或故障时使系统恢复到稳定状态。"

实操： - 每完成一步，把当前状态（已完成步骤、中间结果、下一步计划）落盘。 - 崩溃后从最近检查点恢复，而不是从头跑。 - 长任务（>30 步）必须有这个，否则一次崩溃浪费所有 token。

五、常见的生产化坑（跨书反推）

  • 不设超时：LLM 调用挂死，整个 Agent 跟着挂。
  • 不设速率限制：Agent 循环触发 API 限流，直接被封。
  • 把 API key 写进 prompt：MCP 用环境变量、不写进 system prompt。
  • 多 Agent 之间没有共享状态：每个 Agent 自己记，最后对不上账。
  • 不做评估：上线后只看"能不能跑"，不看"跑对了多少"——《Building Agentic AI Systems》强调"定期监控模型性能"。

来自哪些书的哪些观点

  • 《Building Agentic AI Systems》：唯一一本系统讲 Trust / Safety / Ethics 的；检查点恢复；偏见多层次治理；自主决策边界。
  • 《MCP 原理与实战》（李艮基）：安全机制最具体——OAuth、确认弹窗、工具影响等级标注、凭证环境变量化。
  • 《一本书讲透 MCP》：MCP 是"AI Agent 互联网"的基座——安全和互操作性是绑定的。
  • 《零基础搭建》（徐洋）：回调处理器 = 日志系统；数学短板必须外挂工具。
  • 《动手做 AI Agent》（黄佳）：幻觉问题、"不要胡说要查资料"——给模型的 prompt 也要写这一条。
  • 《大模型项目实战》（高强文）：Gradio 回调线程阻塞的坑——UI 要异步、Crew 要异步线程——这是工程化细节。

下一步动作： 1. 把 Hermes 的 error-ledger 技能从"记录错误"升级到"自动应用已验证修复方案"——这是生产化闭环。 2. 给六员系统加统一的"高风险操作确认"——参考 MCP 的弹窗设计，写操作前自动问人类。 3. 做一份简单的评估集（20-50 个真实 query），每次改 prompt/换模型后跑一遍，看成功率变化——这是《Building Agentic AI Systems》"定期监控"的最小可行版。
