核心模型: 三层图记忆

G-Memory 把多 Agent 协作中的记忆按"抽象程度"分三层, 每层是一张图:

层 存什么 谁用 成本
Insight Graph (泛化经验层) 从多次任务里抽象出来的教训/模式/踩坑经验, 如"flaky 测试不要盲目重跑" 编排层(Hermes)、其他 Agent 复用经验 最低(短摘要)
Query Graph (任务指纹层) 任务指纹 → 派给哪个 Agent → 结果如何, 可复用"这类任务该派谁" 编排层(Hermes) 派单时查 中
Interaction Graph (原始轨迹层) 完整的 Agent 交互原始记录/对话/代码 diff 工程层(Claude/Codex) debug 时多跳追溯 最高(长上下文)

三层互相引用: Interaction 沉淀为 Query, Query 抽象为 Insight; 反向也能从 Insight 下钻到具体 Query 和原始 Interaction。

多视图并行检索

同一张图上, 检索时并行走 4 种边类型: - semantic: 语义相似的记忆 - temporal: 时间邻近(上周/昨天发生了什么) - causal: 因果链(A 导致 B) - entity: 共享实体(同一个项目/同一个错误码)

双向链路: 召回时 insight 在前(先给经验), evidence 在后(再给原始证据支撑)。

对六员的价值

  1. error-ledger 升级: 现在 error-ledger 只有"错误→修复"单层, 按 G-Memory 模型可拆成:
  2. Insight 层 = 泛化经验(~/shared-skills/insight-log.md, 六员共享)
  3. Query 层 = 任务指纹→派谁→结果
  4. Interaction 层 = 原始 trace 归档(state.db / cron output)
  5. 角色差异化检索深度: Hermes 编排只查 Insight(低成本), Claude/Codex 工程查全三层多跳——对应 BudgetMem 的 λ 参数化。
  6. 跨 Agent 经验复用: 一个 Agent 踩的坑沉到 Insight, 其他 Agent 直接召回, 不用重新踩(对应 error-ledger 台账铁律"同一坑不踩第二次")。

反例

  • ❌ 所有记忆都塞一层长上下文 = 没有分层, Insight 和原始轨迹混在一起, 编排层也被迫付高成本
  • ❌ 只有 Insight 没有原始轨迹 = 抽象过头, 工程 debug 时找不到具体证据
  • ❌ 只有原始轨迹没有 Insight = 每次都从零推理, 多 Agent 不复用经验
