Agent 记忆保鲜与冲突治理

一句话结论

persistence ≠ truth —— 存得住不等于还是真的。 这是全行业通病：Mem0 / Letta / Zep 都只优化"存 + 检索"，都没有机制发现记忆已经过期。

硬数字： - TimeQA 上最好模型 46% vs 人类 87% - LongMemEval 上商业助手跨会话掉 30% 准确率

来源：Kymata Labs 2026 白皮书 https://kymatalabs.com/research/memory-staleness

记忆半衰期 5 档（可直接照抄的分档）

档位 例子 半衰期
永久 生日、老家 几十年
慢 住址、雇主 几年
中 当前项目、偏好 几个月
快 今天在干嘛 几小时
易变 价格、额度、可用性 几分钟

与 知识库保鲜与TTL治理 的三分档同源：按"内容会多久变一次"定寿命，而不是按"多重要"定。

冲突判定：别让 LLM 当裁判

这是本主题最反直觉、也最有价值的一条实证：

  • arXiv:2606.01435 实测：让 LLM 判断"哪条记忆更新"，Mem0 只有 18%、Zep 只有 7% 准确率
  • 换成代码 max(timestamp / serial)：直接到 78%（+60 个百分点）

铁律：LLM 只负责识别"这两条是同一件事"，"哪个更新"必须交给代码（取最新 timestamp）。

三家成品实测对比（2026 benchmark）

产品 架构 冲突解决率 备注
Zep 时序图谱 95.8%（Recall@5 93.6%） 胜在 bi-temporal 双时间轴（写入时间 + 事实为真时段）
Letta / MemGPT OS 式分层记忆（core / recall / archival） 89% 分层清晰，可解释
Mem0 向量 + 实体图 76.5% 起步快，冲突处理最弱

来源：https://agentic-pulse.dev/blog/2026-10-02-mem0-vs-letta-vs-zep-ai-agent-long-term-memory-benchmark-2026 选型启示：历史事实会被"改写"的场景（人事、价格、政策）优先时序图谱；只做偏好沉淀用向量+实体图即可。

Kymata 5 个控制项（按性价比排序，本周可落地）

  1. 写入时打 last_verified 时间戳 + fact_class 档位标签 —— 最便宜，解锁其他所有控制项
  2. 过期记忆"可见地标红"，不能静默当新事实端出来（治"自信地撒谎"）
  3. 后台主动重验证"高频被查但久未验证"的记忆
  4. 保留 contradiction-on-write 作为地板而不是天花板
  5. 每条记忆存 provenance（来源），无源记忆信任度最低

Ebbinghaus 时间衰减模型

每条记忆带连续衰减率：

  • 召回成功 → 曲线后移（强化）
  • 长期不召回 → 衰减驱逐

TTL_TIERS 示例：immutable(0) / long(0.001, 1年) / short(0.01, 30天) / session(0.1, 1天)

与 双进程范式 的门控正交：门控决定"要不要慢下来"，衰减决定"这条还值不值得存"。

信念修订追踪（DCPM，arXiv:2606.09483）

  • 每条记忆带时间戳指针，新事实覆盖旧事实但保留演化链，不物理删除
  • 多 Agent 观点漂移：同一问题不同 Agent 的回答按时间轴展开，可看到共识形成 / 破裂
  • 适用长程任务：跨周 / 跨月 Agent 任务不会被过时事实误导

与 G-Memory 的 temporal edge 天然兼容 —— DCPM 可视作 temporal edge 的 schema 细节指南。

反例（不要这么做）

  • ❌ 只做"存 + 检索"，不做过期发现 → persistence ≠ truth，越用越错
  • ❌ 让 LLM 判断"哪条更新" → 实测 7–18% 准确率，比抛硬币还差
  • ❌ 过期记忆静默返回 → 模型会"自信地撒谎"，比"答不知道"危害更大
  • ❌ 冲突时物理删除旧版本 → 丢失演化链，无法回溯共识怎么形成的
