CrewAI 源码解析：对我们的多智能体优化有什么用（2026-10-21）

一句话：CrewAI 是和我们六员同类的多智能体框架，我们不换框架，但它的源码里有 6 个能直接抄的工程做法，能让派单更靠谱。 想看源码细节（真实代码片段）→ CrewAI源码解析-可抄工程实现-20261021.md；想看七条机制对照 → CrewAI精华吸收对照-20261021.md。

它是什么

一个 Python 多智能体框架：给每个 Agent 定义"角色+目标+背景"，给每个 Task 定义"做什么+完成长什么样+依赖谁"，然后按顺序或分层跑。我们的六员（Hermes/DSH/Claude/Codex/OpenClaw/Qwen）是同样思想的自研版。

对我们最有用的 3 个做法（白话版）

  1. 任务要写清"完成长什么样"，而且直接发给干活的——不是写给旁人看的备注。我们的派单卡也要把"完成态"写进任务正文，执行者才知道做到什么程度算完。
  2. 任务之间的依赖要"传产物"不是"标个记号"——前置任务的产出直接拼进下一个任务的输入。我们"等 S5 收口再做 X"现在靠口头，改成显式传产物更稳。
  3. 限流和次数上限是程序强制的，不靠自觉——CrewAI 把"每分钟最多几次""最多迭代几轮"写死在执行层。这正好治我们今天撞的 429 限流、执行者反复重试卡住。

结论

不换框架（切换成本太大，且我们已有 LangGraph 同级能力），抄上面 3+3 个实现进派单卡模板和任务台账，让"派出去的单"更可控。
