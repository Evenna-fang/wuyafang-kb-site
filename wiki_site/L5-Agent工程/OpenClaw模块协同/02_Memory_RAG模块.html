OpenClaw 核心模块 —— Memory RAG（记忆与检索融合）

为什么需要 Memory RAG

在多智能体系统中，记忆（Memory） 用于保存上下文、历史对话、业务状态；检索（Retrieval） 则负责快速定位相关信息。单独的记忆或检索往往不足以满足复杂业务需求： - 记忆的线性增长导致查询效率下降； - 检索只能返回文档片段，缺少业务状态的时序关联。

Memory RAG（Retrieval‑Augmented Generation） 将两者融合：先通过向量检索定位相关文档，再在记忆库中补充时序状态，实现 上下文感知的生成，从而提升回答的准确性与一致性。

体系结构概览

+-------------------+      +----------------------+      +-------------------+
|   用户请求（Task）| ---> |   Routing（分发）      | ---> |   Memory RAG 组件  |
+-------------------+      +----------------------+      +-------------------+
                                                                |
                                                                v
                           +--------------------------+   +------------------------+
                           | 向量检索引擎（Chroma）   |   | 时序记忆数据库（SQLite） |
                           +--------------------------+   +------------------------+
  • 向量检索引擎：使用 Chroma（或 Zilliz）存储文档向量；支持 Hybrid（dense + sparse）检索，返回 Top‑k 片段。
  • 时序记忆数据库：采用 SQLite + JSON 列，记录每一次 Agent 调用的输入、输出、状态以及时间戳。
  • RAG 流程：
  • Chunk 化：用户请求先进行语义 Chunk；
  • 向量检索：返回候选文档片段；
  • 记忆筛选：在 SQLite 中检索符合 session_id、task_type 的历史记录；
  • 融合：把检索到的文档与时序记忆拼接为 Prompt；
  • 生成：交给模型（Claude、OpenAI、DeepSeek）生成答案。

图：Memory RAG 查询数据流

sequenceDiagram
    participant R as Routing
    participant M as MemoryRAG
    participant V as Chroma 向量库
    participant T as SQLite 时序记忆
    participant L as 模型

    M->>T: 写回本次输入输出与时间戳
    M-->>R: 返回答案

关键配置（openclaw.json）

{
  "memory": {
    "rag": {
      "enabled": true,
      "vectorStore": {
        "type": "chroma",
        "path": "~/openclaw/data/chroma",
        "embeddingModel": "bge-m3",
        "topK": 8
      },
      "temporalStore": {
        "type": "sqlite",
        "path": "~/openclaw/data/memory.sqlite",
        "purgeAfterDays": 180
      },
      "fusionStrategy": "concat",   // concat | weighted | rerank
      "weights": {
        "vector": 0.6,
        "temporal": 0.4
      }
    }
  }
}
  • topK 控制检索返回数量；
  • fusionStrategy 支持 加权融合（在生成前对每段打分）或 rerank（调用二次检索模型进行排序）。

动态查询示例（Python）

from openclaw.rag import MemoryRAG

rag = MemoryRAG()
prompt = rag.build_prompt(
    user_query="本月的用户活跃度下降原因是什么？",
    session_id="sess-20261001",
    task_type="analysis"
)
# prompt 已经包含向量检索结果 + 时序记忆
print(prompt)

失效检测与恢复

  1. 向量库损坏：chroma check --path … 若返回错误，执行 chroma rebuild 并从备份恢复；
  2. 时序记忆库锁死：SQLite 锁超时时，openclaw memory reset --mode sqlite 会自动切换到 WAL 模式并进行 VACUUM；
  3. 检索准确率下降：监控 openclaw rag eval --metric recall，当 Recall < 0.7 时自动提示 重新 embeddings（openclaw rag reembed）。

监控指标（Prometheus）

  • openclaw_rag_vector_hits_total – 向量检索命中次数；
  • openclaw_rag_temporal_hits_total – 时序记忆命中次数；
  • openclaw_rag_fusion_latency_seconds – 融合构建 Prompt 所用时间；
  • openclaw_rag_query_total{status="error"} – 异常查询计数（库文件损坏、超时等）。

常见坑点 & 推荐方案

症状 可能原因 解决方案
检索返回空 向量库未同步 / 文档未嵌入 openclaw rag index --path <doc_dir> 并确认 embeddingModel 正常；
时序记忆查询慢 SQLite 未开启 WAL，磁盘 IO 瓶颈 openclaw memory config --sqlite-wal true；增加 PRAGMA journal_mode=WAL；
融合 Prompt 超长 topK 设得过大或 fusionStrategy=concat 将 topK 调低至 6 并改为 weighted 融合；
RAG 生成出现幻觉 检索片段噪声大 启用 rerank 并使用 bge-reranker 进行二次过滤；

与其他模块的协同

  • Routing 会在任务拆分后为每个子任务指明 rag.enabled=true，让 Memory RAG 自动参与；
  • Sandbox 提供安全的执行环境，防止检索到的恶意代码被误执行；
  • Subagent 负责将 RAG 生成的答案包装为 Action（如写入数据库、触发外部 API），并将状态写回时序记忆，实现闭环。

小结

Memory RAG 是 OpenClaw 多模态协作的核心增效器：通过向量检索提供语义上下文、通过时序记忆提供业务状态，实现 “记得过去、懂得现在、生成未来” 的完整闭环。正确的配置、健康的监控以及对常见失效场景的快速定位，是确保系统在生产环境中高可用的关键。
