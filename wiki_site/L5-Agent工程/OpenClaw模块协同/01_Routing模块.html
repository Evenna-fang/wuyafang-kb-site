OpenClaw 核心模块 —— Routing（任务路由）

背景与定位

OpenClaw 作为多智能体协同平台的核心组件之一，承担 任务分发 与 路由调度 的职责。它位于用户请求入口与具体执行子代理（Agent）之间，负责将高层业务需求划分为可由各子代理执行的子任务，并根据策略将这些子任务路由到合适的执行环境（本地进程、容器、远程服务等）。

设计目标

  1. 高可用：路由层必须在 Gateway 异常、子代理崩溃时仍能提供降级路径；
  2. 可扩展：支持插件化的路由策略，能够随时接入新型调度器（如 K8s 调度、云函数等）；
  3. 可观测：提供完整的路由日志与监控指标，便于运维排障。

关键概念

  • Task（任务）：用户通过 OpenClaw CLI 或 API 发送的原始请求。
  • Job（作业）：Task 在内部拆解后的最小执行单元，包含 job_id、payload、deadline、priority 等字段。
  • Router（路由器）：实现 route(job) -> target 接口的组件。默认实现为 RoundRobinRouter，可通过 router.custom 配置自定义实现。
  • Target（目标）：具体的执行环境描述，例如 {type:"local", runtime:"codex"}、{type:"container", image:"openclaw/agent:2026.9"}。

路由流程（伪代码）

func Dispatch(task Task) []Job {
    // 1️⃣ 将原始任务拆分
    jobs := splitTask(task)
    // 2️⃣ 为每个 Job 选择目标
    for i, job := range jobs {
        target := router.Route(job)
        jobs[i].Target = target
    }
    // 3️⃣ 将 Job 写入调度队列
    queue.Enqueue(jobs)
    return jobs
}

拆分策略

  • 命令式拆分：基于正则或关键词匹配，将复合指令拆成多个子指令；
  • 结构化拆分：如果 Task 中提供了 JSON/YAML 结构，则直接映射为多个 Job；
  • AI 辅助拆分：当任务含有自然语言描述时，OpenClaw 会调用内部 Agent（如 Claude）进行意图解析并返回拆分方案。

可配置项（openclaw.json 示例）

{
  "routing": {
    "defaultRouter": "roundRobin",
    "routers": {
      "roundRobin": {
        "type": "builtin",
        "maxConcurrency": 32
      },
      "priority": {
        "type": "builtin",
        "policy": "priorityQueue",
        "preemptive": true
      },
      "k8s": {
        "type": "plugin",
        "pluginPath": "~/openclaw/plugins/k8s-router.so",
        "namespace": "openclaw",
        "maxPods": 64
      }
    }
  }
}
  • defaultRouter 决定默认使用的路由器；
  • maxConcurrency 控制同一目标的并发上限，防止资源争用。

监控与日志

OpenClaw 将路由相关的指标注入到 Prometheus，主要指标包括： - openclaw_router_jobs_total{router="roundRobin"} – 已调度的作业总数； - openclaw_router_job_latency_seconds{router="priority"} – 作业路由延迟； - openclaw_router_target_active{target="local"} – 当前活跃目标数量。

日志格式（JSON）示例：

{"time":"2026-10-30T12:34:56Z","level":"INFO","msg":"job routed","job_id":"c7f9a1","router":"priority","target":"container","latency_ms":12}

故障恢复机制

  1. 目标不可用：路由器在发现 target.health==false 时，会自动降级至 fallbackTarget（默认本地 Runtime）。
  2. 作业超时：若 job.deadline 超过 target.timeout，调度器会重新分配至 backupTarget 并记录 retryCount。
  3. 幂等保证：所有 Job 必须实现幂等 ID（job_id），路由层在重复投递时会检测已有记录并直接返回成功响应，避免业务层面重复执行。

常见坑点

  • 插件路径错误：router.k8s.pluginPath 必须是绝对路径且文件可执行，否则路由器启动失败，Gateway 会报 Plugin load error；
  • 并发阈值过低：默认 maxConcurrency=32 在高负载场景会成为瓶颈，需要根据业务峰值调高；
  • 日志噪声：开启 debug 模式会产生大量 job routed 日志，建议在生产环境关闭 debug。

小结

Routing 模块是 OpenClaw 能够高效调度多子代理的基石。通过灵活的插件化路由器、可配置的拆分策略以及完善的监控体系，开发者能够在保证系统可靠性的前提下，快速实现业务需求的横向扩展与纵向压测。后续章节会结合 Memory RAG、Sandbox 与 Subagent，展示完整的端到端任务流转图。
