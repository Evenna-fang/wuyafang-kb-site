OpenClaw 模块协同流程图

本文件通过 Mermaid 展示 OpenClaw 四大核心模块的端到端协同路径，涵盖从用户请求到最终结果返回的完整闭环。

    A[用户请求（Task）] --> B[Routing 路由]
    B --> C{是否需要 RAG?}
    C -->|是| D[Memory RAG]
    D --> E[检索向量库 & 时序记忆]
    E --> F[融合 Prompt]
    F --> G[Subagent 调度]
    G --> H[Sandbox 隔离执行]
    H --> I[子代理（Model/Script）执行]
    I --> J[结果写回 Memory RAG]
    J --> K[生成最终答案]
    K --> L[返回给用户]
    C -->|否| M[直接 Subagent]
    M --> H

流程说明

  1. 用户请求 通过 OpenClaw CLI、API 或 UI 进入系统。
  2. Routing 根据任务属性（标签、优先级、是否需要 RAG）决定后续路径。
  3. Memory RAG（若需要）进行向量检索与时序记忆融合，生成富上下文 Prompt。
  4. Subagent 调度 根据 Prompt 的 runtime（如 Codex、OpenClaw、Custom）创建对应 Subagent 实例。
  5. Sandbox 为 Subagent 提供 进程/容器级别的安全隔离，并限制资源使用与网络访问。
  6. 子代理执行 完成业务逻辑（代码生成、API 调用、文档摘要等），输出 stdout 与状态。
  7. 结果写回 Memory RAG，将执行产物、日志、资源使用写入时序记忆，供后续任务或审计使用。
  8. 生成最终答案（可能再次走 RAG 进行二次检索），并通过 OpenClaw Gateway 返回给用户。

关键链路指标（Prometheus）

  • openclaw_routing_latency_seconds
  • openclaw_rag_fusion_latency_seconds
  • openclaw_subagent_spawn_latency_seconds
  • openclaw_sandbox_execution_seconds
  • openclaw_response_total

故障回退路径

  • Routing 失效 → 使用 默认本地 Runtime（OpenClaw）直接执行。
  • RAG 检索为空 → 直接跳过 RAG，进入 Subagent（纯生成）。
  • Sandbox 资源超限 → 降级为 本地进程（不启用网络隔离），并记录 SBOX004 错误。
  • Subagent 超时 → 触发 重试（最多 maxRetries），若仍失败则返回错误给用户并记录 SUB004。

    RUN --> TO{"是否超时"}
    TO -->|"是 且未超 maxRetries"| RUN
    TO -->|"是 重试耗尽"| ERR["返回错误 记录 SUB004"]
    TO -->|"否"| DONE["写回 Memory RAG 并返回"]
    L --> DONE
