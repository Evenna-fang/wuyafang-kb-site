Agent 循环怎么设计：ReAct / Plan-and-Execute / Reflection 怎么选

← 返回总入口

这个问题的答案是什么

一句话：三种循环不是"哪个更先进"，而是"任务复杂度"的分层——小任务用 ReAct 边想边走，大任务用 Plan-and-Execute 先规划再执行，要质量的任务叠一层 Reflection 做自我批评。

循环 核心节奏 适合的任务 不适合
ReAct 观察→思考→行动→再观察，循环到结束 步骤 ≤ 5、路径不明确、需要边走边看 步骤多、要全局最优、容易跑偏的长任务
Plan-and-Execute 先一次性拆解成 N 步计划，再逐步执行 任务清晰、步骤 ≥ 5、可分解（库存调度、标书阅读） 路径高度不确定、计划做了也白做
Reflection / Introspection 产出→自我批判→修订 高质量要求（代码、文案、法律文书） 低成本高并发任务（反思贵）

判断口诀：默认先上 ReAct，跑偏了/超步数了加 Planner，产出质量不满意加 Reflection。三层可以叠加——Plan-and-Execute 的每一步内部是 ReAct，最终产出再过一遍 Reflection。

详细内容

一、ReAct：最经典的"边想边干"

《动手做 AI Agent》（黄佳）第 6 章直接拿 LangChain 的 create_react_agent 跑鲜花定价。ReAct 的设计哲学（原书引述）："在动态和不确定的环境中，有效的决策需要持续的学习和适应，以及快速将推理转化为行动的能力，即形成有效的观察—思考—行动—再观察的循环。"

《大模型项目实战》（高强文）基于 AgentScope 的 ReAct Agent 也是同一套：UserAgent 接任务，ReActAgent 走 Reason-Acting 迭代。

ReAct 的坑： - 步数不可控——模型可能在第 10 步还在转圈。必须设 max_iterations。 - 计划视野短——它不看全局，容易走偏。所以只适合"边走边看"的活。

二、Plan-and-Execute：先想清楚再动手

《动手做 AI Agent》第 7 章是 Plan-and-Execute 的标准样例：物流管理、库存调度。核心思路： 1. Planner 一次性把任务拆成 N 步（LLM 生成结构化计划）。 2. Executor 逐步执行，每一步是一个小的 ReAct。 3. 可选 Replanner：执行完几步后回头看是否要调整剩余计划。

《大模型项目实战》里 BabyAGI 是这个范式的极简原型——"根据先前任务的结果和预定义的目标创建任务"，用向量库存任务上下文。原书评价"代码量虽小，但方法论起了意想不到的效果"。

什么时候用：任务可分解、步骤多、路径可预期。发票识别、标书阅读、库存调度都是典型例子。

什么时候不用：任务本身就模糊（"帮我调研一下竞品"）——Planer 第一次拆的步骤就是错的，白规划。

三、Reflection：给自己挑毛病

《Building Agentic AI Systems》第 4 章专门讲 Reflection and Introspection。核心是：Agent 产出后，让另一个 LLM 调用对产出做批判（"这个定价合理吗？数据来源可靠吗？"），把批评喂回去让原 Agent 修订。

Reflection 的价值场景： - 代码生成——写完跑一下测试，过不了就反思。 - 文案生成——写完让 Critic 打分。 - 个性化推荐——《Building Agentic AI Systems》提到"反思型代理"用于营销推荐，通过识别"某些类型的推荐总是低分"调整策略。

Reflection 的坑：贵。每一步都反思 = token 翻倍。只在最终产出或关键节点用，不要每步都反思。

四、组合拳：现实里的 Agent 长什么样

《Building Agentic AI Systems》第 6 章提出 Coordinator-Worker-Delegator 三层编排： - Coordinator：接收任务、做规划（相当于 Planer）。 - Delegator：把子任务分派给 Worker。 - Worker：具体执行，内部是 ReAct 循环。

再叠加 Reflection 在关键节点，就是一个生产可用的 Agent 骨架。

来自哪些书的哪些观点

  • 《动手做 AI Agent》（黄佳）：ReAct/Plan-and-Execute/AutoGen/MetaGPT 全是同一本书的章节，说明这三种循环是教材级标准件。
  • 《大模型项目实战》（高强文）：BabyAGI = Plan-and-Execute 的极简版；CrewAI = 多角色版 Plan-and-Execute。
  • 《Building Agentic AI Systems》：Reflection、Coordinator-Worker-Delegator 是企业级架构；高风险任务"投入更多计算资源做更深入推理"——自适应分配算力。
  • 《零基础搭建》（徐洋）：低代码平台的"工作流节点"其实是 Plan-and-Execute 的可视化版本——每个节点是一步，连线是执行顺序。
