一、MCP 生态（Model Context Protocol）

定义：Anthropic 提出的开放协议，标准化「Agent ↔ 外部工具/数据源」接入（server/client，JSON-RPC）。一个 MCP server 暴露一组工具，任意兼容客户端即插即用。

来源: raw/agent-dev/MCP生态调研-2026-20260928.md（mcpmanager.ai 月搜索榜单，二手综合）

2026 生态格局

  • 公开 MCP server 已破 10,000 个，头部集中度高：前 17 个覆盖 80% 搜索量。
  • 月搜索头部：Playwright(#1, 82k) / Figma(#2) / GitHub(#3, 69k) / Jira(#4) / Context7(#5, 32k)。
  • 安全事件：2026-04 披露一个下载量 1.5 亿的 MCP server 有 RCE 漏洞。

安全红线（硬约束）

  1. 只用官方 vendor server，pin 版本不用 latest
  2. API token 最小权限（DB 只读、GitHub 只勾必要 scope）
  3. 文件访问 scope 到单一项目目录，不开放 ~ 全盘
  4. Web fetch 开 SSRF 防护
  5. 每 agent 活跃 MCP 数 ≤ 6（超了模型工具选择困惑）

二、A2A 协议（Agent2Agent）

定义：Google 2025-04 提出的 Agent 间互操作协议。HTTP(S) + JSON-RPC 2.0 + SSE。核心概念： - Agent Card：/.well-known/agent.json 暴露身份/能力/模态/认证 - Task Lifecycle：submitted → working → input-required → completed/failed/canceled - Rich Artifacts：结果可是文本/文件/JSON，中途动态协商模态 - Client/Server 对称：不暴露内部 memory/tools，只暴露能力边界

来源: raw/multi-agent/A2A协议调研-20260928.md（Google 官方公告 + a2aproject/a2a 仓库）

MCP vs A2A 区别

维度 MCP A2A
解决问题 agent ↔ 工具 agent ↔ agent
交互模式 结构化同步 对话式异步 SSE
能力发现 tool list Agent Card
任务生命周期 无（单次） 完整状态机 + 长时任务

本库落地状态

  • 当前六员协作本质是 Hermes 硬编码派单（delegate_task / shell 调 CLI），是「伪 A2A」。
  • [调研待评估] 短期不直接上 JSON-RPC server（本机 CLI 比 HTTP 开销小），但借两个设计习惯：
  • 给每个 agent 写静态 agent_card.md（能力边界 / 输入契约 / 输出契约）
  • 派单走 task envelope JSON（task_id/status/input/artifacts，落 ~/.hermes/tasks/）
  • [调研待评估] 长期：跨机器协作（如审查任务发云端）时再真上 A2A server。

三、Agent 记忆范式（4 篇论文）

来源: raw/agent-dev/Agent记忆论文-JevMem-GMem-BudgetMem-DMem-20260928.md

3.1 Jev-Mem（写入期 System-One 控制面）

  • 📄 arXiv:2609.23986（UTD，2026-09）
  • 核心：把记忆写入里的高频决策（类型判定/冗余过滤/图视图路由/候选打分/自适应停止）从自回归 LLM 抽出来，交给轻量控制面（小分类器/规则），LLM 只做最后合成。
  • canonical node 挂 4 种 typed edge：semantic / temporal / causal / entity。
  • [调研待评估]：DSH 批量吞吐 N=5 时省 LLM 调用；typed edge 给 shared-skills/ 提供标准 schema。

3.2 G-Memory（多 Agent 三层图记忆）

  • 📄 arXiv:2506.07398（github.com/bingreeky/GMemory）
  • 核心三层：Insight Graph（泛化经验）/ Query Graph（任务指纹→派谁→结果）/ Interaction Graph（原始轨迹）。
  • 多视图并行检索：semantic/temporal/causal/entity 四视图同时召回。
  • [已落地部分]：本库已有 多智能体共享记忆G-Memory.md wiki；error-ledger 现在只有「错误→修复」单层，[调研待评估] 按 G-Memory 升级三层图。

3.3 BudgetMem（查询预算分级路由）

  • 📄 arXiv:2602.06025（ICML 2026）
  • 核心：Low/Mid/High 三档按 query 复杂度自动选检索预算，RL 路由器 λ 参数化。
  • [已落地部分]：六员角色天然对应三档（编排=Low 千级 / 执行=Mid / 工程=High 十万级），已在 AGENTS.md 预算档四元组体现。[调研待评估] 先上规则路由器（按关键词复杂度分档）替代 RL。

3.4 D-Mem（查询期双进程 + Quality Gating）

  • 📄 arXiv:2603.18631
  • 核心：System-1 向量快检索（85% 查询直接出）+ System-2 重读原始历史（精确/复杂才翻），中间 Quality Gating（置信度/证据稀疏度/查询复杂度）做元认知路由。
  • 硬锚：LoCoMo F1=53.5，只付 35.8% token 拿到全量重读 96.7% 效果。
  • [已落地部分]：本库已建 Agent记忆双进程范式.md wiki + Quality Gating τ=0.5 起步。

叠加关系：Jev-Mem 管写入期分层，D-Mem 管查询期双进程，两端正交闭环。

四、PRIME 双进程推理编排

来源: raw/agent-dev/PRIME双进程推理编排-精读-20260928.md（📄 arXiv:2509.22315）

  • 借鉴《思考，快与慢》：System-1（快答兜底）+ System-2（慢思考=规划+检索集成深度推理）按需唤起。
  • 慢思考产出落盘为结构化记忆（规划步骤+检索证据+结论），下次同类问题直接复用。

与本库「三阶评审」融合规则（关键落地）

触发条件 当前做法 PRIME 升级建议
DSH/Codex 一次通过 直接交付 保持（System-1）
两 Agent 投票一致且置信度>0.7 直接交付 保持
两 Agent 分歧但置信度都>0.7 直接升用户 [调研待评估] 先唤起 OC 慢思考归并一轮，仍分歧才升用户
任一 Agent 自报「我不确定」 升用户 [调研待评估] 自动唤起 System-2，不等用户指令
同一问题第 3 次出现 升用户 [调研待评估] 直接复用历史慢思考结论
  • 硬终止：慢思考（OC审）最多 2 轮，每轮必须独立证据，禁止引用前轮结论。
