FastMCP + FastAPI 集成两条路径（2026-10）

WHY

如果要把 RAG 检索 / 知识库查询做成 MCP server 给六员调用，FastMCP 是官方首选框架。但"自动从 FastAPI 转 MCP"和"把 MCP 挂进 FastAPI"两条路径的适用场景完全不同——用错了会导致 LLM 调用工具效果差、session 不初始化、CORS 冲突等坑。本页从 FastMCP 官方文档提炼两条路径的正确用法 + 关键坑 + 本项目落地方案。

WHAT

路径 A：从 FastAPI 生成 MCP server（把现有 API 转成 MCP 工具）

from fastmcp import FastMCP
mcp = FastMCP.from_fastapi(app=app)  # 一行转换
mcp.run()
  • 基于 OpenAPIProvider（v3.0.0+），从 FastAPI 的 OpenAPI spec 抽工具。
  • 工具命名 = FastAPI 的 operation_id —— 必须显式指定，否则生成 list_products_products_get 这种难看名字。
  • 可加新工具/资源：转换后的 mcp 是完整 FastMCP 实例，@mcp.tool 直接加。
  • 支持 RouteMap 自定义端点 → MCP 组件映射（GET→Resource，POST/PUT/DELETE→Tool）。
  • 支持 httpx_client_kwargs 传认证头。

⚠️ 官方警告（重要）：LLM 对手工设计的 MCP server 效果显著优于自动转换的（尤其复杂 API 多端点多参数）。只建议用于 bootstrap / 原型，不建议照搬 REST API 到 LLM 客户端。

路径 B：把 MCP server 挂进 FastAPI 应用（给 web 应用加 MCP 功能）

from fastmcp import FastMCP
from fastapi import FastAPI

mcp = FastMCP("Analytics Tools")
mcp_app = mcp.http_app(path='/mcp')

# 必须传 lifespan（否则 session manager 不初始化）
app = FastAPI(title="E-commerce API", lifespan=mcp_app.lifespan)
app.mount("/analytics", mcp_app)
# 现在：REST API 在 /products/*，MCP 在 /analytics/mcp/
  • 两个 app 有各自 lifespan 时用 combine_lifespans 合并（顺序进入、逆序退出）。
  • 可组合成"REST + MCP 双入口"：一条 codebase 同时提供传统 API 和 MCP 端点。

关键坑（四个）

坑 说明 解法
operation_id 决定 MCP 工具名 不显式指定会生成 list_products_products_get operation_id="get_user_by_id"
lifespan 必须传 app = FastAPI(lifespan=mcp_app.lifespan)，否则 MCP session manager 不初始化 显式传 lifespan
CORSMiddleware 别全局加 跟 OAuth 保护的 MCP server 冲突（.well-known 路由 404、OPTIONS 失败） 用 sub-app 模式，不全局加 CORS
FastAPI 依赖 FastMCP 不含 FastAPI，要单独装 pip install fastmcp fastapi uvicorn

HOW（本项目 RAG 知识库落地方案）

结论：路径 B 更合适

如果以后要把 RAG 检索/知识库查询做成 MCP server 给六员调用： - REST + MCP 双入口：其他 agent（DSH/Codex）可用 REST，LLM（Claude/OC）可用 MCP。 - 现有 rag-kb-mcp 已跑在 8770 端口（FastMCP 构建），如果要加 REST 入口，可以用这条路径重构。 - 关键：RAG 检索工具设计要 purpose-built（手工设计 MCP 工具，别从 REST API 自动转）——官方明确说 LLM 对手工设计的 MCP 工具效果更好。

待验证（两个开放问题）

  • [ ] 本地 rag-kb-mcp 是否值得改成 FastAPI + MCP 双入口（收益 vs 重构成本）
  • [ ] 路径 A 的"自动转换效果差"在 RAG 检索场景下是否也成立（RAG 工具通常参数少，可能影响不大）
