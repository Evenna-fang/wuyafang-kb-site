DCPM 信念修订追踪（双向指针 + 夜间聚类）

📄 一手源：DCPM信念修订追踪-精读-20260928 · Agent记忆论文-6篇-20260928

← 返回总入口 相关：Agent记忆保鲜与冲突治理 · Agent记忆双进程范式 · 多智能体共享记忆G-Memory · Agent框架与协议进展-2026

核心结论

DCPM（Dual-Process Cognitive Memory，arXiv:2606.09483）批判现有长期记忆系统把"用户说过什么/偏好什么/行为模式"三类信息压平成一个检索面，丢失了信念经历过哪些中间状态、偏好为什么漂移——这正是多 Agent 讨论时"观点漂移"不可追溯的根源。它的解法分两个进程：System-1（白天同步写入）在新事实取代旧信念时写入双向 supersedes 指针（old ⇄ new），修订过程记成双链而非覆盖；System-2（夜间异步引擎）把新鲜事实聚类成域内 schema、潜在意图、跨域核心模式，扫出"A 场景与 B 场景矛盾"的漂移点。落地不必引入完整 DCPM，只取双链思想：评审历史每次变更写一条"旧结论 ⇄ 新结论 + 修订原因"，下次再争议时直接读历史链跳到最新版，不用重新吵。

关键细节

批判对象：压平的检索面丢三样东西

丢失的信息 后果
信念的中间状态 只见最终结论，不知道当初从哪个旧结论改过来的
偏好漂移的原因 只知道偏好变了，不知道为什么变
跨域行为的潜在链接 发现不了"用户在 A 场景的行为和 B 场景矛盾"这类漂移点

System-1 / System-2 分工

进程 时机 做什么
System-1 同步写入 每次新对话到来 与向量库已有条目 reconcile（协调）；旧信念被新事实取代时写双向 supersedes 指针（不物理删除），保留演化链
System-2 异步引擎 夜间批量 把新鲜事实聚类成 within-domain schema / latent intentions / cross-domain core-schema，扫跨域矛盾

落地模板：评审历史双链（只取双链思想）

## 条目: <问题指纹>
- 当前结论: <最新结论>
- 修订链: [v1 2026-09-22 DSH提出=X] ⇄ [v2 2026-09-23 OC审改=Y, 原因=证据Z] ⇄ [v3 2026-09-28 最终=Y+补R]
- 漂移原因: <为什么改>
- 下次命中直接跳到 v3, 不重新推理

与现有体系的衔接

  • 与沉淀三问：Q1（新链接）= System-1 写入；Q3（流程优化点）= System-2 夜间聚类的输入；条目复用 = 双链指针查询。
  • 与 G-Memory：DCPM 是 G-Memory temporal edge 的 schema 细节指南，天然兼容（G-Memory 管"记忆怎么分层存"，DCPM 管"时间边上挂什么"）。
  • 与周复盘 cron 对应：System-2 夜间异步聚类正好对应每周一 update 钩子——把一周零散评审结论聚成 schema（哪类问题总是要 OC 审）、扫跨域矛盾（配置类操作 A 场景串行、B 场景并发过）。
  • 与保鲜治理的关系：Agent记忆保鲜与冲突治理 管"这条还值不值得信（新鲜度）"，DCPM 管"这个结论是怎么一步步变成现在这样的（演化链）"，两者互补。

反例（不要这么做）

  • ❌ 覆盖式写入：只留最新结论 = 观点漂移不可追溯，下次争议重新吵一遍。
  • ❌ 只存最终立场：OpenClaw 的 Devil's Advocate 角色需要观点演化链才能有效质疑，只存最终立场等于没有质疑材料。
  • ❌ 跨周/跨月长程任务不带时间指针：会被过时事实误导。
