一、后端基础：FastAPI（day01-day02）

飞书课件定位：用 FastAPI 给后面的 RAG / Agent 应用做一层 HTTP 壳。这部分代码量不大，但参数校验、异步模型、文件上传这三件事是后面所有 Agent API 服务要反复复用的。

1.1 FastAPI 最小示例 + 路径/查询参数（来源：day01）

from enum import Enum
from typing import Annotated
import uvicorn
from fastapi import FastAPI, Path, Query

class ModelName(str, Enum):
    English = "英语"
    Chinese = "中文"
    French  = "法语"

app = FastAPI()

# 1) 路径参数 + 枚举校验：?model_name=xxx 不在枚举里直接 422
@app.get("/models/{model_name}")
async def get_model(model_name: ModelName):
    if model_name is ModelName.English:
        return {"model_name": model_name, "message": "这是英文"}
    if model_name.value == "中文":
        return {"model_name": model_name, "message": "这是中文"}
    return {"model_name": model_name, "message": "这是法语"}

# 2) 路径参数 + 元数据（Swagger 里会显示 description）
@app.get("/users/{id}")
async def get_user(id: Annotated[int, Path(description="用户id")]):
    return {"id": id, "message": f"这是用户id为{id}的人"}

# 3) 查询参数：有默认值 = Query 参数（?skip=0&limit=5）
fake_items = [{"item_name": n} for n in
              ["苹果","香蕉","橙子","笔记本电脑","无线鼠标"]]

@app.get("/items/")
async def read_item(skip: int = 0,
                    limit: Annotated[int, Query(description="条数")] = 5):
    return fake_items[skip: skip + limit]

if __name__ == "__main__":
    uvicorn.run(app)

关键坑： - 接口匹配是按"从上往下"的顺序。/root/{id} 必须写在 /root/test 后面，否则 test 会被当成 id 匹配掉。 - Annotated[int, Path()] 的第一个位置参数必须是类型，后面才是元数据；不要把类型省略。 - 启动后访问 http://127.0.0.1:8000/docs 自动拿到 Swagger UI，这是 FastAPI 免费送的。

1.2 Pydantic 请求体校验（来源：day01）

from typing import Annotated
import uvicorn
from fastapi import FastAPI, Body
from pydantic import BaseModel, Field

class Item(BaseModel):
    name: str = Field(description="商品名称")
    # 字符串长度约束用 max_length；数值约束用 ge / le / lt / gt
    description: str | None = Field(default=None, description="商品描述", max_length=100)
    price: float = Field(description="商品价格", ge=0, le=5000)
    tax: float | None = None

app = FastAPI()

@app.post("/items/")
async def create_item(item: Annotated[list[Item], Body(embed=True)]):
    item_dict = item[0].model_dump()
    if item[0].tax is not None:
        item_dict["price_with_tax"] = item[0].price + item[0].tax
    return item_dict

if __name__ == "__main__":
    uvicorn.run(app, host="127.0.0.1", port=8000)

参数怎么调： - ge=0, le=5000 是数值范围；字符串要用 max_length=100、min_length=2，不要混用。 - Body(embed=True) 表示请求体长这样：{"item": {...}}，不加 embed 则直接是 {...}。批量接收列表时经常踩这个坑。 - model_dump() 把 Pydantic 对象转 dict，是新版本写法（dict() 已 deprecated）。

1.3 文件上传接口（来源：day01）

import uvicorn
from fastapi import FastAPI, File, UploadFile

app = FastAPI()

# 方式 A：bytes 一次性读进内存（小文件用）
@app.post("/uploadfile/")
def create_upload_file(file: bytes = File(description="以字节形式读取")):
    return {"file_size": len(file)}

# 方式 B：UploadFile 流式（大文件、要拿元数据用这个）
@app.post("/uploadfile1/")
async def create_upload_file(file: UploadFile = File(description="流式读取")):
    return {"filename": file.filename,
            "content_type": file.content_type,
            "size": file.size}

if __name__ == "__main__":
    uvicorn.run(app, host="127.0.0.1", port=8000)

常见坑： - RAG 场景下传 PDF / 文档建议用 UploadFile，它是 SpooledTemporaryFile（超阈值自动落盘），不会把几百 MB 文件全读进内存。 - async def + UploadFile 才会享受异步 IO；普通 def 会被丢到线程池。

1.4 前后端分离项目骨架（来源：day02）

day02 是一个 FastAPI + Vue 的完整项目，目录结构大致如下，是后面"Agent 产品化"的参考骨架：

fastapi项目案例/

这部分代码量较大且和业务耦合，课程中没有一个"能独立跑"的最小后端片段，建议直接参考 day02 项目案例的 main.py + chat.py。

二、LlamaIndex 实操（day03-day06）

飞书课件定位：LlamaIndex = RAG 的"瑞士军刀"。和 LangChain 比，它更偏向数据管道 + 索引引擎。day03 入门，day04 文本切分，day05 摄取管道 + 路由，day06 自定义查询/检索/合成。

2.1 索引构建 + 默认 LLM/Embedding 配置（来源：day03）

from dotenv import load_dotenv
from llama_index.core import VectorStoreIndex, SimpleDirectoryReader, Settings
from llama_index.embeddings.huggingface import HuggingFaceEmbedding
from llama_index.llms.dashscope import DashScope
import os

load_dotenv()

model = "qwen3-max"
api_key = os.getenv("DASHSCOPE_API_KEY")
api_base = os.getenv("DASHSCOPE_BASE_URL")

# LlamaIndex 全局默认配置：以后所有节点/查询引擎都用它
Settings.llm = DashScope(model_name=model,
                        api_key=api_key,
                        api_base_url=api_base)
Settings.embed_model = HuggingFaceEmbedding(
    model_name=r"D:\llm\Local_model\BAAI\bge-small-zh-v1___5"
)

# 1) 加载文档（自动按后缀选择 reader）
documents = SimpleDirectoryReader(input_files=["../data/公司规章制度.txt"]).load_data()
# 2) 构建向量索引（内存版；生产上换 Qdrant/Chroma）
index = VectorStoreIndex.from_documents(documents)
# 3) 查询引擎 + 提问
query_engine = index.as_query_engine()
print(query_engine.query("公司的上下班时间？"))

关键参数： - Settings.llm / Settings.embed_model 是全局单例，改一次全工程生效；不要在每个文件里 new 一个 LLM，会重复加载 embedding 模型。 - bge-small-zh-v1.5 适合中文，本地加载快；生产建议 bge-large-zh-v1.5 或 bge-m3。 - VectorStoreIndex.from_documents 内部默认 chunk_size=1024，中文文档建议通过 Settings.chunk_size=512 调小。

2.2 FunctionAgent 最小示例（来源：day03）

import asyncio
from dotenv import load_dotenv
from llama_index.core.agent.workflow import FunctionAgent
from llama_index.llms.dashscope import DashScope
import os

load_dotenv()
llm = DashScope(model_name="qwen3-max",
                api_key=os.getenv("DASHSCOPE_API_KEY"),
                api_base_url=os.getenv("DASHSCOPE_BASE_URL"))

def multiply(a: float, b: float) -> float:
    """两个数相乘并返回乘积"""
    return a * b

def add(a: float, b: float) -> float:
    """两个数相加并返回和"""
    return a + b

# FunctionAgent = 函数自动被识别为工具，docstring 就是工具描述
workflow = FunctionAgent(
    tools=[multiply, add],
    llm=llm,
    system_prompt="你是一个可以使用工具执行基本数学运算的代理。请用中文回答",
)

async def main():
    response = await workflow.run(user_msg="请计算 20+(2*4)?")
    print(response)

if __name__ == "__main__":
    asyncio.run(main())

关键点： - LlamaIndex 的 FunctionAgent 会自动读取函数签名和 docstring 生成工具 schema，docstring 写得越清楚，模型 tool call 越准。 - 千问模型在 LlamaIndex agent 里对某些 tool calling 兼容不好，课件备注建议换 DeepSeek；这是真实踩过的坑。 - 流式输出用 workflow.stream_events() + AgentStream 事件，不要用 print(response) 阻塞等待。

2.3 文本切分器（来源：day04）

from llama_index.core.node_parser import CodeSplitter, HierarchicalNodeParser
from llama_index.core import SimpleDirectoryReader

# 1) 代码切分器：按语言 AST 切，比字符串切分更准
documents = SimpleDirectoryReader(input_files=["./03-MarkdownElement解析器.py"]).load_data()
splitter = CodeSplitter(
    language="python",
    chunk_lines=50,          # 每块目标行数
    chunk_lines_overlap=10,  # 块之间重叠行数
    max_chars=300,          # 单块最大字符
)
nodes = splitter.get_nodes_from_documents(documents)

# 2) 层次节点解析器：生成"粗块-细块"两级，配合 AutoMergingRetriever
node_parser = HierarchicalNodeParser.from_defaults(
    chunk_sizes=[512, 300],  # 从粗到细的 token 数
    chunk_overlap=70,
)
hier_nodes = node_parser.get_nodes_from_documents(documents)

什么时候用哪个： - 普通中文文档 → SentenceSplitter(chunk_size=512, chunk_overlap=50)（day05 用的就是这个）。 - 代码仓库 → CodeSplitter。 - 长文档/制度手册 → HierarchicalNodeParser + AutoMergingRetriever：检索到叶节点后，自动合并回父节点一起喂给 LLM，避免"切太碎导致上下文丢失"。

2.4 摄取管道 IngestionPipeline（来源：day05）

from llama_index.core import SimpleDirectoryReader
from llama_index.core.ingestion import IngestionPipeline
from llama_index.core.text_splitter import SentenceSplitter
from llama_index.core.extractors import TitleExtractor

documents = SimpleDirectoryReader(input_files=["../data/小说.txt"]).load_data()

# 1) 切分器
text_splitter = SentenceSplitter(chunk_size=256, chunk_overlap=30)
# 2) 自动标题抽取器（用 LLM 给每个 chunk 起标题，存进 metadata）
title_extractor = TitleExtractor(
    nodes=5,
    node_template="请为以下文档生成一个简洁的标题: {context_str}",
    num_workers=5,
)

# 3) 管道 = 切分 → 向量化 → 抽取标题，一次跑完
pipeline = IngestionPipeline(
    transformations=[text_splitter, embed_model, title_extractor]
)
nodes = pipeline.run(documents=documents)
for node in nodes:
    print(node.metadata)

为什么用管道： - 普通 VectorStoreIndex.from_documents 背后就是默认管道；一旦你要加自定义抽取器、 embedding、去重、缓存，就得自己写 IngestionPipeline。 - num_workers=5 是并行调用 LLM 抽标题的并发数，文档多时显著加速，但不要超过 API QPS 上限。

2.5 路由索引 RouterQueryEngine（来源：day05）

from llama_index.core import VectorStoreIndex, SimpleDirectoryReader
from llama_index.core.query_engine import RouterQueryEngine
from llama_index.core.selectors import LLMSingleSelector
from llama_index.core.tools import QueryEngineTool, ToolMetadata

# 1) 多个独立文档各自建索引
tech_docs = SimpleDirectoryReader(input_files=["../data/java_basics_manual.md"]).load_data()
product_docs = SimpleDirectoryReader(input_files=["../data/DeepSeek15天指导手册.pdf"]).load_data()
tech_index = VectorStoreIndex.from_documents(tech_docs)
product_index = VectorStoreIndex.from_documents(product_docs)

# 2) 每个索引配一个 query engine，参数不同
tech_engine = tech_index.as_query_engine(similarity_top_k=3, response_mode="compact")
product_engine = product_index.as_query_engine(similarity_top_k=5, response_mode="tree_summarize")

# 3) 包装成"工具"，用 ToolMetadata 描述适用场景
query_tools = [
    QueryEngineTool(query_engine=tech_engine,
                    metadata=ToolMetadata(name="technical_docs",
                                          description="java 基础技术文档库...")),
    QueryEngineTool(query_engine=product_engine,
                    metadata=ToolMetadata(name="product_manual",
                                          description="deepseek 使用手册...")),
]

# 4) RouterQueryEngine 用 LLM 自动选引擎
router = RouterQueryEngine(
    selector=LLMSingleSelector.from_defaults(),
    query_engine_tools=query_tools,
)
print(router.query("怎么在 Java 里写一个单例？"))

关键点： - response_mode：compact 适合快问快答，tree_summarize 适合长文综述，refine 会逐 chunk 迭代修改答案（慢但准）。 - ToolMetadata.description 写得好不好，直接决定 router 能不能选对引擎——这和 agent 工具描述是同一个原理。

2.6 聊天引擎 + 存储持久化（来源：day06）

from llama_index.core import (
    VectorStoreIndex, SimpleDirectoryReader, StorageContext, load_index_from_storage
)

# 1) 首次：建索引并持久化到磁盘
documents = SimpleDirectoryReader(input_files=["../data/公司规章制度.txt"]).load_data()
index = VectorStoreIndex.from_documents(documents)
index.storage_context.persist(persist_dir="./storage")

# 2) 之后：直接从磁盘加载，跳过 embedding 计算
storage_context = StorageContext.from_defaults(persist_dir="./storage")
index = load_index_from_storage(storage_context)

# 3) 聊天引擎（带 memory）
chat_engine = index.as_chat_engine(chat_mode="context", verbose=True)
print(chat_engine.chat("公司请假流程是什么？"))
print(chat_engine.chat("那年假呢？"))  # 自动带上下文

常见坑： - 不持久化 = 每次启动都重新算 embedding，几百块钱的 API 费就没了。生产环境必须 persist。 - chat_mode 选 context（把检索结果作为系统上下文）或 react（把检索结果当工具用）；前者适合单库，后者适合多库。

3.1 中间件：SummarizationMiddleware（来源：day08）

import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware
from langchain_tavily import TavilySearch
from langgraph.checkpoint.memory import InMemorySaver

load_dotenv()
llm = ChatOpenAI(model="qwen3.5-flash-2026-02-23",
                 api_key=os.getenv("DASHSCOPE_API_KEY"),
                 base_url=os.getenv("DASHSCOPE_BASE_URL"),
                 temperature=0.1)

SHORT_SUMMARY_PROMPT = """你是一个记忆压缩专家。请将下方的对话历史压缩成一段简洁的背景摘要，
保留：1) 用户最终目标  2) 已执行的关键步骤  3) 待办事项。
待压缩的对话：{messages}"""

agent = create_agent(
    model=llm,
    tools=[TavilySearch(max_results=1)],
    checkpointer=InMemorySaver(),           # 短期记忆：按 thread_id 存历史
    middleware=[SummarizationMiddleware(    # 中间件：超长自动摘要
        model=llm,
        trigger=[("tokens", 4000), ("messages", 10)],  # 或关系
        keep=("messages", 5),               # 保留最近 5 条，其余做摘要
    )],
)

config = {"configurable": {"thread_id": "user-001"}}
agent.invoke({"messages": [{"role": "user",
                             "content": "2026年3月最新的AI大模型技术趋势？"}]}, config)

关键参数： - trigger 三种触发：("tokens", 4000)、("fraction", 0.5)、("messages", 10)；多个条件是 OR。 - keep=("messages", 5) = 最近 5 条原文保留，更早的全部塞给 LLM 做摘要。 - checkpointer=InMemorySaver() 是内存版；生产换 SqliteSaver / PostgresSaver。 - thread_id 是会话隔离的 key，不同用户必须传不同值，否则会串台。

3.2 自定义中间件：@before_agent 做权限/敏感词拦截（来源：day08）

from langchain.agents import create_agent, AgentState
from langchain.agents.middleware import before_agent
from langchain.messages import HumanMessage, AIMessage
from langchain_openai import ChatOpenAI
from langgraph.runtime import Runtime
from dataclasses import dataclass

@dataclass(frozen=True)
class Context:           # 通过 runtime 注入的运行时上下文
    user_id: str
    user_permissions: str

@before_agent(can_jump_to="end")
def guard_middleware(state: AgentState, runtime: Runtime[Context]):
    # 1) 找到最新用户问题
    user_msg = ""
    for m in reversed(state["messages"]):
        if isinstance(m, HumanMessage):
            user_msg = m.content
            break
    # 2) 敏感词拦截
    sensitive = ["TM", "TMD", "CNM", "垃圾"]
    if any(w in user_msg.upper() for w in sensitive):
        return {"messages": [AIMessage(content="检测到不当言论，请文明交流")],
                "jump_to": "end"}     # 直接结束 agent
    # 3) 权限控制
    if runtime.context.user_permissions != "Vip":
        print("非 VIP，限制可用工具")
    return None

agent = create_agent(model=llm, tools=[...], middleware=[guard_middleware])

中间件钩子全家桶（来自 day08）： - @before_agent：Agent 启动前（权限、敏感词、注入上下文） - @before_model：每次调 LLM 前（动态系统提示词、压缩上下文） - @after_model：LLM 输出后（日志、审计） - @wrap_model_call：包一层 LLM 调用（重试、fallback） - @wrap_tool_call：包一层工具调用（权限、参数清洗）

3.3 Function Calling 真实代码（来源：day09）

import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langchain.agents import create_agent

load_dotenv()
llm = ChatOpenAI(model="qwen3.5-flash",
                 api_key=os.getenv("DASHSCOPE_API_KEY"),
                 base_url=os.getenv("DASHSCOPE_BASE_URL"))

@tool
def calculator(expression: str) -> str:
    """支持多个表达式的数学计算器（使用 numexpr），用分号分隔多个表达式"""
    import numexpr, math
    local = {"pi": math.pi, "e": math.e}
    exprs = [e.strip() for e in expression.split(";") if e.strip()]
    return "\n".join(f"{e} = {numexpr.evaluate(e, local_dict=local)}"
                      for e in exprs)

@tool
def get_weather(city: str) -> str:
    """获取指定城市的实时天气"""
    return f"{city} 今天晴朗，24-28°C"

agent = create_agent(model=llm, tools=[calculator, get_weather])
resp = agent.invoke({"messages": [{"role": "user",
        "content": "北京天气怎么样？另外帮我算一下 (52+18)*2/pi"}]})
print(resp["messages"][-1].content)

关键点： - @tool 装饰器自动把函数签名 + docstring 转成 OpenAI function schema；docstring 第一行 = 工具描述，必须写得让模型看懂"什么时候该用"。 - create_agent 内部自动处理 tool_call 循环（模型返回 tool_calls → 执行函数 → 把结果塞回 messages → 再调 LLM），你不用手写 while 循环。 - 千问/DashScope 兼容 OpenAI 协议，直接 ChatOpenAI(base_url=...) 就能用。

4.1 Plan-and-Execute 推理框架（来源：day10）

import os, math, numexpr
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_experimental.plan_and_execute import (
    PlanAndExecute, load_agent_executor, load_chat_planner
)
from langchain_tavily import TavilySearch
from langchain_core.tools import tool

load_dotenv()
llm = ChatOpenAI(model="MiniMax-M2.1",
                 api_key=os.getenv("DASHSCOPE_API_KEY"),
                 base_url=os.getenv("DASHSCOPE_BASE_URL"))

@tool
def calculator(expression: str) -> str:
    """数学计算器，支持分号分隔多个表达式"""
    local = {"pi": math.pi, "e": math.e}
    return "\n".join(f"{e} = {numexpr.evaluate(e.strip(), local_dict=local)}"
                     for e in expression.split(";") if e.strip())

tools = [TavilySearch(), calculator]

# Planner = 先写计划（一串步骤）
planner  = load_chat_planner(llm)
# Executor = 每一步用 ReAct 执行
executor = load_agent_executor(llm, tools, verbose=True)

agent = PlanAndExecute(planner=planner, executor=executor, verbose=True)
result = agent.invoke(
    "我有5000人民币预算，想去日本旅行5天。按当前汇率在东京能住几晚中等价位酒店？"
)
print(result)

和 ReAct 的区别： - ReAct = 走一步看一步，容易"走偏"或"绕圈"。 - Plan-Execute = LLM 先一次性产出 N 步计划，然后逐步执行；每步失败还能 replan。 - 适合任务可分解、步骤明确的场景（旅行规划、数据处理流水线）；不适合开放式对话。

4.2 Self-ASK 推理模式（来源：day10）

Self-ASK 的核心是：模型输出 Follow up: xxx → 暂停 → 外部搜索工具填 Intermediate answer: xxx → 模型继续问下一个。课件通过自定义 stop words + 中间件实现：

from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="deepseek-chat", ...)
# 关键：让模型在"Intermediate answer:" 处停下来，把控制权交给外部搜索
llm_with_stop = llm.bind(stop=[
    "\nIntermediate answer:", "Intermediate answer:",
    "\nIntermediate answer：", "Intermediate answer：",
])

SELF_ASK_SYSTEM_PROMPT = """你是搜索链推理专家。
规则：
1. 每次只输出一个 "Follow up:" 问题，输出后立即停止。
2. 禁止自己生成 "Intermediate answer:"，那是外部工具填的。
3. 格式：
   Question: [用户输入]
   Are follow up questions needed here: [Yes/No]
   Follow up: [具体搜索问题]
   Intermediate answer: (等待工具)
   So the final answer is: [结论]
"""

什么时候用：多跳问题（"马斯克第二家公司的现任 CEO 是谁"需要先搜"第二家公司是什么"再搜"现任 CEO"）。比纯 ReAct 省 token，因为每一步只问一个问题。

4.3 Reflection / 自我反思（来源：day10）

课件里的 thinking_and_self-Refection 用两个 LLM 节点串联：一个写草稿，一个挑毛病，挑完再写。本质是：

draft_node:    LLM 生成答案
review_node:   LLM 读草稿 → 指出问题
revise_node:   LLM 读草稿+批评 → 改一版

LangGraph 里可以直接用三个节点 + 条件边实现：review 觉得没问题就 END，否则回到 revise。这是 day16 "自定义主管架构"的雏形。

4.5 CrewAI 最小示例（来源：day10）

import os
from dotenv import load_dotenv
from crewai import Agent, Task, Crew, Process, LLM
from crewai_tools import TavilySearchTool

load_dotenv()
llm = LLM(api_key=os.getenv("DASHSCOPE_API_KEY"),
          base_url=os.getenv("DASHSCOPE_BASE_URL"),
          model="MiniMax-M2.1", temperature=0.7)
search = TavilySearchTool(max_results=2)

# 1) Agent = 角色 + 目标 + 背景故事
researcher = Agent(role="技术情报员",
                   goal="搜索最新技术资讯",
                   backstory="你是专业的技术记者",
                   tools=[search], llm=llm, verbose=True, max_iter=1)

analyst = Agent(role="数据分析师",
                goal="分析技术趋势",
                backstory="你能从信息中发现趋势",
                llm=llm, verbose=True, max_iter=1)

writer = Agent(role="科技作者",
               goal="写出高质量技术文章",
               backstory="资深科技记者",
               llm=llm, verbose=True, max_iter=1)

# 2) Task = 具体任务 + 期望输出 + 依赖哪些上游 task
t1 = Task(description="搜索 'AI Agent 框架' 最新信息",
          agent=researcher,
          expected_output="原始信息摘要")
t2 = Task(description="分析关键趋势",
          agent=analyst, context=[t1],
          expected_output="分析报告")
t3 = Task(description="基于分析写一篇 800 字文章",
          agent=writer, context=[t1, t2],
          expected_output="完整文章")

# 3) Crew = 把 agent + task 组装成流水线
crew = Crew(agents=[researcher, analyst, writer],
            tasks=[t1, t2, t3],
            process=Process.sequential,    # 顺序执行
            verbose=True)
result = crew.kickoff()
print(result)

CrewAI vs AutoGen： - CrewAI 是"流水线"思维：Task 有明确依赖（context=[t1, t2]），跑完就结束。 - AutoGen 是"对话"思维：Agent 之间自由聊天，直到满足终止条件。 - 生产上确定性流水线用 CrewAI，开放式协作（调试代码、头脑风暴）用 AutoGen。

五、LangGraph 实操（day11-day16）

LangGraph 是课件后半段的主角。核心模型：StateGraph = 节点(函数) + 边(路由) + 状态(TypedDict)。day11 讲基础，day12 父子图/重试，day13 持久化记忆，day14 流式输出，day15 消息修剪/工具记忆，day16 多智能体交接。

5.1 入门案例：节点 + 边（来源：day11）

from typing import TypedDict
from langgraph.graph import StateGraph

# 状态：TypedDict 定义图中流动的数据结构
class InputState(TypedDict):
    question: str

class OutputState(TypedDict):
    final_answer: str

class MyState(TypedDict):
    question: str
    answer: str
    final_answer: str

# 节点：输入 state，返回要更新的字段 dict
def search_node(state: MyState):
    print(f"搜索: {state['question']}")
    return {"answer": "搜索到的资料片段"}

def llm_result(state: MyState):
    return {"final_answer": f"基于[{state['answer']}]总结的答案"}

# 组装图
g = StateGraph(state_schema=MyState,
               input_schema=InputState,
               output_schema=OutputState)
g.add_node("search_node", search_node)
g.add_node("llm_result", llm_result)
g.set_entry_point("search_node")     # 入口
g.add_edge("search_node", "llm_result")
g.add_edge("llm_result", "__end__")   # 等价 END
graph = g.compile()

print(graph.invoke({"question": "什么是 LangGraph？"}))

关键约定： - 节点函数必须返回 dict（要更新的字段），不能直接改 state。 - input_schema / output_schema 是可选的"视图"：对外暴露的字段 ≠ 内部状态字段。 - compile() 之后才是可执行的图；可以 graph.get_graph().draw_mermaid_png() 可视化。

5.2 归并函数：Annotated + add_messages（来源：day11）

from typing import Annotated, TypedDict
from langgraph.graph import StateGraph
from langgraph.graph.message import add_messages
from langgraph.graph import MessagesState

# 不写归并函数：每个节点返回 messages 会**覆盖**之前的
# 写了 Annotated[..., add_messages]：自动**追加**到列表末尾

class ChatState(MessagesState):           # MessagesState 已经内置 messages: Annotated[list, add_messages]
    pass

def user_input_node(state: ChatState):
    return {"messages": [{"role": "user", "content": "什么是 LangGraph？"}]}

def assistant_node(state: ChatState):
    return {"messages": [{"role": "assistant", "content": "有状态的图编排框架。"}]}

builder = StateGraph(ChatState)
builder.add_node("user_input", user_input_node)
builder.add_node("assistant_reply", assistant_node)
builder.set_entry_point("user_input")
builder.add_edge("user_input", "assistant_reply")
graph = builder.compile()

print(graph.invoke({"messages": []}))

为什么这东西重要： - 对话系统里，每个节点都要往 messages 列表里加东西。如果没有 add_messages，第二次 invoke 会把第一次的消息覆盖掉，上下文就断了。 - 普通字段（非 list）默认是"覆盖"；list 字段要追加必须显式 Annotated[list, operator.add] 或 add_messages。

5.3 并行节点（来源：day11）

import operator
from typing import Annotated, TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    aggregate: Annotated[list, operator.add]   # 并行节点的返回会自动合并

def a(state): return {"aggregate": ["A"]}
def b(state): return {"aggregate": ["B"]}
def c(state): return {"aggregate": ["C"]}
def d(state): return {"aggregate": ["D"]}

builder = StateGraph(State)
for n in [a, b, c, d]:
    builder.add_node(n)
builder.add_edge(START, "a")
builder.add_edge("a", "b")     # a 之后同时去 b 和 c（并行）
builder.add_edge("a", "c")
builder.add_edge("b", "d")
builder.add_edge("c", "d")      # b、c 都完成后才进 d（barrier）
builder.add_edge("d", END)
graph = builder.compile()

print(graph.invoke({"aggregate": ["start"]}))

关键： - 一个节点有多个出边 = 并行分叉。 - 多个节点指向同一个节点 = 等所有上游完成（join/barrier）。 - 归并函数 operator.add 保证并行节点的 list 结果不会互相覆盖。

5.4 条件边 add_conditional_edges（来源：day11）

from typing import TypedDict
from langgraph.graph import StateGraph, END

class MyState(TypedDict):
    type: str
    result: str

def route_condition(state: MyState):
    """路由函数：返回字符串，决定下一步去哪个节点"""
    if state["type"] == "a":    return "A"
    elif state["type"] == "b": return "b"
    else:                       return "default"

def node_a(state):     return {"result": "走了 A 分支"}
def node_b(state):     return {"result": "走了 B 分支"}
def node_default(state): return {"result": "走了默认分支"}

g = StateGraph(MyState)
g.add_node("a", node_a)
g.add_node("b", node_b)
g.add_node("default", node_default)
g.set_entry_point("a")   # 演示：假设入口直接做路由
# 上面的入口可以换成 judge_node；这里简化
g.add_conditional_edges(
    "a",                   # 从哪个节点出发
    route_condition,      # 路由函数
    {"A": "a", "b": "b", "default": "default"},  # 路由返回值 → 目标节点
)
g.add_edge("a", END)
g.add_edge("b", END)
g.add_edge("default", END)
app = g.compile()

坑： - 路由函数返回的字符串必须出现在映射 dict 的 key 里，否则报错。 - 路由函数只做决策，不要在里面改 state；要改 state 单独写一个 judge_node。

5.5 Send 实现 Map-Reduce 并行（来源：day11）

import operator
from typing import Annotated, TypedDict, List
from langgraph.graph import StateGraph, START, END
from langgraph.types import Send

class State(TypedDict):
    numbers: List[int]
    results: Annotated[list[int], operator.add]
    final_sum: int

def split_numbers(state: State):
    """Map 阶段：每个数字发给一个 worker，带临时状态"""
    return [Send("worker", {"number": n}) for n in state["numbers"]]

def calculate_square(state):
    """每个 worker 只处理一个数字"""
    return {"results": [state["number"] ** 2]}

def sum_results(state):
    """Reduce 阶段：阻塞等所有 worker 完成"""
    return {"final_sum": sum(state.get("results", []))}

g = StateGraph(State)
g.add_node("splitter", lambda s: s)        # 分发器
g.add_node("worker", calculate_square)
g.add_node("summer", sum_results)
g.add_edge(START, "splitter")
g.add_conditional_edges("splitter", split_numbers, ["worker"])
g.add_edge("worker", "summer")
g.add_edge("summer", END)
app = g.compile()

print(app.invoke({"numbers": [1, 2, 3, 4, 5], "results": [], "final_sum": 0}))

Send vs 普通并行： - 普通并行：你在画图时就知道有几个分支（a→b, a→c）。 - Send：运行时动态决定分支数（比如"给 100 个文档每个派一个 worker"）。 - Send 的第二个参数是临时局部状态，只发给那个 worker，不污染全局 state。

5.6 持久化 Checkpoint + thread_id（来源：day13 / day15）

import os
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain_core.messages.utils import trim_messages, count_tokens_approximately
from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.checkpoint.memory import InMemorySaver

load_dotenv()
llm = init_chat_model(api_key=os.getenv("DASHSCOPE_API_KEY"),
                      base_url=os.getenv("DASHSCOPE_BASE_URL"),
                      model_provider="openai",
                      model="MiniMax-M2.1")

def call_llm(state: MessagesState):
    # 调 LLM 前先修剪消息，防止 token 爆掉
    messages = trim_messages(
        state["messages"],
        strategy="last",
        token_counter=count_tokens_approximately,
        max_tokens=500,
        start_on="human",
        end_on=("ai", "tools", "human"),
    )
    return {"messages": [llm.invoke(messages)]}

builder = StateGraph(MessagesState)
builder.add_node(call_llm)
builder.add_edge(START, "call_llm")

# 关键：compile 时传入 checkpointer，自动按 thread_id 持久化
graph = builder.compile(checkpointer=InMemorySaver())

config = {"configurable": {"thread_id": "user-001"}}
graph.invoke({"messages": "我叫初见"}, config)
graph.invoke({"messages": "帮我家猫写首诗"}, config)
final = graph.invoke({"messages": "我叫什么名字？"}, config)
print(final["messages"][-1].content)   # 能答出"初见"

关键概念： - checkpointer = 每一步执行完自动把 state 序列化到后端（内存 / SQLite / Postgres / Redis）。 - thread_id = 会话主键；同一个 thread_id 的多次 invoke 会自动加载上次的 state。 - trim_messages = 调 LLM 前按 token 数截断历史，start_on="human" 保证截完第一条永远是用户消息（不会从 AI 半截开始）。 - 生产换 langgraph-checkpoint-sqlite 或 PostgreSQL，重启不丢会话。

5.7 跨会话长期记忆 InMemoryStore（来源：day13）

import uuid
from langgraph.store.memory import InMemoryStore
from langchain_huggingface import HuggingFaceEmbeddings

# 带向量索引的 store：可以语义搜索记忆
store = InMemoryStore(
    index={
        "embed": HuggingFaceEmbeddings(model_name="BAAI/bge-large-zh-v1.5"),
        "dims": 1024,
        "fields": ["hobby", "food_preference"],   # 对哪些字段建向量索引
    }
)

namespace = ("user-001", "memories")   # (user_id, 命名空间)

# 存
store.put(namespace, str(uuid.uuid4()),
          {"hobby": "篮球、音乐、美食、编程"})
store.put(namespace, str(uuid.uuid4()),
          {"food_preference": "臭豆腐、小龙虾、红烧肉"})

# 语义搜：query 是自然语言，自动 embedding 匹配
results = store.search(namespace, query="用户喜欢吃什么？", limit=3)

Checkpointer vs Store： - checkpointer = 短期记忆，按 thread_id 存"当前会话的 state"。 - Store = 长期记忆，按 namespace（user_id）存"跨会话的用户画像"。 - 真实产品里：checkpointer 用 PG，Store 用 PG 或向量库（Qdrant）。

5.8 父子图（subgraph）（来源：day12）

from langgraph.graph import StateGraph, START, END, MessagesState
from langchain.chat_models import init_chat_model
from langchain.messages import HumanMessage

llm = init_chat_model(...)

def sub_plot(state: MessagesState):
    content = state["messages"][-1].content
    summary = llm.invoke(f"用一句话总结：{content}")
    return {"messages": [summary]}

# 子图：本身就是一个完整的 StateGraph.compile()
summary_subgraph = (
    StateGraph(MessagesState)
    .add_node("subplot", sub_plot)
    .add_edge(START, "subplot")
    .compile()
)

def llm_answer_node(state):
    return {"messages": [llm.invoke(state["messages"])]}

# 父图：把子图当普通节点用
parent = (
    StateGraph(MessagesState)
    .add_node("llm_answer", llm_answer_node)
    .add_node("summarize", summary_subgraph)   # 注意：直接传 compiled subgraph
    .add_edge(START, "llm_answer")
    .add_edge("llm_answer", "summarize")
    .add_edge("summarize", END)
    .compile()
)

print(parent.invoke({"messages": [HumanMessage(content="LangGraph 是什么？")]}))

什么时候拆父子图： - 父图和子图共享同一个 state schema → 直接把子图当节点加进去。 - 子图需要自己独立的 state（字段不同）→ 用 add_node("sub", subgraph, input_schema=..., output_schema=...) 做字段映射。

5.9 多智能体交接（来源：day16）

day16 的核心是"主管（supervisor）派单给专家"。核心机制是 LangGraph 的 Command(goto=...)：

from langgraph.types import Command

def supervisor_node(state):
    """根据用户问题决定派给谁"""
    q = state["messages"][-1].content
    if "代码" in q:
        return Command(goto="coder_agent")
    elif "写作" in q:
        return Command(goto="writer_agent")
    else:
        return Command(goto="END")

def coder_agent(state):
    # 写完代码后回传给主管
    return {"messages": [...], "goto": "supervisor"}

实际课件里 day16 用 transfer_to_xxx 工具的方式让 LLM 自己决定交接（比硬编码 if-else 灵活）。这就是 OpenAI Swarm / LangGraph supervisor 的标准范式： - 每个专家 agent 都注册一个 transfer_to_<name> 工具。 - LLM 调用这个工具 = 控制权切到对应 agent。 - 专家干完活，再调 transfer_to_supervisor 把控制权还回来。

六、MCP 模型上下文协议（day17）

MCP = Model Context Protocol，Anthropic 推出的"LLM 工具/资源/提示词"标准化协议。核心三件套：Tools（工具）、Resources（资源）、Prompts（提示词模板）。

6.1 MCP Server 最小示例（FastMCP，来源：day17）

from fastmcp import FastMCP
from typing import Annotated
from pydantic import Field

mcp = FastMCP(name="health_server")

# 1) Tool：给 LLM 当"手"
@mcp.tool()
async def add(a: int, b: int) -> int:
    """计算两数之和"""
    return a + b

@mcp.tool()
async def calculate_bmi(weight_kg: float, height_m: float) -> str:
    """计算 BMI 指数并返回健康建议"""
    if height_m <= 0:
        return "错误：身高必须大于 0"
    bmi = weight_kg / (height_m ** 2)
    tip = "偏瘦" if bmi < 18.5 else "正常" if bmi < 24.9 else "偏胖"
    return f"BMI: {bmi:.2f} ({tip})"

# 2) Resource：给 LLM 当"眼睛"（静态/动态数据）
@mcp.resource("resource://health-guidelines", mime_type="text/plain")
async def get_health_guidelines() -> str:
    """通用健康指南"""
    return "1. 每天 8 小时睡眠  2. 多吃蔬菜水果  3. 每周运动 150 分钟"

# 3) Prompt：给 LLM 当"模板"
@mcp.prompt()
async def analyze_my_health(
    name: Annotated[str, Field(description="用户姓名")],
    weight: Annotated[float, Field(description="体重 kg")],
    height: Annotated[float, Field(description="身高 m")],
) -> str:
    """生成健康分析提示词"""
    return f"用户 {name}，体重 {weight}kg，身高 {height}m。请计算 BMI 并给出建议。"

if __name__ == "__main__":
    mcp.run()   # 默认 stdio 传输；也可以 mcp.run(transport="http")

关键点： - @mcp.tool() / @mcp.resource(uri) / @mcp.prompt() 三种装饰器对应 MCP 三种原语。 - FastMCP 是高层封装，自动生成 JSON Schema；底层写法用 mcp.server.Server + 手动 @server.list_tools()（课件里也讲了，仅在需要动态生成工具时用）。 - 传输默认 stdio（子进程通信），适合本地工具；HTTP/SSE 适合远程 server。

6.2 MCP Client 调用 Server（来源：day17）

import asyncio
from fastmcp import Client

async def main():
    # Client 直接传 server 脚本路径，自动拉起子进程
    async with Client("01-first_mcp_server.py") as client:
        await client.ping()

        # 1) 列出并调用工具
        tools = await client.list_tools()
        print("可用工具:", [t.name for t in tools])
        r = await client.call_tool("add", {"a": 10, "b": 5})
        print("add 结果:", r.content[0].text)

        # 2) 读资源
        resources = await client.list_resources()
        r = await client.read_resource("resource://health-guidelines")
        print("健康指南:", r[0].text)

        # 3) 取提示词模板
        prompt = await client.get_prompt("analyze_my_health",
                                         {"name": "Alice", "weight": "60", "height": "1.65"})
        print(prompt.messages[0].content.text)

asyncio.run(main())

6.3 LangChain Agent 集成 MCP（来源：day17）

import asyncio, os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain.agents import create_agent
from langchain_mcp_adapters.client import MultiServerMCPClient

load_dotenv()
llm = ChatOpenAI(model="kimi-k2.5",
                 api_key=os.getenv("DASHSCOPE_API_KEY"),
                 base_url=os.getenv("DASHSCOPE_BASE_URL"))

async def main():
    # 一个 client 可以连多个 MCP server
    client = MultiServerMCPClient({
        "health_server": {
            "transport": "stdio",
            "command": "python",
            "args": ["./01-first_mcp_server.py"],
        },
    })
    tools = await client.get_tools()    # 自动把所有 server 的 tool 拉成 LangChain Tool

    agent = create_agent(model=llm, tools=tools)
    r = await agent.ainvoke({"messages": [
        {"role": "user", "content": "我体重 75kg，身高 1.80m，算一下 BMI"}]})
    print(r["messages"][-1].content)

asyncio.run(main())

这一步的意义： - MCP 把"工具定义"从你的代码里抽离出来，变成独立的 server 进程。 - 同一个 MCP server 可以被 Claude Desktop / Cursor / LangChain Agent / 自研 Agent 同时复用。 - MultiServerMCPClient 让一个 Agent 同时挂 N 个工具 server，是生产架构的标准做法。
