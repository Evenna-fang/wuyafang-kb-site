Agent 怎么选工具：Function Calling vs MCP vs 自定义工具

← 返回总入口

这个问题的答案是什么

一句话：Function Calling 是"模型会用工具"的能力，MCP 是"工具怎么被标准化提供"的协议，自定义工具是"你自己写函数"的实现——三者不在同一层，不是三选一，而是叠加关系。

层 解决的问题 谁定义 典型形态
Function Calling（FC） 模型怎么决定"现在该调哪个函数、传什么参数" 模型厂商（OpenAI/Anthropic/GLM） 在 prompt 里塞 JSON schema，模型输出 {"name":"...","arguments":{...}}
MCP（Model Context Protocol） 工具怎么被标准化发现、授权、复用 Anthropic 主导的开放协议 工具服务器暴露 tools/list、tools/call，客户端（Claude Desktop/Cursor）统一接入
自定义工具 我自己业务里那个"查库存/开发票"函数怎么写 你 Python 函数 + docstring + 装饰器，被 FC 或 MCP 注册

判断口诀： - 单次 demo、自己一个人用 → 直接写 FC（一个 @tool 装饰器就够）。 - 工具要给多个 Agent / 多个客户端复用 → 包成 MCP server。 - 工具会改外部状态（删库/发邮件/转账）→ 必须 MCP 的授权弹窗，别裸奔 FC。

详细内容

一、Function Calling：让模型"知道怎么用"

《动手做 AI Agent》（黄佳）第 5 章把 FC 讲得最直白：开发人员写好函数描述和实现代码，模型"智能地选择输出包含参数的 JSON 对象"，应用层拿到这个 JSON 后去真正调用函数。这是目前把 LLM 接到外部 API 最可靠的方式——不是让模型自己拼 curl，而是让它只负责选函数和填参数，执行权在你的代码手里。

《大模型项目实战》（高强文）基于 GLM-4 的 FC 开发也印证了这一点：FC 的价值是"更可靠地把 GPT 与外部工具、API 连接起来"，关键在 schema 的描述质量——docstring 写得越清楚，模型选错的概率越低。

二、MCP：把工具从"一次性接入"变成"即插即用"

《MCP 原理与实战》开篇就点出了 MCP 要解决的核心痛点：当 5 种 AI 应用要接 5 种数据源时，传统做法要写 25 套定制接入。MCP 把这个 N×M 变成 N+M——客户端和服务器通过同一套协议对话。

MCP 把工具分成三类组件（同书 2.2 节）： - 资源（Resources）：只读，"万物皆资源"——文档、数据库行、API 返回、截图、日志，都是资源。 - 工具（Tools）：会改外部状态，动态操作。高风险工具必须在描述里标注影响（只读 vs 写操作），主机端才能弹确认框。 - 提示模板（Prompts）：标准化 prompt，团队复用、保证输出一致。

安全机制（2.4 节）是 MCP 相对裸 FC 的最大增量：OAuth 授权、令牌传递、高风险操作弹确认对话框——"大模型想执行删除操作，是否允许？"。这是 FC 原生不带的，你得自己写。

三、自定义工具：业务函数才是真资产

《零基础搭建》（徐洋）把"插件"比作"智能体的工具箱"，并强调模块化解耦——"想用就装，不用就卸，不影响核心系统"。这本质就是自定义工具的设计哲学：工具是可插拔的，Agent 主脑是稳定的。

实操层的建议（来自 7 本书的共识）： 1. 工具粒度要小——一个工具只做一件事，模型选错的概率才低。 2. 工具描述里写清"什么时候用/什么时候不用"——这比函数实现本身更影响准确率。 3. 只读工具和写工具要分开——写工具必须有人审、有日志、有回滚。

来自哪些书的哪些观点

  • 《MCP 原理与实战》（李艮基）：MCP vs FC vs API vs A2A 的系统对比；工具要标注影响等级；OAuth + 确认弹窗是高风险操作的标配。
  • 《一本书讲透 MCP》（占冰强）：MCP 把 N×M 集成变成 N+M；MCP 是"AI Agent 互联网"的基座协议；FC 和 RAG 是 MCP 的前身概念。
  • 《动手做 AI Agent》（黄佳）：FC 是 OpenAI Assistants/Tool Calls 的核心；ReAct 框架本质是"推理-行动"循环里不断调工具。
  • 《大模型项目实战》（高强文）：基于 GLM-4 的 FC 开发；AgentScope 的 ReAct Agent；CrewAI 多角色 Agent 里工具是角色的能力底座。
  • 《零基础搭建 Coze+Dify+LangChain》（徐洋）：插件 = 工具箱；知识库 = 专业词典；低代码平台把"自定义工具"封装成可视化卡片。
