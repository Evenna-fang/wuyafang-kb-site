多 Agent vs 单 Agent 怎么选：什么时候该拆

← 返回总入口

这个问题的答案是什么

一句话：多 Agent 不是更高级，是更贵、更慢、更难调试——只有当"一个 Agent 的 prompt 装不下任务"或"不同子任务需要不同工具集/不同人设"时才拆。

判断维度 单 Agent 就够 该拆多 Agent
任务步数 ≤ 5 步 ≥ 10 步，且能清晰分段
工具数量 ≤ 10 个 20+ 个，混在一起模型选错率飙升
人设需求 一个 persona 搞定 调研/编码/审查需要不同 prompt
成本敏感 要省 token 质量优先，愿意付 2-5 倍 token
调试难度 出问题好定位 能接受"哪个 Agent 出问题"的排查成本

默认结论：先上单 Agent（ReAct 或 Plan-and-Execute），跑一周遇到真实瓶颈了再拆。不要为了拆而拆——这是《动手做 AI Agent》和《Building Agentic AI Systems》两本书共同的警告。

详细内容

一、什么时候必须拆：4 个信号

  1. Prompt 已经装不下：你需要在 system prompt 里塞 30 个工具描述 + 5 套业务规则 + 2 个人格设定，模型注意力被稀释，开始丢三落四。
  2. 工具选错率高：同一个 Agent 既会查数据库、又会发邮件、又会写代码——模型经常选"发邮件"去干"查数据库"的活。拆成"数据 Agent"和"通信 Agent"就解决了。
  3. 需要"对抗"或"批判"：写代码的 Agent 不该自己审自己——《Building Agentic AI Systems》专门强调 Reflection 需要独立的 Critic，不能是同一个 LLM 的自我循环（自己审自己 = 没有审）。
  4. 任务天然分阶段：调研→设计→执行→验收——这是 4 个不同阶段，用不同 Agent 各管一段，状态通过消息/文件传递。

二、多 Agent 的三种典型架构

A. Coordinator-Worker-Delegator（《Building Agentic AI Systems》第 6 章） - Coordinator：全局规划、接收最终结果。 - Delegator：把任务分派给 Worker。 - Worker：具体执行（每个 Worker 是独立单 Agent）。 - 适合：任务可分解、子任务相对独立。

B. 角色对话式（AutoGen / CAMEL）（《动手做 AI Agent》第 9-10 章） - 两个或多个 Agent 通过对话协作：UserProxy + Assistant + Critic。 - 适合：需要多轮辩论、代码生成 + 自审。

C. 流水线式（CrewAI / MetaGPT）（《大模型项目实战》第 14 章） - 定义多个角色（研究员/工程师/测试员），按流程 kickoff。 - 《大模型项目实战》CrewAI 案例：用 Gradio 回调 + 异步线程避免 UI 阻塞——这是工程化的细节。 - 适合：有明确流程的团队模拟。

三、不拆的代价 vs 拆的代价

不拆的代价（单 Agent 跑复杂任务）： - 长上下文导致模型"中间遗忘"（lost in the middle）。 - 工具多导致选错率高。 - 一个 prompt 改一处动全身。

拆的代价（多 Agent）： - Token 成本 2-5 倍（每个 Agent 都有自己的 system prompt）。 - 延迟拉长（串行多 Agent 比单 Agent 慢 3-10 倍）。 - 调试难——"是哪个 Agent 哪一步出的错？"要靠全链路日志。 - 状态传递成本——Agent 之间要传上下文，容易丢。

冲突观点标注： - 《大模型项目实战》偏乐观：CrewAI/AutoGen 看起来很美，多角色协作效果好。 - 《Building Agentic AI Systems》偏保守：强调"高风险任务才投入更多算力做多 Agent"，普通任务单 Agent 足够。 - 我们的判断：先单 Agent 榨干，再拆。多 Agent 是最后手段，不是默认配置。

四、拆的最小可行步骤

  1. 先把单 Agent 的 prompt 按业务域切成 2 份——看看拆完是不是真的更好。
  2. 用最小通信：共享一个文件/数据库，不要搞复杂的消息总线。
  3. 给每个 Agent 加日志（《零基础搭建》划线上第 15 条：回调处理器记录每次运行状态）。
  4. 跑一周看 token 成本和成功率，再决定要不要继续扩。

来自哪些书的哪些观点

  • 《动手做 AI Agent》（黄佳）：从 AutoGPT/BabyAGI（单 Agent 自治）到 CAMEL/AutoGen/MetaGPT（多 Agent 协作）的演进史；"高层次 Agent 决策、低层次 Agent 执行"的分层模型。
  • 《Building Agentic AI Systems》：Coordinator-Worker-Delegator 是企业级标准架构；高风险任务才值得多 Agent；Reflection 必须独立 Critic。
  • 《大模型项目实战》（高强文）：CrewAI 多角色、AutoGen 辅助编程、Qwen-Agent 多智体图像——给了工程化代码模板。
  • 《一本书讲透 MCP》：MCP + A2A 协议的融合——未来多 Agent 互联会走 A2A 协议，不是自己造轮子。

我们已经是多 Agent 系统——但每个 Agent 内部还是单 Agent 循环。下一步要做的不是"再拆一个"，而是把六员之间的通信协议标准化（参考 A2A 协议），减少"派任务靠口头约定"的模糊地带。详见同目录《多智能体协作流程》和《多智能体共享记忆 G-Memory》。
