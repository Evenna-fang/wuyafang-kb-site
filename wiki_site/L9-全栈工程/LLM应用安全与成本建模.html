WHY：安全、成本与合规为什么是交付红线

2
  1. 安全与成本是全栈工程的两条红线，且都由同一个变量驱动——Agent 的"动作集"：给 agent 加一个工具，既是新攻击面，也是新的 token 消耗点。Anthropic Opus 4.6 system card 的实测最能说明问题：同一模型在某环境 0% 攻击成功率、另一环境 78.6%，差异只在可用动作，不在模型本身。
  2. Prompt 注入是"攻防游戏"而非一次性 fix：所有 delimiter/前缀类防御都被官方判定不可靠（LangChain 明示"No prompt or delimiter strategy fully prevents indirect prompt injection"），真正可靠的是架构层的最小权限 + 隔离 + 把检索内容当 data 而非 instruction。
  3. 成本的大头在 LLM 推理：RAG 系统 LLM 推理成本占总账单 60–75%，而最易失控的配置项是检索 chunk 数 k——k 从 3 涨到 8，单 query 输入成本约翻倍。
  4. 模型分层路由 + 缓存命中是两个数量级的杠杆：80% 查询用 flash 级模型即可，仅 20% 复杂推理需 pro 级；配合 prefix caching，输入费可再省约 60%。同规模负载从旗舰换到极低价模型，成本可差 33 倍。
  5. 合规是"到日历日就坏"的变更源：备案/登记/法规生效这类变更无法用技术 workaround 绕过，必须进周/月扫描节奏，而非"需要时再查"。

  • 真实 CVE/事故：Anthropic 自家 Git MCP server 的 CVE-2025-68143/68144/68145（2026-01 披露），攻破点只是让 AI 读到恶意 README 或被投毒的 issue；claude-code-action critical flaw（2026-01）：授权绕过 + 间接注入 + 环境变量外泄，从公开 issue 起步最终把恶意代码推入主分支；Clinejection（2026-02 披露、2/17 野外利用）：一个构造的 GitHub issue → 4 步攻击链 → 推送到 action repo → 传播到所有下游依赖，属供应链级风险。
  • 防御分层（2026 共识）：架构层 = 最小权限（工具白名单）+ 隔离（VM/container，不让 agent 跑在客户 primary OS）+ 数据分级；运行时层 = 输入/输出监控 + 异常动作检测（agent 突然调 unusual tool）+ faithfulness/citation check；治理层 = 高风险动作 HITL 人工审批 + 全量审计日志 + 模型红队评估。
  • MCP 带来的新攻击面：MCP 已被 Microsoft/OpenAI/Google/Amazon 共同支持，让模型可调 terminal/database/filesystem，直接把注入的影响从"说错话"升级到"执行命令"；MCPTox benchmark 专测真实 MCP server 上的 tool poisoning。
  • FDE 交付 red line：任何 delimiter 策略都不可靠；同一模型不同 action 集 = 不同安全等级；GUI/浏览器/文件系统权限必须隔离；注入是持续攻防，要有 roundup 机制；MCP 集成必须做 tool-level audit，每个可调用 tool 都列攻击场景。

LLM 成本建模

3

成本公式：

单 query 成本 = (k × chunk_size + system_prompt_tokens + query_tokens) × input_price
             + answer_tokens × output_price
月度成本 = 单 query 成本 × 月查询数

2026 定价分层（每百万 token，美元；RAG 系统 LLM 推理占总账单 60–75%）：

层 代表模型 Input Output
极致低价 DeepSeek V4-Flash / 小米 MiMo V2 Flash / qwen-turbo $0.14 / ~$0.10 / ≈$0.04 $0.28 / ~$0.40 / ≈$0.08
中端旗舰 Claude Sonnet 5.5 / GPT-5.4 / Gemini 3.8 Flash（促销） $2.00 / $5.00 / $0.75* $10.00 / $8.75 / $3.75*
最贵旗舰 Claude Opus 5 $5.00 $25.00

* Gemini 3.8 Flash 为促销价，2027 年 1 月翻倍。DeepSeek 缓存命中价低至 $0.0028/M（约 miss 价的 1/50）。

  • 分层路由 80/20：约 60% 简单事实问答/摘要/翻译走 flash 级，30% 中等推理走 Haiku/Flash/qwen-plus，10% 复杂推理/代码/数学才上 pro 级；先让 flash 答、置信度低或追问时再升级。整体成本可降 5–15 倍。
  • 控 k 值：默认 k=3 而非 k=10；实测 k 从 3→8，context token 从 1500→4000，单 query 输入成本约翻倍。更省的做法是用 reranker 先取 k=20 再精排到 top-3。
  • 开缓存：system prompt 不变时开 prefix caching；3000 token 上下文里若 2500 是重复内容、命中率 80%，输入费可省约 60%。
  • 量级示例（15 万查询/月，context=2000、answer=400）：GPT-5.4 约 $1,950，Claude Sonnet 5.5 约 $1,050，DeepSeek V4-Flash 约 $59，qwen-turbo 约 $17——换模型相差 33 倍。
  • 别忘 embedding 成本（text-embedding-3-small $0.02/M，bge-m3 本地免费），占比小但要有总量。

HOW：从工具审计到成本与合规复盘

2
  1. 先审计动作集：列出 agent 可调用的每个工具及权限，按最小权限配置白名单；GUI、浏览器、文件系统与 terminal 能力必须隔离，并为每个 MCP tool 写明攻击场景。
  2. 把注入防御落到架构层：检索内容只作为 data，不作为 instruction；叠加运行时输入/输出监控、异常工具调用检测、高风险动作人工审批和全量审计日志，不依赖 delimiter 做一次性修复。
  3. 先算成本再调参：把月查询数、k、chunk 大小、输入/输出 token 与模型单价代入上式，分别测算当前方案和候选方案；embedding 费用也计入总量。
  4. 按三个杠杆实施降本：默认小 k，并用大候选召回后 rerank 到少量上下文；固定 system prompt 前缀并开启 prefix caching；简单请求走低价模型，仅低置信度、追问或复杂推理升级高价模型。
  5. 持续复盘而非一次上线：按月跟踪 cache 命中率、平均上下文 token 和各模型档位的流量比例；把备案、法规生效和 LICENSE 变更纳入周/月扫描，发现合规红线时停止上线或下线整改。
