WHY：为什么成本是 RAG 的第一约束

2

RAG 成本不是"调个便宜模型"就完事，而是三个杠杆的组合优化：80/20 模型分层、k 值控制、prefix caching——LLM 推理占 RAG 总成本 60-75%，其中 k（检索 chunk 数）从 3 增到 8 单 query 成本就翻倍；cache hit 价格仅为 miss 的 1/50~1/100；分层路由案例做到 33 倍成本差（$1950→$59 / 15 万查询）。

WHAT / WHYT：k 值、缓存与分层路由三个杠杆

2
  • 成本公式：查询数 × (context_tokens × 输入价 + answer_tokens × 输出价)。输入侧由 k 和 chunk 大小共同决定，是最可控的旋钮。
  • 价格分层（2026）：低价层 DeepSeek V4-Flash / MiMo V2-Flash（$0.1-0.4/M）；旗舰层 Claude Sonnet 5.5 / GPT-5.4（$2-10/M）。80% 的 RAG 查询只需 Flash 级，20% 复杂推理才上 Pro 级。
  • 缓存杠杆：DeepSeek cache hit $0.0028/M vs miss $0.14/M（低 50-100 倍）；system prompt 固定 + prefix caching 命中率 80% 时，输入费用省 60%。
  • 检索经济学：reranker 先取 k=20 再精排到 top-3，比直接检索 k=8 更便宜且质量更高（大 k 买召回，精排后上下文 token 反而下降）。
  • 分层路由：简单任务走 Flash；置信度低或用户追问时升级 Pro。实测 15 万查询 $1950→$59，33 倍差距。

三个杠杆为什么成立

3
  1. 输入 token 主导成本：RAG 的输出短、上下文长，成本大头在输入侧，所以 k/分块/缓存比换模型更有效。
  2. 缓存是结构性折扣：固定前缀让 provider 侧 KV 复用，价格表层面就是 1/50~1/100，不需要任何质量妥协。
  3. 质量与成本在路由层解耦：不追求"一个模型又便宜又好"，而是用置信度把简单流量导向低价层。

HOW：成本建模、参数预算、缓存改造与路由监控

2
  1. 先建模再优化：月成本 = Q × (k×avg_chunk_tokens×P_in + answer_tokens×P_out)，把 k、缓存命中率、分层比例三个变量代入算敏感度。
  2. k 值预算：默认 k=4~6 + rerank 精排到 top-3；任何把 k 拉到 8 以上的改动必须附成本测算。
  3. 缓存改造：system prompt 与固定指令放最前（prefix 稳定），易变的用户 query 放最后；目标 cache 命中率 ≥ 80%。
  4. 路由阈值：reranker 粗筛 → 精排 → 置信度评分；低置信或追问才升级 Pro 模型。
  5. 监控：按月复盘 cache hit rate、avg context tokens、Flash/Pro 流量比（目标 80/20）。

一句话洞见（L3）

2
  1. 价格分层决定模型选择：80% 的 RAG 查询只需低价层 Flash 模型处理，20% 复杂任务才需旗舰 Pro 模型，这是成本优化的黄金比例。
  2. k 值是成本控制关键阀门：检索 chunk 数（k）从 3 增至 8 会使单 query 成本翻倍，成为最易失控的配置杠杆点。
  3. 缓存机制创造指数级节省：prefix caching 命中率达 80% 可削减 60% 输入费用，cache hit 价格仅为 miss 的 1/100。
  4. 分层路由实现动态优化：先 reranker 粗筛再精排 + 置信度路由策略，可创造 33 倍成本差距的运营效益。
