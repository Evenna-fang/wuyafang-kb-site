WHY

2

项目价值与适用场景

3
  1. 破解大模型幻觉：通用大模型没有企业私有知识，直接问会一本正经地编。RAG 用"先检索再生成"把答案锚定在真实文档上，是当前最主流、成本最低的幻觉治理手段。
  2. 私有数据不出域：企业文档、产品手册、内部规章不能上传到公有大模型。本地部署 Embedding + 向量库 + LLM，数据全程可控。
  3. 知识即时更新：微调要重训、周期长、成本高；RAG 只需增删文档重新入库，知识更新从"天级"降到"分钟级"。
  4. 可溯源、可审计：回答附带命中的原文片段，用户能核对、能追责，满足合规要求。
  5. 跨行业可复用：换一套语料就是换一个行业——教育答疑、法务合同、医疗病历、客服手册、金融研报都能套同一套管线，是全栈工程师最该掌握的"母版项目"。

WHAT

2

系统定义与适用边界

3

一个端到端的私有知识库问答系统：用户上传 PDF/DOCX/TXT 文档，系统自动完成解析→父子分块→向量化→入库，之后用户用自然语言提问，系统检索最相关的文档片段，交给大模型生成带上下文、可溯源的回答。它把"企业散落在文档里的知识"变成"能被对话式调用的能力"。

适用人群与前置知识：面向已掌握 Python 基础、了解大模型 API 调用的全栈/应用工程师。前置需要会用 pip 管理依赖、理解 HTTP 与 JSON、会写基本的类与函数。不需要深厚的机器学习背景——本项目以工程集成为主，模型与向量检索都通过成熟库调用。读完应能独立搭建一个可上传文档、可提问、可溯源的最小 RAG 系统，并知道如何把它优化到能上生产的水准。

在博学谷项目库中它的落地形态是 EduRAG 智慧问答系统（IT 职业教育答疑大模型），在黑马项目库中对应 RAG 智能体开发阶段的综合实战，在课件里对应智能文档检索助手。三者本质同一套骨架，只是换了行业数据（教育答疑 / 企业文档 / 产品手册）。因此本篇以课件中可直接复现的完整实现为主干，再叠加企业级检索策略，做到"看完就能动手"。

HOW

2

实施路径

3

按"需求分析 → 架构设计 → 代码实现 → 部署运维"四段走。代码段全部来自课件可运行实现（智能文档检索助手 项目），已验证其结构完整。

3.1 需求分析

功能需求（FR）
- FR1 文档接入：支持 PDF、DOCX、TXT 上传，自动解析为纯文本。
- FR2 智能分块：父子两级分块（父块给上下文、子块做精准召回）。
- FR3 向量化入库：Embedding 后写入向量库，元数据记录文档/父子归属关系。
- FR4 检索问答：基于问题召回 Top-K 相关块，重排/压缩后拼上下文生成答案。
- FR5 多轮会话：维护 session 与历史对话，支持追问。
- FR6 来源展示：回答附命中的文档片段，供用户核对。
- FR7 管理能力：文档列表、分块数量、删除文档（级联删除向量与记录）。

非功能需求（NFR）
- NFR1 准确率：答案须基于检索上下文，无相关信息时诚实说明（不编造）。
- NFR2 响应：首 token 流式返回，问答 P95 目标 < 3s（本地向量库）。
- NFR3 可扩展：向量库与 Embedding 可替换（Chroma→Milvus，本地 BGE-M3→云端）。
- NFR4 可运维：配置化（config/env）、日志、错误兜底、依赖可一键安装。

数据设计：三张核心表——documents（文档）、parent_chunks（父块）、child_chunks（子块），外加 chat_history（对话）。父子一对多，级联删除。

分层职责
- 前端层：Streamlit（快速搭交互；生产可换 FastAPI + Vue/Next.js，见项目三）。
- 编排层：streamlit_app.py 串联上传、入库、对话；用 @st.cache_resource 热加载核心组件（单例）。
- 核心层：
- DocumentProcessor：加载 + 父子分块；
- VectorStore：嵌入 + Chroma 存取 + 检索器（含上下文压缩）；
- RAGSystem：检索、拼上下文、调 LLM、存历史。
- 数据层：MySQL 存结构化元数据与对话；Chroma 存向量。

关键设计决策（为什么这么做）
- 父子分块（Parent-Child Chunking）：小块（子块）做向量召回更精准，但上下文不全；命中子块后回捞其父块作为最终上下文，兼顾精准与完整。这是该课件项目的核心亮点。
- 子块召回 + 上下文压缩：用 ContextualCompressionRetriever + LLMChainExtractor 对召回结果再抽取，去掉噪声，省 token。
- 元数据桥接：parent_id 把子块和父块关联，检索子块→取 parent_id→查父块文本。
- 流式生成：LLM streaming=True，前端逐 token 渲染，提升体感。

（3）core/document_processor.py——解析 + 父子两级分块

from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_community.document_loaders import PyPDFLoader, TextLoader, Docx2txtLoader
import os
import tempfile

class DocumentProcessor:
    def __init__(self, config):
        self.config = config
        # 父块更大（给完整上下文），子块更小（做精准召回）
        self.parent_splitter = RecursiveCharacterTextSplitter(
            chunk_size=config.CHUNK_SIZE * 2,
            chunk_overlap=config.CHUNK_OVERLAP,
            separators=["\n\n", "\n", "。", "！", "？"],
        )
        self.child_splitter = RecursiveCharacterTextSplitter(
            chunk_size=config.CHUNK_SIZE // 2,
            chunk_overlap=config.CHUNK_OVERLAP // 2,
            separators=["\n", "。", "！", "？", ".", "!", "?", " "],
        )

    def load_document(self, uploaded_file):
        with tempfile.NamedTemporaryFile(
            delete=False, suffix=f".{uploaded_file.name.split('.')[-1]}"
        ) as tmp_file:
            tmp_file.write(uploaded_file.getvalue())
            tmp_path = tmp_file.name
        try:
            if uploaded_file.name.endswith('.pdf'):
                loader = PyPDFLoader(tmp_path)
            elif uploaded_file.name.endswith('.docx'):
                loader = Docx2txtLoader(tmp_path)
            elif uploaded_file.name.endswith('.txt'):
                loader = TextLoader(tmp_path, encoding='utf-8')
            else:
                raise ValueError(f"不支持的文件类型: {uploaded_file.name}")
            return loader.load()
        finally:
            if os.path.exists(tmp_path):
                os.unlink(tmp_path)

    def create_parent_child_chunks(self, documents, fileName):
        parent_docs = self.parent_splitter.split_documents(documents)
        child_docs = []
        for i, parent_doc in enumerate(parent_docs):
            parent_id = f"{fileName}_parent_{i}"
            parent_doc.metadata['parent_id'] = parent_id
            parent_doc.metadata['doc_type'] = 'parent'
            for j, child_doc in enumerate(self.child_splitter.split_documents([parent_doc])):
                child_doc.metadata['parent_id'] = parent_id
                child_doc.metadata['child_id'] = f"child_{i}_{j}"
                child_doc.metadata['doc_type'] = 'child'
                child_docs.append(child_doc)
        return parent_docs, child_docs

（4）core/vector_store.py——嵌入 + 双集合 + 压缩检索

import chromadb
from langchain_chroma import Chroma
from langchain_huggingface import HuggingFaceEmbeddings
from langchain.retrievers import ContextualCompressionRetriever
from langchain.retrievers.document_compressors import LLMChainExtractor
from langchain_openai import ChatOpenAI

class VectorStore:
    def __init__(self, config):
        self.config = config
        # 中文语义嵌入（本地 BGE；生产可换 BGE-M3 支持稠密+稀疏混合）
        self.embeddings = HuggingFaceEmbeddings(
            model_name="BAAI/bge-large-zh-v1.5"
        )
        self.chroma_client = chromadb.PersistentClient(path=config.CHROMA_PERSIST_DIR)
        self.parent_vectorstore = Chroma(
            client=self.chroma_client, collection_name="parent_documents",
            embedding_function=self.embeddings,
        )
        self.child_vectorstore = Chroma(
            client=self.chroma_client, collection_name="child_documents",
            embedding_function=self.embeddings,
        )
        self.llm = ChatOpenAI(
            api_key=config.OPENAI_API_KEY, base_url=config.OPENAI_BASE_URL,
            model="qwen-plus", temperature=0,
        )
        self.compressor = LLMChainExtractor.from_llm(self.llm)

    def add_documents(self, parent_docs, child_docs, document_id):
        for doc in parent_docs + child_docs:
            doc.metadata['document_id'] = str(document_id)
        parent_ids = self.parent_vectorstore.add_documents(parent_docs)
        child_ids = self.child_vectorstore.add_documents(child_docs)
        return parent_ids, child_ids

    def create_retriever(self, use_compression=True):
        # 子块召回，k 取 TOP_K*2 留余量
        child_retriever = self.child_vectorstore.as_retriever(
            search_kwargs={"k": self.config.TOP_K * 2}
        )
        if use_compression:
            return ContextualCompressionRetriever(
                base_compressor=self.compressor, base_retriever=child_retriever
            )
        return child_retriever

    def get_parent_documents(self, child_docs):
        parent_ids = {d.metadata['parent_id'] for d in child_docs if 'parent_id' in d.metadata}
        parent_docs = []
        for pid in parent_ids:
            try:
                results = self.parent_vectorstore.get(where={"parent_id": pid})
                parent_docs.extend(results['documents'][0])
            except Exception as e:
                print(f"获取父文档失败 (parent_id={pid}): {e}")
        return parent_docs

（5）core/rag_system.py——检索 + 上下文 + 生成 + 历史

from langchain_openai import ChatOpenAI
from langchain.prompts import PromptTemplate
import uuid

class RAGSystem:
    def __init__(self, config, db_manager, vector_store):
        self.config, self.db_manager, self.vector_store = config, db_manager, vector_store
        self.llm = ChatOpenAI(
            api_key=config.OPENAI_API_KEY, base_url=config.OPENAI_BASE_URL,
            model="qwen-plus", temperature=0.7, streaming=True,
        )
        self.rag_prompt = PromptTemplate(
            template="""你是一个智能助手。请基于以下上下文信息回答用户的问题。如果上下文中没有相关信息，请诚实地说明。

上下文信息:
{context}

历史对话:
{chat_history}

用户问题: {question}

请提供准确、有帮助的回答:""",
            input_variables=["context", "chat_history", "question"],
        )

    def chat_with_documents(self, question, document_ids, session_id):
        try:
            retriever = self.vector_store.create_retriever(use_compression=True)
            retrieved_docs = retriever.invoke(question)          # 1) 子块召回(+压缩)
            parent_docs = self.vector_store.get_parent_documents(retrieved_docs)  # 2) 回捞父块
            context = "\n\n".join(parent_docs)                    # 3) 拼上下文

            history = self.db_manager.get_chat_history(session_id)
            history_text = "\n".join(
                f"用户: {c.user_message}\n助手: {c.assistant_message}" for c in history[-3:]
            )
            full_prompt = self.rag_prompt.format(
                context=context, chat_history=history_text, question=question
            )
            answer = self.llm.invoke(full_prompt).content          # 4) 生成
            self.db_manager.save_chat_history(
                session_id=session_id, user_message=question,
                assistant_message=answer, document_ids=",".join(map(str, document_ids)),
            )
            return answer, retrieved_docs
        except Exception as e:
            return f"RAG对话出错: {e}", []

（6）core/database.py（要点）——SQLAlchemy ORM 三表 + 级联删除

from sqlalchemy import Column, Integer, String, Text, DateTime, ForeignKey, Index
from sqlalchemy.orm import relationship, declarative_base

Base = declarative_base()

class Document(Base):
    __tablename__ = 'documents'
    id = Column(Integer, primary_key=True)
    filename = Column(String(255))
    chunk_count = Column(Integer, default=0)
    parent_chunks = relationship("ParentChunk", back_populates="document",
                                 cascade="all, delete-orphan")
    child_chunks = relationship("ChildChunk", back_populates="document",
                                cascade="all, delete-orphan")

class ParentChunk(Base):
    __tablename__ = 'parent_chunks'
    id = Column(Integer, primary_key=True)
    document_id = Column(Integer, ForeignKey('documents.id'), nullable=False)
    parent_id = Column(String(100))      # 与向量库元数据对应
    content = Column(Text)
    vector_id = Column(String(100))      # Chroma 中的向量 ID
    document = relationship("Document", back_populates="parent_chunks")

class ChildChunk(Base):
    __tablename__ = 'child_chunks'
    __tablename__ = 'child_chunks'
    id = Column(Integer, primary_key=True)
    document_id = Column(Integer, ForeignKey('documents.id'), nullable=False)
    parent_chunk_id = Column(Integer, ForeignKey('parent_chunks.id'), nullable=False)
    content = Column(Text)
    vector_id = Column(String(100))
    __table_args__ = (Index('idx_child_parent_id', 'parent_chunk_id'),)

（7）streamlit_app.py（主流程骨架）

import streamlit as st
from config.config import Config
from core.database import DatabaseManager
from core.document_processor import DocumentProcessor
from core.vector_store import VectorStore
from core.rag_system import RAGSystem

@st.cache_resource          # 单例热加载，避免每次交互重建
def init_system():
    config = Config()
    db_manager = DatabaseManager(config)
    doc_processor = DocumentProcessor(config)
    vector_store = VectorStore(config)
    rag_system = RAGSystem(config, db_manager, vector_store)
    return config, db_manager, doc_processor, vector_store, rag_system

def upload_and_process_document(uploaded_file, doc_processor, vector_store, db_manager):
    documents = doc_processor.load_document(uploaded_file)
    parent_docs, child_docs = doc_processor.create_parent_child_chunks(documents, uploaded_file.name)
    parent_ids, child_ids = vector_store.add_documents(parent_docs, child_docs, 0)
    db_manager.save_document_with_chunks(
        filename=uploaded_file.name, parent_docs=parent_docs, child_docs=child_docs,
        parent_vector_ids=parent_ids, child_vector_ids=child_ids,
    )
    return True

config, db_manager, doc_processor, vector_store, rag_system = init_system()
st.title("智能文档检索助手 🤖")
uploaded_files = st.file_uploader("上传 PDF/DOCX/TXT", type=["pdf", "docx", "txt"], accept_multiple_files=True)
if uploaded_files:
    for f in uploaded_files:
        upload_and_process_document(f, doc_processor, vector_store, db_manager)

question = st.chat_input("基于文档提问…")
if question:
    answer, docs = rag_system.chat_with_documents(question, document_ids=[], session_id="s1")
    st.chat_message("assistant").write(answer)
    with st.expander("查看引用来源"):
        for i, d in enumerate(docs, 1):
            st.markdown(f"**[{i}]** {d.page_content[:200]}…")

3.4 部署与运维

部署（从 Demo 到生产）
1. 容器化：Dockerfile 打包应用；Chroma 持久化目录与 MySQL 用数据卷挂载，保证重启不丢数据。
2. 向量库升级：单机 Chroma → Milvus（分布式、亿级向量、混合检索）。接入 BGE-M3 稠密+稀疏混合检索 + Reranker 精排，显著提升召回质量。
3. 模型接入：本地 Ollama/私有化 DeepSeek/Qwen 保证数据不出域；或云端 DashScope。Embedding 与 LLM 通过 base_url 切换。
4. 服务化：Streamlit 适合内网工具；对外提供服务时拆 FastAPI（后端）+ Vue/Next.js（前端），RAG 核心逻辑不变，仅换接口层。
5. 缓存：Redis 缓存高频问答（query→answer）与向量检索结果，降本提速（详见 L9《成本是 RAG 第一约束》）。

运维与评估
- 日志：统一 logging，记录 query、召回片段、命中 parent_id、耗时、token 消耗；错误兜底返回可解释信息。
- 检索质量评估（三位一体）：
- 检索层：Precision、Recall、MRR、Context Precision；
- 生成层：Faithfulness（忠实度）、Answer Relevancy、ROUGE-L、BERTScore；
- 系统层：平均延时、QPS、缓存命中率。
- 工具用 Ragas 做端到端评测，badcase 回流改分块/嵌入/Top-K。
- 持续迭代：文档增量入库、过期文档下架；跟踪幻觉率、成本，调 CHUNK_SIZE/TOP_K/是否压缩。
- 安全：API Key 走 env/密钥服务，不进仓库；敏感文档做权限隔离与脱敏。

5.1 分块策略怎么选

分块是 RAG 质量的第一道闸门。块太小，语义被切断、召回碎片化；块太大，噪声多、嵌入被稀释、成本飙升。经验起点是 500~1000 字、10%~20% 重叠，再按语料类型微调：法律/合同按条款切，代码按函数切，问答按段落切。父子分块本质上是"召回用小块、生成用大块"，用空间换质量。递归分隔符优先按语义边界（段落、句号、换行）切，避免硬切把一句话劈成两半。

5.2 检索质量优化四板斧

第一，混合检索：稠密向量（语义）+ 稀疏向量（BM25 关键词）互补，专有名词、型号、编号靠稀疏兜住。第二，重排序（Reranker）：粗召回 Top-50，用 bge-reranker 精排取 Top-5，命中率显著提升。第三，查询改写与扩展：用 LLM 把口语化问题改写成检索友好查询，或做 HyDE（先让 LLM 生成假设性答案再用其嵌入检索）、子查询拆解多跳问题。第四，意图识别与路由：用 BERT 分类器判断问题类型，决定走向量检索、关键词检索还是结构化查询，避免"一刀切"。

5.3 成本与延迟控制

RAG 的成本大头是嵌入和生成 token。高频问答用 Redis 缓存（query 归一化后查缓存）；上下文压缩只保留相关句子，直接砍输入 token；Top-K 从 10 降到 5 往往质量不降、成本减半；简单问题路由到小模型、复杂问题才用大模型。评估不能只看准确率，还要看单次问答成本与 P95 延迟，形成"质量—成本—延迟"三角的权衡基线。

5.4 幻觉治理与可信度

提示词里强制"仅依据上下文回答，无相关信息就说明"；答案附引用片段与行号，让用户可核对；对医疗、法务、金融等高风险场景，宁可"不答"也不"编答"，并加人工复核通道。用 Ragas 的 Faithfulness 持续监控忠实度，一旦下降就回查是不是检索偏了或分块坏了。

5.5 多源与结构化数据

企业知识不只有文档，还有数据库表、FAQ、网页。结构化数据走"文本转 SQL + 结果转自然语言"或"预生成摘要入库"；多源用查询路由分发到不同检索器，结果统一融合重排。增量入库用文档哈希去重、版本管理，过期文档下架并清理向量，避免"僵尸知识"污染答案。

    |---|---|---|
    | 路由 | route_question / _classify_query（L1089） | route=complex_reasoning |
    | 混合检索 | _do_retrieve / retrieve_hybrid | merged top-435 |
    | 重排 | rerank（L890） | 熔断: 回退排序 top-3 |
    | 门禁 | gate_node（L2245） | best_dist=0.2720 dense_gate_threshold=0.5（放行） |

  • 项目里最值得抄的设计：每条失败路径都有对应代码，不是「理论上会处理」——rerank 超时熔断、检索不到拒答（_build_refusal_answer，文案固定为「知识库无此内容: 检索质量未达及格线, 不作答(不编造)。」）、引用无据整句标⚠️。
  • 入口不止一个：命令行 python query.py "问题" --topk 3（本次用）、API python serve.py --port 6400、MCP rag/mcp_server.py（query_knowledge 工具）。同一套检索核心三处复用。
  • 和课件讲法的差异：课件的 RAG 项目通常「检索→拼 prompt→生成」三步；本库多出「路由 / 门禁 / 熔断 / 引用校验」四段，代码量 2727 行里大部分是这四段。
  • 本库暂无：没有前端页面（借 OpenWebUI）、没有多轮对话记忆、没有答案级的人工反馈闭环落库（data/feedback.jsonl 有写但未回灌评测）。
