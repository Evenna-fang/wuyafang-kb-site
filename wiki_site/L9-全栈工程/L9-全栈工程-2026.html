生产版必须回答五个问题：

  1. 首 token 多久到达，用户停止后上游是否立即停止计费？
  2. 上游限流或进程过载时，请求是有界排队、快速失败，还是无限堆积？
  3. SSE 的一个事件被 TCP 拆成两半时，前端是否仍能正确解析？
  4. 首字节之后失败时，用户能否保留部分答案并得到可重试的终止事件？
  5. 检索或工具内容包含恶意指令时，模型能否借此越权读写？

《Hermes 技术内幕》把流式响应解析、中断恢复和流式输出适配分别列为独立章节；《持续交付2.0》强调质量内建与快速反馈。两者合起来的工程结论是：流式协议、后端并发和安全验收不是后补优化，而是交付骨架。

传输与 API 的准确边界

3
  • SSE 是文本事件流，不等于某个模型厂商的 chunk 格式。服务端应自定义稳定事件协议，例如 data: {"text":"..."}\n\n、 event: error、data: [DONE]，避免把 Provider 原始错误和内部字段透给浏览器。
  • 原生 EventSource 适合简单 GET 事件流；需要 POST JSON、自定义请求头和主动取消时，用 fetch + ReadableStream + AbortController。
  • TCP chunk 与 SSE event 没有一一对应关系。前端必须保留跨 chunk 的 buffer，以空行 \n\n 分帧；直接对每个网络 chunk split('\n') 会丢字、错 JSON。
  • FastAPI 官方说明 StreamingResponse 同时接受异步生成器和普通生成器；真正需要避免的是在事件循环里执行阻塞 I/O。第三方客户端支持 await 时用 async def；只有同步客户端时，应使用其线程池/同步路由语义，而不是伪装成异步。
  • 异步任务只有运行到 await 才有机会响应取消。流循环必须真正等待异步 I/O，并在 finally 关闭上游 stream。
  • 若采用 Next.js 全 TypeScript 路线，当前 AI SDK 官方形态是 useChat + DefaultChatTransport + message.parts，服务端用 streamText 产生 UI message stream。该协议与下面的自定义 SSE 示例不同，不能不加适配地混接。

main.py 模板：

import asyncio
import json
import logging
import os
from typing import Literal

from fastapi import FastAPI, HTTPException
from fastapi.responses import StreamingResponse
from openai import AsyncOpenAI
from pydantic import BaseModel, Field

app = FastAPI()
client = AsyncOpenAI()  # 从服务端环境读取密钥
model_name = os.environ["MODEL_NAME"]
gate = asyncio.Semaphore(int(os.getenv("MAX_IN_FLIGHT", "16")))
log = logging.getLogger("chat")

class Message(BaseModel):
    role: Literal["system", "user", "assistant"]
    content: str = Field(min_length=1, max_length=32_000)

class ChatRequest(BaseModel):
    messages: list[Message] = Field(min_length=1, max_length=50)

@app.post("/api/chat")
async def chat(req: ChatRequest):
    # 本例选择快速失败；若改排队，队列也必须有长度与等待超时。
    if gate.locked():
        raise HTTPException(status_code=503, detail="服务繁忙，请稍后重试")

    async def events():
        stream = None
        try:
            async with gate:
                stream = await client.chat.completions.create(
                    model=model_name,
                    messages=[m.model_dump() for m in req.messages],
                    stream=True,
                    timeout=90,
                )
                async for chunk in stream:
                    if not chunk.choices:
                        continue
                    text = chunk.choices[0].delta.content
                    if text:
                        payload = json.dumps({"text": text}, ensure_ascii=False)
                        yield f"data: {payload}\n\n"
                yield "data: [DONE]\n\n"
        except asyncio.CancelledError:
            # 客户端断开或服务器取消：不再继续生成，finally 关闭上游。
            raise
        except Exception:
            log.exception("LLM stream failed")  # 不记录 prompt 与密钥
            yield 'event: error\ndata: {"message":"生成中断，请稍后重试"}\n\n'
        finally:
            if stream is not None:
                await stream.close()

    return StreamingResponse(
        events(),
        media_type="text/event-stream",
        headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"},
    )

下面是与上述 FastAPI 协议配套的核心解析，不依赖 AI SDK：

async function streamChat(messages: unknown[], signal: AbortSignal,
                          append: (text: string) => void) {
  const res = await fetch('/api/chat', {
    method: 'POST',
    headers: {'Content-Type': 'application/json'},
    body: JSON.stringify({messages}),
    signal,
  });
  if (!res.ok || !res.body) throw new Error(`HTTP ${res.status}`);

  const reader = res.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';

  while (true) {
    const {done, value} = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, {stream: true});
    let end: number;
    while ((end = buffer.indexOf('\n\n')) >= 0) {
      const frame = buffer.slice(0, end);
      buffer = buffer.slice(end + 2);
      const data = frame.split('\n')
        .filter(line => line.startsWith('data:'))
        .map(line => line.slice(5).trimStart()).join('\n');
      if (!data || data === '[DONE]') continue;
      const event = JSON.parse(data);
      if (event.text) append(event.text);
    }
  }
  buffer += decoder.decode();  // 收尾时刷新 UTF-8 解码器
}

组件中用 AbortController 绑定“停止”按钮和卸载清理。高频 token 不要无条件触发整棵组件树重渲染：先在外部 store 聚合短时间窗口，再用 React 官方 useSyncExternalStore(subscribe, getSnapshot) 订阅快照；getSnapshot 必须返回缓存值，不能每次新建对象造成循环渲染。

若选 AI SDK，则按同一版本官方文档实现 useChat、transport 和服务端 UI message stream，并渲染 message.parts 中的 text、tool 与 source 部分；锁版本后再抄示例，不能将旧版 maxSteps/parameters 与新版 stopWhen/inputSchema 混用。

3. 安全与交付门禁

3
  • 密钥只在服务端；CORS 列明确来源；会话与历史落数据库，按用户/租户隔离。
  • system prompt、用户输入、检索内容、工具结果分区；后三者都不是高权限指令。写文件、付款、发消息等副作用工具采用参数校验、最小权限和人工审批。
  • 首字节前失败用 4xx/5xx；首字节后失败用脱敏 error event，保留已生成文本。流中途不自动整包重试，避免重复计费和重复副作用。
  • 反代关闭 SSE 缓冲并配置读超时；压测覆盖长答案、慢 Provider、客户端提前断开和上游 429。
  • 验收至少包含：流式逐帧、跨 chunk 分帧、停止传播、超闸 503、错误脱敏、越权检索拒绝、刷新后会话恢复策略。
