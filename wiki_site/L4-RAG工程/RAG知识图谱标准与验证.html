WHY：让关系成为可追溯证据，而不是新的噪声来源

业务价值与质量边界

2

图谱标准的业务价值是让不同文档、框架和维护者对“同一个实体、同一种关系、同一段有效时间”有一致解释。没有标准，别名会碎裂，PART_OF 与 part-of 会被当成两种边，错误关系又会在多跳检索中被放大；只有标准却没有证据和评测，也只是把噪声写得更工整。

本篇 sources 中的图谱重构设计与知识组织一手源对标提供三族谓词、合法边矩阵与来源回溯依据。适用于存在实体关系、多跳或全局问题且能人工核验边的知识库；单一 FAQ、未清洗原文、没有 competency questions 的试点不应先追求复杂本体。SKOS 的概念关系、代码图的符号关系、GraphRAG 的社区层级也不能混为一个“行业统一 schema”。

上线前的合同分三项：结构合法、边有原文支持、检索有净收益。下文论文数字保留各自数据集、日期与转引等级；来源中已有冲突的 0.60/1.00 不在本轮擅自裁决，缺少原文复核就标未定，不补造统一结论。

核心论点

2

图谱类 RAG 在 2026 年是成熟的补强环节而非前沿：它结构性地赢在全局摘要（comprehensiveness 胜率 72–83%）与多跳推理，却在简单事实上比 vanilla RAG 低 13.4%、延迟乘 2.3 倍——所以决策变量是 query 分布里多跳/全局类占多少，不是"要不要上图谱"。真正方向是图谱被吸收进 Agentic 范式（GA-RAG），而非被取代。落地的硬边界在工程侧：SEC 10-K 实验证明 tab/空白污染能让图抽取近乎归零，ontology 救不了上游坏掉的抽取；成本上抽取约占索引 75%，必须便宜模型 + 600-token 窗口 + 增量索引。补的顺序有定论：先补最便宜且已证降 35–67% 检索失败率的 Contextual Retrieval，再上图谱 + ontology，最后才 agentic 化，且双闸门 + 止损线（试点无提升即停、简单事实不能变差）必须前置。

2
  1. 图谱类 RAG 在 2026 年是"成熟的补强环节"，不是最新前沿：它的核心价值（全局摘要 + 多跳关系推理）已被 arXiv 一手 benchmark 反复证实，但索引成本高、对简单事实查询甚至更差。真正的最新方向是 Agentic RAG（检索变成 agent 动态决策循环，arXiv 2501.09136）以及图谱与之融合的 GA-RAG——即"图谱被吸收进 agentic 范式"，而非被取代。
  2. 选型问题不是"要不要上图谱"，而是"query 分布里多跳 / 全局 / agentic 类占多少"：简单事实（单跳）纯向量 + BM25 + reranker 即够；多跳关系、整库摘要才值得上图谱；类型不确定则混合 + 路由。
  3. 本库图谱层从 0 开始：grep graph/entity/relation 零命中、ontology 目录空、无 ttl/owl。补的顺序应是先补 Contextual Retrieval（最便宜、已证降 35–67% 检索失败率）→ 再上图谱 + ontology → 最后 agentic 化。
  4. 调研结论可信度经独立验证为 A-：17 项关键论断与官方源一致、0 项冲突、仅 2 项瑕疵；可作定标基础，但需补核 [6] 原文并给 "83.2%" 补"novel 数据集"限定。

  5. 落地必须设双闸门 + 止损线 + 负面指标：先测 query 分布、chunk 先去重才动图谱；试点无明显提升即停；简单事实不能变差、延迟不能暴涨。

  6. 图谱 RAG 的“agentic 化”不等于全量静态建图：据[一手源]：RAG图谱行业标准调研-20261009（§5 阶段3，引 arXiv 2604.09666，2026-04）——agentic search 大幅缩小 dense RAG 与 GraphRAG 的差距（RL 设定尤甚），但复杂多跳 GraphRAG 仍占优，且离线成本摊销后 agentic 行为更稳定。落地含义：图谱预算只投在已证实的复杂多跳场景，简单场景交给 agentic 循环，不为全部文档建全量静态图。

  7. 本库的真问题是谓词族没分，不是边少：据[一手源]：RAG图谱重构设计定稿v2-20261016——当时 141 条关系里纵向关系只有 9 条，因平级/纵向/映射三类关系混在同一谓词空间；解法是先“只加谓词 + 三族互斥规则”（实测纵向补到 41 条），再谈符号层和双键检索，不一次全量重建（一次建全图无法归因）。

评测标准（行业怎么量化图谱增益）

3
  • GraphRAG 自带评测：LLM-as-judge 头对头，三主标 Comprehensiveness / Diversity / Empowerment + 一对照 Directness（防"长答案赢一切"）；客观替代按可验证 factual claim 计数。
  • 检索层：Evidence Recall + Context Relevance，按 Level 1/2/3 复杂度分层；通用指标 Recall@k / MRR / nDCG / MAP。
  • 多跳 benchmark 构造：MultiHop-RAG = 知识库 + 多跳 query + ground-truth + supporting evidence 四件套；GraphRAG-Bench = 1018 道题、16 学科、9 个 SOTA，且同时测建图耗时 / token 成本 / 非孤立节点比例。
  • 方法论共识：检索与生成分开测；成本与质量并列报告；图本身也要评（非孤立节点比例、平均度、聚类系数）。
  • 据[一手源]：RAG图谱行业标准调研-20261009（§6.1–6.2）补充细节：GraphRAG 论文评测集为 Podcast（约 100 万 token）+ News/VIINA，每集 125 个 LLM 生成的 global sensemaking 问题；Directness 是防“长答案赢一切”的对照标，不是主指标。Recall@k 的 k 常取 {1,2,5,10} 或 {1,3,5,10,20}。主流多跳集：MultiHop-RAG、HotpotQA、2WikiMultiHopQA、MuSiQue，复杂长链用 MoNaCo（1315 题）。大规模自动化评测：RAGBench（10 万例、TRACe 框架），其结论是微调 RoBERTa 在 RAG 评估任务上胜过 LLM-judge；RAGAS 走 reference-free（faithfulness / answer relevancy / context relevance）。

谓词分族与纵向分解（图谱怎么表达“层层拆解”）

3
  • 三族互斥（据[一手源]：RAG图谱重构设计定稿v2-20261016，依 W3C SKOS + ISO 25964-1）：层级族 broader/narrower、关联族 related、映射族 exactMatch/closeMatch/broadMatch/narrowMatch，都挂在顶层属性 skos:semanticRelation 之下，平级与纵向在 TBox 层就分开，纵向关系才不会被平级边淹没。
  • 纵向谓词别自造，用带编码的现成件（同上）：part_of = BFO:0000050，互逆 has_part = BFO:0000051；has_component = RO:0002180（has_part 更严格的子属性，部件语义）；is_a = iso-thes:broaderGeneric（类-类）；组成关系 = iso-thes:broaderPartitive（整体-部分）。唯一要自建的是先修关系 prerequisites_for，schema.org 官方没有这个属性。
  • 文档↔代码的边（同上）：官方谓词叫 documents（Google Kythe：A 用自然语言描述语义节点 B），纵向分解叫 childof；源码锚点用 Software Heritage SWHID（swh:1:cnt:<hash> + path/lines 限定），可校验可复现；分块用 cAST 结构感知切分（按 AST 递归下钻，以非空白字符数度量），RepoEval Recall@5 +4.3。courseware 2.6 万文件不用 LLM 抽：LSP documentSymbol 拿层级树、tree-sitter tags 批量产 def/ref。
  • 纵向层次靠社区分层，不靠 part-of 谓词硬凑（据[一手源]：RAG知识组织对标-一手源-20261016 Q1）：GraphRAG 数据模型里层次字段是 COMMUNITY_ID / COMMUNITY_LEVEL / COMMUNITY_PARENT / COMMUNITY_CHILDREN，外加社区报告表（summary / findings / rank / full_content），“塔尖 = 高层社区报告，塔基 = 底层实体与文本单元”。关系谓词的形态是“自然语言描述 + STRENGTH 数值强度”，实体类型由调用方传入；prompt_tune 能按语料自动调出领域 entity_types，相当于现成的本体模板生成器。
  • 合法边矩阵（同上，LlamaIndex SchemaLLMPathExtractor 官方指南）：kg_validation_schema={"PERSON":["PART_OF","HAS","IS_A"],...} + strict=True，规定哪类实体允许连哪类关系，可直接抄进 ontology；宽松版 DynamicLLMPathExtractor 只引导不强制。谓词命名规范：大写 + 下划线（PART_OF / IS_A）。本库 ontology-triples.csv 里 PART_OF（5 条）与 part-of（4 条）是同一关系的命名分裂（2026-11-02 复测仍未归一），按此规范合并。
  • 代码图与知识图分立（同上，Q2；该条为 OC 对两篇论文的归纳推断，非论文原话）：RepoGraph（arXiv 2410.14684）把仓库级依赖图做成独立插件层；CodexGraph（arXiv 2408.03910）让 LLM 对 code graph 数据库直接发查询，论证相似度检索在复杂任务上 recall 低。知识节点 metadata 只放 file_path + symbol_name + 依赖版本 引用，不把源码复制进知识节点；定位类问题（“哪个文件实现了 X”）走图查询比 embedding 准。AST 分块底座是 tree-sitter（增量解析、容错、可嵌入）。
  • 先修图（据[一手源]：RAG图谱重构设计定稿v2-20261016）：先修边只存一条有向边，反向由工具推导（Wikidata P155/P156 机制），避免两份数组不同步；先修图必须无环且闭合（KST 理论要求）；每条边带 evidence citation（教材原文句子）。
  • 业界没有标准的三处，不许二手猜填（同上）：没有任何官方 schema 把 markdown 知识节点和源码符号节点合进一张图（Kythe 的 documents 最接近，但是编译器索引协议）；没有“图谱层级加多少边导致 Recall 变化”的对照实验，收益验证只能自建评测集；schema.org 没有 prerequisite 属性。
图谱层的知识组织：分层范式、实体归一、时效、元数据3 个重点▾ 点开看本节重点
本节重点
  • chunk 级去重参考 SemDeDup（arXiv 2303.09540，去 50% 数据几乎不掉性能）与 PUFFER（arXiv 2608.28622，MinHash-LSH 增量去重、带 provenance 可撤回）
  • arXiv 2606.01435 的结论更尖锐：新鲜度与冲突判定别交给 LLM，确定性 「max(serial)」 聚合比 LLM 判定高 10.8pp，而该基准里 Zep/Graphiti（bi-temporal KG）反而最差，仅 7.0%
  • 清理派生物（图谱三元组）必须带“收据”：arXiv 2610.17719 显示没有收据时，retraction 后的污染率只从 32.2% 降到 28.0%，几乎没用
3
  • 分层范式的共识是“上层 = 融合提炼的答案层”（据[一手源]：RAG知识组织一手源对标-20261022 §二）：HiRAG（arXiv 2503.10150，EMNLP 2025 Findings）、TreeRAG（ACL 2025 Findings，根→叶 + 叶→根双向检索）、RAPTOR（arXiv 2401.18059，递归聚类摘要）、GraphRAG 社区摘要、Ψ-RAG（arXiv 2605.00529，跨文档多跳 QA 超 RAPTOR 25.9%）上层都是被检索算法实际使用的摘要节点，不是下层文件的链接清单。该调研 10-22 实测本库三层为 raw 89.0% / wiki 10.7% / ontology 0.3%（总 18952 chunk），ontology 层几乎不参与检索；10-14 的知识网盘点口径是 raw 93.8% / wiki 5% / ontology 1.2%（总 33975 chunk），两个口径是不同日期的快照，引用以最新实测为准。
  • 实体归一是图谱质量的前置（据[一手源]：RAG知识组织一手源对标-20261022 §五）：arXiv 2510.14271 指出 LLM / llms / 大小写 / 多语别名会让图谱碎片化，需 entity resolution + triple reflection（LLM-as-judge 删低质三元组）；arXiv 2607.28662 的生产级抽取层用 6 种免模型去重算法加 embedding 解析子系统，设“冲突守卫”（任何相似度分数都不能覆盖），检索 recall 70% → 95%、零错误合并。chunk 级去重参考 SemDeDup（arXiv 2303.09540，去 50% 数据几乎不掉性能）与 PUFFER（arXiv 2608.28622，MinHash-LSH 增量去重、带 provenance 可撤回）。
  • 过期内容是投毒，不只是旧（同上 §5.2）：arXiv 2609.31342——单条过期文档把 83 道医学题翻错 74 道；arXiv 2609.16073 证明 append-only 库有“多数表决陷阱”，新旧矛盾事实并存时注意力偏向旧的多数，需在生成前移除逻辑矛盾；arXiv 2606.26511（MemStrata）用确定性 supersession 规则把 RAG 的 stale-fact 错误率从 15–40% 降到约 0。arXiv 2606.01435 的结论更尖锐：新鲜度与冲突判定别交给 LLM，确定性 max(serial) 聚合比 LLM 判定高 10.8pp，而该基准里 Zep/Graphiti（bi-temporal KG）反而最差，仅 7.0%。口诀：时间字段拿来存，裁决用确定性规则，不让图谱或 LLM 当新鲜度裁判。
  • 时序图谱的标准做法（据[一手源]：RAG知识组织对标-一手源-20261016 Q3）：Graphiti（Zep 开源）把 Facts 定义为“带时间有效性窗口的三元组”，Episodes 是原始入库流（ground truth），每条派生事实可溯源回 episode。对应本库做法：三元组加 valid_at / invalid_at / source_episode 三字段。该源明确声明：freshness 度量指标与淘汰策略没找到可直接复用的成熟定义，衰减打分是设计推断。TG-RAG（arXiv 2510.13590）补充：增量更新只需为新叶节点及其祖先重新生成摘要。
  • 新鲜度打分公式与过期判定（据[一手源]：RAG图谱重构设计定稿v2-20261016 L5）：score = α·cos(q,d) + (1−α)·0.5^(age_days/h)，α = 0.7，h = 14 天；HALO 式过期 V = V0·e^(−λΔ)，λ = ln2 / t_HF，V < θ 判 outdated；门禁形态照 dbt 的 warn_after / error_after 双阈值（ttl 在本库只是字段，业界是能阻断下游的门禁）；淘汰不删除，双时间线 t_valid / t_invalid，过期 = 失效标记 + 归档降权。数字冲突提示：设计定稿写该公式在 arXiv 2509.19376 上 Latest@10 从 0.00 提到 1.00，而知识组织对标调研（10-22）引同一论文写“最新相关项从 0.00 提到 0.60”，两份本地调研口径不一，引用前回溯论文原文，别直接抄任何一个。
  • 元数据不是越多越好（据[一手源]：RAG知识组织一手源对标-20261022 §四，arXiv 2606.29645，ECML-PKDD 2026，24k+ 受控实验）：大多数元数据增强会降低准确率；四类质量元数据里，模型会用 temporal validity（利用率 50–55%），却几乎用不上 provenance（0–6%），confidence 14–49%、conflict 0–15%；无关元数据抢注意力，多跳 QA 反降 5–8%；最优配置只留 plain-text temporal。清理派生物（图谱三元组）必须带“收据”：arXiv 2610.17719 显示没有收据时，retraction 后的污染率只从 32.2% 降到 28.0%，几乎没用。落地：三元组带 source chunk 链接，不另堆元数据字段。（该调研对本库的 valid_from / conflict 字段建议均标【自研·待验证】，尚无本地 A/B。）

踩坑雷点

3

图谱专属雷点：

  • 先清洗再建图：SEC 10-K 实验里 tab 字符 / 空白符污染导致图抽取近乎为零，加 ontology 也无用——ontology 救不了上游坏掉的实体抽取。落地前先做 ingestion 文本清洗审计（去 tab/空白/页眉页脚）。
  • schema / ontology 先行：无 schema 约束的抽取会产噪图；ontology 的真实作用是实体归一化 / 消歧（rerank 须用原始文本）。
  • 原文纠偏：坊间"GraphRAG 2.0"是二手媒体自拟词（实指官方博客的 dynamic community selection），与 PyPI 真实版本号无关；微软 GraphRAG 已进维护期，只修 bug/CVE 不接新功能。
  • 成本失控：抽取占 ~75%，必须用便宜模型 + 600-token 窗口 + 增量索引（LightRAG 只重抽 T_extract，不重建全图）。
  • 图谱条目无条件置顶会吃掉 R@1（据[一手源]：RAG图谱重构设计定稿v2-20261016 §3，2026-10-16 实测）：当时 query.py 把图谱 hit 直接拼在结果最前（(graph_hits + hits)[:top_k]）并豁免 rerank，51 条正样本里 13 条真答案被顶到第 2 位，含图谱槽 R@1 = 19.6%、剔除后 45.1%，图谱槽吃掉 25.5 个点。修法是取消置顶，让图谱条目回到正常 rerank 竞争，与图谱设计解耦、可先修。现在对应的开关是 retrieval.graph_slot_mode 与 graph_taxonomy_only（见 GraphRAG最小示例“怎么用”）。口诀：图谱是候选来源，不是特权位。
  • GraphRAG 抽取模板是“类型 + 自由描述 + 强度”（据[一手源]：RAG知识组织对标-一手源-20261016 Q1）：官方 extract_graph 模板格式为 ("entity"<|>NAME<|>TYPE<|>DESCRIPTION) 与 ("relationship"<|>source<|>target<|>DESCRIPTION<|>STRENGTH)，别指望抽出固定谓词表；要固定谓词就用上面的合法边矩阵（strict 模式）约束。

工程通用雷点（图谱抽取 / 索引落地时同样命中）：

  • LLM 配额与 fallback：抽取是 token 大户，429 / 配额耗尽必须错误分级——配额 / 限流类允许跨渠道 fallback（honor Retry-After + full jitter + 渠道 cooldown），请求本身错误禁止 fallback；fallback 链耗尽要有显式终态。
  • 子进程静默死亡：长任务索引要"进程组级超时 kill（SIGTERM→宽限→SIGKILL）+ 无输出停滞 watchdog + 退出码非零必显式失败"；communicate(timeout) 自身也可能挂死，需外层独立看门狗。
  • 并发写竞态：图库 / 配置写入走"独占 lockfile → 临时文件 → fsync → rename 原子替换"统一封装，读-改-写加版本号乐观校验；Unix 文件锁仅是 advisory，锁不住未合作的写者。
  • 验收断言可重放：进门禁的断言不得依赖墙钟 / 上次运行残留 / 共享可变状态；时间快照断言只许进 smoke 并标注"仅当场有效"；失败先判可复现再处置，禁止盲目重跑去洗绿。
  • 配置单真源 + 漂移检测：desired state 只有一份，定期 refresh→diff→显式二选一（回滚或改 baseline），禁止静默把现实当默认。

  • 图谱工程质量硬边界落到脚本：抽取/构图长任务用进程组超时 kill + 无输出 watchdog（参考 rag/build_wiki_graph.py 的 --dry-run 先行习惯）；graph/ 写出走临时文件+rename（entities.json/relations.json/graph_stats.json 一次落盘），迁移校验见 rag/migrate_graph_to_neo4j.py 的 sha256 比对逻辑。
  • 分阶段落地的验收口径（据[一手源]：RAG图谱行业标准调研-20261009 §5）：阶段 0 Contextual Retrieval（约 1–3 天，成本≈0，验收对比 5.7% 失败率基线；官方三档为 Contextual Embeddings −35%、+Contextual BM25 −49%（→2.9%）、+reranking −67%（→1.9%））；阶段 1 图谱试点（约 1–2 周）优先 LightRAG，备选 nano-graphrag（约 1100 行、自带无 key 离线示例），不建议首选 microsoft/graphrag standard，先只对几十篇核心文档建图，构造 10–20 条多跳 + 5 条全局 query，用 LLM-judge 头对头 + Recall@k 双指标对比纯向量基线；阶段 2 先写 10–15 个 competency questions 再定 schema（arXiv 2511.05991 实证 ontology 引导的 KG 显著超向量基线，且一次性 ontology 学习大幅降低 LLM 用量），存储属性图优先、规模大再上 Neo4j，ttl/OWL/RDF 仅在需要形式化推理或跨组织互操作时引入（Neo4j 官方的 RDF vs 属性图对比有厂商立场，需与中立来源交叉看）；阶段 3 agentic 化（约 1 个月以上），验收看多跳 benchmark + agentic 多轮成功率。每阶段独立可验收、可随时停。证据等级提示：GA-RAG survey 是 ResearchGate 预印本，非 arXiv、未经同行评审，证据等级低于 arXiv 一手论文。
  • 图谱改动的评测红线（据[一手源]：RAG图谱重构设计定稿v2-20261016 L4.5）：golden-q 扩标后对比必须同尺同版本；RAGAS 三指标当时现状 P=.65 / R=.40 / Rel=.41，评测模型须用云端（本地小模型 Faithfulness 会假完成）；badcase 回流分两档，机械档（缺 chunk → 增量 ingest）可自动，语义档（wiki 错 / 过期）必须人审；e2e 验收红线：掉分 ≤1pp 允许调参 1 轮，>1pp 直接回滚，调参后仍降必回滚。
  • 按知识网缺口自检图谱与 ontology 接入（据[一手源]：RAG知识网-WHY-WHAT-HOW-20261014）：该知识网把库拆成 13 模块 × WHY/WHAT/HOW 三层，M7（GraphRAG）当时的缺口是“LightRAG 可运行模板”和“多跳评测集”（golden-q 仅 4 条浅层两实体对比），M10 的缺口是“ontology 术语表被当普通 chunk，检索代码不感知”。前者的模板已由 GraphRAG最小示例补上，后者由 link_ontology_chunks.py + retrieval.linked_chunk 接入，但多跳评测集仍是最该先补的缺口。业内对照里图谱选型一行的判定是：LightRAG（成本约 MS GraphRAG 的 1/100）“双闸门过了再做”，不当保票。该盘点还发现 26 篇 wiki 中 14 篇集中在 Agent 体系与 FDE 流程，RAG 核心链路（切片→检索→重排→融合→GraphRAG）仅 5 篇，是提炼层密度不足的结构性信号。
  • 成本护栏：抽取约占索引 75%，本库直接用人工审校三元组（ontology/ontology-triples.csv）替代 LLM 抽取；若必须 LLM 抽取，参考 scripts/distill_pipeline.py 的 call_llm（temperature=0.2、retries=3、timeout=300）并先算 token 账再全量。
