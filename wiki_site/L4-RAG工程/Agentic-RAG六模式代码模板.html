WHY：按失败成本选模式，不为循环而循环

业务价值与不适用边界

2

六模式的业务价值是把不同的失败交给不同控制节点：分类错归 Router，证据不够归 CRAG，答案无支持归生成后门禁，只有跨文档关系需求才引入图。若把这些职责揉成一个自由循环，系统即使偶尔答对，也无法解释为什么继续检索或何时该停。

来源：Agentic 调研的 Step 2–5强调评价、改写上限与决策路径评测；优化调研方向 5要求先有多步推理需求。适用于基础检索已有基线、错误类型可标注的增量改造；不适用于用模板替代医疗/法律审批，也不适用于没有 trace、负例和退出策略就开放自主工具调用。Self-RAG 门禁只能降低风险，不能保证高风险业务的安全等级。

核心论点

2

六模式不是互斥方案，而是"控制权从工程硬编码逐级让渡给 LLM 自主决策"的同一根光谱，选择依据是你的失败成本而不是技术偏好：要可控先上 Router（一次结构化输出分流），检索不稳加 CRAG 评估兜底，幻觉拦不住才上 Self-RAG 的生成后双门禁——它以 3–8 次 LLM 调用为代价换来法律/医疗级容错。真正的价值断言是：拉开质量差距的永远是评估节点（grade_documents、幻觉与切题双门禁）而非循环本身，缺门控的 Agent-as-retriever 只会盲循环烧 token。边界在于成本与收益的匹配：Agentic-GraphRAG 的索引期 LLM 成本是数量级级别的，只在全库摘要类问题上有意义；而任何模式没有 Recall@K / faithfulness 评测集的验证，都属于盲改。

为什么六模式是"光谱"而非"六选一"（动机与代价）3 个重点▾ 点开看本章重点
本章重点
  • 不理解这个共同轴，选型就会变成"哪个最新用哪个"，结果在简单场景上套最贵的 Self-RAG（3-8 次 LLM 调用）或在幻觉高危场景只上 Router（拦不住幻觉）
  • 光谱视角的动机是按失败成本选刻度：可控性要求高选 Router（便宜可控），检索不稳加 CRAG 评估兜底，幻觉拦不住才上 Self-RAG 双门禁
  • 真正的价值断言是拉开质量差距的是评估节点（grade_documents、幻觉/切题双门禁）而非循环本身——缺门控的模式只是把差检索反复刷

  • 动机（WHY）：Agentic RAG 的六种模式（Router / Agent-as-retriever / CRAG / Self-RAG / Adaptive / Agentic-GraphRAG）常被当成六个互斥方案来"选一个"，但它们实际是同一根控制流光谱上的六个刻度——控制权从"工程硬编码"逐级让渡给"LLM 自主决策"。不理解这个共同轴，选型就会变成"哪个最新用哪个"，结果在简单场景上套最贵的 Self-RAG（3-8 次 LLM 调用）或在幻觉高危场景只上 Router（拦不住幻觉）。光谱视角的动机是按失败成本选刻度：可控性要求高选 Router（便宜可控），检索不稳加 CRAG 评估兜底，幻觉拦不住才上 Self-RAG 双门禁。
  • 代价与权衡：沿光谱右移的每一步都以更多 LLM 调用换更自主的决策——Router 每次多 1 次轻量调用，Agent-as-retriever 必须配 grade_documents 门控否则盲循环烧 token，Self-RAG 3-8 次调用换法律/医疗级容错，Agentic-GraphRAG 索引期 LLM 成本数量级（只在全库摘要类问题有意义）。真正的价值断言是拉开质量差距的是评估节点（grade_documents、幻觉/切题双门禁）而非循环本身——缺门控的模式只是把差检索反复刷。共同前提：六模式全部依赖评测集（Recall@K / faithfulness）验证收益，没有评测集就上任何模式都是盲改。

Graph/local/global 是检索工具候选；拒答与预算耗尽是显式终态

六种模式不是六个互斥方案，而是同一根控制流光谱上的六个刻度，控制权从"工程硬编码"逐级移交给"LLM 自主决策"。Router 最便宜也最可控：一次结构化输出就能分流查询，适合查询类型清晰可枚举的场景（Anthropic 官方定位：存在 distinct categories 就先上 routing）。Agent-as-retriever 把检索器包成 tool 交给 LLM 自主调用，是"是否检索"决策权的让渡，代价是必须配 grade_documents 门控，否则 LLM 会把同一次差检索反复刷。CRAG 解决"检索错了怎么办"——轻量评估器判质量，差则改写 query 转 web 搜索兜底；Self-RAG 再进一步，连生成结果也要过幻觉与切题双重门禁，质量最高但 LLM 调用次数最多（3–8 次）。Adaptive RAG 是前两者的组合拳：先按查询复杂度路由到 no-retrieve / 单步 / 迭代策略，避免"难题才需要 agent、易题直接答"的错配。Agentic-GraphRAG 只在全局摘要类问题（"这批文档的主要主题是什么"）上有意义，向量 RAG 在这类问题上结构性失败，但图索引的 LLM 成本是数量级级别的。取舍结论：从 Router 起步，检索质量不稳加 CRAG，答案幻觉抓不住加 Self-RAG 门禁，查询复杂度方差大再上 Adaptive；六模式全部依赖评测集（Recall@K / faithfulness）验证收益，没有评测集就上任何模式都是盲改。

是什么（定义与边界）

2

定义：本篇是 Agentic RAG 六种工程模式的代码模板库——每个模式给触发条件、核心机制、LangGraph 代码骨架、关键步骤注释与适用场景，外加 Modular RAG 架构原则与本库技术栈对接。六模式 = Router（结构化输出分流）、Agent-as-retriever（检索器包 tool 交 LLM 调用）、CRAG（检索质量评估 + web 兜底）、Self-RAG（生成后幻觉/切题双门禁）、Adaptive（复杂度路由）、Agentic-GraphRAG（图索引 + global/local 搜索工具化）。

边界：
- ✅ 管：各模式的代码骨架、触发条件、代价与适用场景、循环安全（recursion_limit、最大迭代）。
- ❌ 不管：六模式的调研论据与实测数字（Agentic-RAG与多模态RAG调研）、图谱构建成本细节（GraphRAG最小示例）、基础检索流水线（RRF融合加重排）。
- ⚠️ Modular RAG 不是第七个模式，是承载六模式的架构原则（工程结构怎么解耦 vs 运行时控制权放多少，两者正交）——见"补遗"节。
- ⚠️ 选型顺序：从 Router 起步，检索不稳加 CRAG，幻觉抓不住加 Self-RAG 门禁，复杂度方差大再上 Adaptive；每步都要评测集验证，别跳级。
- 据[一手源]：Agentic-RAG-调研-20261012：Anthropic《Building effective agents》的原则是"从最简单的方案开始，只在灵活性收益大于延迟和成本时才增加复杂度"；其 5 种 workflow pattern 为 prompt chaining / routing / evaluator-optimizer / tool use / orchestrator-workers，源里明确的对应只有一条：Agentic RAG 本质是 tool use 的特例（即本表模式二 Agent-as-retriever，Router 则是 routing pattern 的 RAG 用法）；另有 Multi-agent RAG 范式（Anthropic multi-agent research system：主 agent 规划 → 子 agent 并行检索 → 合成），适合复杂研究与多源整合，不在本表六模式内。先单 agent + tool use，不要一上来 multi-agent。
- 据[一手源]：Agentic-RAG-调研-20261012：LangGraph 标准模板是 5 个核心节点——generate_query_or_respond（决定直接回答还是调 retriever）→ retrieve → grade_documents（只答 yes/no，过滤不相关 chunk）→ rewrite_question（基于原 query + "之前检索不相关"改写，最大循环次数设 3 次防无限检索）→ generate；"很多团队以为加个 agent loop 就完事，真正提升质量的是 grade_documents 这个判断节点"。
- 据[一手源]：Agentic-RAG检索循环-外部调研-20261012：Reflection 循环 = Retrieve → Read → Critique → Refine → Loop；没有 critique 步的 agentic RAG 只是把同一检索无限刷，是最常见失败模式。2026 框架选择口诀：stateful 默认选 LangGraph；单厂商栈最快用 OpenAI Agents SDK；"检索是一等公民、agent 是 loop"用 LlamaIndex AgentWorkflow；要 skills-guided retrieval + rubric grading + subagent 用 LangChain Deep Agents。
- 据[一手源]：RAG优化-外部调研-20260929（方向 5）：Agentic RAG 的适用门槛是"多步推理 + 自我纠错 + 判断何时该检索"，代价是慢、贵、难调试；该源对 162 chunk 个人库的裁决是"暂不上，直到 chunk 数 > 5000 或出现'追关系'类 query"，把"不做"写进决策文档防止冲动。

RAG 演进谱系是 Naive（检索+生成拼接）→ Advanced（重写/混合/重排）→ Modular（组件可插拔）→ Agentic（控制权让渡给 LLM）。本表六模式（Router…Agentic-GraphRAG）回答的是运行时"控制权放多少"；Modular RAG（ACM 2026，doi:10.1145/3837856）回答的是工程结构"怎么解耦"，两者正交——工程上用 Modular 架构承载六模式。

Modular RAG 的核心是三层解耦：检索层（可插拔 retriever）→ 生成层（可插拔 LLM）→ 编排层（稳定 state schema），所有组件实现统一抽象基类（BaseRetriever / BaseChatModel / Embeddings / BaseReranker）。收益：换模型/换检索器只改一行注入，不动图结构，A/B 测试与降级回退零成本。反面教材是把 LLM/retriever 直接写死在节点函数里——一旦要对比豆包 vs Qwen 或 bge vs BM25 就得改图。

本库现状：config.yaml 已把 embedding / rerank / llm / 向量库参数外置，具备 Modular 的一半（配置级解耦）；但 query.py 的检索/重排节点仍按具体实现硬编码，未抽象成可插拔基类，属于"配置模块化、代码未模块化"。这与 RAG生产级架构最佳实践 的接口层要求一致，列为 P2 工程项。

依据：Anthropic《Building effective agents》routing 模式（"存在清晰可分的类别，且分类能被准确完成时使用，无论用 LLM 还是传统分类器"）；代码骨架来自 LangGraph 官方 Adaptive RAG 教程的查询路由部分（arXiv:2403.14403 的工程化实现）。

from typing import Literal
from pydantic import BaseModel, Field
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

# 关键步骤 1：结构化输出 schema——Literal 限定路由目标，防止 LLM 自由发挥
class RouteQuery(BaseModel):
    """Route a user query to the most relevant datasource."""
    datasource: Literal["vectorstore", "web_search"] = Field(
        ...,
        description="Given a user question choose to route it to web search or a vectorstore.",
    )

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)  # 本库可换任意兼容模型
structured_llm_router = llm.with_structured_output(RouteQuery)

# 关键步骤 2：system prompt 必须写清 vectorstore 里"有什么"，否则路由靠猜
system = """You are an expert at routing a user question to a vectorstore or web search.
The vectorstore contains documents related to agents, prompt engineering, and adversarial attacks.
Use the vectorstore for questions on these topics. Otherwise, use web-search."""
route_prompt = ChatPromptTemplate.from_messages(
    [("system", system), ("human", "{question}")]
)
question_router = route_prompt | structured_llm_router

# 关键步骤 3：路由函数——返回值即下一节点名，挂在条件边上
def route_question(state):
    print("---ROUTE QUESTION---")
    source = question_router.invoke({"question": state["question"]})
    if source.datasource == "web_search":
        return "web_search"
    elif source.datasource == "vectorstore":

模式二：Agent-as-retriever

3

依据：LangGraph 官方 Agentic RAG 教程。检索器不再是管线固定前置步骤，而是 @tool/create_retriever_tool 封装的工具，LLM 在 generate_query_or_respond 节点自主决定"直接回答"还是"发起检索"。这正是本库调研篇定义的"Agentic 与普通 tool-use 的分水岭"所在：检索后必须有 grade_documents 质量门控 + rewrite_question 改写重试闭环。

from langchain.tools.retriever import create_retriever_tool
from langchain.chat_models import init_chat_model
from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.prebuilt import ToolNode, tools_condition
from pydantic import BaseModel, Field
from typing import Literal

# 关键步骤 1：检索器包成 tool——工具描述决定 LLM 什么时候愿意调它，值得精心打磨（Anthropic ACI 原则）
retriever_tool = create_retriever_tool(
    retriever,                      # 接本库 hybrid_retriever（见"与本库技术栈的对接"）
    "retrieve_blog_posts",
    "Search and return information about Lilian Weng blog posts.",
)

response_model = init_chat_model("openai:gpt-4.1", temperature=0)

# 关键步骤 2：决策节点——bind_tools 后 LLM 要么直接回复，要么产出 tool_calls
def generate_query_or_respond(state: MessagesState):
    """LLM 决定：直接回答，或调用检索工具。"""
    response = response_model.bind_tools([retriever_tool]).invoke(state["messages"])
    return {"messages": [response]}

# 关键步骤 3：质量门控——grade_documents 是路由函数，决定"用结果"还是"改写重试"
GRADE_PROMPT = (
    "You are a grader assessing relevance of a retrieved document to a user question. \n "
    "Here is the retrieved document: \n\n {context} \n\n"
    "Here is the user question: {question} \n"
    "If the document contains keyword(s) or semantic meaning related to the user question, "
    "grade it as relevant. \n"
    "Give a binary score 'yes' or 'no' score to indicate whether the document is relevant."
)

class GradeDocuments(BaseModel):
    """Grade documents using a binary score for relevance check."""
    binary_score: str = Field(
        description="Relevance score: 'yes' if relevant, or 'no' if not relevant"
    )

def grade_documents(state: MessagesState) -> Literal["generate_answer", "rewrite_question"]:
    """评估检索结果与问题的相关性。"""
    question = state["messages"][0].content
    context = state["messages"][-1].content
    prompt = GRADE_PROMPT.format(question=question, context=context)
    response = response_model.with_structured_output(GradeDocuments).invoke(
        [{"role": "user", "content": prompt}]
    )
    return "generate_answer" if response.binary_score == "yes" else "rewrite_question"

# 关键步骤 4：改写闭环——不相关则改写问题回到决策节点（必配最大循环次数，见文末说明）
REWRITE_PROMPT = (
    "Look at the input and try to reason about the underlying semantic intent / meaning.\n"
    "Here is the initial question:\n ------- \n{question}\n ------- \n"
    "Formulate an improved question:"
)

def rewrite_question(state: MessagesState):
    question = state["messages"][0].content
    response = response_model.invoke(
        [{"role": "user", "content": REWRITE_PROMPT.format(question=question)}]
    )
    return {"messages": [{"role": "user", "content": response.content}]}

def generate_answer(state: MessagesState):
    question = state["messages"][0].content
    context = state["messages"][-1].content
    GENERATE_PROMPT = (
        "You are an assistant for question-answering tasks. "
        "Use the following pieces of retrieved context to answer the question. "
        "If you don't know the answer, just say that you don't know. "
        "Use three sentences maximum and keep the answer concise.\n"
        "Question: {question} \nContext: {context}"
    )
    response = response_model.invoke(
        [{"role": "user", "content": GENERATE_PROMPT.format(question=question, context=context)}]
    )
    return {"messages": [response]}

# 关键步骤 5：组装——tools_condition 判断上一步是否产生 tool_calls
workflow = StateGraph(MessagesState)
workflow.add_node(generate_query_or_respond)
workflow.add_node("retrieve", ToolNode([retriever_tool]))   # ToolNode 真正执行检索
workflow.add_node(rewrite_question)
workflow.add_node(generate_answer)
workflow.add_edge(START, "generate_query_or_respond")
workflow.add_conditional_edges(
    "generate_query_or_respond", tools_condition,
    {"tools": "retrieve", END: END},   # 无 tool_calls 则直接结束（LLM 已给出回答）
)
workflow.add_conditional_edges("retrieve", grade_documents)  # 相关→generate_answer，不相关→rewrite_question
workflow.add_edge("generate_answer", END)
workflow.add_edge("rewrite_question", "generate_query_or_respond")  # 改写后回到决策节点
graph = workflow.compile()

本节重点
  • 依据：论文 CRAG（arXiv:2401.15884）+ LangGraph 官方 CRAG 教程
  • web_search: str 关键步骤 1：用标志位记录"是否需要 web 兜底"

    generation: str
    web_search: str          # 关键步骤 1：用标志位记录"是否需要 web 兜底"

    """Binary score for relevance check on retrieved documents."""
    binary_score: str = Field(

system = """You are a grader assessing relevance of a retrieved document to a user question. \n 
    If the document contains keyword(s) or semantic meaning related to the question, grade it as relevant. \n
    Give a binary score 'yes' or 'no' score to indicate whether the document is relevant to the question."""
retrieval_grader = ChatPromptTemplate.from_messages(
    [("system", system), ("human", "Retrieved document: \n\n {document} \n\n User question: {question}")]
) | llm.with_structured_output(GradeDocuments)

def retrieve(state):
    print("---RETRIEVE---")
    documents = retriever.invoke(state["question"])   # 换成本库 hybrid_retrieve
    return {"documents": documents, "question": state["question"]}

# 关键步骤 3：逐条评分，任一不相关即触发 web_search 兜底标志
def grade_documents(state):
    print("---CHECK DOCUMENT RELEVANCE TO QUESTION---")
    question, documents = state["question"], state["documents"]
    filtered_docs, web_search = [], "No"
    for d in documents:
        score = retrieval_grader.invoke({"question": question, "document": d.page_content})
        if score.binary_score == "yes":
            filtered_docs.append(d)
        else:
            web_search = "Yes"
            continue
    return {"documents": filtered_docs, "question": question, "web_search": web_search}

def decide_to_generate(state):

    if state["web_search"] == "Yes":     # 有不相关文档 → 走改写 + web 搜索分支

    return "generate"                    # 全部相关 → 直接生成

# 关键步骤 4：query 改写（对应论文 Corrective 动作前的 Query Rewrite）
system = """You a question re-writer that converts an input question to a better version that is optimized \n

question_rewriter = ChatPromptTemplate.from_messages(

    better_question = question_rewriter.invoke({"question": state["question"]})
    return {"documents": state["documents"], "question": better_question}

# 关键步骤 5：web 搜索兜底（对应论文的 web search extension，用 Tavily）
web_search_tool = TavilySearchResults(k=3)

def web_search(state):

    docs = web_search_tool.invoke({"query": state["question"]})
    web_results = Document(page_content="\n".join([d["content"] for d in docs]))
    documents = state["documents"] + [web_results]   # 兜底结果追加，而非替换
    return {"documents": documents, "question": state["question"]}

    generation = rag_chain.invoke({"context": state["documents"], "question": state["question"]})

# 关键步骤 6：组装——差检索触发"改写→搜索→生成"旁路，好检索直达生成

workflow.add_node("retrieve", retrieve)
workflow.add_node("grade_documents", grade_documents)

模式四：Self-RAG

3

依据：论文 Self-RAG（arXiv:2310.11511）+ LangGraph 官方 Self-RAG 教程。论文定义 4 类 reflection tokens：[Retrieve?]（要不要检索）、[Relevant?]（文档是否相关）、[Supported?]（生成是否被证据支持）、[Useful?]（答案是否有用）；原论文靠训练 LM 输出这些 token，官方教程用 4 个结构化输出 grader 等价实现。与 CRAG 的本质区别：门控从"检索前"延伸到了"生成后"——生成结果必须同时过幻觉检查与切题检查才允许输出。

from pydantic import BaseModel, Field
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langgraph.graph import END, StateGraph, START

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# 关键步骤 1：三个 grader schema（对应 [Relevant?] / [Supported?] / [Useful?]）
class GradeDocuments(BaseModel):
    """Binary score for relevance check on retrieved documents."""
    binary_score: str = Field(description="Documents are relevant to the question, 'yes' or 'no'")

class GradeHallucinations(BaseModel):
    """Binary score for hallucination present in generation answer."""
    binary_score: str = Field(description="Answer is grounded in the facts, 'yes' or 'no'")

class GradeAnswer(BaseModel):
    """Binary score to assess answer addresses question."""
    binary_score: str = Field(description="Answer addresses the question, 'yes' or 'no'")

# 关键步骤 2：幻觉检查 grader——对应论文 [Supported?] token
hallucination_grader = ChatPromptTemplate.from_messages([
    ("system", """You are a grader assessing whether an LLM generation is grounded in / supported by a set of retrieved facts. \n 
     Give a binary score 'yes' or 'no'. 'Yes' means that the answer is grounded in / supported by the set of facts."""),
    ("human", "Set of facts: \n\n {documents} \n\n LLM generation: {generation}"),
]) | llm.with_structured_output(GradeHallucinations)

# 关键步骤 3：切题检查 grader——对应论文 [Useful?] token
answer_grader = ChatPromptTemplate.from_messages([
    ("system", """You are a grader assessing whether an answer addresses / resolves a question \n 
     Give a binary score 'yes' or 'no'. Yes' means that the answer resolves the question."""),
    ("human", "User question: \n\n {question} \n\n LLM generation: {generation}"),
]) | llm.with_structured_output(GradeAnswer)

# 关键步骤 4：生成后双门禁——三路路由是 Self-RAG 的灵魂
def grade_generation_v_documents_and_question(state):
    print("---CHECK HALLUCINATIONS---")
    question, documents, generation = state["question"], state["documents"], state["generation"]
    # 门禁一：是否忠于证据（幻觉检查）
    grade = hallucination_grader.invoke({"documents": documents, "generation": generation}).binary_score
    if grade == "yes":
        print("---GENERATION IS GROUNDED IN DOCUMENTS---")
        # 门禁二：是否回答了问题（切题检查）
        grade = answer_grader.invoke({"question": question, "generation": generation}).binary_score
        if grade == "yes":
            return "useful"             # 双通过 → 出结果
        return "not useful"             # 忠实但跑题 → 改写问题重检索
    print("---GENERATION IS NOT GROUNDED IN DOCUMENTS, RE-TRY---")
    return "not supported"              # 幻觉 → 原地重新生成

# 关键步骤 5：组装——grade_documents 过滤后为空则改写重检索；生成结果过双门禁三路路由
workflow = StateGraph(GraphState)       # GraphState 复用 CRAG 的定义（去掉 web_search 字段）
workflow.add_node("retrieve", retrieve)
workflow.add_node("grade_documents", grade_documents)   # 逐条 [Relevant?] 过滤
workflow.add_node("generate", generate)
workflow.add_node("transform_query", transform_query)
workflow.add_edge(START, "retrieve")
workflow.add_edge("retrieve", "grade_documents")
workflow.add_conditional_edges(
    "grade_documents", decide_to_generate,             # 全不相关 → transform_query → retrieve 闭环
    {"transform_query": "transform_query", "generate": "generate"},
)
workflow.add_edge("transform_query", "retrieve")
workflow.add_conditional_edges(
    "generate", grade_generation_v_documents_and_question,
    {
        "not supported": "generate",      # 幻觉：原地重试（注意防死循环，见文末 recursion_limit）
        "useful": END,
        "not useful": "transform_query",  # 跑题：改写问题重新检索
    },
)
app = workflow.compile()

retrieve / grade_documents / generate / transform_query / decide_to_generate 与 CRAG 模式的同名节点同构（LangGraph 官方两教程共享这套骨架），差异只在：Self-RAG 的 decide_to_generate 判断依据是 filtered_documents 是否为空，且生成后多一道双门禁。这正是调研篇强调的"独立 judge 过 faithfulness 门禁才允许输出"的落地位置。

依据：论文 Adaptive-RAG（arXiv:2403.14403）+ LangGraph 官方 Adaptive RAG 教程。论文核心：用一个小模型分类器（以银标准标签训练）预测查询复杂度，路由到 no-retrieval / single-step / iterative 三档策略，在效率与准确率间取平衡。LangGraph 教程的工程化取舍：不训练分类器，用 LLM 结构化输出做路由（RouteQuery），路由目标简化为 web_search（近期事件）与 vectorstore（索引内内容）两路，vectorstore 分支内嵌完整的自纠正循环（grade_documents → transform_query → retrieve，外加生成双门禁）。

from typing import Literal
from pydantic import BaseModel, Field
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langgraph.graph import END, StateGraph, START

# 关键步骤 1：复杂度路由器（对应论文的 question complexity classifier，工程上换成 LLM 结构化输出）
class RouteQuery(BaseModel):
    """Route a user query to the most relevant datasource."""
    datasource: Literal["vectorstore", "web_search"] = Field(
        ..., description="Given a user question choose to route it to web search or a vectorstore.",
    )

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
structured_llm_router = llm.with_structured_output(RouteQuery)

system = """You are an expert at routing a user question to a vectorstore or web search.
The vectorstore contains documents related to agents, prompt engineering, and adversarial attacks.
Use the vectorstore for questions on these topics. Otherwise, use web-search."""
question_router = ChatPromptTemplate.from_messages(
    [("system", system), ("human", "{question}")]
) | structured_llm_router

def route_question(state):
    print("---ROUTE QUESTION---")
    source = question_router.invoke({"question": state["question"]})
    if source.datasource == "web_search":
        return "web_search"
    elif source.datasource == "vectorstore":
        return "vectorstore"

# 关键步骤 2：web_search 分支独立建图（不经过 grade/rewrite 循环——外部结果没法"改写重检"）
def web_search(state):
    print("---WEB SEARCH---")
    docs = web_search_tool.invoke({"query": state["question"]})
    web_results = Document(page_content="\n".join([d["content"] for d in docs]))
    return {"documents": [web_results], "question": state["question"]}

# 关键步骤 3：组装——Router 在 START 分流；vectorstore 分支 = CRAG 骨架 + Self-RAG 双门禁
workflow = StateGraph(GraphState)     # GraphState 同 CRAG 定义（web_search 字段仅作标志）
workflow.add_node("web_search", web_search)
workflow.add_node("retrieve", retrieve)
workflow.add_node("grade_documents", grade_documents)
workflow.add_node("generate", generate)
workflow.add_node("transform_query", transform_query)
workflow.add_conditional_edges(
    START, route_question,             # 复杂度/时效性路由发生在任何检索之前
    {"web_search": "web_search", "vectorstore": "retrieve"},
)
workflow.add_edge("web_search", "generate")
workflow.add_edge("retrieve", "grade_documents")
workflow.add_conditional_edges(
    "grade_documents", decide_to_generate,   # 全不相关 → 改写后回到 retrieve（迭代检索）
    {"transform_query": "transform_query", "generate": "generate"},
)
workflow.add_edge("transform_query", "retrieve")
workflow.add_conditional_edges(
    "generate", grade_generation_v_documents_and_question,   # 复用 Self-RAG 双门禁
    {"not supported": "generate", "useful": END, "not useful": "transform_query"},
)
app = workflow.compile()

要严格对齐论文的 no-retrieval / single-step / iterative 三档：把 Literal 扩为三值，no_retrieve 直连一个纯 LLM 生成节点即可；论文原版分类器是训练出来的小 LM，流量大到路由调用本身成为成本时值得照做（官方复现在 github.com/starsuzi/Adaptive-RAG）。

模式六：Agentic-GraphRAG

3

依据：Microsoft GraphRAG（arXiv:2404.16130）+ AutoGen 官方 autogen_ext.tools.graphrag 集成文档。GraphRAG 用 LLM 两阶段建图：先抽实体与关系建实体图，再对图做社区检测并预生成社区摘要；查询时 local search 回答具体实体问题、global search 走 map-reduce 回答"这批文档主要讲什么"的全局摘要类问题——后者是向量 RAG 的结构性盲区。Agentic 化的关键（AutoGen 官方做法）：把 GraphRAG 的 local/global 搜索包成 agent 的两个 tool，让 agent 按问题性质自主选用——local 问题调 local_search，全局综合问题调 global_search，这本身就是 Router 思想在图检索上的应用。

# 前置：先用 GraphRAG CLI 建索引（一次性，LLM 成本主要花在这一步）
#   pip install graphrag
#   graphrag init --root ./my-project      # 生成 settings.yaml，配置 LLM provider
#   graphrag index --root ./my-project     # 输入文档放 ./my-project/input/，产出实体图+社区摘要

    #   具体实体/关系 → local_search；跨文档全局主题 → global_search
    assistant_agent = AssistantAgent(
        name="search_assistant",
        tools=[global_tool, local_tool],
        model_client=openai_client,
        system_message=(
            "You are a tool selector AI assistant using the GraphRAG framework. "
            "For broader, abstract questions requiring a comprehensive understanding "
            "of the dataset, call the 'global_search' function. "
            "For specific, detailed information about particular entities or "
            "relationships, call the 'local_search' function."
        ),
    )

    # 关键步骤 3：agent 自主选 tool 运行——全局问题走社区摘要 map-reduce，局部问题走实体邻域扩展
    await Console(assistant_agent.run_stream(
        task="What is the overall sentiment of the community reports?"

from langchain_chroma import Chroma
from langchain_huggingface import HuggingFaceEmbeddings
from FlagEmbedding import BGEM3FlagModel, FlagReranker

# ---- 本库基建 ----
bge_m3 = BGEM3FlagModel("BAAI/bge-m3", use_fp16=True)   # 同时产出 dense + sparse（lexical weights）
reranker = FlagReranker("BAAI/bge-reranker-v2-m3", use_fp16=True)

vectorstore = Chroma(
    collection_name="kb",
    embedding_function=HuggingFaceEmbeddings(model_name="BAAI/bge-m3"),
    persist_directory="./chroma_db",
)

# 离线阶段：为每个 chunk 预存 bge-m3 sparse 向量（token_id -> 权重 的 dict），建倒排打分表
chunk_sparse = {}   # {chunk_id: {token_id: weight}}

def sparse_score(query_lexical, chunk_lexical):
    """bge-m3 lexical weights 的稀疏打分：公共 token 上权重相乘求和"""
    return sum(w * query_lexical.get(t, 0.0) for t, w in chunk_lexical.items())

def rrf_fuse(rankings, k=60):
    """标准 Reciprocal Rank Fusion：score = Σ 1/(k + rank)"""
    scores = {}
    for ranking in rankings:
        for rank, cid in enumerate(ranking):
            scores[cid] = scores.get(cid, 0.0) + 1.0 / (k + rank + 1)
    return scores

def hybrid_retrieve(question: str, top_k=20, top_n=5) -> list:
    """六模式通用的替换点：CRAG/Self-RAG/Adaptive 的 retrieve 节点、
    Agent-as-retriever 的 retriever_tool，都调这一个函数。"""
    # 关键步骤 1：dense 路——Chroma 语义召回
    dense_docs = vectorstore.similarity_search(question, k=top_k)
    dense_ranking = [d.metadata["chunk_id"] for d in dense_docs]
    # 关键步骤 2：sparse 路——bge-m3 lexical weights 词法召回
    q_out = bge_m3.encode([question], return_dense=True, return_sparse=True)
    q_lexical = q_out["lexical_weights"][0]
    sparse_ranking = sorted(chunk_sparse, key=lambda c: -sparse_score(q_lexical, chunk_sparse[c]))[:top_k]
    # 关键步骤 3：RRF 融合两路排序
    fused = rrf_fuse([dense_ranking, sparse_ranking])
    top_ids = sorted(fused, key=fused.get, reverse=True)[:top_k]
    # 关键步骤 4：bge-reranker-v2-m3 精排，输出 Document 列表（带分数供门控复用）
    docs_by_id = {d.metadata["chunk_id"]: d for d in dense_docs}
    pairs = [[question, docs_by_id[c].page_content] for c in top_ids if c in docs_by_id]
    scores = reranker.compute_score(pairs, normalize=True) if pairs else []
    ranked = sorted(zip([c for c in top_ids if c in docs_by_id], scores), key=lambda x: -x[1])
    return [docs_by_id[c] for c, _ in ranked[:top_n]]

配套的评估口径沿用 RAG 评估怎么跑：每接一个模式跑一次 Recall@5 / MRR / faithfulness 回归，重点看门控节点（grade_documents、双门禁）的引入是否真的抬升了 faithfulness（目标 > 0.85）——门控本身的准确率也该用标注集抽验，grader 判错会把好检索扔进改写循环白白烧 token。

  • 接一个新模式的回归流程（条目尾部评估口径的可执行版）：
    bash python3 rag/eval/eval_recall.py # 检索层 Recall@1/@5/@10, golden: rag/eval/golden-q.jsonl python3 rag/eval/run_baseline.py # 6 指标统一 runner（Recall/P@1/Rel/Faith/AnsRel）
