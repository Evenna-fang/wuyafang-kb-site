Python 2 已于 2020-01-01 停止维护（EOL，End of Life），不再有安全补丁。所有新项目一律 Python 3，遇到只支持 Python 2 的老库要么找替代品要么放弃该库。命令层面：Windows 上用 py -3 启动器或 python；macOS 与 Linux 上用 python3，因为系统自带的 python 可能指向 Python 2 或 Xcode 命令行工具链。判断方法只有一条：跑 python3 --version 看输出的主次版本号，别信命令名。

2.2 Python 3.x 小版本选择建议

3
  • 3.12：当前最稳的生产基线，错误消息大幅改进，性能比 3.11 有官方宣称的个位数百分比提升。
  • 3.13：新交互式解释器（PyREPL，支持多行编辑与语法高亮）与实验性 --disable-gil 构建选项；部分第三方库的 wheel 可能滞后发布，装不上时退回 3.12。
  • 3.10 与 3.11：已有项目锁定就继续用，新项目不必主动降级到这两档。
  • 3.9 及以下：3.9 的安全支持已按 PEP 659 时间表结束，不要再用于新项目。

经验阈值一句话：新项目选 3.12，追新特性选 3.13，第三方包装不上就降 3.12，绝不选 3.9 以下。判断"某库支持不支持 3.13"的方法：打开该库的 PyPI 页面看 "Requires: Python" 字段和最新 release 的 wheel 列表（cp313 即支持 3.13）。

3.4 pyenv：管理多个 Python 版本

3

pyenv 让一台机器并存 3.10、3.12、3.13，项目目录内放一个 .python-version 文件即可自动切换。它只管 Python 版本，不管包，所以仍要配合 venv 使用。

# 安装 pyenv（macOS/Linux；Windows 用 pyenv-win）
curl https://pyenv.run | bash
# 写入 ~/.bashrc: eval "$(pyenv init -)" 后 source ~/.bashrc
pyenv install 3.12.7        # 编译安装指定版本
pyenv global 3.12.7         # 全局默认
cd my_project && pyenv local 3.13.0   # 本项目用 3.13，生成 .python-version
pyenv versions              # 验证：带 * 的是当前生效版本

可直接跑的完整脚本（Python 3.12）——检查本机多版本共存情况：

#!/usr/bin/env python3
# check_pyenv_versions.py —— Python 3.12
# 用法: python check_pyenv_versions.py
# 真实路径: 脚本放在项目根目录, 结果写到同目录 env_report.txt
import shutil, subprocess, sys
from pathlib import Path

report = Path(__file__).parent / "env_report.txt"
lines = [f"当前解释器: {sys.executable}", f"版本: {sys.version.split()[0]}"]
if shutil.which("pyenv"):
    out = subprocess.run(["pyenv", "versions", "--bare"],
                         capture_output=True, text=True).stdout
    lines.append("pyenv 已安装版本: " + out.replace("\n", ", "))
else:
    lines.append("pyenv 未安装（可选）")
report.write_text("\n".join(lines), encoding="utf-8")
print(report.read_text(encoding="utf-8"))

4.1 为什么需要虚拟环境

3

全局 Python 里装 50 个包之后，A 项目要 requests==2.28、B 项目要 requests==2.31 就会互相覆盖，谁后装谁赢。虚拟环境把"解释器加一组包"锁在项目目录里，pip install 只影响当前项目。反例：用 sudo pip install 往系统 Python 里装包，会污染 apt 或 dnf 管理的系统包，Debian 系甚至直接报 externally-managed-environment 拒绝执行，此时的正确动作是退出 sudo、建 venv、在 venv 里装。

4.2 venv（推荐起点）1 个重点▾ 点开看本节重点
本节重点
  • mkdir my_project && cd my_project
3 
mkdir my_project && cd my_project
python3 -m venv .venv                 # 用 .venv 隐藏目录名
source .venv/bin/activate             # macOS/Linux
# .venv\Scripts\Activate.ps1          # Windows PowerShell
# 报"禁止运行脚本"时: Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
which python                          # 必须指向 .venv/bin/python
pip install --upgrade pip
pip install requests flask
pip list
deactivate                            # 退出环境
echo ".venv/" >> .gitignore           # 不要提交虚拟环境

三个关键校验点：激活后 which python 的输出必须含 .venv；python -m pip --version 的路径也要含 .venv；pip list 里不应出现你没装过的全局大包。python -m venv 建环境时若报 ensurepip is not available，说明系统装的是无 pip 的精简包，补 sudo apt install python3.12-venv 即可。

4.3 Conda（数据科学场景）

3

Conda 能管 Python 本身和 C 语言、C++ 库等非 Python 依赖，装 GPU 版深度学习栈时最省心。装 Miniconda（比 Anaconda 轻量得多，Anaconda 全家桶动辄 3GB 以上）：

conda create -n dataproj python=3.12 numpy=1.26 pandas=2.2
conda activate dataproj
conda env export > environment.yml    # 导出可复现环境
conda env create -f environment.yml   # 队友按此文件重建
conda env list                        # 列出所有环境
conda env remove -n dataproj          # 删除环境

environment.yml 里 channels 建议优先 conda-forge，dependencies 下的 pip: 小节可以混装 PyPI 独有的包，一条文件同时管住两类依赖。

5.1 VS Code（推荐）

3

安装：Windows winget install Microsoft.VisualStudioCode；macOS brew install --cask visual-studio-code；Linux sudo snap install code --classic。必装扩展四个：Python（ms-python.python）提供语言支持核心；Pylance（ms-python.vscode-pylance）提供基于 LSP 的高性能补全与跳转；Python Debugger（ms-python.debugpy）提供断点调试；Ruff（charliermarsh.ruff）一个扩展同时做 Linter 与 Formatter，可替代 flake8 加 black 的组合。

项目级配置 .vscode/settings.json：

{
    "python.defaultInterpreterPath": "${workspaceFolder}/.venv/bin/python",
    "python.terminal.activateEnvironment": true,
    "[python]": {
        "editor.formatOnSave": true,
        "editor.defaultFormatter": "charliermarsh.ruff",
        "editor.codeActionsOnSave": {
            "source.fixAll.ruff": "explicit",
            "source.organizeImports.ruff": "explicit"
        }
    },
    "python.analysis.typeCheckingMode": "basic",
    "editor.rulers": [88]
}

切解释器：Ctrl+Shift+P 打开命令面板，输入 "Python: Select Interpreter"，选 .venv/bin/python。88 列标尺对应 PEP 8 推荐的行宽上限（Black 与 Ruff 默认 88）。

6.1 pip 常用命令

3 
pip install requests==2.31.0      # 精确版本
pip install "requests>=2.28,<3"   # 版本范围，注意加引号防 shell 解析

pip freeze > requirements.txt 会导出全部间接依赖及其精确版本，适合部署复现；手写 requirements.txt 则只列直接依赖并给版本范围。要同时兼顾"声明简洁"和"复现精确"，用 pip-tools 三步走：requirements.in 写直接依赖；pip-compile requirements.in 生成带完整锁版本的 requirements.txt（每行注释标明 via 来源）；pip-sync 精确同步，多出来的包会被卸载。加新依赖就编辑 .in 再跑一次编译加同步。

  • /usr/bin/env python3
2

可直接跑的完整脚本（Python 3.12 以上，把文件存为项目根目录的 verify_env.py，在激活的 venv 里运行 python verify_env.py）：

#!/usr/bin/env python3
# verify_env.py —— Python 3.12+
# 运行: python verify_env.py
# 期望: 核心检查全部 PASS; 可选项失败不阻塞开工
import sys, shutil
from datetime import datetime

def check(name, ok, detail=""):
    print(f"  {'✅ PASS' if ok else '❌ FAIL'}  {name}" + (f" → {detail}" if detail else ""))
    return ok

def main():
    print(f"Python 环境验证  {datetime.now():%Y-%m-%d %H:%M:%S}")
    ok = True
    major, minor = sys.version_info[:2]
    ok &= check(f"Python {sys.version.split()[0]}", major == 3 and minor >= 12,
                f"建议 3.12 以上，当前 {major}.{minor}")
    check(f"解释器路径 {sys.executable}", True)
    in_venv = hasattr(sys, 'base_prefix') and sys.base_prefix != sys.prefix
    ok &= check("虚拟环境", in_venv, "已激活" if in_venv else "未激活，建议在 .venv 中运行")
    for mod in ["os", "sys", "json", "re", "pathlib", "collections",
                "typing", "logging", "sqlite3"]:
        try:
            __import__(mod); check(f"标准库 {mod}", True)
        except ImportError:
            check(f"标准库 {mod}", False); ok = False
    for lib in ["requests", "pytest"]:
        try:
            m = __import__(lib); check(f"{lib} {getattr(m, '__version__', '')}", True)
        except ImportError:
            check(f"{lib}（可选）", False)
    for tool in ["git", "curl"]:
        check(tool, shutil.which(tool) is not None, shutil.which(tool) or "未找到")
    print("🎉 核心检查通过" if ok else "⚠️ 有失败项，按上面提示修复")

if __name__ == "__main__":
    main()

预期输出形态：每行一个 "PASS 名称" 或 "FAIL 名称"，最后一行是总结。九个标准库模块全部 PASS 说明解释器完整；虚拟环境那行 FAIL 只是提醒，不算硬错误；requests 与 pytest 属于可选项。

8.2 什么情况下别用（反例加替代方案）

3
  • 别用全局 Python 直接 pip install 做项目依赖：会与其他项目版本冲突。替代：先 python3 -m venv .venv 再装。
  • 别用 sudo pip install：污染系统包管理器的地盘，Debian 系直接报 externally-managed-environment。替代：venv；临时救急才用 pip install --user。

  1. python 不是内部或外部命令（Windows）：安装时没勾 "Add python.exe to PATH"。排查：where python 输出为空或指向意外位置。改：重装勾选，或手动把 C:\Users\<你>\AppData\Local\Programs\Python\Python312 与它的 Scripts 子目录加进 PATH。
  2. PowerShell 报"无法加载文件…因为在此系统上禁止运行脚本"：执行策略限制。排查：Get-ExecutionPolicy 显示 Restricted。改：Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser 后重新激活。
  3. pip 安装超时或断流：网络到 PyPI 慢。排查：pip install requests -v 看卡在哪个域名。改：换清华镜像并加 --timeout 60，或配代理。
  4. 装包出现编译错误（Microsoft Visual C++ 14.0 or greater is required）：装了需要 C 扩展的源码包而本机无编译器。改：Windows 装 Visual C++ Build Tools；或 pip install --only-binary :all: 包名 只走预编译 wheel。
  5. 多个 Python 版本冲突，包装进 A 解释器但 B 跑不起来：pip 命令指向别的解释器。排查：which python 与 which pip 不同目录即中招。改：统一用 python -m pip install，让 pip 与解释器绑定。
  6. Jupyter 里 ModuleNotFoundError: No module named 'requests' 但终端里明明装了：内核指向的不是那个 venv。排查：Jupyter 里跑 import sys; print(sys.executable)。改：venv 里 python -m ipykernel install --user --name myproject 后切换内核。
  7. WSL 里跑 python 却调用了 Windows 的 python.exe：PATH 里 Windows 路径排在前面。排查：which python 输出 /mnt/c/... 即中招。改：~/.bashrc 确保 /usr/local/bin:/usr/bin 在 Windows 路径之前，然后重开终端。
  8. ModuleNotFoundError 但 pip list 里有这个包：装到了另一个 venv 或另一个 Python。排查：python -m pip list 看路径，与 sys.executable 对不上就是。改：激活正确 venv 后用 python -m pip install 重装。
  9. pip install 报 No matching distribution found：镜像未同步或 Python 版本超出该包支持范围。排查：同一命令加 -i https://pypi.org/simple 换官方源再试。改：等镜像同步，或选支持当前版本的包版本号。

按顺序执行，每步都有验收命令，任何一步验收不过就停在那一步修，不要带病往下走。第一步装解释器：Windows 跑 winget install Python.Python.3.12，macOS 跑 brew install python@3.12，Ubuntu 跑 sudo apt install python3.12 python3.12-venv，装完 python3 --version 必须输出 3.12 以上。第二步配镜像：pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple，验收方式是 pip config list 能看到 index-url。第三步建项目目录并创建虚拟环境：mkdir demo && cd demo && python3 -m venv .venv，验收 ls .venv/bin/python 存在。第四步激活并升级 pip：source .venv/bin/activate && python -m pip install --upgrade pip，验收 which python 含 .venv。第五步装编辑器与四个扩展，打开 demo 目录选 .venv 解释器。第六步把第 7 节的 verify_env.py 存进 demo 目录跑一遍，核心项全 PASS 即完成。这条流水线的总耗时瓶颈在下载：官方包约 25MB，VS Code 约 90MB，四扩展合计约 60MB，国内网络配好镜像后通常 10 分钟内装完，未配镜像时 pip 阶段可能单包就超时 60 秒以上。

老项目的典型症状是根目录只有一个裸 requirements.txt，甚至只有 import 列表。标准动作分四步。第一步看代码里的 import 语句，人工列出直接依赖清单，排除标准库。第二步建干净 venv，用 pip install -r requirements.txt 或逐个 pip install 装，报版本冲突时用 pip install 包名==版本 逐个降级试，把能跑起来的组合记录下来。第三步 pip freeze > requirements.lock.txt 固化当前可运行组合，把它提交进 git，原 requirements.txt 保留不动作为历史。第四步补一个最小冒烟脚本：导入核心模块并调用一个主入口函数，跑通就算接手完成。若老项目声明支持 Python 3.8 而你的机器是 3.12，优先用 pyenv 建一个 3.8 的解释器按原版本跑通，不要直接上 3.12 改代码，因为 3.12 移除了 distutils 等旧模块，老依赖可能整包装不上。

11. 讲给完全新手的一页：命令行、脚本、解释器到底是什么3 个重点▾ 点开看本章重点
本章重点
  • 这一节补给没碰过命令行的读者，老手可跳过
  • 命令行是一个输入文字命令、按回车执行的窗口：Windows 叫 PowerShell 或 CMD，macOS 叫终端，WSL 里是 bash
  • 和图形界面点图标的区别是，命令行可以被复制、被记录、被写进脚本批量执行，这正是自动化和可复现的基础
2

这一节补给没碰过命令行的读者，老手可跳过。命令行是一个输入文字命令、按回车执行的窗口：Windows 叫 PowerShell 或 CMD，macOS 叫终端，WSL 里是 bash。和图形界面点图标的区别是，命令行可以被复制、被记录、被写进脚本批量执行，这正是自动化和可复现的基础。解释器是把 .py 文件里的文本逐行翻译成机器动作的程序，python3 xxx.py 的意思就是"用 Python 解释器执行这个文件"。脚本就是一个纯文本的 .py 文件，可以用任何编辑器写，VS Code 只是让写的过程更舒服（补全、跳转、高亮），不用它照样能写。模块和包是把代码拆成多个文件的办法：import json 是用标准库的 json 模块，pip install requests 是先从 PyPI 下载 requests 包再用 import requests 引入。

第一次敲命令的三条纪律。第一，命令区分大小写，Python 和 python 不是一回事。第二，路径里有空格要加引号，Windows 路径反斜杠在 Python 字符串里要写成两个 \\ 或改用正斜杠 /。第三，看报错从最后一行往上读，最后一行通常是异常类型加消息（例如 FileNotFoundError: [Errno 2] No such file or directory: 'a.txt'），它直接告诉你错在哪个文件哪类问题。

一个零风险的练手实验：建目录 mkdir ~/py-demo，进入 cd ~/py-demo，用 echo 'print("hello")' > hello.py 生成一个文件，再 python3 hello.py 运行，看到 hello 输出就说明"写文件、跑解释器、看输出"这条链路通了。链路不通时的排查顺序固定为三问：which python3 看解释器在哪、pwd 看当前目录对不对、ls 看文件在不在。这三个命令的答案组合起来就能定位九成的"跑不起来"。

和虚拟环境的衔接：上面实验用的是系统 Python，它适合跑一次性的练习脚本；一旦开始 pip install 第三方包，就切到第 4 节的 venv 流程。判断标准很简单：文件里出现 import 一个非标准库模块之前，系统 Python 够用；从第一次 pip install 开始，就用 .venv。这个分界线记住了，就不会把"练习脚本装包"和"项目依赖管理"混成一锅粥。

12. 三套完整演练脚本：从安装到验收一条龙

2

下面三段都是可以直接复制运行的命令块，推荐在一台干净机器（或新建的 ~/py-lab 目录）里照做一遍。每段末尾给出验收标准，不满足就按括号里的提示修。

演练一：一键建项目骨架（bash，Linux/WSL/macOS 通吃）

#!/usr/bin/env bash
# new_project.sh —— 用法: bash new_project.sh my_app
# 真实路径: 存到 ~/bin/new_project.sh 并 chmod +x
set -euo pipefail
NAME="${1:?用法: bash new_project.sh 项目名}"
ROOT="$HOME/py-lab/$NAME"
mkdir -p "$ROOT/src/$NAME" "$ROOT/tests"
cd "$ROOT"
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip -q
python -m pip install pytest ruff -q
printf '.venv/\n__pycache__/\n' > .gitignore
printf '[tool.ruff]\nline-length = 88\n' > pyproject.toml
printf 'def add(a: int, b: int) -> int:\n    return a + b\n' > "src/$NAME/core.py"
printf 'from %s.core import add\n\ndef test_add():\n    assert add(1, 2) == 3\n' "$NAME" > tests/test_core.py
python -m pytest -q && ruff check .
echo "骨架就绪: $ROOT"

验收标准：最后一行输出"骨架就绪"，且 pytest 显示 1 passed。若 python3 -m venv 报 ensurepip 缺失，先装 python3-venv 系统包再重跑。

演练二：一键验收环境（Python 3.12，把第 7 节脚本的精简版做成体检器）

#!/usr/bin/env python3
# env_health.py —— Python 3.12, 用法: python env_health.py
# 输出写到 ./health_report.txt, 返回码 0 表示核心全过
import sys, json
from pathlib import Path

REQUIRED = ["os", "sys", "json", "re", "pathlib", "collections", "logging"]
score, missing = 0, []
for mod in REQUIRED:
    try:
        __import__(mod); score += 1
    except ImportError:
        missing.append(mod)
in_venv = hasattr(sys, "base_prefix") and sys.base_prefix != sys.prefix
report = {
    "python": sys.version.split()[0],
    "executable": sys.executable,
    "in_venv": in_venv,
    "stdlib_score": f"{score}/{len(REQUIRED)}",
    "missing": missing,
}
Path("health_report.txt").write_text(json.dumps(report, ensure_ascii=False, indent=2),
                                     encoding="utf-8")

#!/usr/bin/env python3
# hello_env.py —— Python 3.12
# 运行: python hello_env.py
# 真实路径: 存到 ~/py-demo/hello_env.py
import platform   # 标准库模块，读操作系统与解释器信息
import sys        # 标准库模块，读解释器运行时状态

def main():                      # def 定义函数，main 是入口名（惯例）
    py_ver = platform.python_version()   # 取版本号字符串，例如 "3.12.7"
    os_name = platform.system()          # 取系统名，例如 "Linux"

    print(f"操作系统: {os_name}")
    print(f"解释器路径: {sys.executable}")
    name = input("你的名字是: ")          # 阻塞等待用户输入一行文字
    print(f"你好，{name}！这是你的第一个 Python 脚本。")

if __name__ == "__main__":   # 只有直接运行本文件时才执行 main
    main()

脚本 B：number_play.py（Python 3.12）——数值类型与类型转换的实感

#!/usr/bin/env python3
# number_play.py —— Python 3.12
# 运行: python number_play.py
a = 7            # int 整数，Python 的整数没有大小上限
b = 3
print(a / b)     # 真除法，结果 2.3333333333333335
print(a // b)    # 整除（地板除），结果 2
print(a % b)     # 取余数，结果 1
print(a ** b)    # 幂运算，7 的 3 次方 = 343

price = "19.90"                # 字符串形式的金额，常见于用户输入
total = float(price) * 3       # float() 把字符串转成小数，再乘数量
print(f"3 件总价: {total:.2f} 元")   # :.2f 保留两位小数

# 类型转换的坑：带小数点的字符串不能直接转 int
try:
    int("19.90")               # 抛 ValueError
except ValueError as e:
    print("int('19.90') 失败:", e)   # 正确做法是先 float 再 int
    print("正确做法:", int(float("19.90")))   # 结果 19（截断小数，不四舍五入）

验收标准：输出包含 2.3333…、2、1、343 以及 3 件总价 59.70 元，最后两行打印转换失败的消息和正确做法的结果 19。注意 int(float(...)) 是截断不是四舍五入，要四舍五入用 round(float("19.90")) 得 20。

脚本 C：text_play.py（Python 3.12）——字符串索引切片与常用方法

#!/usr/bin/env python3
# text_play.py —— Python 3.12
s = "Hello, Python 3.12"
print(s[0])        # 索引从 0 开始，取第一个字符 H
print(s[-1])       # 负索引从右数，取最后一个字符 2
print(s[7:13])     # 切片 [起:止]，含头不含尾，取 Python
print(s[::2])      # 步长 2，每隔一个字符取一个

words = s.split(", ")         # 按分隔符切成列表
print(words)                  # ['Hello', 'Python 3.12']
joined = " | ".join(words)    # 用连接符把列表拼回字符串
print(joined)                 # Hello | Python 3.12

clean = "  padded  ".strip()  # 去掉两端空白字符
print(repr(clean))            # repr 显示真实内容，验证空白已去掉
print(s.startswith("Hello"), s.count("o"))   # 判断前缀、统计字符

验收标准：第一行输出 H，第三行输出 Python，split 后打印含两个元素的列表。若切片结果和预期差一个字符，记住"含头不含尾"这条规则。

脚本 D：mini_calc.py（Python 3.12）——把前三段知识串成小工具

#!/usr/bin/env python3
# mini_calc.py —— Python 3.12
# 运行: python mini_calc.py "12 + 5"  或  python mini_calc.py
import sys

def calc(expr: str) -> float:        # 类型注解：参数是字符串，返回小数
    for op in "+-*/":                # 依次尝试四种运算符
        if op in expr:
            left, right = expr.split(op, 1)   # 只按第一个运算符切开
            a, b = float(left.strip()), float(right.strip())
            return {"+": a + b, "-": a - b, "*": a * b, "/": a / b}[op]
    raise ValueError(f"不支持的表达式: {expr}")

if __name__ == "__main__":
    expr = sys.argv[1] if len(sys.argv) > 1 else input("输入如 12 + 5: ")
    try:
        print(f"{expr} = {calc(expr)}")
    except ZeroDivisionError:
        print("除数不能为零")
    except ValueError as e:
        print("输入错误:", e)

验收标准：python mini_calc.py "12 + 5" 输出 12 + 5 = 17.0；python mini_calc.py "8 / 0" 输出"除数不能为零"。这个脚本顺带演示了三个工程习惯：函数带类型注解、用字典做运算符分发、异常按类型分别捕获。

15. FAQ：十二个真实提问与短答案

2

问 1：虚拟环境建好后可以整体复制给别人用吗？ 不建议。venv 里写死了绝对路径，换台机器路径就失效。正确做法是给对方 requirements.txt，让他在自己机器重建。

问 2：.venv 和 venv 命名有讲究吗？ 有。带点前缀是社区惯例，多数 .gitignore 模板和工具会默认忽略它；不带点则容易被误提交进 git。

问 3：pip 和 python -m pip 有什么区别？ pip 是独立入口，可能指向别的解释器；python -m pip 保证用当前解释器配套的 pip。团队脚本里一律用后者。

问 4：升级 Python 小版本（3.12.5 到 3.12.7）要重建 venv 吗？ 建议重建。小版本升级后 venv 里的符号链接仍指向旧的可执行文件，重建成本低（一次 python -m venv 加 pip install -r），比排查奇怪报错便宜。

问 5：Windows 上装了 Python 但终端敲 python 打开的是微软商店？ 这是 Windows 的应用执行别名（App Execution Alias）抢了 PATH。改法：设置里搜"管理应用执行别名"，关掉 python.exe 与 python3.exe 的商店别名。

问 6：WSL 里要不要同时装 Windows 版和 Linux 版 Python？ 不要。WSL 项目只用 Linux 版，Windows 版留给纯 Windows 项目。两套混用最容易出第 8.3 节第 7 条那种路径混淆。

问 7：conda 和 venv 能嵌套用吗？ 能但别。conda 环境里再建 venv 会造成"两层隔离"，谁装的包在哪里极难排查。选一个体系走到底。

问 8：requirements.txt 里要不要写版本号？ 要。不写版本号等于把版本选择权交给安装当天的 PyPI 状态，三个月后重装可能装出完全不同的组合。最低要求是直接依赖写 == 精确版本。

问 9：pip install 卡在 Building wheel 是什么信号？ 信号是这个包没有预编译 wheel，正在本地编译 C 扩展。等几分钟正常；十分钟以上就是缺编译器，按第 8.3 节第 4 条处理。

问 10：怎么确认某个包装在哪个环境？ 跑 python -m pip show 包名 看 Location 字段；或在代码里 import 包名; print(包名.__file__) 打印真实文件路径，路径里含 .venv 才对。

问 11：多个项目共用一个大环境行不行？ 小团队短期可以，长期必翻车。共用环境的依赖升级是全局动作，A 项目的升级会静默改变 B 项目的运行时。项目超过 2 个就一项目一 venv。

问 12：怎么把本机环境迁移到新电脑？ 三件套：git 仓库（代码加 requirements.txt）、pyenv 的 .python-version（解释器版本）、README 的环境小节（特殊配置）。新机器按第 12 节演练一建骨架、装依赖、跑冒烟即可。
