WHY

2

真实数据分析不是把 CSV 读进来再随便画一张图，而是要连续完成数值计算、表格清洗、分组关联、图形表达和结论核验。numpy、pandas、matplotlib、seaborn 分别承担这些环节中的不同职责；缺少这套分层心智，常见问题不是「不会某个 API」，而是循环慢、键类型漂移、缺失被静默丢弃、关联后行数膨胀、图形口径误导。

不建立这些纪律，分析结果可能看似正常却不可复现、不可核对：链式赋值没有改到原表，value_counts 悄悄丢掉 NaN，服务器绘图因后端错误挂起，均值和分位数被异常值拉扯。学习四件套的目的，是把「读→洗→算→画→结论」变成带断言、带口径、可复跑的工作流，而不是背四份 API 清单。

1. numpy：数组思维的三个纪律

3

1.1 ndarray 的心智模型：形状 + dtype + 连续内存

np.ndarray 是"同类型、固定形状、连续内存"的块。三个属性随时可查：arr.shape（形状元组）、arr.dtype（元素类型）、arr.flags["C_CONTIGUOUS"]（内存是否连续）。形状错误是 numpy 代码 80% 的报错来源，防御式写法是每个变换后 print(arr.shape) 或 assert arr.shape == (n, d)。

dtype 的实际影响比想象大：float32 比 float64 省一半内存（嵌入向量存储常用），int64 到 int8 差 8 倍；但 float32 的机器精度 eps ≈ 1.19e-7，float64 是 2.22e-16——数值敏感的计算（求逆、条件数）用 float64，纯存储用 float32。numpy 2.x 的 np.array([1,2,3]).dtype 是 int64（Linux），CSV 读进来整列可能是 int，算比率时真除法（/）照样给浮点，但 // 是整除，见《线性代数白话》§11.5。

1.2 向量化与广播

向量化 = 用整块数组操作替代 Python 循环。实测（numpy 2.4.3，20 万行数据）：df["x"].apply(lambda v: v*2+1) 耗时约 53.5 毫秒，df["x"]*2+1 耗时约 1.7 毫秒——30 倍差距，且向量化版本可读性更好。规则：apply/循环是最后手段，先想"这能不能写成数组表达式"。

广播是 numpy 的隐式形状对齐：(3,4) + (4,) 合法（沿行广播），(3,4) + (3,) 报错（形状不对齐）。规则从后往前对齐维度，拿不准先 print(a.shape, b.shape)。陷阱见《线性代数白话》§11.2 的实测：一维数组加矩阵是沿行广播，写错方向结果形状对但内容错。

2.1 DataFrame 的心智模型：列是 Series，索引是标签

df 是"共享索引的 Series 字典"。df["col"] 返回 Series（一维），df[["col1","col2"]] 返回 DataFrame（二维）——单括号和双括号是两个类型，新手最高频的混淆点。索引（index）默认是 0..n-1 的 RangeIndex，但 set_index 后可以是任意标签（时间戳、ID），loc 按标签取、iloc 按位置取，两者混用是第二高频的坑。

2.2 读写与 dtype

pd.read_csv 的 dtype 推断：整数列→int64，含缺失的数值列→float64，字符串列在 pandas 3.x 默认 StringDtype（不再是 object）。实测（pandas 3.0.6）：

import pandas as pd, io
csv = "id,name,val\n1,a,10\n2,b,NaN\n3,c,30"
d = pd.read_csv(io.StringIO(csv))
print(d.dtypes.to_dict())
# 实跑：{'id': dtype('int64'), 'name': StringDtype(storage='python', na_value=nan), 'val': dtype('float64')}
print(d.isna().sum().to_dict())   # 实跑：{'id': 0, 'name': 0, 'val': 1}

工程纪律：读 CSV 时显式给 dtype（dtype={"id": "int64", "name": "string"}），否则上游数据格式变化（比如 id 前面补了空格变成字符串）会让 dtype 静默漂移，下游 merge 全空。大文件用 use_cols 只读需要的列、nrows 先探样，df.memory_usage(deep=True).sum() 查真实内存占用（实测 4 行 3 列的 DataFrame 约 196 字节，deep=True 才算字符串真实大小）。

去重——drop_duplicates(subset=..., keep=...)：

dup = pd.DataFrame({"id": [1, 1, 2, 3], "v": [10, 11, 20, 30]})
print(len(dup), len(dup.drop_duplicates(subset="id")))          # 4 3
print(dup.drop_duplicates(subset="id", keep="last")["v"].tolist())  # [11, 20, 30]

keep="first"/"last"/False 三选一，语义是"重复键保留哪一条"。实测 4 行去重后 3 行，keep="last" 保留第二条的 v=11。去重要么显式写 keep 并注明理由，要么先排序再 keep="last"，不写参数的默认 "first" 在乱序数据上等于随机选。

2.4 Copy-on-Write：pandas 3.x 的最大行为变化

pandas 3.0 默认启用 Copy-on-Write（CoW），链式赋值（chained assignment）不再静默失败也不再警告，而是直接抛 ChainedAssignmentError。实测（pandas 3.0.6）：

import pandas as pd
df = pd.DataFrame({"a": [1, 2, 3]})
df[df["a"] > 1]["a"] = 99      # ← 抛 ChainedAssignmentError
print(df["a"].tolist())        # 原数据不变：[1, 2, 3]

df.loc[df["a"] > 1, "a"] = 99  # ← 正确写法，单步 .loc
print(df["a"].tolist())        # [1, 99, 99]

实测报错文本（pandas 3.0.6）：ChainedAssignmentError: A value is being set on a copy of a DataFrame or Series through chained assignment. Such chained assignment never works to update the original DataFrame or Series, because the intermediate object on which we are setting values always behaves as a copy (due to Copy-on-Write). Try using '.loc[row_indexer, col_indexer] = value' instead。

这条报错信息本身就是文档，照它说的改用 .loc 即可。从 pandas 1.x/2.x 迁移的代码要重点排查两处：①df[cond]["col"] = value 全部改 df.loc[cond, "col"] = value；②view = df[:]; view["x"] = 0 不再影响原表（CoW 下 view 是副本），依赖共享内存的旧代码语义变了。迁移清单：搜 ][" 后跟 = 的模式，逐个改 .loc。

4.1 三类图与数据形状要求

seaborn 的函数按"数据形状"分三类，调错数据形状是最常见的报错：

  • 关系类（scatterplot/lineplot/relplot）：两个数值变量，data=df, x=, y=。
  • 分布类（histplot/kdeplot/ecdfplot）：一个数值变量。
  • 分类类（boxplot/violinplot/barplot/catplot）：一个分类变量 + 一个数值变量。

relplot/catplot 是"图级"函数（FacetGrid，自动分子图），scatterplot/boxplot 是"轴级"函数（画在指定 ax 上）。工程代码里轴级更可控，图级适合探索阶段快速看分面。

脚本 A：向量化数据清洗管道（可直接跑）

"""numpy 向量化清洗：异常值截断 + 标准化 + 缺失值处理。
运行: numpy 2.4.3"""
import numpy as np

rng = np.random.default_rng(2026)
X = rng.normal(loc=50, scale=15, size=(1000, 5))
X[::100] += 100                                # 注入每 100 行一个的异常值
X[rng.random(X.shape) < 0.02] = np.nan         # 注入 2% 缺失

print("缺失率:", np.round(np.isnan(X).mean(axis=0), 4))
# 实跑：[0.015 0.018 0.019 0.019 0.017]  ← 每列约 1.5~1.9% 缺失
med = np.nanmedian(X, axis=0)                  # 用中位数填充（抗异常值）
inds = np.where(np.isnan(X))
X[inds] = np.take(med, inds[1])                # 按列取中位数填充

lo, hi = np.nanpercentile(X, [1, 99], axis=0)  # 1%/99% 分位数截断
X = np.clip(X, lo, hi)                         # 向量化截断，无循环

z = (X - X.mean(axis=0)) / X.std(axis=0, ddof=1)
print("标准化后各列均值:", np.round(z.mean(axis=0), 6))   # 全部 ≈ 0
print("标准化后各列标准差:", np.round(z.std(axis=0, ddof=1), 6))  # 全部 ≈ 1
assert np.isfinite(z).all()
print("shape:", z.shape, "dtype:", z.dtype)    # 实跑：(1000, 5) float64

from scipy import stats

6.1 链式赋值（§2.4）

df[cond]["col"] = v 抛 ChainedAssignmentError，改 df.loc[cond, "col"] = v。pandas 3.x 强制，2.x 只警告。

6.2 value_counts 默认丢 NaN

实测（pandas 3.0.6）：pd.Series(["x","y",None,"x","x"]).value_counts() 给 {'x': 3, 'y': 1}，None 被丢弃；加 dropna=False 才给 {'x': 3, 'y': 1, nan: 1}。统计分组占比时忘了 dropna=False 会让"缺失"这一类消失，占比分母悄悄变小。规则：凡是要"占比总和=1"的场景，value_counts(normalize=True, dropna=False)。

6.3 apply 慢 30 倍

20 万行实测：apply 53.5ms vs 向量化 1.7ms。规则：apply 只留给无法向量化的复杂逐行逻辑（且优先想 np.vectorize 或列运算）。

6.4 merge 键类型不匹配静默给空

int 键 merge str 键不报错、结果为空。规则：merge 前 assert set(left["id"].dtype) == ... 不现实，改用 validate="one_to_one" + 结果行数断言，或显式 astype 统一类型。

6.5 groupby 默认丢 NaN 键

groupby 默认 dropna=True，NaN 键的行被丢出分组。规则：groupby(..., dropna=False) 显式保留，或先填充键。

6.6 SettingWithCopy 警告的真身

pandas 2.x 的 SettingWithCopyWarning 在 3.x 被 ChainedAssignmentError 取代（§2.4），但语义根源同一个：你以为改了原表，实际改的是临时副本。凡是要改数据，用 .loc 单步写。

6.7 切片视图的 CoW 语义变化

v = df[:]; v["x"] = 0 在 pandas 1.x 可能改到原表（视图），3.x CoW 下 v 是副本、原表不变。依赖旧语义的代码会静默失效（以为改了实际没改）。规则：要改原表就直接 df["x"] = 0 或 df.loc[..., "x"] = 0，别经过中间变量。

import pandas as pd, numpy as np

orders = pd.DataFrame({
    "order_id": [1, 2, 3, 4, 5],

    "amount": [250.0, 130.0, 90.0, 310.0, 55.0],
})
users = pd.DataFrame({
    "user_id": [101, 102, 103, 104],
    "tier": ["gold", "silver", "gold", "bronze"],
    "signup": pd.to_datetime(["2025-01-01", "2025-03-15", "2025-06-20", "2025-09-01"]),
})

# 1) 校验键唯一性后再 merge
assert users["user_id"].is_unique, "用户表主键有重复"
m = orders.merge(users, on="user_id", how="left", validate="many_to_one")
print("merge 后行数:", len(m), "（应等于订单数", len(orders), "）")
assert len(m) == len(orders), "merge 行数膨胀/丢失！"

# 2) 聚合：按 tier 算人均消费（ratio of sums，见《统计直觉》§12.2）
g = m.groupby("tier")["amount"].agg(["sum", "count", "mean"])
g["avg_per_order"] = g["sum"] / g["count"]
print(g.round(2))

# 3) 交叉验证：分组总和 == 总表总和
assert np.isclose(g["sum"].sum(), orders["amount"].sum())
print("总量守恒 ✓")

# 4) 老用户 vs 新用户的订单额（时间维度）
m["signup_days_ago"] = (pd.Timestamp("2026-01-01") - m["signup"]).dt.days
m["is_new"] = m["signup_days_ago"] < 200
print(m.groupby("is_new")["amount"].agg(["count", "mean"]).round(2))

11.1 两类函数的分工

# 图级：col="time" 自动分成左右两个子图，hue 再按 smoker 上色
g = sns.relplot(data=tips, x="total_bill", y="tip", col="time",

# 轴级：自己开画布

fig.savefig("/tmp/boxplot_demo.png", dpi=80)   # 轴级用 fig.savefig
plt.close(fig)

11.2 catplot 与 barplot 的统计语义

sns.catplot(kind="bar") 画的是均值 + 置信区间（默认 95% CI，bootstrap 重采样算的），不是"每组的柱子就是数值本身"。这是最常见的误读：看到柱子高度以为是中位数或总和。实测（seaborn 0.13.2）：catplot(data=df, x="g", y="v", kind="bar") 输出的柱高是各组均值，误差棒是 bootstrap CI。要画"每组中位数"用 kind="box" 或 estimator=np.median 参数显式指定。

import pandas as pd, numpy as np
import matplotlib; matplotlib.use("Agg")
import seaborn as sns; import matplotlib.pyplot as plt

rng = np.random.default_rng(3)
d = pd.DataFrame({"g": ["A"] * 80 + ["B"] * 80,
                  "v": np.concatenate([rng.normal(0, 1, 80), rng.normal(0.5, 1, 80)])})

g = sns.catplot(data=d, x="g", y="v", kind="bar", height=3, aspect=1.2)   # 均值+CI
g.savefig("/tmp/catplot_bar.png", dpi=80)
print("分组中位数:", d.groupby("g")["v"].median().round(3).to_dict())
# 实跑：{'A': -0.05, 'B': 0.439}   ← 注意这不是 barplot 画的高度（那是均值）
plt.close("all")

实跑中位数 {'A': -0.05, 'B': 0.439}，而 barplot 画的是均值（A≈0、B≈0.5）——中位数和均值在正态数据上接近但不相等，右偏数据上差距巨大。规则：报告里说"柱子代表什么"必须写明 estimator（mean/median/sum），这是 §12.2 口径纪律的可视化版本。

12.1 元素清单：一张合格的图必须有什么

标题（说结论不只说数据）、坐标轴标签（带单位）、图例（hue/size 的对照）、网格线（alpha=0.3 不抢戏）、合适的长宽比（趋势图 16:9，对比图 4:3）。缺标题/单位的图在报告里等于没说。实测保存链（matplotlib 3.11.2）：fig.tight_layout() 防标签被裁，fig.savefig(..., dpi=120, bbox_inches="tight") 双保险，dpi=300 用于论文投稿。

12.2 三个误导性陷阱

  1. y 轴不从 0 开始：柱状图 y 轴截断会把 5% 差异画成"翻倍"。规则：柱状图 y 轴必须从 0 开始；折线图可以不从 0 但要标注。
  2. 双 y 轴：两条曲线各用一个 y 轴，交叉点完全是缩放假象。替代：分两幅子图，或归一化后同轴。
  3. 色图非线性：默认 viridis 感知均匀（推荐），但 jet（旧默认）在青色段压缩严重，读者误判梯度。规则：连续量用 viridis/cividis，发散量用 vlag/coolwarm，禁用 jet。

15. 实战补充脚本：排列检验与 bootstrap 差值（可直接跑）

3 
"""非参数检验两件套：排列检验算 p 值、bootstrap 算差值置信区间。
运行: numpy 2.4.3"""
import numpy as np

rng = np.random.default_rng(2026)
a = rng.normal(10.0, 2.0, 200)
b = rng.normal(10.0, 2.0, 200)          # 两组同分布
r = rng.random(200)
a = a.copy(); a[r < 0.3] += 0.8          # 只对 A 组 30% 样本加 0.8 的"局部效应"

both = np.concatenate([a, b])
obs = float(a.mean() - b.mean())

# 1) 排列检验：零假设下两组可交换，打乱标签 2000 次看差异分布
diffs = np.empty(2000)
for i in range(2000):
    p = rng.permutation(both)
    diffs[i] = p[:200].mean() - p[200:].mean()
perm_p = float((np.abs(diffs) >= abs(obs)).mean())
print(f"观察差异={obs:.3f}  排列检验 p={perm_p:.4f}")
print(f"排列分布 2.5%/97.5% 分位数={np.round(np.percentile(diffs, [2.5, 97.5]), 3)}")
# 实跑：观察差异 0.344，排列检验 p=0.101（202/2000），分布 [-0.391, 0.417]

# 2) bootstrap 差值 CI：直接重采样两组各算均值差
rng2 = np.random.default_rng(11)
x = rng2.normal(5, 1, 80); y = rng2.normal(5.8, 1, 80)
boot = np.array([rng2.choice(y, 80, replace=True).mean()
                 - rng2.choice(x, 80, replace=True).mean() for _ in range(3000)])
print("bootstrap 差值 95% CI:", np.round(np.percentile(boot, [2.5, 97.5]), 4))
se = np.sqrt(x.var(ddof=1)/80 + y.var(ddof=1)/80)
print("正态近似差值 95% CI:", np.round((y.mean()-x.mean()-1.96*se,
                                       y.mean()-x.mean()+1.96*se), 4))
# 实跑：bootstrap [0.5707, 1.1575]，正态近似 [0.5582, 1.1537] ← 两者接近

这段演示两个非参数工具的正确用法。排列检验实跑结果非常有教学价值：真实效应是"30% 样本加 0.8"（真实分组比例 0.29），观察差异 0.344 但排列检验 p=0.101——p>0.05 不代表没效应，而是这个设计（200 样本、30% 局部效应、σ=2）功效不足以把它与噪声分开。这正是《L0-统计直觉》§5.3"功效不足别下'无差异'结论"的活例子。bootstrap 与正态近似的差值 CI 几乎一致（[0.5707, 1.1575] vs [0.5582, 1.1537]），n=80+80 时正态近似已够用；样本更小或分布更偏时以 bootstrap 为准。

排列检验的工程价值：不假定分布、可检验任意统计量（中位数差、方差比、相关系数），代价是计算量（2000 次重排 = 2000 次统计量计算）。大数据集上用 rng.permutation 的向量化版本或减到 500 次（p 值分辨率 0.002，够用）。

17. 性能实测：四个降耗技巧（pandas 3.0.6 实跑）1 个重点▾ 点开看本节重点
本节重点

3

数据量上到 20 万行以上时，写法差异开始有体感。以下四个技巧的实测数字（20 万行，pandas 3.0.6）：

17.1 category dtype：内存降 50 倍、groupby 快 3.8 倍

低基数字符串列（性别、地区、类型，唯一值 < 行数 10%）转 category：

import numpy as np, pandas as pd, time

n = 200_000
df = pd.DataFrame({"a": np.arange(n, dtype="int64"),
                   "b": np.random.default_rng(0).normal(size=n)})
df["c"] = np.where(df["a"] % 7 == 0, "x", "y")     # 低基数字符串列

df_obj = df.copy()
df_cat = df.copy()
df_cat["c"] = df_cat["c"].astype("category")

print("内存 obj:", df_obj["c"].memory_usage(deep=True),
      "category:", df_cat["c"].memory_usage(deep=True))
# 实跑：10000132 vs 200232 字节 ← 50 倍差距

t0 = time.perf_counter(); df_obj.groupby("c")["b"].sum(); t1 = time.perf_counter()
df_cat.groupby("c", observed=True)["b"].sum(); t2 = time.perf_counter()
print("groupby obj:", round((t1-t0)*1000, 1), "ms; category:", round((t2-t1)*1000, 1), "ms")
# 实跑：11.7ms vs 3.1ms ← 3.8 倍

observed=True 是 category groupby 的必要参数（pandas 3.x 默认 observed=False 会为所有"可能出现但实际没有"的类别建空组）。规则：读 CSV 后立刻 astype("category") 低基数列，groupby/merge/过滤全都受益。

17.2 query 与布尔掩码：简单过滤掩码更快

df.query("a > 100000 and b < 2") 可读性好但要解析字符串，实测 6.1ms；布尔掩码 df[(df["a"] > 100000) & (df["b"] < 2)] 实测 2.7ms，快 2.3 倍且结果行数完全一致（97679 行）。规则：性能敏感路径用布尔掩码，可读性优先（复杂表达式、变量多）用 query——query 的真实价值是表达式里可以直接引用变量名（df.query("a > @threshold")），比拼字符串拼接安全。

17.3 eval：不是万能加速器

df.eval("a * 2 + b") 走 pandas 的表达式引擎（numexpr 后端），实测 4.0ms；朴素写法 df["a"]*2 + df["b"] 实测 0.6ms，反而更快——numexpr 的开销在小表达式上不划算。规则：单行表达式用朴素写法；多步链式大表达式（a*b + c/d - e 这种 5+ 项）才值得 eval/query，且要 pd.set_option("compute.use_numexpr", True) 确认后端在用。这是"听起来高级的优化不一定快"的典型案例，任何优化都要先测。

17.4 chunksize 分块读：内存不炸的关键

5 万行 CSV 全量读和 chunksize=10000 分块读的行数完全一致（50000），但内存峰值差一个量级：全量读整表驻留内存，分块读每次只有 1 万行。规则：文件 > 100MB 或内存紧张时用 pd.read_csv(path, chunksize=...) 迭代；聚合类任务（求和/计数/分组均值）天然可分块——每块算局部聚合，最后合并（均值不能直接加，要按块样本量加权，或每块输出 sum+count 两种局部量最后 total_sum/total_count，这正是 §12.2 ratio of sums 的分块版本）。

20. SQL ↔ pandas 对照：五个等价模式（附实测输出）

3

数据团队里"SQL 写惯了的人转 pandas"高频踩坑点是同名不同义：SQL 的 RANK()、pandas 的 rank()，语义细节不同；SQL 的 GROUP BY 悄悄丢 NULL，pandas 也丢但参数不同。下面是五个高频模式的等价写法和实测输出（pandas 3.0.6）：

20.1 窗口函数 RANK ↔ groupby.rank

import pandas as pd

df = pd.DataFrame({"dept": ["a","a","b","b","b"],
                   "name": ["x","y","p","q","r"],
                   "sal": [3, 1, 5, 2, 4]})
df["rank"] = df.groupby("dept")["sal"].rank(ascending=False, method="first")
print(df.sort_values(["dept", "rank"]).to_string())
# 实跑：a 组 x=3 排 1、y=1 排 2；b 组 p=5 排 1、r=4 排 2、q=2 排 3

method="first" 对应 SQL RANK() 的"并列时按出现顺序"；method="min" 对应 SQL RANK() 的"并列同名次"；method="average" 对应 DENSE_RANK 的平均版。method 不选默认是 "average"，并列值会给小数名次——SQL 用户最常踩的差异。

20.2 LAG/DIFF ↔ diff / pct_change

SQL 的 LAG(col) OVER (ORDER BY ts) 对应 pandas 的 s.diff()（差值）和 s.pct_change()（环比）。实测（pandas 3.0.6）：[10, 12, 11, 15] 的 diff() 是 [NaN, 2.0, -1.0, 4.0]、pct_change() 是 [NaN, 0.2, -0.083, 0.364]——首元素是 NaN（没有前一行），与 SQL 的 LAG 首行为 NULL 一致。注意 pct_change 的分母是前值，前值为 0 时给 inf/NaN，先清洗零值。

20.3 多聚合 ↔ pivot_table / agg

SQL GROUP BY g SELECT AVG(v), COUNT(v) 对应 df.groupby("g")["v"].agg(["mean","count"]) 或 pivot_table(index="g", values="v", aggfunc=["mean","count"])。实测（pandas 3.0.6）：g=a 均值 2.0 计数 2，g=b 均值 5.0 计数 2。pivot_table 的列变成多级索引（("mean","v")），用 .droplevel(0, axis=1) 扁平化。

20.4 UNNEST ↔ explode

SQL 的 UNNEST(array_col) 对应 pandas 的 df.explode("col")。实测（pandas 3.0.6）：id=1 的 tags=["x","y"] 拆成两行（id=1,x / id=1,y），id=2 的 tags=["z"] 一行。explode 后索引重复（id=1 出现两行），要 reset_index(drop=True) 重排，或聚合前 groupby("id")——explode 是行数膨胀操作，和 §13.3 的 merge 膨胀同类，行数守恒断言要按"展开后行数 = 原数组元素总数"验。

20.5 派生列链式写法：assign

SQL 的 SELECT *, v*10 AS b, v*10+1 AS c 对应 df.assign(b=lambda t: t["a"]*10, c=lambda t: t["b"]+1)。实测（pandas 3.0.6）：a=[1,2,3] 生成 b=[10,20,30]、c=[11,21,31]——assign 的 lambda 里可以引用本链新增的列（t["b"] 在第二个 lambda 里可用），这是 assign 链式调用的关键特性，也是 §2.4 链式赋值的"合法替代"：assign 返回新表，不触发 CoW 错误。

数据分析的最后一公里是"数字上墙"——监控看板、日报、SLO 面板。这一节处理三个上墙前的口径问题，实测数字来自 numpy 2.4.3。

22.1 EMA 趋势线：比移动平均更平滑且不缩短序列

§12.3（统计直觉篇）说移动平均会缩短序列并滞后 w/2，EMA（指数移动平均）是标准替代：EMA_t = α·x_t + (1-α)·EMA_{t-1}，序列长度不变、滞后约 1/α 的量级。实测（numpy 2.4.3）：10 个点的上涨序列 [10.0, 10.4, ..., 12.6]，α=0.3 的 EMA 输出 [10.0, 10.12, 10.144, 10.371, 10.65, 10.785, 11.089, 11.422, 11.596, 11.897]（平滑但滞后）；α=0.7 的 EMA 是 [10.0, 10.28, 10.224, 10.697, 11.119, 11.106, 11.592, 12.018, 12.005, 12.422]（更贴原始曲线）。α 越大越灵敏、越小越平滑，看板上 α=0.3 是常用默认，告警检测用 α=0.7 或干脆用原始值。

22.2 SLO 错误预算：p99 与违例率是两个指标

SLO 面板上"p99 延迟 < 150ms"和"超 150ms 的请求占比 < 1%"是两个不同的口径。实测（numpy 2.4.3）：950 个正常请求（均值 50ms）+ 50 个慢请求（均值 200ms），全局 p99 = 216.8ms、p95 = 72.9ms、超过 150ms 的违例率 = 5.0%——p99（216.8ms）超 SLO（150ms）且违例率 5% 也超预算（1%），两个指标都亮红；但如果慢请求占比降到 0.8%，违例率达标而 p99 仍可能超线（p99 只看最差 1%，对"少量极慢"敏感）。规则：SLO 面板同时挂 p99 和违例率两个指标，任何一个超线都算违约；错误预算（error budget）按"违例率 × 时间窗"算剩余预算，预算耗尽冻结发布——这是 SRE 的标准纪律，本质是《L0-统计直觉》§2.2 分位数口径的运维版。

22.3 双 y 轴的合法替代：归一化后同轴

§12.2 说双 y 轴误导，但"两个量纲不同的趋势想放一张图"是真实需求。合法替代是归一化到 0~1 后同轴：实测（numpy 2.4.3）a=[100,200,300]（金额）与 b=[1,2,3]（次数）归一化后都是 [0.333, 0.667, 1.0]，np.allclose(a/a.max(), b/b.max()) 为 True——量纲不同的两条曲线，除以各自最大值后可以同轴比较形状，不失真也不用双轴。看板上的实现：每条曲线加"相对基准 %"的标签（"金额 100%"、"次数 100%"），图例注明"已归一化，形状可比、绝对值见 tooltip"。如果绝对值也重要，用 sparkline（ASCII 迷你图）或小多图（small multiples，每指标一格，共享 x 轴）。

import numpy as np

# EMA 趋势线（α=0.3 平滑，α=0.7 贴近）
s = np.array([10., 10.4, 10.2, 10.9, 11.3, 11.1, 11.8, 12.2, 12.0, 12.6])
def ema(x, alpha):
    out = [x[0]]
    for v in x[1:]:
        out.append(alpha * v + (1 - alpha) * out[-1])
    return np.array(out)
print(np.round(ema(s, 0.3), 3))   # 实跑：[10. 10.12 10.144 10.371 10.65 10.785 11.089 11.422 11.596 11.897]

# SLO 口径：p99 与违例率并挂
lat = np.concatenate([np.random.default_rng(1).normal(50, 5, 950),
                      np.random.default_rng(2).normal(200, 20, 50)])
p99 = np.percentile(lat, 99)
viol = float((lat > 150).mean())
print(f"p99={p99:.1f}ms 违例率={viol:.4f}")   # 实跑：p99=216.8ms 违例率=0.0500

# 双 y 轴的替代：归一化同轴
a = np.array([100., 200., 300.]); b = np.array([1., 2., 3.])
print("归一化后形状一致:", bool(np.allclose(a / a.max(), b / b.max())))   # 实跑：True

三个问题的共同点：上墙的数字必须口径明确——趋势线写清 α、SLO 写清"p99 还是违例率"、对比图写清"归一化后形状可比"。看板是给决策用的，口径不清的看板比没有看板更危险（假精确）。

24. 特征工程里的统计口径：四个上墙前的标准动作

3

数据清洗完、特征造好，进模型前还有一层"统计口径"要对齐。以下四个动作实测于 numpy 2.4.3，都是特征工程流水线的标准件。

24.1 稳健缩放：异常值下的标准化

z-score 标准化 (x-mean)/std 被异常值污染（§6 的循环依赖），稳健缩放 (x-median)/IQR 是替代。实测（numpy 2.4.3）：60 个 normal(100,5) 样本塞一个 500 的异常值，z-score 后异常值的 |z|=7.58（仍显眼但正常值被压缩），稳健缩放后异常值 76.04（异常值依旧显眼但正常值分布不被拉扯）——两者对异常值都"放大"，但 z-score 的 mean/std 已被污染、分母失真，稳健版的 median/IQR 不受影响。特征工程规则：①树模型不用缩放（树只看序）；②线性模型/神经网络用 z-score，但先 winsorize（§17.2）；③数据明显有异常值时用 robust scaler（sklearn.preprocessing.RobustScaler 或手写 (x-median)/IQR）。

24.2 分位数分箱：把连续特征变类别

把连续特征按分位数切桶（等频分箱），每桶样本数相同。实测（numpy 2.4.3）：60 个样本按 25/50/75 分位数切 4 桶，各桶 [15, 15, 15, 15] 个样本——等频分箱保证每桶样本均衡，避免等宽分箱在偏态数据上"大部分样本挤第一桶"。分箱的价值：①线性模型的非线性表达（桶内 one-hot）；②抗异常值（极端值落最后一桶，不主导）；③可解释（"第 4 桶用户转化率 12%"）。规则：分箱边界只用训练集算，验证/测试集沿用训练边界（防止数据泄漏）；分位数用 np.percentile(x, [25,50,75]) 计算后存成常量。

24.3 滚动统计特征：均值 vs 中位数

时间序列特征常用"过去 7 天均值"，但异常值场景用滚动中位数更稳。实测（numpy 2.4.3）：60 个 normal(100,5) 样本、第 30 个塞 500 的异常值，含异常值的 5 窗口滚动均值是 182.4、滚动中位数是 105.0——异常值把均值拉高 74%，中位数只涨 5%。规则：延迟/金额/时长这类重尾特征的滚动窗口用中位数；计数/比率类特征用均值（异常值少）。窗口大小 ≥5 时中位数才有意义（<5 时中位数=某个真实值，噪声大）。

import numpy as np

def feature_gate(X, name="features"):
    assert np.isfinite(X).all(), f"{name}: 有 NaN/inf"        # 数值有效性
    assert X.std(axis=0).min() > 1e-6, f"{name}: 有常量列"      # 常量列检查
    c = np.corrcoef(X.T)
    np.fill_diagonal(c, 0.0)
    assert np.abs(c).max() < 0.99, f"{name}: 有近似共线列"      # 共线性检查
    print(f"{name} gate passed: shape={X.shape} max|corr|={np.abs(c).max():.3f}")

rng = np.random.default_rng(0)
X = rng.normal(size=(200, 5))
X[:, 4] = X[:, 0] * 0.5 + rng.normal(scale=0.05, size=200)   # 与第 0 列强相关
try:
    feature_gate(X)
except AssertionError as e:
    print("被拦下:", e)   # 实跑：被拦下: features: 有近似共线列

四道断言对应四类静默事故：NaN 流进模型（预测变 NaN）、常量列白占维度、共线列让线性模型系数爆炸（《线性代数白话》§3.3 的病态矩阵）。实跑输出：构造的第 4 列与第 0 列相关约 0.98，max|corr| 超 0.99 阈值被拦下——特征流水线就该这样"不合格不放行"，和 §7 的 merge 断言、§5 的 assert notna 是同一套纪律。

26.1 异常值诊断的两种 z-score

z-score（(x-mean)/std）和稳健 z-score（(x-median)/(1.4826·MAD)）在污染数据上结论相反。实测（numpy 2.4.3）：[10.1, 9.8, 10.3, 10.0, 9.9, 10.2, 25.0]（含一个 25 的异常值），普通 z-score 的最大 |z|=2.267，2.5 阈值下不报警（异常值把 mean/std 撑大，自己"伪装"正常）；稳健 z-score 的异常值 |z|=50.25，其他点都在 1.1 以下，准确揪出 1 个异常值。这是 §6（统计直觉）"异常值污染统计量"的又一实测证据。巡检规则：异常值检测一律用稳健 z-score 或 IQR 规则，普通 z-score 只在数据已知干净时用。

26.2 小样本非参数检验：精确 vs 渐近 p 值

stats.mannwhitneyu 的 method="exact" 在小样本给出精确 p 值，不依赖正态近似。实测（scipy 1.18.1）：a=[1,2,3,4,5] vs b=[6,7,8]（完全分离），精确 p=0.0357、渐近 p 也是 0.0357（n 小且完全分离时两者巧合一致）；但样本有并列值或 n 更小时两者会分叉，规则：n₁·n₂ < 400 且无大量并列时用 method="exact"。这是《L0-统计直觉》§5.2"小样本别用正态近似"的 scipy 落地。

28. 回归诊断：残差、杠杆值、强影响点（附实测）

3

回归模型的"数据问题"藏在残差里，不看残差就上线等于闭眼开车。三个诊断工具，实测于 numpy 2.4.3 / scipy 1.18.1。

28.1 残差图的三种读法

残差 = 实际值 - 预测值，画"残差 vs 预测值"散点图看三件事：①随机散布 = 模型没问题；②漏斗形（喇叭口）= 异方差（方差随预测值变化），修复加权最小二乘或对 y 取对数；③曲线形 = 漏了非线性项，加多项式特征或换模型。残差的均值必须 ≈0（OLS 的性质），残差均值显著 ≠0 说明漏了截距或有系统偏差。

28.2 杠杆值（Leverage）：帽子矩阵的对角线

H = X(XᵀX)⁻¹Xᵀ 是帽子矩阵（把 y "戴"到预测值上），对角线 hᵢ 是第 i 个样本的杠杆值，衡量"这个 x 离群会不会拉走拟合面"。实测（numpy 2.4.3）：20 个样本、1 个截距 + 1 个特征的回归，杠杆值均值 0.100（= p/n = 2/20）、最大 0.309、总和 2.000（= p，恒等式）。杠杆值 > 2p/n 的样本是高杠杆点（远离其他 x 的样本），本身不一定是错误点，但会主导拟合——比如"只有一个超高收入用户"会把收入回归线整个拉歪。

28.3 Cook 距离：杠杆 × 残差 = 影响力

杠杆值只看 x 的位置，残差只看 y 的偏差，Cook 距离把两者结合：Dᵢ = (残差ᵢ²·hᵢ)/(p·MSE·(1-hᵢ)²)，衡量"删掉第 i 个样本后拟合变化多大"。判据（经验值，待验证）：D > 4/n 值得查、D > 1 是强影响点必须查。实测逻辑（numpy 2.4.3）：20 样本的回归里 4/n = 0.2，任何 Cook 距离超 0.2 的样本都要人查——是数据录入错误就删，是有意义的极端个案就保留但报告注明。诊断流程：残差图看形状 → 杠杆值找高杠杆 → Cook 距离定强影响点 → 逐个决策（删/留/单独建模）。

import numpy as np

rng = np.random.default_rng(3)
X = np.c_[np.ones(20), rng.normal(size=20)]           # 截距 + 1 特征
H = X @ np.linalg.inv(X.T @ X) @ X.T                  # 帽子矩阵
lev = np.diag(H)
print("杠杆值 均值/最大/总和:", round(float(lev.mean()), 3),
      round(float(lev.max()), 3), round(float(lev.sum()), 3))
# 实跑：0.1 0.309 2.0   （均值=p/n=2/20，总和=p=2 恒等式）
print("高杠杆阈值 2p/n =", 2 * X.shape[1] / len(X))   # 0.2
