数据可视化体系（四）：从业务问题到可交付图表

WHY

2

1. 为什么可视化必须从业务问题走向可复核交付

3

可视化项目的成果不是“成功画出一张图”，而是读者能够准确理解数据、复核指标，并据此做出合理判断。完整流程包含问题定义、数据契约、清洗、聚合、图型选择、视觉编码、文字解释和交付核验。任何一步发生偏差，都可能得到技术上能运行、业务上却误导的结果。例如，取消订单混入销售额，会让促销日表现虚高；把金额缺失填零，会制造不存在的低客单价；只展示总额而忽略工作日数量，会把月份天数差异解释为增长。

本篇提供图型选择决策、配色与可访问性规范，并实现一个完全离线、可复现的销售分析案例。示例使用 NumPy 生成模拟交易，使用 Pandas 清洗和聚合，再用 Matplotlib 与 Seaborn 绘图。模拟数据便于学习处理方法，但案例结论不能当成真实企业的经营证据。正式项目应替换数据来源，同时保留口径、校验和解释流程。

如果只学习绘图接口而跳过分析契约与交付核验，图表越精美，错误口径反而越容易传播。因此，本篇先明确“算什么、何时用什么图”，再给出可以照做、可以核对、可以复现的完整实施链路。

WHAT / WHYT

2

2. 先定义分析契约

3

从问题到可计算指标

在写绘图代码前先写一句完整的问题：“在同一统计期间内，哪些渠道的已完成订单净销售额更高，变化来自订单数量还是客单价？”这句话限定了时间范围、订单状态、分析维度和解释方向。接着定义观察单位是一张订单，销售额是数量乘单价再减折扣后的金额。若一张订单有多行商品明细，必须先明确按订单聚合，避免订单量被明细行数放大。

契约项 本案例定义 正式项目需补充
观察单位 每行一张订单 多行订单的去重与归并规则
时间口径 订单创建日期，按自然月 时区、结算时间、迟到数据
销售额 数量乘单价乘一减折扣 税费、退款、汇率和收入确认
有效订单 状态为 completed 部分退款与取消的处理方式
客单价 销售额除有效订单数 订单编号是否跨系统重复
缺失类别 保留为 Unknown 追溯来源并评估偏差

指标命名应包含必要单位。图上写“销售额”时，纵轴还要注明元、万元或其他币种。百分数需要说明分母，是全部订单、有效订单，还是某个渠道内部订单。涉及同比或环比时，比较区间应具有相近的覆盖程度，未结束月份不能直接与完整月份比较。

flowchart TD
    A[提出业务问题] --> B[声明观察单位]
    B --> C[定义有效数据范围]
    C --> D[明确指标公式与单位]
    D --> E[清洗并记录剔除原因]
    E --> F[聚合并校验总量]
    F --> G[选择图型与配色]
    G --> H[写出证据支持的解读]
    H --> I[导出复核与归档]

3. 图型选择决策树

3

先看数据类型，再看分析目的

同一组数值可以画成直方图、折线图或箱线图，但这些图回答不同的问题。时间序列关心顺序和变化，分布图关心集中程度和尾部，分类图关心组间差异。图型选择应由问题决定，不能因为某种图好看就把数据硬套进去。

flowchart TD
    A[数据类型与任务] --> B{是否有时间顺序}
    B -->|有，观察趋势| C[折线图或面积图]
    B -->|无或不关注时间| D{比较对象是什么}
    D -->|类别与数值| E[条形图或点图]
    D -->|单个连续变量| F[直方图或密度图]
    D -->|多个组的分布| G[箱线图或小提琴图]
    D -->|两个连续变量| H[散点图]
    D -->|二维网格| I[热力图]
    D -->|部分与整体| J[百分比堆叠条形图]
    H --> K{点是否严重重叠}
    K -->|是| L[透明度 抽样或六边形分箱]
    K -->|否| M[增加类别形状或趋势线]
输入类型 主要问题 推荐图型 常见误用
时间加数值 趋势、季节性、突变 折线图 时间未排序就连接
类别加汇总值 排名、差距 水平条形图 类别太多仍用饼图
连续数值 偏态、集中、长尾 直方图、密度图 不报告分箱规则
类别加原始数值 分布差异 箱线图、散点叠加 只用均值柱状图隐藏差异
两个连续数值 关联与离群 散点图 把相关性写成因果关系
两个类别加数值 二维强弱结构 热力图 多张图使用不同色域却直接比较
类别占比 组成变化 百分比堆叠条形图 混用不同分母

饼图并非绝对不能用，但类别应少，比例差异明显，且总和确实代表完整整体。精确比较细小差异时，条形图更容易读数。三维柱状图通常会引入遮挡和透视失真，业务报告中优先使用二维表达。双轴图需要特别谨慎，因为改变两个轴的范围就可能让无关曲线看起来同步；优先考虑上下对齐的两个子图。

4. 配色体系与可访问性

3

三种颜色语义

定性色用于无序类别，例如渠道和地区；顺序色用于从小到大的数量，例如销售额；发散色用于存在有意义中点的数值，例如相对预算的正负偏差。不能用随机彩虹色带表达连续金额，因为视觉明暗不一定与数值大小对应。对于相关系数，固定范围为负一到一并把零设为中心，读者才能在不同图之间比较。

语义 示例配色 适用对象 约束
定性 colorblind 或固定字典 渠道、产品、地区 同类跨图保持同色
顺序 viridis、YlGnBu 销售规模、频次 高低关系对应明确明暗变化
发散 RdBu_r、vlag 盈亏、偏差、相关性 必须明确中点与两端范围
强调 灰色背景加单个强调色 异常月份、重点渠道 强调必须对应分析目的

可访问性不能只依赖“选择色盲友好调色板”。折线图应增加点形、线型或直接标签；柱状图可以标注关键数值；热力图应保留颜色条和单位。图表在黑白打印时也要能够区分类别。文本与背景要有足够对比，不能把浅灰小字放在白底上，再认为它只是辅助信息。图例的含义应该可以通过文字完整理解，而不是写成“红色部分表现较好”。

flowchart LR
    A[识别字段语义] --> B{类别还是连续数值}
    B -->|类别| C[稳定的定性颜色字典]
    B -->|连续且有中点| D[发散色带并固定中心]
    B -->|连续无中点| E[顺序色带]
    C --> F[增加形状线型和直接标签]
    D --> F
    E --> F
    F --> G[灰度检查与目标尺寸检查]

5. 运行配色示例：让颜色与形状共同编码

import numpy as np
import pandas as pd
import seaborn as sns
import matplotlib.pyplot as plt

data = pd.DataFrame({"month": np.tile(np.arange(1, 7), 2),
                     "channel": np.repeat(["Online", "Store"], 6),
                     "revenue": [80, 92, 89, 110, 120, 124,
                                 75, 78, 84, 83, 92, 98]})
palette = {"Online": "#0072B2", "Store": "#D55E00"}
fig, axis = plt.subplots(figsize=(7, 4))
sns.lineplot(data=data, x="month", y="revenue", hue="channel",
             style="channel", markers=True, dashes=True,
             palette=palette, estimator=None, ax=axis)
axis.set(xlabel="Month", ylabel="Revenue (thousand)")
fig.tight_layout()
plt.show()

这段示例通过颜色与形状同时标识渠道，因此即使读者无法分辨两种颜色，也可以利用标记读取曲线。正式项目把颜色字典放在统一配置位置，避免不同分析人员各自为同一渠道分配颜色。

6. 销售分析完整案例

3

第一步：生成数据并引入可追踪的质量问题

下面代码是一个完整脚本。保存运行后会在 sales_visualization_output 中生成清洗数据、指标表和三种格式的分析图。代码不依赖网络，随机种子固定，图中使用英文标签以便在没有中文字体的机器上运行。正文解释采用中文，正式中文报告可按目标环境安装并配置字体。

from pathlib import Path
import json
import numpy as np
import pandas as pd
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
import seaborn as sns

rng = np.random.default_rng(20261029)
order_count = 1200
orders = pd.DataFrame({
    "order_id": [f"ORD-{index:05d}" for index in range(order_count)],
    "order_date": pd.Timestamp("2026-01-01") + pd.to_timedelta(
        rng.integers(0, 181, order_count), unit="D"),
    "region": rng.choice(["East", "West", "North", "South"], order_count),
    "channel": rng.choice(["Online", "Store"], order_count, p=[0.6, 0.4]),
    "quantity": rng.integers(1, 8, order_count),
    "unit_price": np.round(rng.lognormal(4.2, 0.4, order_count), 2),
    "discount": rng.choice([0.0, 0.05, 0.10, 0.15], order_count),
    "status": rng.choice(["completed", "cancelled"], order_count, p=[0.94, 0.06]),
})
orders.loc[5, "region"] = None
orders.loc[12, "unit_price"] = np.nan
orders.loc[20, "quantity"] = -1
raw = pd.concat([orders, orders.iloc[[3, 8]]], ignore_index=True)

# 第二步：清洗，并以订单编号作为唯一性边界。
duplicate_count = int(raw.duplicated("order_id").sum())
clean = raw.drop_duplicates("order_id", keep="first").copy()
clean["order_date"] = pd.to_datetime(clean["order_date"], errors="coerce")
for column in ["quantity", "unit_price", "discount"]:
    clean[column] = pd.to_numeric(clean[column], errors="coerce")
clean["region"] = clean["region"].fillna("Unknown")
valid_mask = (
    clean["order_date"].notna()
    & clean["quantity"].gt(0)
    & clean["unit_price"].gt(0)
    & clean["discount"].between(0, 1)
)
invalid_count = int((~valid_mask).sum())
valid = clean.loc[valid_mask].copy()
completed = valid.loc[valid["status"].eq("completed")].copy()
completed["net_sales"] = (
    completed["quantity"] * completed["unit_price"]
    * (1 - completed["discount"])
).round(2)
completed["month"] = completed["order_date"].dt.to_period("M").astype(str)

# 第三步：生成业务聚合，并保留分母。
monthly = completed.groupby("month", as_index=False).agg(
    sales=("net_sales", "sum"), orders=("order_id", "nunique")
)
monthly["average_order_value"] = monthly["sales"] / monthly["orders"]
region = completed.groupby("region", as_index=False).agg(
    sales=("net_sales", "sum"), orders=("order_id", "nunique")
).sort_values("sales", ascending=False)
month_order = pd.period_range("2026-01", "2026-06", freq="M").astype(str)
region_order = ["East", "West", "North", "South", "Unknown"]
matrix = completed.pivot_table(index="region", columns="month",
                                values="net_sales", aggfunc="sum")
matrix = matrix.reindex(index=region_order, columns=month_order)
assert completed["order_id"].is_unique
assert np.isclose(monthly["sales"].sum(), completed["net_sales"].sum())
assert np.isclose(region["sales"].sum(), completed["net_sales"].sum())
assert monthly["orders"].sum() == len(completed)

# 第四步：四张图分别回答趋势、排名、分布与结构问题。
sns.set_theme(style="whitegrid", context="notebook")
palette = {"Online": "#0072B2", "Store": "#D55E00"}
fig, axes = plt.subplots(2, 2, figsize=(14, 10), layout="constrained")
sns.lineplot(data=monthly, x="month", y="sales", marker="o",
             estimator=None, color="#0072B2", ax=axes[0, 0])
axes[0, 0].set(title="Monthly net sales", xlabel="Month", ylabel="Sales (CNY)")
axes[0, 0].tick_params(axis="x", rotation=30)
sns.barplot(data=region, x="sales", y="region", color="#009E73",
            errorbar=None, ax=axes[0, 1])
axes[0, 1].set(title="Regional ranking", xlabel="Sales (CNY)", ylabel="Region")
sns.boxplot(data=completed, x="channel", y="net_sales", hue="channel",
            palette=palette, legend=False, ax=axes[1, 0])
axes[1, 0].set(title="Order value distribution", xlabel="Channel",
               ylabel="Order net sales (CNY)")
sns.heatmap(matrix, mask=matrix.isna(), cmap="YlGnBu", annot=True,
            fmt=".0f", cbar_kws={"label": "Sales (CNY)"}, ax=axes[1, 1])
axes[1, 1].set(title="Region and month", xlabel="Month", ylabel="Region")
fig.suptitle("Sales review: completed orders, January–June 2026", fontsize=16)

# 第五步：保存数据、证据和图形，关闭画布。
output = Path("sales_visualization_output")
output.mkdir(exist_ok=True)
completed.to_csv(output / "clean_completed_orders.csv", index=False)
monthly.to_csv(output / "monthly_metrics.csv", index=False)
region.to_csv(output / "regional_metrics.csv", index=False)
audit = {
    "raw_rows": len(raw),
    "duplicate_rows_removed": duplicate_count,
    "invalid_rows_removed": invalid_count,
    "valid_noncompleted_rows": len(valid) - len(completed),
    "completed_orders": len(completed),
    "net_sales_cny": round(float(completed["net_sales"].sum()), 2),
    "amount_rounding": "round each order to 2 decimals, then sum",
}
(output / "audit.json").write_text(
    json.dumps(audit, ensure_ascii=False, indent=2), encoding="utf-8")
for extension in ["png", "svg", "pdf"]:
    fig.savefig(output / f"sales_dashboard.{extension}", dpi=180,
                bbox_inches="tight", facecolor="white")
plt.close(fig)
print(monthly.round(2).to_string(index=False))
print(json.dumps(audit, ensure_ascii=False, indent=2))

第二步的关键解释：不要让清洗规则偷偷改变业务

示例把完全重复的订单编号保留第一条，仅适合这里明确构造的重复副本。真实业务中，同一订单编号可能对应状态更新、支付分次或不同商品明细，因此必须先比较冲突字段，再根据更新时间和业务规则确定保留记录。直接执行 drop_duplicates 可能丢失有效退款或修订信息。

金额缺失和负数量被记录为无效后排除，地区缺失则保留在未知类别中。两种处理的理由不同：没有金额无法可靠计算销售额，而地区未知不影响该订单的销售额总量。不能为了让图形看起来整齐就把未知地区整行删除，否则总额和渠道分析也会受到影响。若无效比例很高，应停止业务解读并修复数据来源。

代码按每张订单保留两位小数后汇总，这是明确的教学口径。实际财务系统可能使用整数分或十进制定点数，以避免浮点计算的舍入差异。正式对账应采用业务账本一致的金额类型和舍入顺序，不能仅凭 np.isclose 就认定财务核对完成。

第三步的关键解释：总额、订单量和客单价一起看

销售额上升可能来自订单数量增加，也可能来自客单价提高。月度表同时保存三个指标，便于用“销售额等于订单量乘客单价”进行拆解。比较渠道时也应报告有效订单数，因为大量低金额订单和少量高金额订单可能产生相近总额，但运营策略完全不同。

热力图保留没有观测记录的空白，不自动把它填成零。这里不知道某地区某月是否营业完整，也没有覆盖日历表，因此不能声称缺失就是零销售。正式项目应结合门店营业日历、渠道上线日期和数据采集状态，只有确认完整覆盖且没有交易时才能填零。

第四步的关键解释：如何写可靠结论

趋势图首先描述哪几个月较高或较低，然后结合月度表区分订单数与客单价的贡献。地区排名只能说明本期有效订单的销售规模，不能直接说明地区经营效率，因为人口、门店数、投入和营业天数尚未控制。箱线图描述订单金额分布，不能把较高的箱体自动解释为利润更高，因为案例没有成本字段。

每条解读建议使用“观察事实、支持指标、解释边界、下一步核查”的结构。例如：某渠道订单金额中位数较高，箱线图与分位数表支持这一观察；但渠道客户构成可能不同，应进一步按客户类型或产品组合比较。不要编造促销、季节、天气等数据中没有的信息。示例中的随机波动尤其不能写成真实经营规律。

7. 最佳实践清单

3

数据与统计检查

  • 写明时间范围、时区、观察单位、过滤规则和指标公式，并记录数据提取时间。
  • 核验唯一键、缺失值、类型、异常范围及分组样本量，保留清洗数量与原因。
  • 保证汇总表与原始有效数据的总量一致，核对占比总和与百分比的分母。
  • 对分箱数量、异常值处理和尺度选择做敏感性检查，避免结论依赖单个参数。
  • 区分置信区间、标准差和预测区间；时间序列与重复测量不能随意当作独立样本。

视觉与文字检查

  • 柱状图一般从零开始，若截断坐标轴必须显著说明；折线图可按任务调整范围，但不能隐藏范围变化。
  • 同一个维度保持顺序、颜色和单位一致，多图比较时固定有意义的色域和坐标尺度。
  • 标题说明对象与期间，轴标签说明单位，图注交代过滤规则及缺失处理。
  • 保留必要上下文，避免装饰遮挡数据，减少没有分析作用的网格、阴影和三维效果。
  • 在实际导出尺寸下检查字号、图例、文字裁切和颜色区分，不只在交互窗口检查。

可复现与交付检查

项目应保留依赖版本、随机种子、输入快照标识、运行脚本、指标表和导出文件。图形生成与数据清洗尽量放在同一个可执行流程中，避免手工修改表格后忘记重新绘图。若报告需要长期更新，应把颜色、类别排序和指标公式集中管理，并在数据字段变化时给出清晰失败信息。

8. 常见错误与排错

3
症状 常见原因 排查与处理
中文显示为方框 缺少字体或字体名错误 列出本机字体，选择实际存在且许可合适的中文字体
保存的图是空白 保存时引用错误画布或已关闭 用创建时保存的 fig 导出，保存后再关闭
折线回折或顺序异常 日期是字符串或数据未排序 先转日期，再按时间排序；检查重复时间点
柱状图数值与总额不一致 默认均值聚合与业务求和不同 先在 Pandas 明确聚合，再关闭不需要的估计行为
同一渠道颜色变化 每张图自行分配颜色 使用固定颜色字典和类别顺序
密度曲线出现负金额 核平滑越过自然边界 设置 cut=0，必要时改直方图并说明边界偏差
热力图空白或全零 透视字段错误或误填缺失 检查透视前行数、矩阵类型、缺失与零的语义
文件很大或批处理内存增长 点太多、分辨率过高、画布未关闭 使用合理抽样或聚合，保存后关闭画布
SVG 中字体与本机不同 阅读环境没有对应字体 按交付要求选择文字转路径或提供允许分发的字体
对数轴报错或缺点 数据含零或负值 检查业务含义，不能为画图随意加常数

排错应该先检查输入数据和口径，再检查绘图参数。若某地区销售额突然变为零，先确认数据采集和筛选条件，而不是立即更换色带。若代码升级后出现警告，阅读对应版本的官方迁移说明，确认默认统计方式是否改变。屏蔽警告不能替代修复，也不应在教程中把弃用接口继续包装成推荐用法。

9. 交付复核小结

3

可视化体系的价值在于建立可复核的分析链路。图型选择围绕问题与数据类型，配色服务于语义和可访问性，代码明确清洗与聚合口径，文字只陈述数据能够支持的结论。销售案例展示了从模拟原始交易到审计记录、指标表和多格式图形的完整流程。把这些步骤固化后，每次更新都能减少人为漂移，让读者同时获得清晰图形和可信依据。
