Python 核心编程：从容器与函数到可测试模块

本文合并「Python 基础语法、数据结构、函数与模块、OOP 与爬虫」。学习主线不是语法清单，而是把外部 JSON 记录变成有校验、可组合、可测试的程序。爬虫保留为受控 I/O 应用，不用绕过反爬或访问控制来制造案例。

验证边界：JSONL 处理器与 unittest 示例使用标准库，已离线实跑；联网抓取示例未实跑。代码以 Python 3.11+ 语法编写，执行时应在隔离项目环境中运行。

WHY

2

1. 只会语法，为什么仍做不了 AI 应用

3

模型 API、RAG 与数据处理都反复出现相同结构：请求和响应是嵌套字典，文档是列表，批次需要迭代，异常需要定位，多个阶段需要拆成函数与模块。若只会在交互窗口写几行，面对真实数据常出现：键不存在导致 KeyError、字符串数字未转换、整批数据一次读入内存、异常被 except Exception: pass 吞掉、所有代码挤在一个文件无法测试。

后果不是「代码不够漂亮」，而是数据错、错误不可见、修改不可回归。AI 生成代码可以加快初稿，却不能替代输入契约、依赖边界和测试。学习者需要先能手写并解释最小版本，再使用框架和生成工具。

2. 为什么把 OOP、生成器、装饰器和爬虫放在一篇

3

它们分别解决同一程序的不同问题：数据类固定记录形状，生成器控制数据流，装饰器复用横切行为，爬虫提供真实外部输入。拆成四篇会重复语法，也容易让人误以为学会类就等于学会工程。这里的收敛原则是：先用内置容器和函数解决问题；需要不变量与行为封装时才建类；需要流式处理时用生成器；需要复用前后逻辑时用装饰器。

WHAT / WHYT

2

3. 数据结构按访问语义选择

3
类型 是否可变 典型访问 何时用 何时不用
list 可变 位置、顺序遍历 有序记录、可追加批次 大量成员存在性检查
tuple 不可变 位置、解包 固定形状返回值、字典键的组成部分 需要原地增删的记录集
dict 可变 键查找 JSON 对象、按 ID 索引 键语义不清、随意堆全局状态
set 可变 成员、交并差 去重、权限/标签集合 需要顺序和重复计数
生成器 有状态迭代 顺序消费 大文件逐行、惰性变换 需要反复随机访问同一结果

「不可变」要区分对象和容器：元组本身不可改，但元组中的列表仍可改。字典推导式不是自动的数据校验；外部输入必须显式检查类型、必填键和允许值。

4. 函数、模块、类和异常的边界

3
  • 函数封装一个明确变换，优先输入→输出，避免隐式修改无关全局状态。默认参数不要写成可变对象，用 None 再在函数内创建。
  • 模块组织稳定职责，例如 models.py 管记录、io.py 管读写、report.py 管聚合；不是按「utils」堆积所有函数。
  • 类把数据和不变量放在一起。优先组合已有类，只有确实存在「是一种」且能遵守父类契约时才继承。
  • dataclass减少记录类样板，不等于业务校验自动完成；__post_init__ 或工厂方法仍需验证。
  • 异常用于无法在当前层正常完成的情况。捕获范围要具体到可处理类型，并保留行号、操作与原因；不要把所有异常转成成功。
  • 迭代器/生成器一次提供一个元素，节省的是不必同时持有全部结果，不会让 CPU 运算本身更快。
  • 装饰器包装函数并复用日志、重试、缓存等逻辑；用 functools.wraps 保留原函数元数据。重试只适合可重试失败，且要考虑幂等与退避。

5. 论文怎么说，我们怎么用

3

WEAVE（arXiv:2610.22039）指出真实软件修改往往跨文件、跨 PR、带依赖关系，并构造 200 个需要协调修改的任务，强调测试验证与依赖结构。论文研究的是仓库级 Agent 评估，不是「学了模块就能完成任意 PR」的证据。

我们的落点是：练习不能只问「写一个函数」，还要给一个小仓库，要求按依赖顺序改记录模型、解析器和报告，并让测试保持可复跑。模块边界应由变化原因决定，测试应覆盖公共契约，而不是为了堆文件数量。

6. 一个可测试的 JSONL 处理器

3

目录结构如下；练习文件在测试后可直接删除，不属于 wiki 正文副本：

jsonl_demo/
├── processor.py
└── test_processor.py

processor.py（已实跑）：

from __future__ import annotations

from dataclasses import dataclass
from functools import wraps
import json
from pathlib import Path
from typing import Callable, Iterable, Iterator, TypeVar

T = TypeVar("T")


def traced(func: Callable[..., T]) -> Callable[..., T]:
    """最小装饰器：不吞异常，不重试非幂等操作。"""
    @wraps(func)
    def wrapper(*args, **kwargs):
        print(f"call {func.__name__}")
        return func(*args, **kwargs)
    return wrapper


@dataclass(frozen=True)
class Record:
    doc_id: str
    score: float
    tags: tuple[str, ...] = ()

    @classmethod
    def from_dict(cls, raw: dict) -> "Record":
        if not isinstance(raw.get("doc_id"), str) or not raw["doc_id"]:
            raise ValueError("doc_id 必须是非空字符串")
        score = float(raw["score"])
        if not 0.0 <= score <= 1.0:
            raise ValueError("score 必须在 [0, 1]")
        tags = tuple(raw.get("tags", ()))
        if not all(isinstance(tag, str) for tag in tags):
            raise ValueError("tags 必须全部是字符串")
        return cls(raw["doc_id"], score, tags)


def iter_records(path: Path) -> Iterator[Record]:
    """逐行读取；坏行报出行号，不让整批静默缺数据。"""
    with path.open(encoding="utf-8") as handle:
        for line_no, line in enumerate(handle, 1):
            if not line.strip():
                continue
            try:
                raw = json.loads(line)
                yield Record.from_dict(raw)
            except (json.JSONDecodeError, KeyError, TypeError, ValueError) as exc:
                raise ValueError(f"{path}:{line_no}: {exc}") from exc


@traced
def summarize(records: Iterable[Record]) -> dict[str, float | int]:
    rows = list(records)
    if not rows:
        raise ValueError("没有可汇总记录")
    return {
        "count": len(rows),
        "mean_score": sum(row.score for row in rows) / len(rows),
        "tag_count": len({tag for row in rows for tag in row.tags}),
    }

这里有意不在读取函数中「跳过坏行继续」：教学批处理宁可明确失败。真实项目若要隔离坏行，应返回结构化错误清单并限制错误比例，不能直接忽略。

7. 测试正常、边界和故障注入

3

test_processor.py（已实跑）：

import json
from pathlib import Path
import tempfile
import unittest

from processor import Record, iter_records, summarize


class ProcessorTest(unittest.TestCase):
    def write_rows(self, directory: str, rows: list[str]) -> Path:
        path = Path(directory) / "records.jsonl"
        path.write_text("\n".join(rows), encoding="utf-8")
        return path

    def test_summary(self) -> None:
        with tempfile.TemporaryDirectory() as directory:
            path = self.write_rows(directory, [
                json.dumps({"doc_id": "a", "score": 0.5, "tags": ["x"]}),
                json.dumps({"doc_id": "b", "score": 1.0, "tags": ["x", "y"]}),
            ])
            result = summarize(iter_records(path))
        self.assertEqual(result["count"], 2)
        self.assertAlmostEqual(result["mean_score"], 0.75)
        self.assertEqual(result["tag_count"], 2)

    def test_reject_out_of_range_score(self) -> None:
        with self.assertRaisesRegex(ValueError, "score"):
            Record.from_dict({"doc_id": "bad", "score": 1.2})

    def test_bad_json_reports_line(self) -> None:
        with tempfile.TemporaryDirectory() as directory:
            path = self.write_rows(directory, ['{"doc_id":"a","score":0.5}', '{bad'])
            iterator = iter_records(path)
            self.assertEqual(next(iterator).doc_id, "a")
            with self.assertRaisesRegex(ValueError, "records.jsonl:2"):
                next(iterator)


if __name__ == "__main__":
    unittest.main()

在 jsonl_demo 目录执行（已实跑）：

python -m unittest -v

验收包含三个层次：正常路径数值正确；越界输入被拒绝；第二行坏 JSON 明确报行号。只验证「脚本退出码为 0」无法发现错误数据被静默吞掉。

8. 从脚本扩展为模块，而不是一次性重写

3
  1. 保持公共函数签名不变，先把 Record 移到 models.py，把读取移到 io.py，汇总移到 report.py。
  2. 每一步运行同一组测试；若改 import 后失败，先修依赖方向，不增加全局变量。
  3. 新功能先加失败测试，例如重复 doc_id 是否拒绝、空文件是否允许、score 为 NaN 是否拒绝。
  4. 若增加磁盘写入，区分可重试读取与不可盲目重试的写入，并记录幂等键。
  5. 引入第三方框架前，保留这个小核心作为无框架基准。

注意：当前 float("nan") 能通过 0.0 <= score <= 1.0 之外的比较陷阱——实际上 NaN 的比较为 False，因此上述范围检查会拒绝 NaN；但 float("inf") 等边界仍应加入显式测试。不要把这段说明当测试替代，新增用例后再确认。

9. 受控网页读取：超时、编码、许可与最小解析

3

仅对允许抓取的公开页面使用 GET；先看 robots.txt、站点条款和版权要求，不绕过登录、验证码、频控或访问控制。以下标准库示例未实跑，仅抓取调用者明确提供的公开 URL，不上传本地内容：

from html.parser import HTMLParser
from urllib.request import Request, urlopen


class TitleParser(HTMLParser):
    def __init__(self) -> None:
        super().__init__()
        self.in_title = False
        self.parts: list[str] = []

    def handle_starttag(self, tag: str, attrs) -> None:
        self.in_title = tag == "title"

    def handle_endtag(self, tag: str) -> None:
        if tag == "title":
            self.in_title = False

    def handle_data(self, data: str) -> None:
        if self.in_title:
            self.parts.append(data)


def read_title(url: str) -> str:
    if not url.startswith("https://"):
        raise ValueError("练习仅允许明确的 HTTPS 公开 URL")
    request = Request(url, headers={"User-Agent": "L0-learning/1.0"})
    with urlopen(request, timeout=15) as response:  # nosec: URL 由调用者按许可提供
        content_type = response.headers.get_content_type()
        if content_type != "text/html":
            raise ValueError(f"不是 HTML：{content_type}")
        charset = response.headers.get_content_charset() or "utf-8"
        html = response.read(1_000_001).decode(charset, errors="replace")
    if len(html.encode(charset, errors="replace")) > 1_000_000:
        raise ValueError("页面超过练习上限")
    parser = TitleParser()
    parser.feed(html)
    return "".join(parser.parts).strip()

生产爬虫还需限制重定向目标、防 SSRF、按域名限速、缓存条件请求、重试退避、结构化日志与停止条件；这个入门函数不是完整采集框架。不要因为它能读取标题，就把任意内网 URL 交给它。

本库真实落地（源码核对，2026-11-04）

  • 本库把「Python 核心能力」用得最密的一处是配置合并：三层优先级用一次递归 merge 落地（rag/query.py L72 _deep_merge，docstring 写明「配置优先级: config.yaml < 环境变量(RAG_*) < 命令行参数」）：
    python def _deep_merge(base: dict, override: dict) -> dict:
    这是 dict/递归/可变对象的经典组合：嵌套 dict 递归覆盖，标量直接覆盖。学 Python 核心编程时最该练的就是这种「几行函数扛住一个业务规则」的写法。
  • 类型标注不是装饰：rag/query.py L1073 class RAGState(TypedDict) 把 11 个字段（question/route/documents/relevant_docs/answer/rewrite_count/best_dist…）定成 LangGraph 的状态契约，节点之间只靠这个 dict 通信。
    新增一个字段就要在 7 个节点里逐一处理，TypedDict 在这里的作用是「改一处就编译期全暴露」，比任何文档都管用。
  • 上下文管理器与锁（rag/ingest.py L1037 _ingest_lock，配 rag/.ingest.lock）：入库是长任务，本库用「文件锁 + contextlib.contextmanager」保证同一时刻只有一个 ingestion 写库，注释写死「锁文件必须保留，不能 unlink，否则等待者可能锁到不同 inode 而同时写库」（L36-37）。
    这条注释是 Python 文件锁最容易踩的坑，学到 with/fcntl 时值得逐字读一遍。
  • 和课件讲法的差异：课件练的是列表推导、闭包、装饰器玩具例子；本库核心编程知识的真考场在 I/O + 并发 + 契约（配置三层合并、文件锁、TypedDict 状态机）。学到「类与装饰器」一节后，建议直接读 rag/query.py L72-230 的 load_config()。
  • 本库暂无：没有 mypy/ty 的全量类型检查通过记录（rag/.prek.toml 配了 ty check，但没有提交通过报告），类型标注目前是「写给自己看」的约束，不是门禁。
