3.1 参数五形态与顺序

3

位置参数按顺序传 add(3, 5)；默认参数给缺省值 greet(name, greeting="你好")；关键字参数用名字传 profile(age=18, name="小明") 可乱序；可变位置参数 *args 收集成元组 total(1, 2, 3)；可变关键字参数 **kwargs 收集成字典。混合时顺序固定：位置参数 → 默认参数 → *args → **kwargs，写反 SyntaxError。默认参数陷阱：def f(lst=[]) 的默认列表在多次调用间共享（可变默认值只求值一次），改法 def f(lst=None): lst = lst if lst is not None else []。

本节重点
  • 提前返回（guard clause）比嵌套 if 清晰：函数开头 「if not data: return []」 直接挡掉边界情况，主体逻辑保持平铺
  • 返回值超过 3 个时改返回 dict 或 namedtuple，别让调用方记位置
3

return x 返回单值；return a, b 语法上返回元组，调用方 lo, hi = min_max(lst) 解包；不写 return 或 return 后无值返回 None。提前返回（guard clause）比嵌套 if 清晰：函数开头 if not data: return [] 直接挡掉边界情况，主体逻辑保持平铺。返回值超过 3 个时改返回 dict 或 namedtuple，别让调用方记位置。

4. 作用域、闭包与 lambda

2
4.1 LEGB 查找规则2 个重点▾ 点开看本节重点
本节重点
  • 名字查找顺序是 Local（函数内）→ Enclosing（外层函数）→ Global（模块级）→ Built-in（内置）
  • 函数内赋值默认建局部变量，要改全局必须 「global count」；嵌套函数要改外层变量用 「nonlocal」
3

名字查找顺序是 Local（函数内）→ Enclosing（外层函数）→ Global（模块级）→ Built-in（内置）。函数内赋值默认建局部变量，要改全局必须 global count；嵌套函数要改外层变量用 nonlocal。翻车现场：函数内读全局列表然后 lst.append(x) 没问题（改对象），但 lst = [] 就是建了同名局部变量，全局那个没动。判断信号：函数外打印变量发现没变。

4.2 闭包

3

闭包是"内层函数引用外层函数的变量并被返回"。make_multiplier(2) 返回的 multiplier 记住了 n=2，调用 double(5) 得 10。闭包的价值是"记住状态"，是装饰器和工厂函数的基础。翻车点：闭包里修改外层变量要用 nonlocal，直接赋值会 UnboundLocalError。

4.3 lambda1 个重点▾ 点开看本节重点
本节重点
  • 限制是只能写一个表达式（不能写语句、不能有注释），超过一行就该改用 「def」
3

lambda 是单表达式匿名函数 lambda x: x ** 2，常用在 sort(key=lambda s: s[1])、map(lambda x: x*2, lst)、filter(lambda x: x > 0, lst)。限制是只能写一个表达式（不能写语句、不能有注释），超过一行就该改用 def。反例是拿 lambda 写三元嵌套，可读性比 def 差。

5. 装饰器：不改原函数加功能

2
5.1 最简装饰器1 个重点▾ 点开看本节重点
本节重点
  • print("🎉 函数执行前")
3

装饰器是"接收函数、返回新函数"的高阶函数，@my_decorator 是语法糖，等价于 say_hello = my_decorator(say_hello)。

def my_decorator(func):
    def wrapper():
        print("🎉 函数执行前")
        func()
        print("✅ 函数执行后")
    return wrapper

@my_decorator
def say_hello():
    print("你好，世界！")

say_hello()

5.2 带参数的函数用 args/*kwargs

3

被装饰函数有参数时，wrapper 用 *args, **kwargs 原封不动转发：

import time
def timer(func):
    """计时装饰器"""
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)     # 原样传参
        print(f"⏱️ {func.__name__} 耗时 {time.perf_counter()-start:.4f}s")
        return result                       # 原样返回
    return wrapper

@timer
def calculate_sum(n: int) -> int:
    return sum(range(1, n + 1))

calculate_sum(1_000_000)
5.3 保留原函数信息：functools.wraps2 个重点▾ 点开看本节重点
本节重点
  • 直接装饰会让 「func.__name__」 变成 「wrapper」，日志和调试会认错函数
  • @wraps(func) 关键一行
3

直接装饰会让 func.__name__ 变成 wrapper，日志和调试会认错函数。加 @functools.wraps(func) 把原函数的 __name__、__doc__、__module__ 复制过来：

from functools import wraps
def timer(func):
    @wraps(func)              # 关键一行
    def wrapper(*args, **kwargs):
        ...
    return wrapper

5.4 带参数的装饰器（装饰器工厂）

3

装饰器本身要参数（比如"重试 3 次"）时，写三层嵌套：最外层收装饰器参数、中层收函数、内层是 wrapper。

from functools import wraps
import time

def retry(max_attempts=3, delay=0.5):
    """失败重试装饰器工厂"""
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, max_attempts + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    if attempt == max_attempts:
                        raise
                    print(f"第 {attempt} 次失败: {e}，{delay}s 后重试")
                    time.sleep(delay)
        return wrapper
    return decorator

@retry(max_attempts=3, delay=0.5)     # 像调用函数一样传参数
def unreliable_api_call():
    import random
    if random.random() < 0.7:
        raise ConnectionError("模拟网络抖动")
    return "成功"

叠加顺序从下往上装饰、从外往里执行：@bold @italic def greet() 等价于 greet = bold(italic(greet))，执行时 bold 的前置代码先跑、italic 的次之。判断执行顺序的方法：在每个 wrapper 里 print 标记看输出顺序。

5.6 实战三例：权限、缓存、日志

3

权限装饰器给需要登录的接口统一加校验，未登录抛 PermissionError；缓存装饰器用 functools.lru_cache(maxsize=128) 给纯函数加记忆化，重复调用直接返回缓存（参数必须可哈希）；日志装饰器统一打印"调用参数、返回值、耗时"。三个都是"横切逻辑"，散在每个函数里写会重复十遍，抽成装饰器写一遍全局生效。

6.1 生成器：惰性产出数据

3

yield 让函数变成生成器，每次 next() 产出一个值、暂停在 yield 处。价值是省内存：处理 10GB 日志文件时逐行产出，不用一次性读进内存。yield from 委托子生成器，send() 双向通信（少用）。生成器表达式 (x**2 for x in range(10)) 是列表推导式的惰性版，可直接喂给 sum()、max()。

6.2 上下文管理器：自动清理资源3 个重点▾ 点开看本节重点
本节重点
  • 「with open(...) as f:」 保证文件关闭；自定义两种写法：类方式实现 「__enter__」/「__exit__」，或 「@contextmanager」 装饰生成器函数（「yield」 前获取资源、「yield」 后清理）
  • 异常处理里的上下文管理器可以"抑制特定异常"（「contextlib.suppress(FileNotFoundError)」）
  • 判断何时用：有"获取资源、用完释放"模式（文件、锁、数据库连接、网络连接）就用 with，别手写 try/finally
3

with open(...) as f: 保证文件关闭；自定义两种写法：类方式实现 __enter__/__exit__，或 @contextmanager 装饰生成器函数（yield 前获取资源、yield 后清理）。异常处理里的上下文管理器可以"抑制特定异常"（contextlib.suppress(FileNotFoundError)）。判断何时用：有"获取资源、用完释放"模式（文件、锁、数据库连接、网络连接）就用 with，别手写 try/finally。

10.1 什么情况下用（适用场景加前置条件）

3
  • 函数：逻辑重复 2 次以上、职责一句话说清、代码块超过 20 行。
  • 装饰器：给多个函数加同一种横切逻辑（计时/重试/权限/缓存/日志）。
  • 生成器：数据量大于内存、只需顺序遍历一次。
  • 上下文管理器：有获取-释放配对的资源（文件、锁、连接）。
  • 模块与包：代码超过 3 个文件、要被多个脚本复用。

10.2 什么情况下别用（反例加替代方案）3 个重点▾ 点开看本节重点
本节重点
  • 别写超过 50 行的函数：难测试难读
  • 别用装饰器改函数返回值类型：装饰器应保持接口签名
  • 别拿生成器存中间结果：生成器产出即丢，要复用得转 list
3
  • 别写超过 50 行的函数：难测试难读。替代：拆子函数。
  • 别用装饰器改函数返回值类型：装饰器应保持接口签名。替代：改原函数或写适配函数。
  • 别拿生成器存中间结果：生成器产出即丢，要复用得转 list。替代：需要多次遍历就用 list。
  • 别用 from module import *：命名空间污染。替代：显式导入。
  • 别用可变默认参数：def f(lst=[]) 跨调用污染。替代：默认值写 None。
  • 别把所有代码塞进 __init__.py：包初始化应轻量。替代：业务逻辑放 core.py 等模块。
  • 别在深层函数里 print 调试：替代 logging.debug 或装饰器统一日志。

10.3 翻车长什么样（真实失败形态加排查信号加怎么改）

3
  1. 装饰后 func.__name__ 变成 wrapper：忘加 @functools.wraps(func)。排查：打印 func.__name__。改：加 wraps。
  2. 可变默认参数跨调用污染：def f(lst=[]); lst.append(1) 第二次调用看到上次的值。排查：打印 lst 的 id。改：默认值写 None。
  3. 闭包里改外层变量 UnboundLocalError：忘了 nonlocal。改：加 nonlocal 变量名。
  4. 装饰器叠加顺序反了：@a @b def f() 实际是 a(b(f))，执行顺序从外到里。排查：wrapper 里 print 标记。改：调整装饰器顺序。
  5. import 找不到自己的模块：脚本直跑时 sys.path 不含项目根。排查：print(sys.path)。改：用 python -m mypkg.main 以模块方式跑，或加 sys.path 临时补（不推荐）。
  6. ModuleNotFoundError: No module named 'mypkg'：没装成包。改：pip install -e . 以开发模式安装，或确认 pyproject.toml 的 packages 配置。
  7. 生成器只能遍历一次：第二次 for x in gen: 得到空。排查：第二次循环无输出。改：需要复用就 gen = list(gen) 存住。
  8. 上下文管理器的异常被吞：__exit__ 里 return True 抑制了异常。改：不拦截就 return False 或不写 return。
  9. mypy 报类型不匹配：函数返回值注解写 int 实际返回 str。改：改注解或改返回值，类型注解是合同。

脚本 A：decorator_lab.py（Python 3.12）——计时、缓存、重试三装饰器

#!/usr/bin/env python3
# decorator_lab.py —— Python 3.12
# 运行: python decorator_lab.py
import time, random
from functools import wraps, lru_cache

def timer(func):                      # 计时装饰器
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"⏱️ {func.__name__} 耗时 {time.perf_counter()-start:.4f}s")
        return result
    return wrapper

@timer
def slow_sum(n: int) -> int:
    return sum(range(n))

@lru_cache(maxsize=128)               # 缓存装饰器（参数需可哈希）
def fib(n: int) -> int:
    return n if n < 2 else fib(n-1) + fib(n-2)

def retry(max_attempts=3, delay=0.1):  # 重试装饰器工厂
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, max_attempts + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    if attempt == max_attempts:
                        raise
                    print(f"第{attempt}次失败: {e}")
                    time.sleep(delay)
        return wrapper
    return decorator

@retry(max_attempts=3)
def flaky():
    if random.random() < 0.5:
        raise ConnectionError("模拟抖动")
    return "成功"

if __name__ == "__main__":
    print(slow_sum(1_000_000))
    print(fib(30), "缓存命中秒出")
    print(flaky())

验收标准：slow_sum 打印耗时、fib(30) 立即输出 832040（缓存生效）、flaky 可能重试后成功。装饰器三形态一次跑齐。

#!/usr/bin/env python3

from contextlib import contextmanager
import time

def countdown(n: int):                # 生成器：惰性产出
    for i in range(n, 0, -1):
        yield i

print(list(countdown(5)))             # [5, 4, 3, 2, 1]

@contextmanager
def timed(label: str):                # 上下文管理器（生成器版）
    start = time.perf_counter()
    try:
        yield                          # with 块执行处
    finally:
        print(f"[{label}] 耗时 {time.perf_counter()-start:.4f}s")

with timed("排序"):
    sorted(range(100000), reverse=True)

【part3 补充】带过期时间的缓存装饰器 cache_with_timeout(seconds=10) 比 lru_cache 多一个"过期"维度：cache 字典存 (结果, 时间戳)，命中时先看 now - timestamp < seconds 是否还在有效期，过期就重算。它还给 wrapper 挂了 cache_clear 方法（wrapper.cache_clear = lambda: cache.clear()），调用方可手动清缓存。对比 lru_cache：lru_cache 按最近使用淘汰、无过期概念、参数必须可哈希；cache_with_timeout 支持过期、可手动清、但只支持位置参数（args 作键）。选型：纯计算且参数可哈希用 lru_cache，带时效的数据（配置、令牌、汇率）用 cache_with_timeout。

两个案例的共同点是"把横切逻辑封装进装饰器，业务函数保持干净"，这是装饰器存在的全部理由。写自己的装饰器时永远记住三件事：*args/**kwargs 转发参数、return result 转发返回值、@functools.wraps 保留元信息。

16. 迭代器与生成器的完整关系（part3 补充）

2

【part3 补充】可迭代对象与迭代器的协议区别：可迭代对象（Iterable）实现 __iter__()，能被 for 遍历（列表、字符串、字典都是）；迭代器（Iterator）同时实现 __iter__() 和 __next__()，能用 next() 手动取下一个值。手动转换用 iter(my_list) 得到迭代器，连续 next() 取元素，取完抛 StopIteration 结束。for 循环的底层就是"取迭代器、循环 next、捕获 StopIteration"，理解这一点就明白为什么"生成器只能遍历一次"（迭代器耗尽即止）。

自定义迭代器的两种写法：类方式实现 __iter__ 返回 self、__next__ 里维护状态并抛 StopIteration（Countdown 案例倒计时 5 4 3 2 1）；生成器方式用 yield 一行搞定（countdown(n) 函数）。yield 的三条魔力：执行到 yield 暂停并返回值、下次调用从暂停处继续、函数结束自动抛 StopIteration。优先用生成器写迭代器，类方式只在需要复杂状态管理时用。

生成器表达式与列表推导式的内存对比：[x**2 for x in range(1_000_000)] 立即创建百万个元素的列表占几十 MB；(x**2 for x in range(1_000_000)) 只是一个生成器对象占几十字节，按需产出。sum(x**2 for x in range(1, 101)) 直接把生成器喂给 sum，不需要中间列表。判断何时用生成器表达式：数据量大、只需遍历一次、配合聚合函数（sum/max/min/any/all），三者同时满足就用生成器表达式。

【part3 补充】类方式实现 __enter__ 和 __exit__：__enter__ 的返回值赋给 as 后面的变量（with Timer() as t: 里 t 就是 __enter__ 返回的 self）；__exit__ 接收三个异常参数 exc_type/exc_val/exc_tb（无异常时全为 None），返回 True 会吞掉异常、返回 False 或 None 会继续抛出。这个返回值语义是最容易翻车的地方：写 return True 会让调用方完全看不到异常，调试时"代码没报错但结果不对"多半是这里吞了。正确做法是默认 return False，只有明确要"抑制特定异常"时才返回 True。

@contextmanager 生成器版更简洁：yield 之前等价于 __enter__（获取资源），yield 之后等价于 __exit__（释放资源），yield 的值赋给 as 变量。异常处理模式是 try: yield resource except Exception: raise finally: 清理，finally 保证清理总执行、except 可以加日志后重新抛出。对比两种写法：类方式适合复杂状态（多个方法、需要复用）、生成器版适合简单获取释放（几行搞定）。

异常抑制的正确场景：contextlib.suppress(FileNotFoundError) 用于"文件不存在就算了"这类可预期的缺失；Timer 的 __exit__ 返回 True 吞异常则几乎总是错的。判断原则：抑制异常前先问"调用方需要知道这个异常吗"，需要就别吞，不需要就 suppress 明确写出来。

20. 类型注解：给函数上合同（part3 补充）

2

【part3 补充】类型注解的价值三条：提高可读性（一看就知道参数返回什么类型）、提前发现 Bug（mypy 静态检查，不跑代码就能查出类型不匹配）、增强 IDE 补全与重构。关键认知：Python 运行时不强制执行类型注解，它只是"建议"，写错注解不会抛异常，只会在 mypy 检查时报。基础写法：变量 name: str = "小明"、函数 def add(a: int, b: int) -> int、返回多类型用 str | int（3.10+，之前要 Union[str, int]）、可选用 dict | None。

容器与高阶类型注解：Sequence[float] 接受 list 和 tuple（比写 list[float] 更通用，Sequence 是抽象基类）、Callable[[int, int], int] 表示"接收两个 int 返回 int 的函数"（装饰器、回调参数常用）、TypeAlias 给复杂嵌套类型起别名 UserDict = dict[str, dict[str, str | int]]。泛型 TypeVar 加 Generic[T] 写"类型无关"的容器类（栈、队列、结果包装类），3.12+ 简化为 class Stack[T]: 新语法。

翻车点：注解写 list[float] 但传了 [1, 2]（int 列表），运行不报错但 mypy 报错；Optional[int] 是 3.10 之前的可选写法，3.10+ 统一用 int | None；注解只是字符串注释，from __future__ import annotations 会让所有注解延迟求值（前向引用友好）。判断何时上类型注解：函数超过 3 个参数、被多处调用、要写库给别人用，三者任一就该写注解。

40. 无限生成器、yield from 与 send()（part3 补充）

2

【part3 补充】无限生成器用 while True: yield 实现，典型是斐波那契数列 fibonacci()（a, b = b, a + b 每次推进一位）。无限生成器不能用 for 直接遍历（永不结束），要用 next(fib) 手动取或 itertools.islice(fib, 9, 15) 做惰性切片（取第 10 到 15 个）。内存对比的证据：list(range(1_000_000)) 占约 8MB，range(1_000_000) 本身只占 48 字节（range 就是惰性的），这就是"惰性求值省内存"的直接证明，用 sys.getsizeof() 可以自己跑出来。

yield from 委托子生成器：递归展平嵌套列表 flatten([1, [2, 3], [4, [5, 6]]]) 时，遇到子列表就 yield from flatten(item) 把产出委托给递归调用，省掉手写内层循环。它还自动转发 send()、throw()、close() 调用，是生成器组合的标准语法。什么时候用：生成器内部要遍历另一个可迭代对象并逐个产出时，yield from iterable 比 for x in iterable: yield x 更简洁。

send() 双向通信：生成器不仅能产出值还能接收值，value = yield average 处暂停时外部 avg.send(10) 把 10 送进 value 继续执行。运行平均值案例：send(10) 得 10.0、send(20) 得 15.0、send(30) 得 20.0。注意启动规则：第一次必须 next(avg) 或 send(None) 启动（此时没有值可接收），之后才能 send(数据)。send 的实际用途不多（协程控制、状态机），日常写生成器用 yield 产出即可，遇到"生成器要接收外部输入"的场景再回来查这节。

【part3 补充】泛型让容器类"类型无关"：T = TypeVar("T") 声明类型变量，class Stack(Generic[T]) 定义泛型栈，push(item: T)、pop() -> T 用 T 表示"存什么类型就取什么类型"。使用时 int_stack: Stack[int] = Stack() 特化成整数栈、str_stack: Stack[str] 特化成字符串栈，mypy 能检查出"往 int 栈里塞字符串"的错误。价值是写一次容器逻辑、到处复用且类型安全。Python 3.12 的 PEP 695 新语法更简洁：class Queue[T]: 直接在类名后声明类型参数，type Point = tuple[float, float] 定义类型别名（type 语句是 3.12+ 专属）。

44. 装饰器三细节：wraps、工厂、叠加（part3 补充）

2

【part3 补充】functools.wraps 的具体效果：装饰后 greet.__name__ 保持 "greet"（不是 "wrapper"）、greet.__doc__ 保持原文档字符串、greet.__module__ 保持原模块。没加 wraps 的后果是日志里全打 "wrapper"、help() 看不到原文档、调试栈指错函数。wraps 的实现是把原函数的 __name__、__doc__、__dict__ 等元属性复制到 wrapper，一行装饰器解决所有元信息丢失问题。写装饰器的检查清单：wrapper 用 *args, **kwargs 转发、return result 转发返回值、加 @functools.wraps(func)，三条全对才算合格。

重试装饰器工厂 retry(max_attempts=3, delay=1.0) 的完整逻辑：for 循环尝试至多 max_attempts 次，每次 try 调用原函数，成功直接 return；失败打印"第 N 次尝试失败"，若还有机会就 time.sleep(delay) 等待后重试，最后一次失败就 raise 重新抛出（不吞异常）。参数选择的经验值：网络请求 max_attempts=3、delay=0.5 到 1 秒（指数退避更专业，delay * 2**attempt）；文件写入 max_attempts=2、delay=0.1。判断何时用重试：操作有瞬时失败可能（网络、锁、临时文件占用），永久性错误（参数不对、权限不足）重试无意义。

装饰器叠加顺序：@bold @italic def greet() 是"先 italic 后 bold"，因为 Python 从下往上逐个包装、执行时从外往里进。输出验证：greet("小明") 得 <b><i>你好，小明！</i></b>，外层是 bold 的标签。排序规律：离函数最近的装饰器最先执行内层逻辑。多个装饰器叠加时注意顺序影响语义（比如"先鉴权后计时"还是"先计时后鉴权"会得到不同的耗时统计），有依赖关系时把基础装饰器放下面。

脚本 D：decorator_stack.py（Python 3.12）——装饰器叠加与 wraps 对照

#!/usr/bin/env python3
# decorator_stack.py —— Python 3.12
# 运行: python decorator_stack.py
from functools import wraps

def bold(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return f"<b>{func(*args, **kwargs)}</b>"
    return wrapper

def italic(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return f"<i>{func(*args, **kwargs)}</i>"
    return wrapper

@bold
@italic                         # 先 italic 后 bold
def greet(name: str) -> str:
    """向某人打招呼"""
    return f"你好，{name}！"

print(greet("小明"))             # <b><i>你好，小明！</i></b>
print(greet.__name__)           # greet（不是 wrapper，wraps 生效）
print(greet.__doc__)            # 向某人打招呼

def bad_decorator(func):        # 反例：忘加 wraps
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@bad_decorator
def farewell(name: str) -> str:
    """告别语"""
    return f"再见，{name}"

print(farewell.__name__)        # wrapper（元信息丢失）

验收标准：greet 输出 <b><i>...</i></b> 证明叠加顺序、greet.__name__ 是 greet 证明 wraps 生效、farewell.__name__ 是 wrapper 展示不加 wraps 的后果。对照第 5.3 节和第 44 节。

#!/usr/bin/env python3
# pipeline_lab.py —— Python 3.12
# 运行: python pipeline_lab.py
import tempfile, os

def read_lines(path: str):                # 生成器：逐行读
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.rstrip("\n")

def filter_errors(lines):                 # 生成器：过滤 ERROR
    for line in lines:
        if "ERROR" in line:
            yield line

def parse_level(lines):                   # 生成器：提取级别
    for line in lines:
        yield {"level": line.split()[1] if len(line.split()) > 1 else "?",
               "raw": line}

with tempfile.NamedTemporaryFile("w", suffix=".log", delete=False, encoding="utf-8") as t:
    t.write("2026-10-23 INFO 启动成功\n2026-10-23 ERROR 数据库连接失败\n2026-10-23 ERROR 网络超时\n")
    tmp = t.name

pipeline = parse_level(filter_errors(read_lines(tmp)))   # 三层生成器链
for rec in pipeline:
    print("🔴", rec["level"], rec["raw"])
os.unlink(tmp)

验收标准：打印两条 ERROR 记录、内存占用恒定（生成器链惰性）、临时文件被清理。对照第 38 节。
