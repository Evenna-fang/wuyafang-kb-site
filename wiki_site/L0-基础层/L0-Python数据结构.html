3.1 构造与基本操作

3

列表用方括号构造，元素类型可以混（但实际项目里同质更好）。核心操作：append(x) 尾插、insert(i, x) 指定位置插、extend(lst) 批量加、pop() 弹末尾、pop(i) 弹指定位置、remove(x) 删第一个匹配值、sort() 原地排序、sorted(lst) 返回新列表不改原、reverse() 原地反转、copy() 浅拷贝。切片 lst[::2] 取偶数位、lst[::-1] 反转，切片总是返回新列表。

3.2 复杂度与选型边界3 个重点▾ 点开看本节重点
本节重点
  • 尾插 「append」 摊还 O(1)，中间插入 「insert(0, x)」 是 O(n)（后面所有元素要挪位）；查找 「x in lst」 是 O(n) 线性扫描，10 万元素的列表里查一个要遍历全部
  • 判断信号：数据量超过几千且频繁查找时脚本明显变慢，改法是换成 set 或 dict 做 O(1) 查找
  • 「pop(0)」 弹头部也是 O(n)，队列场景应该用 「collections.deque」 的 「popleft()」（O(1)）

3.3 可变对象的共享陷阱

3 
a = [1, 2, 3]
b = a              # b 和 a 指向同一个列表！
b.append(4)
print(a)           # [1, 2, 3, 4] —— a 也变了
c = a.copy()       # 浅拷贝，c 是新列表但元素仍共享
c.append(5)
print(a, c)        # [1, 2, 3, 4] [1, 2, 3, 4, 5]

这是数据结构篇第一大翻车点：函数参数传列表、把列表存进类属性、循环里复用同一个列表变量，都会踩到。改法：需要独立副本就 copy() 或 list(a)，嵌套结构用 copy.deepcopy(a)。

4. 元组 tuple：不可变记录3 个重点▾ 点开看本章重点
本章重点
  • 元组用圆括号构造 「(1, 2, 3)」，一旦创建不能增删改
  • 价值有三：不可变所以安全共享、可哈希所以能当字典键和集合元素（列表不行）、轻量比列表省内存
  • 典型用途是"一条记录"：坐标 「(x, y)」、数据库一行 「(id, name, score)」、函数返回多值 「return lo, hi」
2

元组用圆括号构造 (1, 2, 3)，一旦创建不能增删改。价值有三：不可变所以安全共享、可哈希所以能当字典键和集合元素（列表不行）、轻量比列表省内存。典型用途是"一条记录"：坐标 (x, y)、数据库一行 (id, name, score)、函数返回多值 return lo, hi。collections.namedtuple 给字段起名，Point = namedtuple("Point", ["x", "y"]) 后 p.x 比 p[0] 可读。

翻车现场：t = (1) 是整数不是元组（括号被当运算符），单元素元组必须写 t = (1,) 带逗号。判断信号：type(t) 显示 <class 'int'>。另一个坑是"元组不可变"指元素引用不可变，t = ([1, 2], 3) 里 t[0].append(9) 是合法的（列表本身可变）。

字典用花括号构造 {"name": "小明", "age": 18}，3.7 起正式保证插入顺序。核心操作：d["key"] 取值（键不存在抛 KeyError）、d.get("key", default) 安全取、d["key"] = v 增改、d.pop("key") 删并返回、d.setdefault("k", v) 不存在才设、d.update(other) 批量更新、d.keys()/d.values()/d.items() 三个视图。遍历写 for k, v in d.items():。

5.2 键的要求与哈希

3

字典键必须可哈希（hashable）：int、float、str、tuple、frozenset 都行，list、dict、set 不行（可变对象不能哈希）。翻车现场：d[[1, 2]] = 3 抛 TypeError: unhashable type: 'list'。改法：把列表转成元组 d[(1, 2)] = 3 或转成字符串键。哈希冲突是 dict 内部机制，用户不用管，但要知道"哈希值相等是键相等的前提"。

6. 集合 set：去重与集合运算

2

集合用花括号构造 {1, 2, 3}（空集合必须写 set()，{} 是空字典）。去重：set([1, 1, 2, 3]) 得 {1, 2, 3}。运算四件套：并集 s1 | s2、交集 s1 & s2、差集 s1 - s2、对称差 s1 ^ s2。方法：add(x) 添加、discard(x) 安全移除（不存在不报错）、remove(x) 移除（不存在抛 KeyError）、issubset/issuperset 判包含。集合无序，不能用索引取 s[0]。

选型边界：需要"判断某元素在不在"的高频场景（比如校验用户输入的 ID 是否在白名单），把白名单放 set 比放 list 快一个数量级。frozenset 是不可变版本，可哈希可作字典键。翻车现场：s = {} 以为建了集合实际是空字典，s.add(1) 抛 AttributeError；改法写 s = set()。

  • 反例是推导式里塞太多逻辑：两层 for 加三个 if 的推导式可读性比循环差，超过两个 for 或一个 if 就改回普通循环
  • 判断标准：同事看一眼要问"这行什么意思"就该改写
2

推导式用一行表达式构造列表、字典、集合，比手写循环短且快（C 层优化）。列表推导式 [x**2 for x in range(10)]、带条件 [x for x in lst if x > 0]、带表达式 [x if x > 0 else 0 for x in lst]。字典推导式 {k: v for k, v in d.items() if v > 5}。集合推导式 {x % 3 for x in range(20)}。生成器表达式 (x**2 for x in range(10)) 用圆括号，惰性求值省内存，可直接喂给 sum()、max()。

反例是推导式里塞太多逻辑：两层 for 加三个 if 的推导式可读性比循环差，超过两个 for 或一个 if 就改回普通循环。判断标准：同事看一眼要问"这行什么意思"就该改写。

8. 浅拷贝与深拷贝

2

copy()、list(a)、切片 a[:] 都是浅拷贝：外层容器是新的，内层元素仍共享。嵌套结构（列表套列表）用浅拷贝改内层会影响原对象。深拷贝 copy.deepcopy(a) 递归复制所有层，完全独立。判断信号：改了"副本"的内层发现原对象也变了。性能上深拷贝比浅拷贝慢得多（要递归遍历），只在真有嵌套且要完全独立时用。

10. 性能实测：用数据说话

2

不要凭感觉说"字典快"，用 timeit 实测。判断复杂度的通用方法：把数据量翻倍看耗时是否翻倍（O(n)）还是不变（O(1)）。典型实测结论（CPython 3.12，10 万元素）：x in list 约 1 到 10 毫秒、x in set 约 0.0001 毫秒，差距五个数量级；list.pop(0) 每次约 0.5 毫秒、deque.popleft() 约 0.0001 毫秒；列表推导式比等价 for 循环快 1.5 到 2 倍。实测脚本见第 13 节脚本 D。补充一组最小复现（可直接跑，Python 3.12）：

# list_vs_set_lookup.py —— 运行: python list_vs_set_lookup.py
import timeit
lst = list(range(100_000))
s = set(lst)
t_list = timeit.timeit(lambda: 99_999 in lst, number=1000)
t_set = timeit.timeit(lambda: 99_999 in s, number=1000)
print(f"list: {t_list:.4f}s  set: {t_set:.6f}s  倍数: {t_list/t_set:.0f}x")

同理，队列操作的差距用 deque 验证：

# deque_vs_list_pop.py —— 运行: python deque_vs_list_pop.py
from collections import deque
import timeit
lst = list(range(100_000))
dq = deque(range(100_000))
t1 = timeit.timeit(lambda: lst.pop(0), number=1000)
t2 = timeit.timeit(lambda: dq.popleft(), number=1000)
print(f"list.pop(0): {t1:.4f}s  deque.popleft(): {t2:.6f}s")

两段输出都印证：成员判断用 set、队列弹出用 deque，数量级差距（1000 倍以上）不是微优化。

11.1 什么情况下用（适用场景加前置条件）

3
  • list：有序、要增删、按索引访问。前置：元素量级千以内或只在尾部操作。
  • tuple：固定记录、要当字典键、函数返回多值。前置：数据确定不再改。
  • dict：按名取值、去重计数、JSON 互转。前置：键可哈希。
  • set：去重、高频成员判断、集合运算（交并差）。前置：只关心"在不在"不关心顺序。
  • Counter：词频统计、Top N。前置：元素可哈希。defaultdict：按 key 分组收集。deque：队列、滑动窗口。namedtuple：多字段记录但不想写类。
11.2 什么情况下别用（反例加替代方案）3 个重点▾ 点开看本节重点
本节重点
  • 别用 list 存白名单做高频查找：O(n) 会拖垮脚本
  • 别用 「list.pop(0)」 当队列：每次弹出 O(n)
  • 替代：「deque.popleft()」

  • 别用 list 存白名单做高频查找：O(n) 会拖垮脚本。替代：set。
  • 别用 list.pop(0) 当队列：每次弹出 O(n)。替代：deque.popleft()。
  • 别用 {} 建空集合：那是空字典。替代：set()。

  • 别用可变默认参数：def f(lst=[]) 默认列表在多次调用间共享。替代：def f(lst=None): lst = lst or []。
  • 别在推导式里写三层嵌套：可读性崩塌。替代：普通循环。
  • 别用 sorted() 后指望原列表变了：sorted 返回新列表。替代：要原地排序用 lst.sort()。

11.3 翻车长什么样（真实失败形态加排查信号加怎么改）

3
  1. 改了 b 发现 a 也变了：共享可变对象。排查：print(id(a), id(b)) 相同即中招。改：b = a.copy() 或 copy.deepcopy(a)。
  2. TypeError: unhashable type: 'list'：拿列表当字典键或集合元素。改：转 tuple。
  3. KeyError：d["missing"] 取不存在的键。改：d.get("missing", 默认值)。
  4. s = {}; s.add(1) 抛 AttributeError：把字典当集合。改：s = set()。
  5. 单元素元组变成整数：t = (1) 少逗号。改：t = (1,)。
  6. 可变默认参数跨调用污染：def f(lst=[]); lst.append(1) 第二次调用看到上次的值。改：默认值写 None。
  7. 排序后原列表没变：用了 sorted(lst) 没接返回值。改：lst.sort() 或 lst = sorted(lst)。
  8. 集合遍历顺序不稳定：set 无序。改：要顺序就 sorted(s) 或用 list。
  9. 字典推导式值重复覆盖：{v: k for k, v in d.items()} 值重复只剩最后。改：值改用列表收集 defaultdict(list)。

16. 常见容器选型的深度对照（场景化）

2

场景一：日志统计 IP 访问次数。用 list 存 (ip, count) 记录每次都要线性找，10 万条日志会慢到秒级；用 dict counts[ip] = counts.get(ip, 0) + 1 是 O(1) 更新；用 Counter 更短 Counter(ip for ip in ips)。结论：计数场景三选一，优先 Counter，要自定义逻辑用 dict。

场景二：白名单校验。用户输入 ID 要判断在不在允许列表里。白名单存 list 每次 O(n)，1 万个白名单 100 万次校验会跑几分钟；转成 set 后每次 O(1)，总耗时降到秒级。结论：高频成员判断一律 set，这是最常见、收益最大的一次选型。

场景三：任务队列。生产者放任务消费者取任务，先进先出。list 的 append 加 pop(0) 每次弹头 O(n)；deque 的 append 加 popleft() 两端都是 O(1)。结论：队列一律 deque，别用 list.pop(0)。

场景四：坐标或配置项。存 (x, y) 坐标或 {"host": ..., "port": ...} 配置。坐标用 tuple（不可变、可哈希、轻量）；配置用 dict（字段可读、可 JSON 互转）。结论：数据会不会变决定 tuple 还是 dict，字段多且会改就 dict。

场景五：去重保序。要给一个列表去重但保留原始顺序。set(lst) 去重但顺序丢失；list(dict.fromkeys(lst)) 在 3.7+ 保序去重（字典保插入顺序）；小数据量直接写推导式配合已见集合 seen = set(); out = [x for x in lst if not (x in seen or seen.add(x))]（这行可读性差，仅作了解）。结论：保序去重用 dict.fromkeys。

【part5-mastery 补充】题一：== 和 is 的区别。== 比较值是否相等，is 比较是否同一对象（内存地址）。a = [1,2,3]; b = [1,2,3] 时 a == b 为 True 但 a is b 为 False；c = a 后 a is c 为 True。陷阱是小整数缓存（-5 到 256）和字符串驻留：x = 256; y = 256 时 x is y 可能 True，257 就 False。结论：判断值相等用 ==，判断 None 用 is None，其余场景别用 is 比值。

题二：深拷贝与浅拷贝的区别。浅拷贝只复制一层，嵌套对象仍是引用；深拷贝递归复制所有层。original = [[1,2],[3,4]]; shallow = copy.copy(original); shallow[0].append(999) 后 original 也被改（第一层共享）；换成 copy.deepcopy 就不受影响。还有一个细节：不可变对象不需要深拷贝，但"元组里套列表"这种混合结构 a = (1, [2,3]) 浅拷贝后改列表元素仍会影响原元组，因为元组不可变的是引用不是内容。

题三：GIL 对数据结构选择的影响。GIL（Global Interpreter Lock，全局解释器锁）让 CPython 同一时刻只有一个线程执行字节码，主要影响 CPU 密集型任务的多线程性能，IO 密集型不受影响（IO 等待时释放 GIL）。对数据结构的影响是：多线程共享 dict 或 list 时要加锁（threading.Lock）防止竞态；CPU 密集型改用 multiprocessing 的进程池，每个进程有自己的数据副本；IO 密集型用 asyncio 加异步 HTTP 客户端。Python 3.13 实验性去除 GIL 的构建选项可让真多线程并行，但需特殊编译，数据结构选型不变。

【part1 补充】课件的"带标签的盒子"比喻在数据结构语境下要精确化：变量赋值不是"把数据复制进盒子"，而是"给对象贴一个新标签"。x = y = z = 0 三个名字指向同一个整数对象（整数不可变所以看不出问题）；换成 x = y = z = [] 就是三个名字指向同一个列表，改 x 会影响 y 和 z。这条规则在本文第 3.3 节的共享陷阱、第 8 节的拷贝语义、第 11.3 节的翻车清单里反复出现，是数据结构篇的第一原理。

多变量同时赋值 a, b, c = 1, 2, 3 等号两边元素个数必须一致，a, b = 1, 2, 3 抛 ValueError。它的实用形态是解包：lo, hi = min_max(lst)、for k, v in d.items():、a, b = b, a（不用临时变量交换）。元组、列表、字符串都能解包，字典解包取键、集合解包无序慎用。解包星号语法 first, *rest = lst 把剩余元素收成列表，处理"第一个是表头、其余是数据"的场景很方便。

重赋值与原地修改的区别：x = 20 是把标签 x 挪到新对象 20 上，原对象 10 不受影响；lst.append(9) 是在原地改列表对象，所有指向它的标签都会看到变化。判断某操作属于哪类的方法：操作后打印 id(x)，id 变了是重赋值，没变是原地修改。这条判据能解释九成"为什么我的副本被改了"的问题。

31. 广播、向量化与花式索引（NumPy 三大核心，衔接进阶）

2

【part5-mastery 补充】广播（Broadcasting）让不同形状的数组直接运算：matrix 是 3x3、vector 是长度 3 的一维数组，matrix + vector 时 vector 自动"广播"到每一行，得到逐行相加的结果；换成列向量 [[1],[2],[3]] 就是逐列加。广播的规则是"从尾部维度对齐，维度为 1 的自动扩展"，形状不兼容时抛 ValueError。它省掉了手写双重循环，是 NumPy 最省代码的特性。

向量化 vs 循环的实测对比：100 万元素的 i**2 + i*3 计算，Python 循环约 0.2 秒、NumPy 向量化约 0.005 秒，典型加速比 20 到 50 倍。原因不是 NumPy 的 Python 代码快，而是运算下沉到 C 层批量执行、数据连续内存布局缓存友好。判断何时改写：循环里做纯数值运算且元素超过 1 万，就值得改 np.arange 加向量化表达式；循环里有复杂业务分支（if/elif）就留在 Python 循环。

花式索引与布尔索引：arr[arr > 5] 布尔掩码取子集（等价于"过滤大于 5 的元素"）；arr[np.array([0, 2]), np.array([1, 3])] 用索引数组取指定位置；np.where(arr > 5, arr, -1) 条件选择（大于 5 保留、否则置 -1），等价于"向量化的三元表达式"。这三种索引方式把"遍历列表筛选"压缩成一行，是数据处理的主力写法。翻车点：布尔掩码的形状必须和原数组一致，否则抛 IndexError。

【part5-mastery 补充】滚动窗口 rolling(window=N)是时间序列分析的主力：df['Close'].rolling(window=5).mean() 计算 5 日移动平均、.std() 计算滚动标准差（波动率）、.sum() 滚动求和。窗口越大越平滑，但前期数据不足时结果是 NaN（前 4 行的 MA5 为空），这是正常现象不是 bug。布林带是它的组合应用：MA20 + 2 * rolling(20).std() 画上轨、减 2 倍标准差画下轨，价格超出上下轨是超买超卖信号。

shift(n) 做时间平移：df['MA5'].shift(1) 把昨天的值对齐到今天，用于"比较今天和昨天"的场景。金叉判定（短期均线上穿长期均线）的完整写法是 (MA5 > MA20) & (MA5.shift(1) <= MA20.shift(1))，即"今天在上、昨天在下"。pct_change() 计算日收益率（相对变化率）、diff() 计算差分（绝对变化）、cummax() 累计最大值（算最大回撤用 (Close / Close.cummax() - 1).min()）。

实战模板：股票分析的标准流程是"读 CSV 带日期索引 → 算技术指标（MA、波动率、RSI）→ 生成信号（金叉死叉）→ 汇总统计（年化收益、最大回撤、夏普比率）"。四个关键参数记牢：一年约 252 个交易日（年化用 mean() * 252）、年化波动率用 std() * sqrt(252)、RSI 窗口 14 日、移动平均常用 5/20/60 日。这套模板可以直接搬去做任何带时间戳的指标计算（流量监控、温度变化、销售趋势）。

【part5-mastery 补充】Estimator 三步 API是所有 scikit-learn 模型的共同接口：model = SomeModel(超参数) 构造、model.fit(X_train, y_train) 训练、model.predict(X_test) 预测、model.score(X_test, y_test) 评估。记住这四行就能用任何模型（逻辑回归、随机森林、SVM、梯度提升），差别只在构造函数的超参数。数据结构的衔接点：X 是二维特征矩阵（NumPy 数组或 DataFrame，形状 (n_samples, n_features)）、y 是一维标签（Series 或数组），传进模型前要保证形状对。
