学习路径与 AI 通识：从概念判断到可验收的最小路线

本文是「AI 通识 + AI 通识导航 + 学习路径导航 + 课程结构对标」的唯一正文。目标不是让读者背完术语，而是能回答三个实践问题：下一步学什么、当前问题该用 Prompt/RAG/微调中的哪一种、怎样证明这一阶段真的学会。

验证边界：文中的本地路径检查可离线执行；tiktoken 安装与 Token 计数示例未实跑，不连接模型、不需要 API Key。论文结果属于原作者实验设置，不当作本机或所有模型的收益承诺。

1. 为什么先建立地图，而不是直接追工具

3

零基础最常见的浪费不是学得慢，而是顺序错误：不会读写 JSON 就开始搭 RAG，不理解 Token 就比较上下文价格，把「模型不知道私有资料」误判成「提示词不够长」，或者在还没有评测集时直接微调。工具名称几个月就换，数据表示、概率生成、检索与评估这些底层概念却能反复复用。《AI 工程》划线摘录也提醒「工具更新换代很快，底层知识的生命力更为持久」；这里据此把路线组织为能力而不是产品清单。

不建立地图会有四种直接后果：

  1. 学习目标不可验收：「看完 Python」无法判断能否解析模型返回；「能读 JSON、处理嵌套字典、写出测试」才可以。
  2. 问题层级混淆：知识缺失、行为不稳定、参数能力不足是三类问题，分别对应检索、提示/流程约束、训练，不可互相替代。
  3. 只追求能跑：模型能流畅生成不等于内容正确，Demo 成功不等于可交付。
  4. 课程大纲代替个人路径：课程覆盖广不等于每个人都要顺序学完。2026-10-26 的两份课程大纲对标显示，博学谷偏技术纵深，黑马偏阶段化项目与工程落地；这是当时大纲的结构比较，不是教学质量排名，也不是当前招生承诺。

2. 为什么 AI 通识必须落到工程决策

3

课件的符号主义与联结主义对比，不只是历史故事。符号系统把人写清的规则交给机器执行，优点是规则显式、易审计，难点是规则覆盖；神经网络从数据调整参数，优点是学习复杂模式，难点是数据、泛化和解释。现实中的 AI 应用往往把两者组合：模型负责语义表示与生成，代码负责权限、 Schema、阈值、检索条件和验收规则。

不理解生成机制，就会把「像真的」当成「是真的」。书籍《大模型是怎样跑起来的》的划线摘录把生成描述为根据前文反复预测下一个 Token，并特别提醒冷门、过时、模糊或需要严密推理的问题可能「答得流畅但并不一定正确」。因此，AI 通识的最终产出应是验证意识：要求来源、检查边界、抽样复核，而不是对模型人格化。

3. 一条最小能力链：表示 → 计算 → 生成 → 应用 → 验证

3
层级 核心概念 与相邻概念的区别 能指导什么实践
表示 Token、Embedding Token 是模型处理序列的离散单位；Embedding 是数值向量表示 Token 影响上下文与计费；向量用于相似度检索
计算 矩阵变换、自注意力 矩阵运算是计算形式；注意力是按内容分配信息权重的机制 理解为什么需要向量化计算与 GPU
生成 预训练、解码、采样 预训练学参数；解码用已有参数生成；采样从候选分布选输出 温度等参数改变输出分布，不补充可靠事实
应用 Prompt、RAG、Agent、微调 四者作用层不同，不是同一功能的竞品 按知识、流程、工具、行为问题选型
验证 单元测试、检索评测、答案评测 代码正确、证据找对、答案可信是不同问题 每阶段留可复跑证据，不靠肉眼一句「挺好」

Token 不是字，也不是词。不同分词器、语言和模型会得到不同切分；不能用字符数乘固定系数冒充精确 Token 数。上下文窗口是模型可处理的序列预算，通常同时受输入与输出占用，具体口径看所用模型文档。API Key 是访问凭据，不是「模型账号密码」的同义词，也不应写入源码、课件、日志或派单文本。

自注意力不是数据库检索。注意力在当前模型计算的上下文中学习关联；RAG 则从外部集合查出证据并放入上下文。前者是模型内部计算，后者是应用系统的数据管线。二者可以组合，不能互相解释。

4. Prompt、RAG、微调与 Agent 的适用边界

3
当前症状 首选动作 何时不用这条路
输出格式、语气、任务定义不稳定 改 Prompt，加明确输入、约束、输出 Schema 和反例 私有事实缺失时，继续堆指令不会创造事实
需要最新或私有资料，并要求引用 建 RAG：解析、切块、索引、检索、组装、答案校验 数据本身错误或无权限时，检索只会放大问题
要让模型调用工具、按状态推进流程 建 Agent/工作流，并设置权限、超时、人工确认与恢复 单次确定性转换不需要开放式自主循环
已证明知识供给和 Prompt 足够，但稳定行为仍不达标 有数据与评测后再考虑 SFT/偏好优化等训练 没有评测集、只想补实时事实时，不应先微调

「RAG 解决知识、微调解决行为」是有用的第一层分工，但不是绝对定律：训练也可能改变知识关联，RAG 的提示模板也会影响行为。工程上仍需用对照实验判定瓶颈。

5. 论文怎么说，我们怎么用

3

个性化学习不是多给内容，而是让目标、活动、评价和修订形成闭环。Agentic University（arXiv:2610.40492）提出学习者参与的可修订 Capability Program，用反馈与表现决定后续支持；论文报告其评估中的平均增益为 12.19 对 5.61（50 分制），这是该研究设置的结果，不证明任意多智能体课程都有效。我们借鉴的是组织原则：每一阶段都保留「目标—练习—测评—修订」，不照搬多智能体架构，也不把论文分数当本路线承诺。

生成加速是独立工程问题，不是「Token 越少就一定越快」。ReaDy（arXiv:2610.20503）研究混合线性注意力模型中的推测解码，利用循环状态辅助草稿，并报告特定模型、B200 GPU 与七项基准上的平均加速。我们用它纠正两个入门误区：一是生成不止简单的「逐字打印」，底层可采用草稿—验证等优化；二是论文加速数字有硬件、模型和任务边界，学习阶段先建立正确性基线，不能为追速度牺牲验收。

6. 课程结构怎么取舍

3

两份大纲的可复用结论是「骨架阶段化、专题按需加深」：入门可以借低代码或 AI 编程获得正反馈，但 Python、数据与 Transformer 基本机制不能永久跳过；RAG/Agent 可作为应用主线，微调、多模态、底层训练按目标选修。本库不复制任何一家的 95 天或 200+ 知识点安排，而采用下面的过关制路线。

每周只维护一张表，不另建散篇：

「首次结果」必须保留失败，不能只填最好的一次。修订依据应落到具体错误，例如「JSON 解析失败：把模型 Markdown 围栏直接交给 json.loads」，而不是「状态不好」。

9. 第二步：用同一问题做技术分界实验

3

选一个固定问题，例如「根据公司 2026 年差旅制度，住宿上限是多少，并给出来源」。按顺序实验：

  1. 无资料 Prompt：要求只根据已知回答；若没有可靠来源，应允许回答不知道。
  2. 提供原文的 Prompt：给一小段制度，检查答案是否逐字受证据支持。
  3. 小型 RAG：把多份制度切块检索，记录召回片段与答案引用。
  4. 固定评测：至少准备「答案存在、答案不存在、跨文档、旧版本干扰、无权限资料」五类问题。
  5. 是否训练的决策：只有当知识已正确提供、输出合同清楚、失败仍呈稳定行为模式时，才评估微调；否则先修数据或流程。

这个实验比背定义更能区分 Prompt、RAG 与微调。真实模型调用因需要外部服务与凭据，未实跑；这里给的是可照做的实验协议，不宣称已获得某项准确率。

10. 第三步：用真实分词器测 Token，不用字符数猜

3

下面是兼容 o200k_base 分词器的示例，不代表其他模型分词结果。安装与运行未实跑：

python -m venv .venv
source .venv/bin/activate        # Windows PowerShell 改用 .venv\Scripts\Activate.ps1
python -m pip install tiktoken
python token_budget.py

# token_budget.py
import tiktoken

encoding = tiktoken.get_encoding("o200k_base")
prompt = "只依据给定资料回答；资料不足时说不知道。"
context = "住宿上限以审批时有效制度为准。"
max_output_tokens = 200
used = len(encoding.encode(prompt + context))
budget = 4096  # 仅作演示，必须替换为目标模型官方上下文口径

print({"input_tokens": used, "reserved_output": max_output_tokens,
       "total_planned": used + max_output_tokens})
assert used + max_output_tokens <= budget

实际项目还要把系统消息、工具定义、历史消息和检索片段计入，并以目标服务商返回的 usage 为账单核对依据。不要把本示例的 4096 当成任何现役模型参数。
