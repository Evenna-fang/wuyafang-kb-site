L1 Web 全栈开发实战：API 契约、前后端分离与可验收交付

← 返回总入口
本篇合并原 FastAPI + Vue 课件实操与 Web 前后端分离散篇，补齐接口契约、数据边界、负例和端到端验收。示例是教学用内存任务服务，重启后数据清空；不包含生产认证与持久化。所有安装、启动、curl 和浏览器步骤均未实跑，不能据此宣称服务已部署。

WHY：为什么“前端能画、后端能返回”还不算打通

2

一个页面从按钮到数据库通常要穿过浏览器、开发服务器或反向代理、HTTP 接口、输入校验、业务规则和数据层。任何一层只按自己的假设工作，都会出现典型的“单件都正常、联调全失败”：前端把 priority 发成字符串，后端期待整数；接口发生 422，页面却只显示“网络错误”；静态路由 /tasks/stats 被 /tasks/{task_id} 抢先匹配；本地允许所有跨域来源，上线后又把同一宽松配置带到公网。

前后端分离的价值不是把代码机械地放成两个目录，而是建立可独立开发、共同遵守、能自动验收的契约：

  • 前端可以先用固定 JSON 开发交互，后端可以用 curl/测试客户端验证业务，不必互相等待。
  • Web、移动端和第三方可以复用同一 API，但权限和输入校验必须在服务端重做，不能相信页面隐藏了按钮。
  • 前端静态资源和后端服务可以独立扩缩容、回滚，但版本兼容、缓存与发布顺序由此成为显式工作。
  • 契约不清时，分离反而增加网络失败、跨域、重复状态和多套模型，小型服务端渲染页面未必需要它。

《持续交付 2.0》目录把部署流水线、自动化测试、配置管理、低风险发布和监测列为连续能力，公开摘录还强调从生产过程开始质量内建。落到 Web 实战，就是不要等“页面完成后联调”：先冻结请求/响应示例与错误语义，再让前端、后端各自用同一组样本测试。

WHAT / WHYT：核心概念、区别与适用边界

2

1. 前后端分离不等于 MVC，也不等于微服务

3

传统服务端 MVC 中，控制器处理请求，视图模板通常在服务器生成 HTML。前后端分离中，后端主要返回数据，浏览器中的前端应用负责渲染和交互。二者都能有模型、视图、控制器思想，差别主要在视图在哪里执行、页面与数据怎样交付。

方案 适用场景 代价与边界
服务端渲染/模板 内容页、小型后台、首屏与 SEO 优先 交互复杂后前后端职责可能纠缠
SPA + API 富交互、多客户端、前端团队独立交付 首屏、SEO、状态同步、跨域和接口版本更复杂
同构/SSR 框架 既要首屏与 SEO，又要富交互 构建与运行链路更复杂，不是本篇最小 demo 的目标
微服务 多个独立业务边界和发布单元 是后端组织方式，与是否前后端分离无必然关系

2. FastAPI、Pydantic、SQLAlchemy、Vue 各管一段

3
  • FastAPI负责 HTTP 路由、依赖注入、请求/响应模型接入与 OpenAPI 文档。它不会替开发者决定业务权限。
  • Pydantic负责数据解析和校验。请求通过校验只说明形状与约束合格，不说明用户有权操作。
  • SQLAlchemy负责 Python 与关系数据库之间的连接、ORM 或 SQL 表达；本篇为突出契约先用内存存储，真实持久化见数据库篇。
  • Vue负责声明式 UI、组件和响应式状态。本地课件强调其渐进式特点：可以从页面渲染和表单开始，需要时再引入组件、路由与集中状态，不必起步就堆齐全家桶。

课件的 FastAPI 代码还给出两个直接教训：路径参数用 Annotated[int, Path(...)] 等类型与元数据表达约束；动态 /root/{id} 若写在静态 /root/test 前面，可能先把 test 当动态段匹配。因此路由顺序和负例测试是设计的一部分。

3. REST、GraphQL、WebSocket 不是互斥的“先进程度”

3
  • REST 风格 HTTP适合资源边界清楚、缓存与状态码语义有用的 CRUD。不要把 URI 当装饰，重点是统一资源和错误契约。
  • GraphQL适合调用方确实需要灵活选择字段、聚合多种数据的场景；同时需要查询复杂度、权限和缓存治理，不是“复杂查询就自动选它”。
  • WebSocket/SSE适合服务端持续推送或双向交互；普通创建任务不需要长连接。
  • OpenAPI描述 HTTP API 的契约，Swagger UI 是文档界面；文档生成不等于业务正确，更不等于端到端测试通过。

4. 论文怎么说，我们怎么用

3

WebHarbor（arXiv:2611.03634）为 GUI Web Agent 构建了 153 个可执行、Docker 化网站环境和 3,518 个任务，强调真实网站内容不断变化、访问受限，而合成环境又常缺功能深度；其流程由 Agent 实现变化、人类审计视觉保真度、功能正确性和任务有效性。

本篇不声称复现 WebHarbor，也不把它的 Agent 训练结果当成普通 Web 项目收益。可直接借用的是验收方法：把网站变成可重复启动的环境，把关键交互写成可重放任务，并同时审视觉、功能和任务有效性。因此下面的验收不只 curl 200，还包括浏览器创建、校验失败、删除和刷新后的真实状态；需要稳定回归时，再按Docker Compose 篇把前端、后端及依赖容器化。

HOW：从零做一个可联调、可测负例的任务应用

第一步：建立两个进程和一份契约

3

依赖安装后应把实际通过测试的版本写进锁文件；上面只负责搭建练习环境，未固定版本，也不代表长期可复现构建。后端使用 8000，Vite 默认使用 5173。最小契约为：

操作 请求 成功响应 必测失败
创建任务 POST /api/tasks，JSON 含 title/priority 201 + 完整任务 空标题、优先级越界 → 422
任务列表 GET /api/tasks 200 + 数组 limit=0 → 422
单个任务 GET /api/tasks/{id} 200 + 任务 不存在 → 404
完成任务 PATCH /api/tasks/{id}/complete 200 + 更新后任务 不存在 → 404
删除任务 DELETE /api/tasks/{id} 204，无响应体 不存在 → 404

第二步：实现后端，输入模型与响应模型分开

3

保存为 backend/main.py：

from fastapi import FastAPI, HTTPException, Query
from fastapi.middleware.cors import CORSMiddleware
from pydantic import BaseModel, Field

app = FastAPI(title="Task Demo", version="1.0.0")
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],
    allow_credentials=False,
    allow_methods=["GET", "POST", "PATCH", "DELETE", "OPTIONS"],
    allow_headers=["Content-Type"],
)

class TaskCreate(BaseModel):
    title: str = Field(min_length=1, max_length=100)
    priority: int = Field(default=0, ge=0, le=5)

class TaskOut(BaseModel):
    id: int
    title: str
    priority: int
    completed: bool

# 教学内存库：进程重启即清空，不用于多 worker 或生产。
tasks: dict[int, TaskOut] = {}
next_id = 1

@app.post("/api/tasks", response_model=TaskOut, status_code=201)
def create_task(payload: TaskCreate):
    global next_id
    task = TaskOut(id=next_id, completed=False, **payload.model_dump())
    tasks[next_id] = task
    next_id += 1
    return task

@app.get("/api/tasks", response_model=list[TaskOut])
def list_tasks(limit: int = Query(default=20, ge=1, le=100)):
    return list(tasks.values())[:limit]

@app.get("/api/tasks/{task_id}", response_model=TaskOut)
def get_task(task_id: int):
    if task_id not in tasks:
        raise HTTPException(status_code=404, detail="任务不存在")
    return tasks[task_id]

@app.patch("/api/tasks/{task_id}/complete", response_model=TaskOut)
def complete_task(task_id: int):
    task = get_task(task_id)
    tasks[task_id] = task.model_copy(update={"completed": True})
    return tasks[task_id]

@app.delete("/api/tasks/{task_id}", status_code=204)
def delete_task(task_id: int):
    if task_id not in tasks:
        raise HTTPException(status_code=404, detail="任务不存在")
    del tasks[task_id]
    return None

这里故意不复用 TaskCreate 作为响应：输入没有 id/completed，输出必须包含它们。生产还应添加认证、授权、持久化、并发控制和迁移，不能靠 Pydantic 代替这些职责。若增加 /api/tasks/stats，要放在 /api/tasks/{task_id} 之前，或设计不冲突的路径并加测试。

第三步：实现 Vue 调用层，把 422 和网络失败分开

3

替换 frontend/src/api.js：

const BASE_URL = 'http://127.0.0.1:8000/api'

async function request(path, options = {}) {
  let response
  try {
    response = await fetch(`${BASE_URL}${path}`, {
      ...options,
      headers: { 'Content-Type': 'application/json', ...options.headers },
    })
  } catch (error) {
    throw new Error('无法连接服务器，请检查后端是否启动')
  }
  if (response.status === 204) return null
  const body = await response.json().catch(() => null)
  if (!response.ok) {
    const message = response.status === 422
      ? '输入未通过校验，请检查标题和优先级'
      : body?.detail || `请求失败：HTTP ${response.status}`
    throw new Error(message)
  }
  return body
}

export const listTasks = () => request('/tasks')
export const createTask = (data) => request('/tasks', {
  method: 'POST', body: JSON.stringify(data),
})
export const completeTask = (id) => request(`/tasks/${id}/complete`, { method: 'PATCH' })
export const deleteTask = (id) => request(`/tasks/${id}`, { method: 'DELETE' })

替换 frontend/src/App.vue：

<script setup>
import { onMounted, ref } from 'vue'
import { listTasks, createTask, completeTask, deleteTask } from './api'

const tasks = ref([])
const title = ref('')
const priority = ref(0)
const error = ref('')
const loading = ref(false)

async function refresh() {
  try {
    tasks.value = await listTasks()
  } catch (e) {
    error.value = e.message
  }
}

async function submit() {
  error.value = ''
  loading.value = true
  try {
    await createTask({ title: title.value, priority: priority.value })
    title.value = ''
    priority.value = 0
    await refresh()
  } catch (e) {
    error.value = e.message
  } finally {
    loading.value = false
  }
}

onMounted(refresh)
</script>

<template>
  <main>
    <h1>任务清单</h1>
    <form @submit.prevent="submit">
      <label>标题 <input v-model="title" required maxlength="100" /></label>
      <label>优先级 <input v-model.number="priority" type="number" min="0" max="5" /></label>
      <button :disabled="loading">{{ loading ? '提交中' : '创建' }}</button>
    </form>
    <p v-if="error" role="alert">{{ error }}</p>
    <ul>
      <li v-for="task in tasks" :key="task.id">
        {{ task.title }}（优先级 {{ task.priority }}）
        <span>{{ task.completed ? '已完成' : '未完成' }}</span>
        <button @click="completeTask(task.id).then(refresh).catch(e => error = e.message)">完成</button>
        <button @click="deleteTask(task.id).then(refresh).catch(e => error = e.message)">删除</button>
      </li>
    </ul>
  </main>
</template>

第四步：跑一遍真正端到端验收

3
  1. 首次打开页面，列表为空且无网络错误。
  2. 创建合法任务，页面出现新项；直接 GET API 也能看到同一项。
  3. 用 curl 提交空标题和越界优先级，收到 422；页面输入非法数据时有可读提示，不是永久 loading。
  4. 请求不存在的 ID，API 为 404；页面不会把错误任务插入列表。
  5. 点击完成和删除，再次查询 API 验证服务端状态，而不是只看按钮变色。
  6. 刷新浏览器，当前内存示例仍保留数据；重启后端后应清空。这个结果是存储设计的结果，不是“丢数据 bug”。
  7. 停止后端再点击创建，页面显示连接失败；恢复后端后可以重试。
  8. 需要稳定 GUI 回归时，固定依赖、种子数据和截图环境，把上述流程变成自动化任务。WebHarbor 的启发是环境确定性与人类多维审计，而不是只增加测试数量。

    共享核心只 import 表壳另写，是 Web 分层里最该学的一条：改检索逻辑只改 query.py，服务层不会被分叉。
  • 真正实现了的 4 个端点（L299-379）：GET /health、GET /v1/models、POST /v1/chat/completions（同时挂 /chat/completions 兼容路径）、POST /v1/completions——面向 OpenAI 协议而不是自定义协议，客户端不用写适配层。
  • 前端在本库是「借用现成的」：用 OpenWebUI 直连 rag/serve.py（文件头 docstring 第 3 行「OpenAI 兼容 RAG 服务, 供 OpenWebUI (3001) 接入本地知识库」）；仓库里没有自己写的前端页面，wiki_site/ 下 395 个 HTML 是知识库阅读站（由 scripts/link_sources.py 等生成），不是业务前端。
  • 和课件讲法的差异：课件的前后端分离项目是「Vue 前端 + FastAPI 自带 JWT/Vue Router」；本库的前端是可插拔的第三方 UI（OpenWebUI），后端只守 OpenAI 契约——接口标准化比自建前端省得多，代价是拿不到自定义交互。
  • 本库暂无：没有鉴权（rag/serve.py 路由上无 Depends(auth)）、没有前端构建产物、没有 CORS 白名单到具体域名（CORSMiddleware 已 import，配置以代码为准）。
