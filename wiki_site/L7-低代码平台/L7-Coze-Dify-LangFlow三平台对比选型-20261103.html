低代码平台的最大隐性成本不是订阅费，而是锁定效应：平台里的工作流、知识库索引、插件资产各有各的私有格式，用得越深，迁出越贵。

  • Coze SaaS 的云端资产无法导出，停服即清零；
  • 知识库要重建索引、工作流要逐节点翻译，迁移工作量可能超过当初搭建的数倍；
  • 三平台表面都是"拖拽 + 大模型"，但范式完全不同：Coze 是 Bot/渠道导向，Dify 是应用/工作流导向，LangFlow 是代码组件图导向——选错范式，项目从第一周就别扭。

结论：选型是一次性动作，锁定是持续代价。花一小时对比，比三个月后返工便宜一个数量级。

四、和其他 RAG 平台的位置关系（出自 RAG 应用平台课件）

3

低代码不止三家，课件对比的四个 RAG 专用平台各有侧重，作为选型补充：

  • QAnything（网易）：两阶段检索 + 混合检索，bce-embedding-base_v1 + bce-reranker-base_v1 组合，Rerank 是其核心；
  • RagFlow：深度文档理解（OCR、文档版面分析），自研文档解析，复杂版式文件场景强；
  • FastGPT：知识库问答 + 工作流编排，入库支持 QA 模式（LLM 预生成问答对）；
  • Dify：上述课件对比中最均衡的通用应用平台。

判断：纯 RAG + 特殊文档解析需求看 RagFlow/QAnything；要"RAG + 工作流 + Agent"一体化，仍在 Coze/Dify/LangFlow 三家中选。

HOW：怎么执行选型（半天内出结论）

2
  1. 锁需求（15 分钟）：先回答四问——数据能否出内网？要不要发布到 IM/渠道？使用者是业务人员还是开发者？流程里有没有循环/多 Agent？四问的答案直接映射第三节决策表。
  2. 核实版本（10 分钟）：打开各仓库 Releases 页核对最新版本与发布日期（不要采信二手文章的版本号，本目录就有编造前车之鉴）。
  3. 做最小 PoC（2-3 小时）：用同一个真实任务在候选平台各搭一遍，建议"读一个 PDF 回答 3 个问题 + 一个带分支的工作流"。PoC 时同步记录：搭了多久、中间变量能不能看到、导出物长什么样。
  4. 验迁移路径：在 PoC 最后执行一次导出（Dify：DSL/.ifpkg；LangFlow：flow JSON；Coze SaaS：确认无导出），确认资产可带走再定生产。
  5. 定运维与备份：私有化方案提前确定数据卷备份（docker compose down -v 会删数据，严禁误触）、升级窗口与升级指南阅读责任人。
