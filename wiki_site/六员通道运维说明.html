关键字段在 env 块：

{
  "env": {
    "ANTHROPIC_BASE_URL": "https://node-cf.sssaicodeapi.com",
    "ANTHROPIC_AUTH_TOKEN": "<SSSAI token，勿外传>",
    "ANTHROPIC_MODEL": "claude-sonnet-5-5",
    "ANTHROPIC_SMALL_FAST_MODEL": "claude-haiku-5-5"
  }
}
  • 注意：ANTHROPIC_BASE_URL 当前为 https://node-cf.sssaicodeapi.com（SSSAI CF2 节点规范为 https://node-cf.sssaicodeapi.com/api，若请求 404 先核对是否要补 /api 后缀）。
  • ANTHROPIC_DEFAULT_{SONNET,HAIKU,OPUS}_MODEL 被覆盖为 mimo-v2.6-pro——这是跨厂商映射，换通道时注意别和 ANTHROPIC_MODEL 混淆。
  • 切通道脚本：~/.claude/switch-to-volc.sh / switch-to-xiaomi.sh（切换前先备份）。

2.2 Codex — ~/.codex/config.toml + ~/.codex/auth.json

3

config.toml（PackyAPI 官方格式）：

model_provider = "packycode"
model = "gpt-6-astra"          # 必须是 Codex 分组实时在售的模型 ID
model_reasoning_effort = "high"
disable_response_storage = true
model_verbosity = "high"

[features]
web_search_request = true

[model_providers.packycode]
name = "packycode"
base_url = "https://cf.api.fan/v1"
wire_api = "responses"
requires_openai_auth = true

auth.json：

{ "OPENAI_API_KEY": "<PackyAPI Codex 分组 key>" }

要点：
- model_provider 必须与 [model_providers.*] 段名一致（这里叫 packycode，不是 packyapi）。
- model 填 Codex 分组在售模型 ID（gpt-6-astra、gpt-6-sol、gpt-6.1-sol、gpt-6.1-terra、gpt-5.6-sol 等；gpt-5.3-codex 及以下已被官方删除）。mimo-v2.6-pro 属于 mimo-officially 分组，不能用于 Codex 分组令牌，填了会 400/403。
- key 用 PACKYAPI_GPT_API_KEY（Codex/GPT 分组），不是 PACKYAPI_API_KEY（通用）也不是 PACKY_CLAUDE_API_KEY（Claude 分组）。
- 分组实时列表：https://www.packyapi.ai/pricing （左侧选「可用令牌分组」）。

3.1 通用：通道不通1 个重点▾ 点开看本节重点
本节重点
  • （本章节内容见子章节/表格，展开查看原文。）
3 
# 1) 先测端点存活（401 也算通，只是没带/带错 key；连不上才是通道不通）
curl -s -m 15 -o /dev/null -w "HTTP %{http_code}\n" <base_url>/models -H "Authorization: Bearer dummy"

# 2) 带真 key 测鉴权（key 从 secrets.env 读，勿在命令行明文粘贴）
source ~/.hermes/secrets.env
curl -s -m 15 -o /dev/null -w "HTTP %{http_code}\n" https://cf.api.fan/v1/models \
  -H "Authorization: Bearer $PACKYAPI_GPT_API_KEY"

判读：000/超时 → 网络/代理/DNS 问题（WSL 下先查 curl -s -m 5 https://www.baidu.com）；401/403 → key 或分组不对；404 → base_url 少/多路径后缀（如 /api、/v1）；200 → 通道 OK，问题在客户端配置。

3.2 模型 400 / model not found

3

报错含 model not found、invalid model、400：

  1. 查当前配置里的 model 名（各员对照表第 1 节）。
  2. 对照该 token 分组的实时模型列表（PackyAPI：https://www.packyapi.ai/pricing ；其它渠道看各自控制台）。模型 ID 必须属于该 key 的分组——跨分组（如拿 Codex 分组 key 调 mimo-v2.6-pro）必 400/403。
  3. 修配置后重启对应智能体进程（配置多为启动时读取）。
# 快速看某员当前配的模型
grep -E '^model(_provider)?\s*=' ~/.codex/config.toml
python3 -c "import json;d=json.load(open('$HOME/.qwen/settings.json'));print(d['model'])"

# ── 改 Codex 到 PackyAPI 官方格式（Python 读写防转义，不打印密钥）──
python3 - <<'EOF'
import json, os, shutil, time
home = os.path.expanduser("~")
cfg = f"{home}/.codex/config.toml"; auth = f"{home}/.codex/auth.json"
ts = time.strftime("%Y%m%d_%H%M%S")
shutil.copy2(cfg, cfg + f".bak-{ts}"); shutil.copy2(auth, auth + f".bak-{ts}")
t = open(cfg).read()
t = t.replace('model_provider = "xiaomimimo"', 'model_provider = "packycode"')
t = t.replace('model = "mimo-v2.6-pro"', 'model = "gpt-6-astra"')
open(cfg, "w").write(t)
secrets = dict(l.split("=",1) for l in open(f"{home}/.hermes/secrets.env")
               if "=" in l and not l.startswith("#"))
key = secrets["PACKYAPI_GPT_API_KEY"].strip().strip('"').strip("'")
json.dump({"OPENAI_API_KEY": key}, open(auth, "w"), indent=2)
os.chmod(auth, 0o600)
print("done: model_provider=packycode model=gpt-6-astra auth<-PACKYAPI_GPT_API_KEY")
EOF

# ── 通用：换某员的 base_url / model（以 QwenCode 为例）──
python3 - <<'EOF'
import json, os
p = os.path.expanduser("~/.qwen/settings.json")
d = json.load(open(p))
d["baseUrl"] = d["security"]["auth"]["baseUrl"] = "<新端点>"
d["model"]["name"] = "<新模型ID>"
json.dump(d, open(p, "w"), ensure_ascii=False, indent=2)
print("qwen updated")
EOF

5. 变更纪律

2
  1. 改任何配置前先备份（cp X X.bak-$(date +%Y%m%d_%H%M%S)）。
  2. 密钥只从 ~/.hermes/secrets.env 读，写入目标文件后 chmod 600；输出中只露前 6 位。
  3. 改完跑 §4 验证三连（端点 HTTP 码 + 配置字段 + 鉴权），确认通过再收工。
  4. 同一改动涉及多员时（如统一换 key），逐员改完逐员验证，防止漏改 profile 副本（DSH）或双 baseUrl（QwenCode）。
