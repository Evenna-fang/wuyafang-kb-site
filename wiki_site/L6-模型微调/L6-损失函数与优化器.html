L6 损失函数与优化器：从标签到训练稳定性

知识网挂接：总地图“四之一知识层”的 L6 模型微调内容，服务 N2 训练方案设计与 N4/N5 稳定性诊断。

运行边界：本文所有代码、配置与命令均为“示例，未实跑”。本次没有执行 numpy/PyTorch 实验、GPU 训练或产生实验输出，因此不沿用旧篇中“本次已实测”的数字。文中学习率、warmup、weight decay 与梯度裁剪只能按小实验起点理解，不存在适合所有模型、数据和框架的固定值。

本章重点

训练不稳定时，最容易犯的错误是直接换一个优化器，或把学习率、裁剪阈值照抄成“标准答案”。实际上，loss 为 NaN 可能来自标签全被忽略、某个批次含异常值、FP16 溢出、学习率过大、分布式某个 rank 先失败，也可能来自自定义算子。不同根因需要不同处理；一律把学习率除以十，可能只把故障推迟到更晚。

先把四个职责拆开：

  1. 损失函数决定优化什么。因果语言模型通常用下一 token 的交叉熵；标签掩码决定哪些位置进入损失。
  2. 优化器决定如何利用梯度更新参数。Transformer 微调常用 AdamW，但它不会修复错误标签或坏数据。
  3. 学习率调度、weight decay、梯度裁剪分别控制步长随时间的变化、参数正则与异常梯度幅度，三者不能互相替代。
  4. 模型结构与数值精度决定梯度能否稳定传播、计算是否容易饱和或溢出。残差、归一化、初始化与混合精度属于这一层。

微调还有一层特殊性：基础模型已经带有可用权重。面对预训练大模型的 NaN，第一件事通常不是重新初始化或改残差结构，而是回到数据、标签、学习率和精度的最小闭环。只有从头训练或明确修改架构时，才把结构与初始化作为主要干预点。

框架选型、OOM 与 ZeRO 排错见《L6 微调框架与分布式实战》。本文专注“损失是否算对、更新是否发生、数值是否稳定”。

WHAT

2
1. 交叉熵、位移标签与 -1003 个重点▾ 点开看本节重点
本节重点
  • 训练通常对有效位置求平均或按实现约定归约
  • 模型输出的是 logits，不应先手动对 logits 做 softmax 再交给已经包含相应数值处理的交叉熵实现
  • 对二分类 sigmoid 情形，交叉熵对 logit 的梯度为 \(p-y\)；相比把均方误差直接套在饱和概率输出上，它在“自信但错误”的位置仍能给出明确纠错信号
3

对词表大小为 (V) 的分类问题，某个目标 token 的交叉熵可写为：

[
L_t=-\log p_\theta(y_t\mid x_{<t})
]

训练通常对有效位置求平均或按实现约定归约。模型输出的是 logits，不应先手动对 logits 做 softmax 再交给已经包含相应数值处理的交叉熵实现。对二分类 sigmoid 情形，交叉熵对 logit 的梯度为 (p-y)；相比把均方误差直接套在饱和概率输出上，它在“自信但错误”的位置仍能给出明确纠错信号。

因果语言模型预测下一个 token，因此输入与标签存在一位位移。很多高层模型会在内部完成位移，但自写数据整理器或自定义 loss 时必须确认由谁位移，避免重复移位或完全不移位。比公式更容易出错的是监督范围：

  • 做全序列语言建模时，提示与回答通常都参与目标；
  • 做“只学回答”的指令微调时，提示位置的标签设为 -100，回答及需要学习的结束符保留真实 token id；
  • padding 位置通常设为 -100，不参与损失；
  • 不要因为 PAD 与 EOS 复用同一个 token id，就把所有等于该 id 的标签都屏蔽。 EOS 是否参与监督应按模板目标决定，PAD 是否忽略应按位置掩码决定。

PyTorch CrossEntropyLoss 的 ignore_index 默认约定为 -100，主流语言模型训练工具也广泛采用这一约定。真正要验收的是每个 batch 至少存在有效监督位置，以及有效位置确实落在预期答案上。若整个 batch 都是 -100，不同实现的归约可能产生无意义值或 NaN，不能把这种情况当成普通收敛慢。

类别不平衡不是一律换 Focal Loss

分类或 token 级结构化任务中，如果多数类样本淹没少数类，可以按顺序比较：

  1. 先修正采样、数据切分和评价指标，保留真实的验证分布；
  2. 尝试类别加权交叉熵或重采样，观察少数类召回、多数类误报和概率校准；
  3. 当大量“容易负例”仍主导训练时，再评估 Focal Loss。其形式为 (-\alpha_t(1-p_t)^\gamma\log p_t)，通过降低容易样本权重聚焦难例。

Focal Loss 的 (\alpha) 与 (\gamma) 需要小实验，不能从某篇检测论文直接搬成所有任务的默认值。类别加权与 Focal 都会改变优化目标，可能损害概率校准；评价不能只看总 accuracy，应同时看各类 precision/recall、混淆矩阵和业务成本。对于普通生成式 SFT，词表频率天然不均不等于要给所有稀有 token 加权，先把数据质量、模板和任务指标查清楚。

2. AdamW、学习率、warmup 与 weight decay

3

Adam 为每个参数维护梯度一阶矩和二阶矩估计，用历史梯度调节更新尺度。AdamW 将 weight decay 从梯度中的 L2 项解耦，使正则不再被 Adam 的二阶矩缩放混在一起。对 Transformer 而言，AdamW 是常见起点，不是“任何任务都无需比较”的定律。

几个超参的作用要分开：

  • 学习率 lr：控制更新步长。过大可能震荡、loss 突跳或 NaN；过小可能在预算内几乎不动。LoRA 与全参的可训练参数、损失面与优化器状态不同，不能直接共用同一个所谓标准 lr。
  • warmup：在训练初期逐步放开学习率，给 Adam 状态、数据流和分布式通信一个稳定过程。调度通常按优化器更新步计，而不是按梯度累积的微批次计；读日志时要确认口径。
  • 调度器：控制 warmup 后如何衰减。cosine、linear 等只是曲线形状，不会决定业务效果；总更新步数改变时，应重新检查 warmup 和衰减落在何处。
  • weight decay：抑制部分权重无约束增长。它不是梯度裁剪，也不等同于直接给 loss 加同一个 L2 项。常见做法是对归一化参数和 bias 使用不同分组，具体以框架与模型惯例为准。
  • 梯度裁剪：在反向传播后、优化器更新前限制梯度的范数或数值。它主要处理异常大梯度，不能治疗因学习率过小、标签为空或深层梯度消失造成的“不学习”。

一个可执行的小实验方法是以当前可运行配置的 lr0 为锚，比较 0.3 × lr0、lr0、3 × lr0 三档，其他条件不变，短跑并观察固定区间。这里的倍数只是小实验起点，不是普适搜索空间；一旦出现 NaN，应先停止扩大方向并回到最近稳定点。裁剪阈值也可先记录不裁剪基线的 pre-clip grad norm 分布，再选择只约束异常尾部的阈值；若几乎每个 step 都被强裁剪，模型可能长期欠拟合。

结构层面的四种手段：

  • 残差连接 (y=x+F(x)) 提供跨层直接路径，反向时有不经残差分支变换的通路；它不是“梯度永远不会异常”的保证。
  • LayerNorm/RMSNorm 等归一化稳定层内激活尺度。Transformer 变长序列与小批量场景常用层内归一化，而不是依赖跨样本统计。
  • Xavier、He 等初始化通过匹配输入/输出维度控制前向与反向方差。它们服务于从头训练或新增层，不应对正在微调的预训练主干随意重新初始化。
  • GELU、ReLU 等激活影响饱和与稀疏性，但激活函数不能单独修复错误的权重尺度、过大的 lr 或坏数据。

4. 混合精度、loss scale 与 NaN

3

FP16 的表示范围较小，梯度可能上溢为 Inf，也可能下溢为接近零。动态 loss scaling 先把 loss 乘上尺度，使反向梯度落到更适合 FP16 表示的区间；优化器更新前再 unscale，并检查非有限梯度。检测到溢出时，实现可能跳过本次更新并降低 scale，连续稳定后再尝试提高。于是“loss 还在打印”并不证明“参数每次都在更新”。

BF16 的指数范围更接近 FP32，通常不需要 FP16 式 GradScaler，但精度、硬件和算子支持仍需核对。把 FP16 改成 BF16 可能缓解溢出，却不会修复空标签或非法输入；FP32 小实验则是重要的分流工具：

  • FP32 同配置仍 NaN：优先查数据、标签、学习率、模型或自定义计算，不应继续只调 loss scale。
  • FP32 稳定而 FP16 NaN：优先查溢出、scale、算子精度与异常样本。
  • 单卡稳定而多卡 NaN：还要查各 rank 数据、梯度同步和最早失败 rank。

绝不能通过把 NaN 静默替换成零、无限跳过坏 batch 或只隐藏日志来“恢复训练”。这些做法会破坏可观测性，可能让模型长期不更新。

5. LoRA 训练与全参训练的差异3 个重点▾ 点开看本节重点
本节重点
  • LoRA 减少的是可训练参数及其部分训练状态，不会让所有梯度、激活和基础权重消失
  • QLoRA 的量化基座也不等于“训练全在低比特完成”
  • 二者出现 loss 不降时，除了通用标签与 lr 检查，还必须看日志中的可训练参数、目标模块名称和实际 optimizer step

2. 有序操作步骤

3

第一步：冻结变量并回到最小闭环

保留失败目录，复制配置形成新实验。使用固定小批干净样本和固定随机种子，先做短流程过拟合测试，目的只是验证“数据—loss—反向—更新—保存”链路。少量样本能记住不代表泛化，也不代表业务质量。

同时准备一个基座模型或最近稳定 checkpoint 作为回退点。每轮只改一个变量：标签、lr、精度、裁剪或 LoRA 目标模块之一。不要同时换框架、模型、数据和优化器。

第二步：先验标签，再谈优化器

以下是只构造一条样本的示例，未实跑。它省略真实聊天模板，仅展示“提示屏蔽、答案保留、EOS 单独决定”的关系：

# 示例，未实跑：真实项目应使用模型对应 tokenizer 和聊天模板
prompt_ids = [11, 12, 13]
answer_ids = [21, 22]
eos_id = 2
input_ids = prompt_ids + answer_ids + [eos_id]
labels = [-100] * len(prompt_ids) + answer_ids + [eos_id]

valid_positions = [i for i, label in enumerate(labels) if label != -100]
assert len(input_ids) == len(labels)
assert valid_positions, "当前样本没有任何有效监督位置"
assert all(labels[i] == input_ids[i] for i in valid_positions)
# 若高层模型内部做下一位位移，此处不再手工右移；否则按所用实现明确处理。

批次整理后还要断言有效 token 数大于零，并打印或人工检查一条解码后的“输入—标签”对照。若 PAD 与 EOS 同 id，应按位置构造标签，而不是写 labels[labels == pad_id] = -100 这种会误伤 EOS 的简化逻辑。

第三步：用小实验确定更新尺度

以下 YAML 是配置骨架示例，未实跑，占位符不是可直接运行值：

# 示例，未实跑：字段名按实际框架映射
optimizer: adamw
learning_rate: "<lr0；用相对小实验搜索>"
warmup_ratio: "<较小起点；不能占满短实验>"
weight_decay: "<wd0；按参数分组核对>"
max_grad_norm: "<来自稳定基线的 pre-clip 分布>"
bf16: "<仅在硬件和算子支持时开启>"
gradient_accumulation_steps: "<先固定，便于比较 lr>"

操作顺序：

  1. 固定数据、有效批量和步数，以 lr0 跑短基线。
  2. 分别测试 0.3 × lr0 与 3 × lr0；若大方向出现 spike/NaN，不再继续放大。
  3. 选择能稳定更新的区间后，再加入较短 warmup，确认它按 optimizer step 生效。
  4. 最后才加入或调整 weight decay，并检查参数分组。不要用 weight decay 代替 lr 修复爆炸。
  5. 记录不裁剪基线的 pre-clip grad norm，再设置只拦截异常尾部的裁剪起点；观察是否过度裁剪。

第四步：按正确顺序处理混合精度与裁剪

import torch

optimizer = torch.optim.AdamW(
    [p for p in model.parameters() if p.requires_grad],
    lr=lr0,
    weight_decay=wd0,
)
scaler = torch.cuda.amp.GradScaler()

optimizer.zero_grad(set_to_none=True)
with torch.autocast(device_type="cuda", dtype=torch.float16):
    outputs = model(input_ids=input_ids, labels=labels)
    loss = outputs.loss

assert torch.isfinite(loss), "先检查当前 batch、有效标签和 logits"
scaler.scale(loss).backward()
# 裁剪前必须先还原真实梯度尺度
scaler.unscale_(optimizer)
pre_clip_norm = torch.nn.utils.clip_grad_norm_(
    [p for p in model.parameters() if p.requires_grad],
    max_norm=clip_threshold,
)
# scaler.step 遇到非有限梯度时可能跳过更新；需另记实际更新和 scale
scaler.step(optimizer)
scaler.update()

若使用 BF16，不应机械照搬这段 FP16 scaler 流程。若框架已经管理 AMP、梯度累积和裁剪，不要再手写第二套更新逻辑；应改为读取框架日志中的 scale、grad norm 和 step。

第五步：按诊断结果选择处理，不全线调参

  • 确认梯度爆炸：先回放异常 batch，排除数据；回到稳定 lr，检查 warmup；按真实梯度尺度裁剪；FP16 再查 scale。严重发散时从最近良好 checkpoint 恢复，而不是从已损坏权重继续。
  • 确认梯度消失：先查低层是否被冻结、LoRA 是否未命中、标签是否只覆盖极少位置。从头训练才进一步检查残差、归一化、激活和初始化。不要为了微调 NaN 重初始化整个预训练模型。
  • 确认类别不平衡：先固定真实验证分布，再比较采样、class weight 和 Focal；每轮同时看少数类召回、多数类误报和校准。
  • 确认 LoRA 特有故障：检查适配器参数是否可训练、target modules 是否存在、保存的是适配器还是 checkpoint；不要把基础模型冻结误解为无需梯度检查。
  • 确认 NaN 与精度相关：用同数据同 seed 做 FP32/BF16/FP16 对照，逐个样本定位最早非有限值。不要只截断最终错误日志。

每轮诊断应留下：配置差异、软件与模型版本、首个异常 batch 的最小样本、逐 step 指标、当前与回退 checkpoint、基座/微调固定输入对比、独立验证集结果。坏样本若含业务数据，只保留在授权本地目录，不写入公开 issue 或外部跟踪服务。

验证按以下门槛理解，而不是仅看训练进程退出：

  1. 一条人工样本能解释每个有效标签的位置，且不存在全 -100 batch。
  2. 短实验中 loss、grad norm、logits 为有限值，optimizer 确实发生更新。
  3. 调 lr 或裁剪后，改善能在相同数据、步数、有效批量下重复出现。
  4. FP16 问题时能看到 scale 与跳过更新记录；改 BF16/FP32 的对照结论有证据。
  5. LoRA 实验能列出实际可训练参数与命中模块；全参实验能说明冻结和 decay 分组。
  6. 最终模型在独立验证集和固定回归问题上比较，不能只用小样本过拟合曲线验收。
  7. 若训练后期失败，能从最近良好 checkpoint 恢复，并跳过或修复已经确认的坏数据/坏配置。

3
常见坑 为什么误导 回退动作
把某个 LoRA lr、全参 lr 或 clip 值当普适常数 模型、批量、数据、目标模块与调度都不同 回到自己的稳定基线，用相对小实验重新定标
所有 PAD/EOS 同 id 位置一律设 -100 可能把应学习的结束符一起屏蔽 按位置掩码重建标签，先验一条样本
把 warmup 按微批次理解 梯度累积后实际预热区间与预期不符 以 optimizer update 重新计算并看 lr 日志
在未 unscale 的 FP16 梯度上裁剪 阈值对应的是缩放后的尺度 恢复正确顺序，记录 pre-clip norm
反复跳过 NaN batch 却不记录 可能长时间没有有效更新 回到首个坏 batch，保存样本 ID，修复根因
看到深层不动就重初始化预训练模型 破坏已有权重，且可能根因只是冻结或空标签 回退预训练权重，先查 requires_grad 和标签
Focal 解决了少数类却损害整体 难例权重过强、概率失真或多数类误报 回到加权 CE/重采样，重新按业务指标比较
训练 loss 降就宣布微调有效 可能过拟合或学了数据泄漏 回到独立测试集与通用能力回归
多变量一起改后“碰巧稳定” 无法知道哪项有效，也难以复现 从最近稳定配置重做单变量短实验

回退不是失败后的附加动作，而是实验设计的一部分：始终保留最近稳定配置和 checkpoint，新实验使用独立输出目录。若坏权重已产生，应回退权重；若只是日志与配置问题，可回退配置后从同一检查点重跑。不要以删除失败记录代替定位。
