WHAT：这个节点的最佳答案

一、什么时候需要微调 / 什么时候不要3 个重点▾ 点开看本节重点
本节重点
  • 1. RAG 解决不了——需要模型改变行为方式（输出风格、语气、特定格式），不是"知道更多事实"
  • ├── 单卡 16GB → QLoRA (4-bit)
  • ├── 单卡 24GB → LoRA (fp16)
3

触发条件（全部满足才值得做）：
1. RAG 解决不了——需要模型改变行为方式（输出风格、语气、特定格式），不是"知道更多事实"。
2. 数据量足够：至少 500-1000 条高质量标注样本。少于这个量级，噪声大于信号。
3. 延迟/成本敏感：RAG 每次推理要注入上下文，微调后模型内化知识/风格，推理更轻。
4. 领域特异性强（医疗对话、法律文书、代码补全）。
5. 数据私密性：不能把私有数据发给云端 API，需私有化部署。

不要微调：

情况 正确做法
只是缺知识 RAG 或 Prompt
数据少于 500 条 Few-shot Prompt
需要频繁更新知识 RAG（微调后更新要重新训练）
只有通用 GPU 云 API，别自己部署

决策树：

问题需要"更多知识"还是"更好的行为方式"？
├── 更多知识 → RAG（上传文档即可）
└── 更好的行为方式 → 有 500+ 条标注数据吗？
    ├── 没有 → Few-shot Prompt
    └── 有 → 有 GPU 吗？
        ├── 单卡 16GB → QLoRA (4-bit)
        ├── 单卡 24GB → LoRA (fp16)
        └── 多卡 A100 → 全量微调

二、三阶段训练（底层全景）

3
阶段 数据 目标 产物
预训练 无标注文本（TB 级，Common Crawl 权重 ~0.44 + 高质量语料配比） 下一词预测（自监督，模型自己生成标签） 基座模型（聪明但不会聊天，只会"接话"）
SFT 指令-回答对（万-十万条，可 Self-Instruct 强模型生成再人工筛） 学习问答格式 会答题的模型
对齐（RLHF/DPO） 偏好排序数据（万条） 优化人类偏好 有用无害的助手

RLHF 三步走：① 收集同问题多回答人类排序；② 训练奖励模型模仿打分；③ PPO 强化学习让语言模型最大化奖励分数。

DPO：跳过单独训练奖励模型，直接用偏好数据优化语言模型，数学上等价于简化版 RLHF，省去 PPO 稳定性问题，现在很多团队默认用 DPO。

⚠️ "生成得像真的 ≠ 一定是真的"——三阶段训练目标里没有"必须正确"这一项，只有"像不像人写的"，事实性错误仍需 RAG/校验兜底。

三、Transformer 为什么有效（三个底层支撑）3 个重点▾ 点开看本节重点
本节重点
  • 1. 自注意力：同一层里每个词直接跟所有其他词算"我该多看你一眼还是少看你一眼"（Q/K/V 三矩阵：Q 跟每个 K 算相似度得权重，对 V 加权求和）
  • 2. 位置编码：自注意力对词序不敏感（打乱排列相似度不变），所以必须给每个位置加"位置向量"跟词向量相加，告诉模型顺序
  • 3. 并行计算：RNN 串行（等前一个词算完才能算下一个），Transformer 把所有词的自注意力矩阵一次性丢给 GPU Tensor Core 并行——这就是 GPT 能从几百万参数涨到几千亿的硬件基础

  1. 自注意力：同一层里每个词直接跟所有其他词算"我该多看你一眼还是少看你一眼"（Q/K/V 三矩阵：Q 跟每个 K 算相似度得权重，对 V 加权求和）。长句里相距很远的两个词（如"它"和 50 字外的主语）能立刻建立联系，不靠层层传递。
  2. 位置编码：自注意力对词序不敏感（打乱排列相似度不变），所以必须给每个位置加"位置向量"跟词向量相加，告诉模型顺序。
  3. 并行计算：RNN 串行（等前一个词算完才能算下一个），Transformer 把所有词的自注意力矩阵一次性丢给 GPU Tensor Core 并行——这就是 GPT 能从几百万参数涨到几千亿的硬件基础。

四、梯度消失四大解法（深层网络才训得动）

3

深度网络反向传播时每过一层乘小于 1 的数，前几层梯度归零——前层学不到东西。四招一起上：

  1. ReLU 激活：正区间导数恒等于 1，反向传播梯度不衰减（sigmoid 导数最大 0.25，叠 10 层 ≈ 0.000001）。
  2. 残差连接：y = F(x) + x，+x 直连通道让梯度不经过权重层直接流回前面（"给梯度修高速公路"）。GPT 每个 Transformer block 都用。
  3. LayerNorm：对每个样本在该层所有神经元输出归一化到均值 0、方差 1，再学缩放平移。不用 BatchNorm 是因为大模型 batch 小、句子长度不一，batch 维度统计不稳。
  4. 参数初始化：Xavier / He 初始化按输入输出维度缩放随机数方差，保证前向反向数值不指数级变大或变小。
五、LoRA 到底省了什么（三个维度）3 个重点▾ 点开看本节重点
本节重点
  • 语言微调时权重变化本身是低秩的，这个近似够用
  • LoRA 可训练参数降到几百万，优化器状态缩到几百 MB；原权重以 FP16 冻结加载，不配套梯度——这是单张 24GB 卡能微调 7B 的关键
  • 全量微调 7B 模型光优化器状态就吃 7B×4×2 ≈ 56GB
3

核心思想：冻结原模型权重 W，只训练两个小矩阵 A 和 B，使 W' = W + BA（低秩分解）。语言微调时权重变化本身是低秩的，这个近似够用。

参数量：原 W 形状 (d,d) = (4096,4096) ≈ 1600 万；r=8 时 A=(4096,8)、B=(8,4096)，可训练参数降到 ~6.5 万（约 0.4%）。

显存：训练时每个可训练参数要配套梯度（同大）+ Adam 动量 m（同大）+ Adam 方差 v（同大）+ 混合精度副本——1 个参数实际占 4-8 倍显存。全量微调 7B 模型光优化器状态就吃 7B×4×2 ≈ 56GB。LoRA 可训练参数降到几百万，优化器状态缩到几百 MB；原权重以 FP16 冻结加载，不配套梯度——这是单张 24GB 卡能微调 7B 的关键。

速度与部署：① 训练时可训练参数少，反向传播快；冻结权重可用更低精度加载。② 推理时 B×A 可直接合并回 W，得到 W' = W + B×A，跟全量微调无区别，无额外开销。③ 一个基座可挂多个 LoRA（不同任务/风格），切换只换几 MB 小矩阵，不用重载几十 GB 权重。

六、LoRA / QLoRA 超参与 Pipeline

3

关键超参数：
- r（秩）：8/16/32/64。默认 8 或 16。
- alpha（缩放系数）：通常设为 r 的 2 倍。实际缩放 = alpha / r。
- dropout：0.05~0.1，防过拟合。
- target_modules：对哪些层加 LoRA。通常对 attention 的 q_proj, v_proj 加。

三方案对比：

方案 训练参数量 显存需求 效果 适用
全量微调 100%（7B≈14GB fp16） 40GB+ 最好 有大量数据、A100
LoRA 0.1%-1%（7B≈10MB 增量） 16-24GB 接近全量 绝大多数场景首选
QLoRA 0.1%-1%（量化基座） 8-12GB 略低于 LoRA 单卡消费级 GPU

量化：fp16（1x，无损失）→ int8（2x，极小损失，推理部署）→ nf4（4x，小损失，QLoRA 训练基座）。QLoRA = 4-bit 量化基座 + LoRA 以 fp16 训练。

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, TaskType

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.float16,
    bnb_4bit_use_double_quant=True,
)

model_name = "Qwen/Qwen2-7B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_name, trust_remote_code=True)
tokenizer.pad_token = tokenizer.eos_token   # 关键：不设 pad_token 输出会乱码

model = AutoModelForCausalLM.from_pretrained(
    model_name, quantization_config=bnb_config,
    device_map="auto", trust_remote_code=True,
)

lora_config = LoraConfig(
    task_type=TaskType.CAUSAL_LM, r=16, lora_alpha=32,
    lora_dropout=0.05, target_modules=["q_proj", "v_proj"],
)
model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# trainable params: 16,777,216 || all params: 7,740,073,472 || trainable%: 0.2167

训练（SFTConfig 关键参数）：

from trl import SFTTrainer, SFTConfig

training_args = SFTConfig(
    output_dir="./qwen2-7b-lora-output",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,   # 等效 batch = 16
    learning_rate=2e-4,              # LoRA 学习率通常比全量大（1e-4~5e-4）
    warmup_ratio=0.03,
    logging_steps=10,
    save_strategy="epoch",
    bf16=True,                      # A100/H100 用 bf16
    optim="paged_adamw_8bit",        # 配合 QLoRA
    report_to="none",
)
trainer = SFTTrainer(model=model, args=training_args,
    train_dataset=dataset["train"], eval_dataset=dataset["test"],
    peft_config=lora_config, max_seq_length=1024)
trainer.train()
trainer.save_model("./qwen2-7b-lora-final")
