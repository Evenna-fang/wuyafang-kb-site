Transformer 之所以能打败 RNN/CNN 成为大模型的底座，靠三件事：自注意力让每个词直接看到所有词、位置编码补上"顺序"信息、并行计算让 GPU 能真正发力。前两件解决"模型能理解长句子"的问题，第三件解决"训练得起、跑得动"的问题。

RNN 处理句子时是一个词一个词顺着读的，读到第 100 个词时，第 1 个词的信息要经过 99 次传递才能到达——中间任何一步丢失或变形，就忘了。这就是 RNN 处理长句"失忆"的根本原因。

自注意力换了个思路：在同一层里，每个词都直接跟句子里所有其他词算一遍"我该多看你一眼还是少看你一眼"。具体做法就是 Q/K/V 三个矩阵：用 Q（Query）跟每个 K（Key）算相似度，得到一组权重，再用这组权重对 V（Value）做加权求和。翻译时翻到"I"就重点看原文的"我"，翻到"Today"就重点看"今天"——这是《大语言模型：原理、应用与优化》里给的经典例子。

通俗点说，《大模型是怎样跑起来的》里那句最直白："每个 Token 在参与计算时，都会回头看前面出现过的 Token，判断谁对自己更重要。" 因为所有词互相直接计算，长句子里相距很远的两个词（比如"它"和前面 50 个字外的主语）也能立刻建立联系，不需要靠中间一层层传递。

2. 位置编码：自注意力本身"不识数"，得人为告诉它顺序

3

自注意力有个致命副作用：它对词的顺序是不敏感的。你把句子里词的排列打乱，每个词跟其他词算的相似度其实没变。但语言是有顺序的——"狗咬人"和"人咬狗"意思完全相反。

《从零构建大模型》里写得很直接："由于大语言模型的自注意力机制本质上与位置无关，因此向模型中注入额外的位置信息是有帮助的。" 《Transformer 模型开发从 0 到 1》也强调："由于 Transformer 模型不包含递归和卷积操作，所以为了使 Transformer 模型能够利用输入序列的顺序，它引入了一些关于输入序列的相对或绝对位置信息。"

做法就是给每个位置加一个"位置向量"，跟词向量加在一起喂进网络。这样模型既知道这个词是什么，又知道它在第几个位置。

3. 并行计算：GPU 终于有活儿干了3 个重点▾ 点开看本节重点
本节重点
  • RNN 是串行的——必须等前一个词算完才能算下一个，GPU 再多核心也只能在一个时间步里干一件事

RNN 是串行的——必须等前一个词算完才能算下一个，GPU 再多核心也只能在一个时间步里干一件事。Transformer 把这一层的所有词同时算自注意力矩阵，整个矩阵乘法可以一次性丢给 GPU 的 Tensor Core 并行处理。

《大模型是怎样跑起来的》硬件篇点出了关键："大模型需要大量矩阵乘法，而现代 AI GPU 里有专门为矩阵乘法加速的硬件。" 斋藤康毅在《深度学习入门》里也早就强调过："通过矩阵的乘积一次性完成计算的技巧，在实现的层面上可以说是非常重要的。"

这就是为什么 GPT 能从几百万参数一路涨到几千亿——不是 Transformer 结构更聪明，而是它能把规模真正转化为算力，而不是卡在串行瓶颈上。

来自哪些书的哪些观点（标注来源）

2
  • 《大模型是怎样跑起来的（轻科技）》：注意力机制的通俗解释——每个 Token 回头看前面出现过的 Token，判断谁更重要；GPU 有专门为矩阵乘法加速的硬件（Tensor Core/HBM），这是大模型能跑起来的硬件基础。
  • 《大语言模型：原理、应用与优化》：翻译任务中注意力权重的例子（翻到"I"关注"我"，翻到"Today"关注"今天"）。
  • 《Transformer 模型开发从 0 到 1》：Transformer 不含递归和卷积，必须显式引入位置信息才能感知序列顺序；自注意力通过 Q/K 相似度 × V 加权得到表示。
  • 《从零构建大模型》：自注意力本质上与位置无关，所以必须额外注入位置嵌入；大语言模型的成功一方面靠 Transformer 架构，一方面靠海量数据。
  • 《深度学习入门：基于 Python 的理论与实现》（斋藤康毅）：矩阵乘积的向量化计算是深度学习能在 GPU 上高效运行的实现基础。
  • 《深度学习详解》（李宏毅）：编码器由多个 block 堆叠而成，每个 block 输入一组向量输出另一组向量——这是 Transformer 能堆到几十上百层的结构前提。
