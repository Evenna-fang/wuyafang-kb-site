LoRA 微调到底省了什么

LoRA（Low-Rank Adaptation）的核心思想是：微调时不要动原模型的几十亿参数，而是在每个权重矩阵旁边加两个瘦长的小矩阵 A 和 B，让它们俩的乘积去"近似"权重矩阵需要的变化量。因为语言微调时的权重变化本身是低秩的，所以这个近似够用。省的东西具体体现在三个方面：可训练参数量从几十亿降到几百万、显存占用砍掉 70% 以上、训练和推理速度都明显变快。

详细内容

1. 参数量：从"全动"变成"只动 0.1%"3 个重点▾ 点开看本节重点
本节重点
  • 假设原模型某一层的权重矩阵是 W，维度 d×d，d 可能是 4096 或 8192

3

假设原模型某一层的权重矩阵是 W，维度 d×d，d 可能是 4096 或 8192。全量微调时 W 里所有 d² ≈ 1600 万到 6700 万个参数都要更新，还要给每个参数存一份梯度和一份优化器状态（Adam 要 m、v 两份）。

LoRA 的做法是：把要学的 ΔW 拆成两个小矩阵 B（d×r）和 A（r×d），其中 r 通常取 8 或 16。原来要学 d² ≈ 1600 万个数，现在只学 d×r + r×d ≈ 2×4096×8 ≈ 6.5 万个参数——参数量直接降到原来的 0.4% 左右。原模型的 W 全程冻结，不更新。

Sebastian Raschka 在《从零构建大模型》附录 E 专门有一节"使用 LoRA 进行参数高效微调"；《大语言模型：原理、应用与优化》第 7.3 节"低参数量微调"、第 7.4 节"超低参数量微调的探索"也是围绕这个思路展开的——为什么叫"低参数量"而不是"压缩"？因为它不是把模型本身变小，而是把"要训练的那部分"变小。

2. 显存：优化器状态这一块大头省了

3

训练时显存吃紧主要不是模型权重本身，而是每个可训练参数都要配套存：梯度（跟参数同大）、Adam 的动量 m（同大）、Adam 的方差 v（同大），加上混合精度还要一份副本。也就是说，可训练参数每多 1 个，实际要占 4-8 倍的显存。

全量微调一个 7B 模型，光优化器状态就要吃掉 7B×4×2 ≈ 56GB 显存——这就是为什么普通人单卡根本微调不动 7B 模型。

换成 LoRA 后，可训练参数从 7B 降到几百万，优化器状态也跟着缩到几百 MB。原模型权重虽然还得放显存里（以 FP16 冻结加载），但不用给它配套梯度和优化器状态。这是 LoRA 能在单张 24GB 卡上微调 7B 模型的关键。

《大语言模型：原理、应用与优化》第 6.5 节"内存优化策略"讲了 FlashAttention 等手段，但 LoRA 属于另一个方向——从"训练多少参数"这个根上省显存，而不是从计算细节上抠。

3. 训练速度和推理速度3 个重点▾ 点开看本节重点
本节重点
  • 训练时，因为可训练参数少，反向传播要更新的梯度少，optimizer step 快；同时冻结的原模型权重可以用更低精度（FP16/INT8）加载，减少显存读写
  • 《Happy-LLM》第 6.3 节"高效微调"就是把 LoRA 跟混合并行一起用——8 卡 A100 能轻松训百亿参数，其中 LoRA 贡献很大
  • 这是它比 Prefix-Tuning、Adapter 这类方法更受欢迎的原因之一
3

训练时，因为可训练参数少，反向传播要更新的梯度少，optimizer step 快；同时冻结的原模型权重可以用更低精度（FP16/INT8）加载，减少显存读写。《Happy-LLM》第 6.3 节"高效微调"就是把 LoRA 跟混合并行一起用——8 卡 A100 能轻松训百亿参数，其中 LoRA 贡献很大。

推理时更妙：LoRA 学完后，B×A 这个乘积可以直接合并回原权重 W，得到一个新的 W' = W + B×A，跟全量微调后的模型在推理时没有任何区别——没有额外计算开销，也不能说"LoRA 推理慢"。这是它比 Prefix-Tuning、Adapter 这类方法更受欢迎的原因之一。

另外一个隐性收益：一个基座模型可以挂多个 LoRA（不同任务、不同风格），切换时只换几 MB 的小矩阵，不用重新加载整个几十 GB 的模型权重。这在做"一个底座多场景部署"时是巨大的工程优势。

来自哪些书的哪些观点（标注来源）

2
  • 《从零构建大模型》（Sebastian Raschka）：附录 E"使用 LoRA 进行参数高效微调"——PEFT 是独立章节；大语言模型构建通常包括预训练和微调两个阶段，但微调不必动全部参数；针对特定领域定制的模型往往优于通用模型，这也是 LoRA 存在的意义。
  • 《大语言模型：原理、应用与优化》（苏之阳等）：7.2 全量参数微调、7.3 低参数量微调、7.4 超低参数量微调——三档对比；6.5 内存优化策略（FlashAttention、FP16/FP32 混合精度）是配套手段；9.1 模型小型化一节提到"减小参数位宽意味着更小的内存存储和更快的整数运算"，这个逻辑同样适用于 LoRA 减少可训练参数。
  • 《Happy-LLM：从零开始构建大模型》：6.3 节"高效微调"作为独立章节，跟预训练、SFT 并列；6.1 提到"利用混合并行训练方式，在 8 卡 A100 集群上可轻松支持百亿参数模型的高效训练"——LoRA 是能做到这件事的关键之一。
  • 《深度学习详解》（李宏毅）：第 17 章"网络压缩"提到知识蒸馏、深度可分离卷积——这些是模型侧的压缩思路，LoRA 是训练侧的参数高效思路，两者互补。
  • 《Transformer 模型开发从 0 到 1》：GPT 系列训练时使用混合权重的高质量数据集——说明预训练已经把基座训到位，后续微调只需在小范围参数上做适配，这是 LoRA 能 work 的前提。
