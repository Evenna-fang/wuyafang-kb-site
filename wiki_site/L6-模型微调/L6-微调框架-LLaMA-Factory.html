LLaMA-Factory 微调框架实操

本文以 LLaMA-Factory v0.9.3、Linux/WSL2、NVIDIA GPU、Python 3.11 为参考环境，用公开的 Qwen2.5 模型演示完整操作链。版本固定用于复现，不代表推荐永远使用旧版本。升级时应一起核对框架、Transformers、PEFT、TRL 和数据加载器的兼容范围。文中的命令供读者在训练机执行；阅读本文不会自动安装环境、下载模型或启动训练。

所有相对路径均从克隆后的 LLaMA-Factory 仓库根目录计算。代码上方标明保存位置的 YAML、JSON，请保存后再运行后续命令。全参、LoRA、QLoRA 是三条可选择的训练路线，推理示例统一使用 LoRA 路线的产物；选择其他路线时应相应替换模型目录。微型数据只用于验证链路，正式训练必须换成经过清洗和切分的业务数据。

LLaMA-Factory 把模型加载、模板适配、数据转换、训练算法与导出包装成统一命令入口。使用者主要维护数据注册表和 YAML，无需为每个模型重写训练循环。框架仍然依赖 Transformers、PEFT、Accelerate 等底层库；遇到兼容问题，应先确定错误发生在哪一层。

按职责可以理解为 data、model、training、hparams 四层，但 v0.9.3 的真实训练目录叫 train，不是 training。data 处理数据注册、对话模板和标签构造；model 负责 tokenizer、权重、量化和适配器加载；train 按 SFT、RM、DPO、KTO 等阶段组织训练器；hparams 定义和校验配置参数。排查未知参数找 hparams，排查角色或列名错误找 data，排查量化和适配器错误找 model。

训练参数里的 dataset 指向注册名，不是任意 JSON 文件路径。下面的注册脚本会保留已有条目，并追加自定义数据集；后面的偏好数据也预先在这里注册。保存每个数据文件后，执行脚本即可。file_name 相对 dataset_dir 解析，因此配置中使用 dataset_dir: data 时，注册项不能再重复加一层 data/。

# 在仓库根目录执行；只在读者自己的训练仓库更新注册表
import json
from pathlib import Path

path = Path("data/dataset_info.json")
registry = json.loads(path.read_text(encoding="utf-8")) if path.exists() else {}
registry.update({
    "tech_alpaca": {
        "file_name": "local/tech_alpaca.json",
        "columns": {"prompt": "instruction", "query": "input", "response": "output"}
    },
    "tech_sharegpt": {
        "file_name": "local/tech_sharegpt.json", "formatting": "sharegpt",
        "columns": {"messages": "conversations"},
        "tags": {"role_tag": "from", "content_tag": "value",
                 "user_tag": "human", "assistant_tag": "gpt"}
    },
    "tech_pref": {
        "file_name": "local/tech_pref.json", "ranking": True,
        "columns": {"prompt": "instruction", "query": "input",
                    "chosen": "chosen", "rejected": "rejected"}
    },
    "tech_kto": {
        "file_name": "local/tech_kto.json",
        "columns": {"prompt": "instruction", "query": "input",
                    "response": "output", "kto_tag": "label"}
    }
})
path.write_text(json.dumps(registry, ensure_ascii=False, indent=2), encoding="utf-8")
print("registered:", ", ".join(k for k in registry if k.startswith("tech_")))

tokenizer 长度与数据验收

3

cutoff_len 限制的是 token 长度，不是汉字数量。模板控制符、系统消息、多轮历史与答案都需要预算；直接统计文本字符会低估真实长度。下面用同一个模型的聊天模板作长度预检。它是快速筛查，框架正式预处理时还会处理监督掩码与特殊终止符，应继续抽查日志中打印的样本。

长样本被截断后，可能只剩很少答案 token，甚至完全失去有效监督。先查看长度分布，再选择缩短历史、拆分文档或增大上下文。验证集应按来源或会话拆分，避免同一问题的轻微改写同时落入训练和验证。

# 在仓库根目录执行，检查实际模板下的 token 长度和字段
import json
import numpy as np
from pathlib import Path
from transformers import AutoTokenizer

tok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-1.5B-Instruct")
rows = json.loads(Path("data/local/tech_alpaca.json").read_text(encoding="utf-8"))
lengths = []
for i, row in enumerate(rows):
    assert all(isinstance(row[k], str) for k in ("instruction", "input", "output")), i
    assert row["output"].strip(), f"第 {i} 条答案为空"
    user = "\n".join(x for x in [row["instruction"], row["input"]] if x)
    ids = tok.apply_chat_template([
        {"role": "user", "content": user},
        {"role": "assistant", "content": row["output"]}
    ], tokenize=True, add_generation_prompt=False)
    lengths.append(len(ids))
print("P50/P95/P99:", np.percentile(lengths, [50, 95, 99]))
print("超过 2048:", sum(n > 2048 for n in lengths), "/", len(lengths))
4. 训练方式一：SFT 全参微调3 个重点▾ 点开看本章重点
本章重点
  • 全参微调更新全部模型权重，优化器状态和梯度也随参数量增长
  • 先用较小模型验证数据、保存和恢复流程，再估算大模型资源
  • 下面保存为 「configs/qwen_full_sft.yaml」
2

全参微调更新全部模型权重，优化器状态和梯度也随参数量增长。先用较小模型验证数据、保存和恢复流程，再估算大模型资源。下面保存为 configs/qwen_full_sft.yaml。两条 Alpaca 加一条多轮数据仅供链路检查，演示中不切验证集；真实实验需要独立验证数据，并配置 eval_dataset、eval_strategy 和评测间隔。

# configs/qwen_full_sft.yaml：完整配置
model_name_or_path: Qwen/Qwen2.5-1.5B-Instruct # 基础模型与 tokenizer 来源
stage: sft # 监督微调阶段
do_train: true # 启用训练
finetuning_type: full # 更新全部参数
dataset_dir: data # 注册表所在目录
dataset: tech_alpaca,tech_sharegpt # 使用上节注册的两份数据
template: qwen # 匹配 Qwen2.5 的对话模板
cutoff_len: 2048 # 模板编码后的最大序列长度
preprocessing_num_workers: 2 # 数据预处理进程数
dataloader_num_workers: 0 # 小规模实验采用主进程加载
output_dir: outputs/qwen-full-sft # 全参模型和检查点输出目录
logging_steps: 1 # 每个更新步记录日志
save_steps: 50 # 检查点保存间隔
save_total_limit: 2 # 限制保留的检查点数量
per_device_train_batch_size: 1 # 每张卡上的微批量
gradient_accumulation_steps: 8 # 累积八次后更新参数
learning_rate: 1.0e-5 # 全参微调采用较小初始学习率
num_train_epochs: 3.0 # 数据遍历次数
lr_scheduler_type: cosine # 余弦学习率调度
warmup_ratio: 0.05 # 预热步数比例
bf16: true # 要求设备支持 BF16
gradient_checkpointing: true # 用重复计算减少激活显存
plot_loss: true # 输出损失曲线
report_to: none # 不使用外部实验跟踪服务
seed: 42 # 固定随机种子

# 单卡全参训练；BF16 不支持的卡需同时关闭 bf16 并开启 fp16
CUDA_VISIBLE_DEVICES=0 llamafactory-cli train configs/qwen_full_sft.yaml
# 下列是替代启动方式，适用于不支持 BF16 的设备
CUDA_VISIBLE_DEVICES=0 llamafactory-cli train configs/qwen_full_sft.yaml \
  bf16=false fp16=true output_dir=outputs/qwen-full-fp16

ZeRO-3 中的保存聚合选项便于得到可直接加载的权重，但保存瞬间仍有额外开销。CPU offload 可以进一步减少显存，代价是主存、PCIe 通信和训练速度，不能理解为免费扩容。下面的两个命令是替代方案，按硬件与模型选择其中之一。

  llamafactory-cli train configs/qwen_full_sft.yaml \

# 双卡 ZeRO-3

5. 训练方式二：LoRA、QLoRA 与导出

2

LoRA 冻结基础权重，只训练低秩增量。QLoRA 在此基础上把冻结的基础模型以低比特表示，适配器计算与梯度并不是全部变成四比特。保存下面配置为 configs/qwen_lora_sft.yaml。它使用同一个较小模型，便于把后续推理链路先跑通；迁移到七十亿参数模型时，先重新做显存测量。

在 PEFT Python API 中常见的参数名是 target_modules，在本版本 LLaMA-Factory YAML 中对应 lora_target。直接写 target_modules 会触发未知参数或解析错误。all 覆盖适用的线性层，通常比仅注意力投影有更强适配能力，同时增加可训练参数；自定义模块名应先检查模型结构。

# configs/qwen_lora_sft.yaml：完整 LoRA 配置
model_name_or_path: Qwen/Qwen2.5-1.5B-Instruct # 基础模型
stage: sft # 监督微调
do_train: true # 开启训练
finetuning_type: lora # 冻结主干，训练适配器
lora_rank: 16 # 低秩矩阵的秩
lora_alpha: 32 # LoRA 缩放系数
lora_dropout: 0.05 # LoRA 分支的 dropout
lora_target: q_proj,k_proj,v_proj,o_proj # 对应 PEFT target_modules
dataset_dir: data # 数据注册表目录
dataset: tech_alpaca,tech_sharegpt # 本地训练集
template: qwen # 模型对话模板
cutoff_len: 2048 # 上下文预算
output_dir: outputs/qwen-lora-sft # 适配器保存目录
per_device_train_batch_size: 1 # 每卡微批量
gradient_accumulation_steps: 8 # 梯度累积

1.5B 约 0.70 GiB 约 4–8 GiB 适合先验证流程
7B–8B 约 3.26–3.73 GiB 约 10–18 GiB 二十四 GB 卡通常更有余量
13B–14B 约 6.05–6.52 GiB 约 18–30 GiB 二十四 GB 可能需要进一步压缩配置

9. eval 模式：MMLU 与 C-Eval

2

训练中的验证 loss 与知识选择题 benchmark 是不同指标。llamafactory-cli eval 使用专门的评测参数，其中 task 需要包含任务名和切分名，例如 mmlu_test、ceval_validation。C-Eval 本地有答案的验证集适合复现实验，测试集通常用于官方评测流程；不要把无有效答案的测试文件直接用于本地准确率计算。

该版本的评测依赖本地 evaluation 下的数据脚本、题库压缩包和 mapping.json。如果源码分发未带题库，必须先准备资源。下面从公开原始来源下载 MMLU 和 C-Eval，将 MMLU 原始 tar 转成脚本所需的 zip，并根据题库生成映射。为避免伪造学科归属，映射统一归入 Other，可用于总准确率比较；要看官方大类分数，应换成官方完整分类映射。

# 在训练仓库执行一次：准备公开 benchmark 资源，不使用业务训练数据
import io
import json
import tarfile
import urllib.request
import zipfile
from pathlib import Path

def save_mapping(folder, subjects):
    mapping = {name: {"name": name.replace("_", " "), "category": "Other"}
               for name in sorted(subjects)}
    (folder / "mapping.json").write_text(json.dumps(mapping, indent=2), encoding="utf-8")
    print(folder, "subjects:", len(mapping))

mmlu = Path("evaluation/mmlu")
ceval = Path("evaluation/ceval")
mmlu.mkdir(parents=True, exist_ok=True)
ceval.mkdir(parents=True, exist_ok=True)
# 上游发布的是 tar，LLaMA-Factory 的脚本使用名为 mmlu.zip 的文件
raw = urllib.request.urlopen("https://people.eecs.berkeley.edu/~hendrycks/data.tar", timeout=180).read()
subjects = set()
with tarfile.open(fileobj=io.BytesIO(raw), mode="r:*") as src, \
     zipfile.ZipFile(mmlu / "mmlu.zip", "w", compression=zipfile.ZIP_DEFLATED) as dst:
    for member in src.getmembers():
        if member.isfile() and member.name.endswith(".csv"):
            name = member.name.removeprefix("./")
            stream = src.extractfile(member)
            assert stream is not None
            dst.writestr(name, stream.read())
            if name.startswith("data/test/") and name.endswith("_test.csv"):
                subjects.add(Path(name).name.removesuffix("_test.csv"))
assert subjects, "MMLU 压缩包结构与预期不符"

url = "https://huggingface.co/datasets/ceval/ceval-exam/resolve/main/ceval.zip"
urllib.request.urlretrieve(url, ceval / "ceval.zip")
with zipfile.ZipFile(ceval / "ceval.zip") as src:
    subjects = {Path(name).name.removesuffix("_val.csv") for name in src.namelist()
                if name.startswith("val/") and name.endswith("_val.csv")}
assert subjects, "C-Eval 压缩包结构与预期不符"

显存 OOM：先定位，再按六条路线处理

3

先判断是在模型加载、前向、反向、优化器更新还是保存时失败。加载阶段 OOM 通常与参数副本有关，首次优化器更新时的增长可能来自状态初始化；长样本偶发 OOM 则更接近激活峰值。查看 GPU 上的真实进程，记录失败时的序列长度和配置，不要只截最后一行错误。

六种常用处理方式如下；每次先改一项并保留独立输出目录，便于确认改善来自哪里。

  1. 减小每卡微批量，再用梯度累积恢复有效批量；已经为一时不能继续减。
  2. 缩短序列长度并清理异常长样本，同时确认目标答案仍保留足够监督 token。
  3. 开启梯度检查点，以额外计算换激活显存；支持时配合 FA2 或 SDPA。
  4. 调整精度或训练方式，从全参转 LoRA/QLoRA；这会改变实验方法，需要重新记录基线。
  5. 分片模型状态或 offload，使用 ZeRO-3，必要时将状态卸载到 CPU；提前评估主存与通信成本。
  6. 清理本任务闲置模型进程并处理碎片，可设置分配器选项；只有实际存在闲置副本或碎片时才有效。

CPU offload 是第五条路线的具体例子。它把 ZeRO-3 的参数与优化器状态卸载到主存，对机器内存要求很高；当主存不足时可能转而触发系统杀进程。下面生成独立配置，不覆盖前面的 ZeRO 基线。

# 从现有 ZeRO-3 配置生成 CPU offload 版本
python - <<'PY'
import json
from pathlib import Path
p = Path("configs/ds_zero3.json")
cfg = json.loads(p.read_text())
cfg["zero_optimization"].update({
    "offload_optimizer": {"device": "cpu", "pin_memory": True},
    "offload_param": {"device": "cpu", "pin_memory": True}
})
Path("configs/ds_zero3_offload.json").write_text(json.dumps(cfg, indent=2))
PY
FORCE_TORCHRUN=1 CUDA_VISIBLE_DEVICES=0,1 NPROC_PER_NODE=2 \
  llamafactory-cli train configs/qwen_full_sft.yaml \
  deepspeed=configs/ds_zero3_offload.json output_dir=outputs/oom-offload

torch.cuda.empty_cache() 只释放未使用的缓存，不会释放仍被 Python 引用的张量，也不能让单样本超过物理显存的模型突然可训练。评测阶段 OOM 要减评测批量和生成长度，保存阶段 OOM 要关注权重聚合；不要只修改训练批量。

pad_token 与 tokenizer 不一致3 个重点▾ 点开看本节重点
本节重点
  • 框架模板通常会修复 tokenizer 的必要特殊 token
  • 先检查原始配置、训练日志与导出目录，确认训练和推理使用同一套 tokenizer
  • 自写推理代码若发现没有 pad token，可以在存在 EOS 的前提下复用 EOS，并明确传入 attention mask；不能据此在训练时把所有等于 EOS 的标签一律屏蔽
3

框架模板通常会修复 tokenizer 的必要特殊 token。先检查原始配置、训练日志与导出目录，确认训练和推理使用同一套 tokenizer。自写推理代码若发现没有 pad token，可以在存在 EOS 的前提下复用 EOS，并明确传入 attention mask；不能据此在训练时把所有等于 EOS 的标签一律屏蔽。

# 自写 Transformers 推理的实际处理；不修改已保存的 tokenizer 文件
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

path = "outputs/qwen-merged"
tok = AutoTokenizer.from_pretrained(path, padding_side="left")
model = AutoModelForCausalLM.from_pretrained(path, torch_dtype="auto").to("cuda")
if tok.pad_token_id is None:
    if tok.eos_token_id is None:
        raise ValueError("没有 EOS，需显式新增 PAD 并同步调整词嵌入")
    tok.pad_token = tok.eos_token
model.config.pad_token_id = tok.pad_token_id
text = tok.apply_chat_template([{"role": "user", "content": "解释梯度检查点。"}],
                               tokenize=False, add_generation_prompt=True)
batch = tok([text], padding=True, return_tensors="pt").to(model.device)
with torch.inference_mode():
    result = model.generate(**batch, max_new_tokens=128, do_sample=False,
                            pad_token_id=tok.pad_token_id)
print(tok.decode(result[0, batch["input_ids"].shape[1]:], skip_special_tokens=True))

如果新增一个全新的 PAD token，必须让模型词嵌入同步扩容，并在保存与导出时保留相应权重；本版本量化路径不能随意调整 embedding 大小。对现有 Qwen 模型通常应先沿用官方 tokenizer，避免在排查中额外引入词表变化。

loss 不下降与数据字段错误

3

loss 不下降先检查是否确实存在非空答案、模板是否匹配，以及样本是否被截成只剩提示。接着确认 LoRA 目标模块存在、日志显示有可训练参数，再观察学习率、梯度范数和有限数值。用少量干净样本做短时间过拟合实验，可以验证优化链路是否成立，但不能将过拟合结果当作泛化证明。

常见的 Undefined dataset 是注册名错误；KeyError 常来自 columns 指向不存在的原始字段；角色警告可能来自 ShareGPT 的顺序和 tags。修改数据或模板后，应使用新缓存路径或覆盖预处理缓存。若已经设置 tokenized_path，缓存优先级会影响重新预处理，必须同步检查，不能只修改 JSON 后假定训练一定读取了新内容。
