DeepSpeed 分布式训练与大模型微调实操

本文围绕单机多卡到多节点的实际操作组织。主线使用 Hugging Face Trainer 完成因果语言模型训练，再切换 ZeRO 阶段、卸载方式和启动器。示例默认 Linux、NVIDIA GPU、已匹配的 CUDA 版 PyTorch；模型采用公开的 Qwen/Qwen2.5-0.5B，先用小模型验证链路，再替换成目标大模型。文中的下载命令需要网络；内部数据训练应改为本地路径，并保持 report_to="none"。本文不执行训练或下载。

JSON 块均为严格合法的 JSON，不添加双斜线注释。每个字段的单行说明紧随配置；同名字段在后续配置中沿用其解释。不要把正文说明复制进 JSON。示例路径和设备数量对应明确的实验环境，迁移时先核对磁盘、GPU 数量、网络及模型访问权限。

DeepSpeed 是训练与推理运行时：接管分布式通信、优化器执行、混合精度和状态切分，而数据清洗、指令模板与数据集切分通常由上层框架负责。ZeRO 沿数据并行组切分训练状态；流水线并行沿网络层切分；张量并行把层内部的大矩阵拆开。三者可以在支持的模型实现中形成三维并行，但不是往普通 Trainer 配置里填三个数字就自动生效。

混合精度用较少字节保存部分张量并加速矩阵计算；梯度检查点通过反向时重算前向降低激活占用。两者与 ZeRO 解决不同的内存来源。先确定瓶颈究竟是参数、优化器状态还是长序列激活，再选择开关，避免显存下降却因通信和重算使训练时间失控。

方案 主要职责 典型入口 适合的实际情况
DeepSpeed ZeRO 切分优化器、梯度、参数，支持 CPU/NVMe 卸载 Trainer 的 deepspeed 参数 单机多卡微调到跨节点扩展，需要显存与卸载选项
PyTorch FSDP 原生参数、梯度和优化器状态分片 PyTorch FSDP 或框架适配 已有 PyTorch 分布式工程，希望减少外部运行时依赖
Megatron-Core 面向 Transformer 的张量、流水线及上下文并行 Megatron 训练工程 超大模型预训练，愿意适配模型结构和并行检查点

三者并非只按速度排名。网络拓扑、算子实现、模型结构和保存格式会决定真实结果。下面先读取 GPU 能力，确认是否适合后文的 BF16 路径。

3. ZeRO 阶段、切分原理与显存估算3 个重点▾ 点开看本章重点
本章重点
  • 设参数数量为 P，数据并行卡数为 D
  • 尤其 70B 的 stage 3 静态状态已约 130 GiB/卡，不能据此声称八张 80GB 卡可直接全参数训练
  • 采用经典混合精度 Adam 模型状态口径：低精度参数每参数 2 字节，低精度梯度 2 字节，FP32 主参数与两个动量共 12 字节
2

设参数数量为 P，数据并行卡数为 D。采用经典混合精度 Adam 模型状态口径：低精度参数每参数 2 字节，低精度梯度 2 字节，FP32 主参数与两个动量共 12 字节。于是每卡静态状态约为：stage 0：16P；stage 1：4P+12P/D；stage 2：2P+14P/D；stage 3：16P/D。这里的 stage 0 是未开启 ZeRO 的基准，不属于“三个切分阶段”。实际 BF16 梯度累积精度、优化器实现和量化方案可能改变字节数。

1 按 D 切分 每卡完整 每卡完整 更新后的参数同步

5. 接入 Hugging Face Trainer 的完整训练脚本

2

将以下代码保存为实验目录的 train.py。默认训练内置中文样本，便于先排除数据读取因素；正式训练通过 --data_path train.jsonl 指向包含 text 字段的本地 JSONL。这里采用普通续写目标，助手回复监督训练应由数据模板和标签掩码实现，不能把所有指令文本都当作仅回复损失。

关键顺序是先创建 TrainingArguments，再加载模型，使 Transformers 有机会在加载时识别 ZeRO-3。不要使用 device_map="auto"；那是模型分发/推理常见入口，不能代替这里的一进程一卡训练。脚本不提前执行 model.cuda()，设备分配交给 Trainer 与 DeepSpeed。

import argparse
import os
import torch
from datasets import Dataset, load_dataset
from transformers import (
    AutoModelForCausalLM, AutoTokenizer, DataCollatorForLanguageModeling,
    Trainer, TrainingArguments, set_seed,
)


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--model_name_or_path", default="Qwen/Qwen2.5-0.5B")
    parser.add_argument("--data_path", default=None)
    parser.add_argument("--deepspeed", default="ds_config.json")
    parser.add_argument("--output_dir", default="./outputs/qwen-ds")
    parser.add_argument("--max_steps", type=int, default=40)
    parser.add_argument("--resume_from_checkpoint", default=None)
    parser.add_argument("--local_rank", "--local-rank", type=int, default=-1)
    cli = parser.parse_args()
    set_seed(42)
    if not torch.cuda.is_available():
        raise RuntimeError("此示例需要 CUDA GPU")
    local_rank = int(os.environ.get("LOCAL_RANK", max(cli.local_rank, 0)))
    torch.cuda.set_device(local_rank)
    if not torch.cuda.is_bf16_supported():
        raise RuntimeError("GPU 不支持 BF16，请按第 9 节同步改用 FP16")

    args = TrainingArguments(
        output_dir=cli.output_dir,
        deepspeed=cli.deepspeed,
        per_device_train_batch_size=1,
        gradient_accumulation_steps=8,
        learning_rate=2e-5,
        weight_decay=0.01,
        adam_beta1=0.9,
        adam_beta2=0.999,
        adam_epsilon=1e-8,
        warmup_steps=5,
        max_steps=cli.max_steps,
        max_grad_norm=1.0,
        bf16=True,
        fp16=False,
        gradient_checkpointing=True,
        logging_steps=5,
        save_strategy="steps",
        save_steps=20,
        save_total_limit=2,
        report_to="none",
        ddp_timeout=1800,
        dataloader_num_workers=0,
        seed=42,
    )
    tokenizer = AutoTokenizer.from_pretrained(cli.model_name_or_path)
    if tokenizer.pad_token_id is None:
        tokenizer.pad_token = tokenizer.eos_token
    tokenizer.padding_side = "right"
    model = AutoModelForCausalLM.from_pretrained(
        cli.model_name_or_path, torch_dtype=torch.bfloat16
    )
    model.config.use_cache = False
    if cli.data_path:
        raw = load_dataset("json", data_files=cli.data_path, split="train")
    else:
        raw = Dataset.from_dict({"text": [
            "分布式训练需要让各个进程以相同顺序参加集合通信。",
            "梯度累积可以在不增加单次前向显存的情况下增大全局批量。",
            "保存检查点应同时考虑优化器状态、随机数状态和恢复位置。",
            "显存估算需要包含参数、梯度、优化器和中间激活。",
        ] * 64})
    if "text" not in raw.column_names:
        raise ValueError("JSONL 每条记录必须包含 text 字段")

    def tokenize(batch):
        return tokenizer(batch["text"], truncation=True, max_length=512)

    data = raw.map(tokenize, batched=True, remove_columns=raw.column_names)
    collator = DataCollatorForLanguageModeling(tokenizer=tokenizer, mlm=False)
    trainer = Trainer(model=model, args=args, train_dataset=data,
                      data_collator=collator)
    result = trainer.train(resume_from_checkpoint=cli.resume_from_checkpoint)
    trainer.log_metrics("train", result.metrics)
    trainer.save_metrics("train", result.metrics)
    trainer.save_model(cli.output_dir)
    if trainer.is_world_process_zero():
        tokenizer.save_pretrained(cli.output_dir)


if __name__ == "__main__":
    main()

示例通过动态补齐构造批次，损失标签由数据整理器生成；填充位置被忽略。正式数据应预先检查空文本、超长截断比例和有效标签数。若把 EOS 同时用作 PAD，默认整理器也会屏蔽同标识位置，精细控制结束符监督时应写专用整理器。先用固定长度、固定数据量比较配置，再引入 packing，否则很难分辨吞吐变化来自运行时还是数据组织。

以下两个命令是同一训练脚本的两种启动入口，二选一执行，不能把 deepspeed 包在 torchrun 外面。--num_gpus 是启动器参数，脚本后的 --deepspeed 是脚本接收的配置路径。此处假定单机可见四张 GPU，配置中的全局批量由 Trainer 根据实际 world size 补齐。

# 单机四卡，使用 DeepSpeed 启动器。
deepspeed --num_gpus 4 train.py --deepspeed ds_config.json

7. ZeRO-Infinity 与 NVMe 卸载

2

CPU 卸载把优化器状态或参数移到主内存，NVMe 卸载进一步用本地固态盘承载状态。ZeRO-Infinity 主要面向 ZeRO-3 的分层内存管理；offload_optimizer 可用于 ZeRO-1/2/3，offload_param 只适用于 ZeRO-3。它适合显存不足、主存也吃紧、且能接受磁盘吞吐代价的任务，不适合把低速网络盘冒充本地 NVMe。

将以下完整配置保存为 ds_nvme.json，在每个节点提前准备 /local_nvme/ds。同机不同任务应使用不同目录，以免临时交换文件混在一起。需要额外核对容量、挂载点及各进程读写权限；空目录存在不代表底层是 NVMe。

{
  "train_batch_size": "auto",
  "train_micro_batch_size_per_gpu": "auto",
  "gradient_accumulation_steps": "auto",
  "gradient_clipping": "auto",
  "bf16": {"enabled": "auto"},
  "zero_optimization": {
    "stage": 3,
    "offload_optimizer": {
      "device": "nvme",
      "nvme_path": "/local_nvme/ds",
      "pin_memory": true,
      "buffer_count": 4,
      "pipeline_read": true,
      "pipeline_write": true
    },
    "offload_param": {
      "device": "nvme",
      "nvme_path": "/local_nvme/ds",
      "pin_memory": true,
      "buffer_count": 5,
      "buffer_size": 100000000,
      "max_in_cpu": 1000000000
    },
    "sub_group_size": 100000000,
    "stage3_gather_16bit_weights_on_model_save": true
  },
  "aio": {
    "block_size": 1048576,
    "queue_depth": 8,
    "thread_count": 1,
    "single_submit": false,
    "overlap_events": true
  },
  "optimizer": {
    "type": "AdamW",
    "params": {"lr": "auto", "betas": "auto", "eps": "auto", "weight_decay": "auto"}
  },
  "scheduler": {
    "type": "WarmupDecayLR",
    "params": {"total_num_steps": "auto", "warmup_min_lr": 0, "warmup_max_lr": "auto", "warmup_num_steps": "auto"}
  }
}
  • offload_optimizer：优化器状态卸载配置容器。
  • offload_param：参数卸载配置容器。
  • device：此处为 NVMe，改为 cpu 时不再依赖磁盘交换路径。
  • nvme_path：每台机器上的本地卸载路径。
  • pin_memory：使用锁页主存，可能提高传输速度，但会增加不可换出的内存。
  • offload_optimizer.buffer_count：优化器交换缓冲区个数，Adam 通常至少需要四个状态缓冲区。
  • pipeline_read：尝试把下一块状态读取与当前计算重叠。
  • pipeline_write：尝试把上一块状态写回与当前计算重叠。
  • offload_param.buffer_count：参数交换缓冲区个数。
  • buffer_size：单个参数缓冲区的元素数量。
  • max_in_cpu：使用 NVMe 时允许在 CPU 保留的参数元素数量。
  • sub_group_size：优化器处理参数分组粒度，可影响临时内存与交换行为。
  • aio：顶层异步输入输出配置容器，不能放进 offload_param。
  • block_size：一次输入输出块的字节大小。
  • queue_depth：异步请求队列深度。
  • thread_count：单请求内部读写并行线程数。
  • single_submit：是否逐个提交请求，此例批量提交。
  • overlap_events：是否重叠处理异步事件。

8. 三维并行：数据、流水线、张量并行3 个重点▾ 点开看本章重点
本章重点
  • 示例采用小型全连接网络以完整展示 API，不能据此认为任意 Hugging Face 模型无需改造就支持流水线
  • 原生 「PipelineModule」 当前不兼容 ZeRO-2/3；这里使用 stage 0，避免把互不兼容的配置拼在一起
  • 需要完整的 TP×PP×DP 大模型训练时，应采用提供模型张量切分实现及并行组管理的训练工程，例如 Megatron-DeepSpeed，并按其版本支持选择 ZeRO 阶段
2

并行规模满足总进程数 W=DP×PP×TP，但 ZeRO 的 D 是对应数据并行组大小，而不是无条件等于全部 GPU 数量。下面给出可运行的原生 DeepSpeed 流水线示例：八卡分成两段流水线，每段四个数据并行副本，因此 PP=2、DP=4、TP=1。示例采用小型全连接网络以完整展示 API，不能据此认为任意 Hugging Face 模型无需改造就支持流水线。

原生 PipelineModule 当前不兼容 ZeRO-2/3；这里使用 stage 0，避免把互不兼容的配置拼在一起。需要完整的 TP×PP×DP 大模型训练时，应采用提供模型张量切分实现及并行组管理的训练工程，例如 Megatron-DeepSpeed，并按其版本支持选择 ZeRO 阶段。

# 保存为 train_pipe.py，随后用八卡命令启动。
import torch
import deepspeed
from torch import nn
from torch.utils.data import TensorDataset
from deepspeed.pipe import PipelineModule, LayerSpec


def main():
    deepspeed.init_distributed()
    torch.manual_seed(42)
    model = PipelineModule(
        layers=[LayerSpec(nn.Linear, 32, 64), LayerSpec(nn.ReLU),
                LayerSpec(nn.Linear, 64, 2)],
        loss_fn=nn.CrossEntropyLoss(),
        num_stages=2,
        partition_method="uniform",
        activation_checkpoint_interval=1,
    )
    data = TensorDataset(torch.randn(1024, 32), torch.randint(0, 2, (1024,)))
    config = {
        "train_batch_size": 32,
        "train_micro_batch_size_per_gpu": 2,
        "gradient_accumulation_steps": 4,
        "zero_optimization": {"stage": 0},
        "optimizer": {"type": "Adam", "params": {"lr": 0.001}},
    }
    engine, _, _, _ = deepspeed.initialize(
        model=model, model_parameters=model.parameters(),
        training_data=data, config=config,
    )
    for _ in range(10):
        engine.train_batch()


if __name__ == "__main__":
    main()

# 八张 GPU：2 段流水线 × 4 个数据副本，批量为 2×4×4=32。
deepspeed --num_gpus 8 train_pipe.py

inference、kernel_inject 常出现在张量并行介绍中，但 deepspeed.init_inference 创建的是推理引擎。它不能替代上面的训练配置。以下 GPT-2 示例使用两卡推理张量并行；replace_with_kernel_inject 是 Python 接口名，配置模型中也可见 kernel_inject 别名。模型必须受当前版本的注入策略支持。

# 保存为 infer_tp.py，使用下一条命令启动。
import os
import torch
import deepspeed
from transformers import AutoModelForCausalLM, AutoTokenizer

deepspeed.init_distributed()
local_rank = int(os.environ["LOCAL_RANK"])
torch.cuda.set_device(local_rank)
tokenizer = AutoTokenizer.from_pretrained("openai-community/gpt2")
model = AutoModelForCausalLM.from_pretrained(
    "openai-community/gpt2", torch_dtype=torch.float16
)
engine = deepspeed.init_inference(
    model=model,
    dtype=torch.float16,
    tensor_parallel={"tp_size": 2},
    replace_with_kernel_inject=True,
)
inputs = tokenizer("Distributed training", return_tensors="pt").to(local_rank)
with torch.no_grad():
    logits = engine(**inputs).logits
if int(os.environ["RANK"]) == 0:
    print(tuple(logits.shape))

# 这是两卡推理，不是 Trainer 的训练张量并行开关。
deepspeed --num_gpus 2 infer_tp.py

9. 混合精度、激活检查点与 Adam 实现

2

支持 BF16 的 GPU 通常优先 BF16，因为其指数范围更接近 FP32。FP16 需要动态损失缩放，若发生溢出应检查数据、学习率和缩放日志，而不是只把跳过更新误判为通信卡住。下面片段替换完整配置的精度块，不能同时启用 BF16 和 FP16；第 5 节脚本也需同步改为 bf16=False、fp16=True、模型加载类型改为 torch.float16，并移除 BF16 能力检查。

{
  "bf16": {"enabled": false},
  "fp16": {
    "enabled": true,
    "loss_scale": 0,
    "initial_scale_power": 16,
    "loss_scale_window": 1000,
    "hysteresis": 2,
    "min_loss_scale": 1
  }
}
  • fp16：半精度与损失缩放配置容器。
  • fp16.enabled：启用 FP16；必须与训练参数保持一致。
  • loss_scale：零表示动态损失缩放。
  • initial_scale_power：初始缩放取二的该次幂。
  • loss_scale_window：连续稳定更新达到该窗口后尝试提高缩放。
  • hysteresis：降低缩放前的溢出容忍计数。
  • min_loss_scale：损失缩放下限。

Trainer 的 gradient_checkpointing=True 会调用模型自身的激活重算实现。DeepSpeed 的 activation_checkpointing 属于另一套 API；仅添加配置并不会自动改写任意模型前向。下面展示原生重算的完整最小例子，保存为 checkpoint_demo.py 后可单卡运行。普通单卡示例不启用激活分片，多维模型并行工程还需传入正确的并行组管理对象。

import torch
import deepspeed
from deepspeed import checkpointing

torch.cuda.set_device(0)
checkpointing.configure(mpu_=None, deepspeed_config={
    "activation_checkpointing": {
        "partition_activations": False,
        "contiguous_memory_optimization": False,
        "cpu_checkpointing": False,
        "synchronize_checkpoint_boundary": False,
        "profile": False
    }
})
layer = torch.nn.Sequential(torch.nn.Linear(128, 512), torch.nn.GELU(),
                            torch.nn.Linear(512, 128)).cuda()
x = torch.randn(4, 128, device="cuda", requires_grad=True)
checkpointing.checkpoint(layer, x).square().mean().backward()
print("gradient norm:", layer[0].weight.grad.norm().item())
  • activation_checkpointing：DeepSpeed 激活重算配置容器。
  • partition_activations：是否沿模型并行组切分保存的激活。
  • contiguous_memory_optimization：是否使用连续激活缓冲区，启用时还需满足缓冲区数量等约束。
  • cpu_checkpointing：是否将检查点激活转存 CPU，需按并行配置验证支持条件。
  • synchronize_checkpoint_boundary：是否在检查点边界同步，用于调试或计时。
  • profile：是否记录检查点前后向耗时。

CPU Adam 在 CPU 上更新卸载的优化器状态，Fused Adam 面向 GPU 融合更新。不要因为看到 AdamW 名称就认定实现相同；应查看实际优化器类及算子加载日志。下面直接检验两种类的构建路径，不建议在 Trainer 之外重复创建另一份优化器交给同一模型。

import torch
from deepspeed.ops.adam import DeepSpeedCPUAdam, FusedAdam

cpu_parameter = torch.nn.Parameter(torch.randn(8))
cpu_opt = DeepSpeedCPUAdam([cpu_parameter], lr=2e-5, adamw_mode=True)
cpu_parameter.square().sum().backward()
cpu_opt.step()
print(type(cpu_opt).__name__)
gpu_parameter = torch.nn.Parameter(torch.randn(8, device="cuda"))
gpu_opt = FusedAdam([gpu_parameter], lr=2e-5, adam_w_mode=True)
gpu_parameter.square().sum().backward()
gpu_opt.step()
print(type(gpu_opt).__name__)
10. 批量、通信和吞吐调优3 个重点▾ 点开看本章重点
本章重点
  • 全局批量等于每卡微批量乘梯度累积次数乘数据并行副本数
  • 纯 ZeRO 数据并行下，四卡、每卡一条、累积八次，对应每次更新三十二条样本
  • 固定全局批量时，提高微批、减少累积可能增加计算效率，但会增加激活峰值
2

全局批量等于每卡微批量乘梯度累积次数乘数据并行副本数。纯 ZeRO 数据并行下，四卡、每卡一条、累积八次，对应每次更新三十二条样本。固定全局批量时，提高微批、减少累积可能增加计算效率，但会增加激活峰值。存在流水线或张量并行时，要用 DP 副本数，不能把总卡数都乘进去。

# 同时给出样本吞吐与有效 token 吞吐计算，计时需覆盖完整更新区间。
micro_batch, accumulation, dp = 1, 8, 4
global_batch = micro_batch * accumulation * dp
measured_updates, elapsed_seconds = 100, 240.0
processed_nonpadding_tokens = 1500000
print("global_batch:", global_batch)
print("samples/sec:", global_batch * measured_updates / elapsed_seconds)
print("nonpadding tokens/sec:", processed_nonpadding_tokens / elapsed_seconds)

统计应跳过首次算子编译和预热，不在比较区间插入保存或评估；固定序列长度和 packing 策略。多进程计时必须取最慢进程耗时，不能将各 rank 的每秒样本数随意重复相加。Trainer 的 train_samples_per_second 是一次训练整体指标，通常包含启动和保存开销，适合任务级比较；稳定区间的更新吞吐需另取连续日志或 profiling。

用户有时把开关写成 zero_optimization_overlap_comm，这不是 DeepSpeed JSON 中的合法顶层字段；正确位置是 zero_optimization.overlap_comm。通信桶越大，调用次数可能越少，但缓冲区占用越高。先保持其他变量不变，分别比较重叠开关，再试桶大小；显存接近上限时先降低桶，不要盲目打开更多预取。

# 从现有 ZeRO-2 配置生成一个关闭重叠、减小通信桶的对照文件。
python - <<'PY'
import json
with open("ds_config.json", encoding="utf-8") as f:
    cfg = json.load(f)
zero = cfg["zero_optimization"]
zero["overlap_comm"] = False
zero["contiguous_gradients"] = True
zero["reduce_bucket_size"] = 20000000
zero["allgather_bucket_size"] = 20000000
with open("ds_zero2_small_bucket.json", "w", encoding="utf-8") as f:
    json.dump(cfg, f, indent=2)
PY
# 分开运行两组实验，避免输出目录相互覆盖。
torchrun --standalone --nproc_per_node=4 train.py \
  --deepspeed ds_zero2_small_bucket.json --output_dir outputs/small-bucket

训练时可以运行 nvidia-smi dmon 观察 GPU 利用率与显存，在独立监控终端运行 iostat -x 1 查看卸载磁盘等待。若输入数据加载慢，优先改数据预处理和 DataLoader，而不是把通信参数改一遍。不同阶段应记录相同的样本数、有效 token 数、更新步数和峰值显存，才能解释速度变化。

  --output_dir outputs/qwen-swift-ds3 \
  --report_to none

调试卸载策略时可把最后的预设替换成 --deepspeed ds_nvme.json，前提是该版本支持文件路径且训练参数与 JSON 一致。LLaMA-Factory、SWIFT 的检查点目录布局、模板处理和续训参数存在差异，不应直接互换运行目录。跨框架迁移通常先导出普通模型，再按新框架重建优化器。

13.1 NCCL 超时与进程组不一致3 个重点▾ 点开看本节重点
本节重点
  • 先找最早出错的 rank
  • 一个进程先 OOM 或数据加载异常，其他进程往往最后才报 NCCL watchdog 超时；延长等待不能解决最初的问题
  • 「NCCL_IB_TIMEOUT」 是 InfiniBand 传输参数，不等于训练集合通信超时
3

先找最早出错的 rank。一个进程先 OOM 或数据加载异常，其他进程往往最后才报 NCCL watchdog 超时；延长等待不能解决最初的问题。NCCL_TIMEOUT 常见于第三方启动脚本，但不是通用有效的 NCCL 官方进程组超时开关；Trainer 应设置 ddp_timeout，原生 PyTorch 应给 init_process_group 的 timeout 传 timedelta。NCCL_IB_TIMEOUT 是 InfiniBand 传输参数，不等于训练集合通信超时。

# 先打开日志；eth0 只是示例，实际网卡先用 ip -br addr 确认。
ip -br addr
NCCL_DEBUG=INFO TORCH_DISTRIBUTED_DEBUG=DETAIL \
  torchrun --standalone --nproc_per_node=2 train.py --deepspeed ds_config.json
# 仅用于已经确认 eth0 是训练互通网卡的多节点环境。
export NCCL_SOCKET_IFNAME=eth0

第 5 节已用 ddp_timeout=1800 设置进程组等待时间。原生脚本可使用下面的独立初始化入口，不能在 Trainer 已初始化分布式之后再次调用。

# 以 torchrun 启动此脚本，明确设置原生进程组超时。
import os
from datetime import timedelta
import torch
import torch.distributed as dist

torch.cuda.set_device(int(os.environ["LOCAL_RANK"]))
dist.init_process_group("nccl", timeout=timedelta(minutes=30))
dist.barrier()
print("rank:", dist.get_rank())
dist.destroy_process_group()

13.2 各阶段 OOM 与设备不一致

3

stage 1 的参数和梯度仍完整保留，stage 2 的参数仍完整保留；若模型加载就 OOM，提高梯度累积次数无济于事。stage 3 的初始化也要正确进入分片加载路径，普通加载后才开启 ZeRO 可能已来不及。反向时 OOM 更可能与激活、序列长度或通信缓冲区有关；保存时 OOM 则重点检查权重聚合。

Expected all tensors to be on the same device 应检查输入、标签、模型缓冲区以及临时张量。原生代码必须按 LOCAL_RANK 选设备；不要在所有 rank 上固定 cuda:0。Trainer 路径让框架移动 batch，模型内部新建张量则应跟随已有输入的设备。

# 在模型前向内部使用此模式，张量跟随当前输入设备。
import torch

def causal_positions(input_ids):
    return torch.arange(input_ids.shape[-1], device=input_ids.device)

x = torch.ones((2, 8), dtype=torch.long, device="cuda")
positions = causal_positions(x)
assert positions.device == x.device
13.3 ZeRO-3 gather、梯度检查点与 KV cache2 个重点▾ 点开看本节重点
本节重点
  • 不能把它概括成“所有 ZeRO-3 推理必须关闭 cache”：正常独立推理可使用 KV cache；在训练引擎中临时生成、参数仍受 ZeRO hook 管理或遇到当前版本兼容问题时，关闭 cache 是先验证的路径
  • 多 rank 生成还要保证参与通信的进程都调用生成逻辑，不能只有 rank 0 进入仍需集合通信的模型
3

训练时通常设 model.config.use_cache=False，尤其使用梯度检查点时，缓存机制与重算流程容易冲突。不能把它概括成“所有 ZeRO-3 推理必须关闭 cache”：正常独立推理可使用 KV cache；在训练引擎中临时生成、参数仍受 ZeRO hook 管理或遇到当前版本兼容问题时，关闭 cache 是先验证的路径。多 rank 生成还要保证参与通信的进程都调用生成逻辑，不能只有 rank 0 进入仍需集合通信的模型。

# 对受 ZeRO 管理的简单线性层，所有 rank 都参与上下文，rank 0 负责打印。
import deepspeed
import torch.distributed as dist

def print_full_weight_shape(layer):
    with deepspeed.zero.GatheredParameters([layer.weight], modifier_rank=None):
        if dist.get_rank() == 0:
            print(tuple(layer.weight.shape))

上述上下文只聚合明确指定的参数。不要把整个七百亿参数模型随意聚合到每张卡，也不要把聚合后的张量引用长期缓存在模块外；退出上下文后参数可能再次变为分片。训练中评估和最终推理最好分别验证，避免将训练引擎的临时状态带到独立推理流程。

13.4 检查点体积、合并与恢复

3

可续训检查点通常包含优化器状态、学习率调度、随机数状态及各 rank 分片，体积远大于只有低精度权重的导出目录。ZeRO-3 下保存不一定意味着得到一个可直接 from_pretrained 加载的完整权重文件。保留整个 checkpoint-20 目录及其中子目录，不能只复制某个 rank 的文件；恢复前还要确认模型、优化器、数据顺序和并行规模的兼容性。

# 第 5 节脚本中明确保存过第 20 步后，再执行这一恢复命令。
torchrun --standalone --nproc_per_node=4 train.py \
  --deepspeed ds_config.json \
  --resume_from_checkpoint outputs/qwen-ds/checkpoint-20
# 若该检查点根目录包含 DeepSpeed 生成的 zero_to_fp32.py，可离线合并。
python outputs/qwen-ds/checkpoint-20/zero_to_fp32.py \
  outputs/qwen-ds/checkpoint-20 outputs/qwen-fp32.bin

FP32 合并要准备充足主存和磁盘，可能需要接近完整权重多倍的工作内存。合并得到权重不等于得到完整 Transformers 模型目录，还应保留 config、tokenizer 等必要文件。第 5 节的 trainer.save_model 与 ZeRO-3 保存聚合开关配合，更适合导出可独立加载的模型；续训仍使用训练检查点。
