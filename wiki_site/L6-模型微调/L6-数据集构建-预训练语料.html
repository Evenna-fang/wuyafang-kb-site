预训练与继续预训练语料：从原始文档到可训练快照

适用范围：从零预训练与在既有基座上做继续预训练（CPT）。本文不把 SFT 指令格式混入 CPT；指令、对话和偏好数据应走各自的数据管线。

1. 先分清预训练、CPT 与 SFT

3

起点 随机初始化或新建模型 已有 base，特定场景也可评估其他起点 已有 base 或 instruct
核心样本 连续文档 token 流 通用与领域连续文档 token 流 指令/上下文与目标回答

数据验收 规模、质量、覆盖、许可、污染与训练稳定性 另加基座兼容和通用能力保留 另加答案正确、模板与 label mask
直接产物 基座模型 领域适配基座 指令模型

CPT 不是把领域文档改成问答，也不是 SFT 的“大号版本”。如果目标只是让模型按格式回答，优先评估 SFT；如果目标是最新内部知识问答，优先评估 RAG。只有连续文本分布适配确有必要、且小实验显示收益时，才承担 CPT 的成本。训练路线选择见 大模型训练与微调总览。

2. 质量、许可与隐私是并列门禁3 个重点▾ 点开看本节重点
本节重点
  • “质量高”不能抵消“无权训练”，“公开可访问”也不自动等于“允许任意再分发或训练”
  • 每个来源都应记录获取方式、许可或合同依据、允许用途、署名/再分发限制、保留期限和责任人；无法确认的来源进入隔离区，不随主数据集默认放行
  • 涉及个人信息时，还要区分删除、掩码、泛化与保留的必要性，并由适用的法律与组织制度决定，不用单一正则宣称“已匿名”
3

“质量高”不能抵消“无权训练”，“公开可访问”也不自动等于“允许任意再分发或训练”。每个来源都应记录获取方式、许可或合同依据、允许用途、署名/再分发限制、保留期限和责任人；无法确认的来源进入隔离区，不随主数据集默认放行。涉及个人信息时，还要区分删除、掩码、泛化与保留的必要性，并由适用的法律与组织制度决定，不用单一正则宣称“已匿名”。

质量门槛同样不能照抄统一数值。技术文档中的 URL、代码和公式可能是有效内容，在普通网页规则里却会被误判；中英混排、繁体与少数民族语言也可能被单语言阈值误杀。每条规则都要按来源和语言切片观察保留率、误杀样本与下游小实验，再确定是否启用。

WHAT：可训练语料的九个组成面

2
1. 来源台账与许可证据3 个重点▾ 点开看本节重点
本节重点
  • 先建立“来源级”清单，再处理正文
  • 一个来源可以是某次网页快照、一个代码仓库版本、一批内部文档或一份开放数据集
  • 处置决定：「approved / restricted / quarantined / rejected」 及审批证据
3

先建立“来源级”清单，再处理正文。一个来源可以是某次网页快照、一个代码仓库版本、一批内部文档或一份开放数据集。最少记录：

  • source_id、原始定位、获取时间、内容类型、语言与预期用途；
  • 许可证/合同/授权依据及其适用范围，是否允许训练、修改、再分发和商业使用；
  • 原始文件哈希、采集或导出版本、负责人、保留与删除要求；
  • 已知风险：个人信息、机密、 copyrighted 内容、恶意提示文本、成人内容、评测题、重复转载；
  • 处置决定：approved / restricted / quarantined / rejected 及审批证据。

公开数据集也有自己的模型卡、数据卡和许可，不因被二次打包就自动获得上游全部权利。内部数据还需检查员工、客户和用户的授权边界。训练快照只引用已批准版本，来源被撤回时应能定位受影响文档、派生分片及模型训练记录。

2. 文档抽取、规范化与语言识别

3

抽取阶段尽量保留标题、段落、列表、代码块、公式和文档边界，避免把页眉页脚、菜单、推荐链接与正文无差别拼接。扫描件 OCR 要保留置信度与页码，低质量页进入复核，不用“看着像文字”作为可训练证明。

规范化只做有明确收益且可逆记录的操作，例如 Unicode 归一化、换行与空白统一、可识别乱码修复。NFKC 等操作可能改变代码、数学符号、兼容字符和精确匹配结果，因此应保留原文哈希与处理规则，按内容类型决定是否启用。简繁转换也不应默认全覆盖；若产品需要繁体能力，就应把语言变体作为独立切片评估。

语言识别输出应是信号而非真相。保存主语言、次语言、置信度和混合比例，技术中文中大量英文术语不应因此被删除。语言门槛按切片抽检误杀与漏放后设定，不把某个固定概率当跨领域标准。

3. PII、机密与敏感内容处理3 个重点▾ 点开看本节重点
本节重点
  • 1. 用规则、词典、NER 或专用检测器发现邮箱、电话、证件号、账号、地址等候选；高召回与高精度模式分开使用
  • 2. 根据上下文和用途选择删除整篇、删除片段、稳定占位符替换或泛化
  • 稳定占位符可保留句法，但映射表本身属于敏感资产，不进入训练快照
3

PII 处理应形成“检测—决策—复核—审计”闭环：

  1. 用规则、词典、NER 或专用检测器发现邮箱、电话、证件号、账号、地址等候选；高召回与高精度模式分开使用。
  2. 根据上下文和用途选择删除整篇、删除片段、稳定占位符替换或泛化。稳定占位符可保留句法，但映射表本身属于敏感资产，不进入训练快照。
  3. 对密钥、访问令牌、内部域名、客户机密等使用独立检测与处置流程；发现真实凭据时应按安全流程处理，而不是只替换文本后继续训练。
  4. 分语言、来源和实体类型抽检漏检/误检。无法证明匿名化的内容按受限数据处理，限制访问与导出。

成人、暴力、仇恨或其他敏感内容是否过滤，取决于模型目标、法律政策和安全策略。要记录分类器版本与人工复核口径，避免过滤器把医学、法律或安全教育文本无差别清除。

4. 质量过滤：规则与模型都要校准

3

质量信号可分为四组：

  • 可读性：乱码、异常字符、极端重复、断裂句子、模板残留；
  • 信息性：正文密度、段落结构、事实或技术内容的完整性；
  • 来源信誉：域名、作者、版本、审核流程等可用元数据；
  • 学习型质量：分类器或人工标注定义的教育性、专业性、领域适配度。

启发式规则适合解释和粗筛，分类器适合学习复杂分布，但会继承正负例偏差。把“百科/书籍”为正例、“随机网页”为负例，可能把口语、论坛和新颖文体都判低质。因此，模型打分必须与人工分层抽检、来源切片和训练消融共同使用。质量分不应直接等同于事实正确；事实核查、安全和可读性仍是不同维度。

过滤与去重的先后顺序没有脱离数据的唯一答案。先粗过滤可降低去重成本，先去重可减少质量计算量；高转载来源还要决定保留哪个 canonical 版本。无论采用哪种顺序，都应在小样本上比较误删、计算成本与最终训练效果，并保存各阶段输入输出统计。

5. 精确与近重复去重3 个重点▾ 点开看本节重点
本节重点
  • 1. 文件/文档精确重复：基于规范化正文哈希合并，保留所有来源引用
  • 适度重复可能承担采样权重，关键是不能让无意转载隐性支配配比
  • 2. 文档内重复：识别重复段落、导航行、模板和异常 n-gram，区分有意重复与采集故障
3

去重至少覆盖三个层级：

  1. 文件/文档精确重复：基于规范化正文哈希合并，保留所有来源引用。
  2. 文档内重复：识别重复段落、导航行、模板和异常 n-gram，区分有意重复与采集故障。
  3. 跨文档近重复：用 shingles/n-gram 与 MinHash+LSH 等候选生成方法，再按确认的相似度规则合并或删除。

MinHash 的排列数、band/row、n-gram 大小与确认阈值共同决定召回、精度和成本，不能单独复制某个“常用值”。中文按字、词或 subword 构造 shingles 会改变结果；代码、表格和短文档也需单独校准。候选对要抽样查看，尤其检查“同一法规的不同版本”“同一文章的更新版”“模板相同但实体不同”等不应简单删除的情况。

去重不是盲目追求零重复。适度重复可能承担采样权重，关键是不能让无意转载隐性支配配比。应分别报告原始文档数、唯一文档数、唯一 token 估计和跨来源重复簇，避免把重复 epoch 当成新增数据。

6. 语言、领域与来源配比

3

配比应按进入训练的有效 token计算，而不是只按文件数或磁盘大小。至少保留来源、语言、领域、质量层和时间层的分布表，并回答：

  • 通用与领域数据分别承担什么目标？
  • 多语言是否按能力目标采样，还是被高资源语言天然主导？
  • 同一小来源是否因重复 epoch 被过度放大？
  • 高质量子集被提高权重后，是否降低了文体和人群覆盖？
  • CPT 是否保留足够通用 replay 以监测和缓解遗忘？

不要沿用固定 Web/Code/领域百分比。先提出少量可解释的候选配比，在相同模型、训练预算和解码条件下做对照，以领域测试、通用回归、损失曲线和资源成本共同选择。若某来源被上采样，报告实际曝光 token 与唯一 token，不只报告采样比例。

7. 分词、文档边界与 packing3 个重点▾ 点开看本节重点
本节重点
  • 从零训练可训练新分词器；CPT 通常应复用基座分词器和特殊 token，除非有充分理由并承担替换嵌入/词表的复杂度
  • 每个文档末尾是否添加 EOS、文档间是否允许跨注意力、position id 是否重置，都要与训练框架和模型目标一致
  • 分词器验收包括：各语言与领域的压缩/膨胀情况、未登录或异常 byte、代码与数字表现、特殊 token 冲突，以及与基座词表和模型配置的一致性
3

从零训练可训练新分词器；CPT 通常应复用基座分词器和特殊 token，除非有充分理由并承担替换嵌入/词表的复杂度。分词器验收包括：各语言与领域的压缩/膨胀情况、未登录或异常 byte、代码与数字表现、特殊 token 冲突，以及与基座词表和模型配置的一致性。

清洗后的数据仍以文档为单位；训练前才编码并拼接为 token 流。每个文档末尾是否添加 EOS、文档间是否允许跨注意力、position id 是否重置，都要与训练框架和模型目标一致。Packing 能提高固定长度序列的填充利用率，但朴素跨文档拼接和带文档边界隔离的实现并不等价，需通过小实验和框架配置核对。

长文档可以按结构切块、保留重叠或按长度分桶；切块时记录 parent_doc_id 与片段序号。不能为凑满序列而跨训练/验证边界拼接。短文本、表格和代码的分桶也应避免形成“某个长度桶几乎只有一种来源”的隐性偏差。

8. 评测污染与数据泄漏防控

3

污染控制必须在训练前做，而不是报告阶段补一句“可能有小部分重合”。冻结预训练/CPT 的通用与领域评测集后：

  • 对题面、答案、参考文档及可公开获取的变体建立禁止匹配库；
  • 用规范化精确匹配、n-gram 重叠和近重复检索发现候选，再人工判断语义等价；
  • 按来源与时间切片报告命中、删除和保留理由；
  • 对 CPT 特别检查业务测试题是否来自同一批内部文档；
  • 将评测库及其密钥/访问权限与训练数据生产隔离，记录每次规则版本。

过强过滤也可能删掉正常知识，使评测变成“避开训练集后的偏题”。因此应同时保留污染审计和正常文本误删抽检。发现污染后，旧模型分数不能与清理后模型的分数直接比较，应明确作废旧报告或重建对照。

  • 快照包括文档分片、采样索引、tokenizer 配置、packing 参数、来源台账、清洗规则、代码版本、统计报告和文件哈希

3

每次训练只引用不可变数据快照。快照包括文档分片、采样索引、tokenizer 配置、packing 参数、来源台账、清洗规则、代码版本、统计报告和文件哈希。任何规则、配比或评测禁止库变化都产生新版本，不原地覆盖旧版本。

数据血缘要支持两类反向追踪：某条问题样本能追到来源与处理步骤；某个来源撤回时能定位所有派生分片和训练 run。正文可分权存储，训练清单与审计报告不应包含不必要的 PII 正文或秘密。

3. 分阶段执行3 个重点▾ 点开看本节重点
本节重点

3

阶段 0：建立验收合同。 在跑全量前写明必需字段、许可状态、隐私处置、污染规则、抽检方案、配比比较指标和快照格式。阈值先留空，通过小样校准后填入并版本化。

阶段 1：来源准入。 每个来源先登记再抽样。未确认许可、含未授权机密或无法追溯来源的数据进入隔离区。保存原始文件只读副本与哈希，后续处理不修改原始区。

阶段 2：小样剖析。 按来源、语言、长度和内容类型分层抽样，人工查看正文与误删候选。统计抽取失败、乱码、模板、语言混合、PII 候选、重复簇和长度分布。根据这些证据选择规则，而不是先抄一套英文网页阈值。

阶段 3：抽取与规范化。 保留文档结构和原文哈希，运行正文抽取、编码处理、空白规范化与语言识别。为每条规则输出命中计数和前后样例；对代码、公式、表格等切片单独验收。

阶段 4：隐私与安全处置。 先运行检测，再按策略掩码、删除或隔离。对漏检和误检分别抽检；高风险命中由人工升级。只有通过隐私门禁的文档才能进入批准区。

阶段 5：质量与去重。 运行可解释粗筛和必要的质量模型，保留分数及版本。再做文档内、快照内和跨来源去重，保留 canonical 选择依据。调整顺序时生成新快照并比较误删，不覆盖已有结果。

阶段 6：污染阻断。 使用冻结评测禁止库扫描，人工确认高影响命中。命中记录写入审计报告，训练正文不复制评测答案。数据切分在去重族或父文档层级进行，防止近重复跨 split。

阶段 7：配比小样与训练对照。 生成少量候选采样计划，按有效 token、唯一 token、来源曝光和语言/领域切片报告差异。用相同训练预算做小实验，比较领域指标、通用回归和稳定性，再选择放大方案。

阶段 8：编码与 packing。 固定 tokenizer 后编码，检查特殊 token 与文档边界。生成长序列分片、采样索引和长度/来源统计；从分片解码少量样本，验证没有错位、意外拼接或 split 泄漏。

阶段 9：冻结发布。 对文档分片和索引计算哈希，写入 manifest 与验收报告，将快照转为只读。训练 run 只引用快照 ID；发现缺陷时新建修复版，并按血缘评估旧 run 是否作废。

6. 验收清单

3

发布门槛由项目在小样上定义，以下项目必须逐项有证据，不能用总文档数代替。

  • [ ] 所有放行来源均有许可/授权依据、责任人、获取版本和撤回定位方式。
  • [ ] 原始区只读，任一输出文档可追到原文哈希与处理版本。
  • [ ] 文本、代码、表格、OCR 和各语言切片分别抽检，无未解释的系统性乱码或正文错切。
  • [ ] PII/机密检测报告包含漏检、误检和人工复核；受限内容未进入批准区。
  • [ ] 质量过滤规则有命中样例与误杀检查，分类器有版本和偏差说明。
  • [ ] 精确/近重复去重覆盖跨来源与跨快照，canonical 选择可解释，重复族未跨 split。
  • [ ] 配比报告同时给出文档数、有效 token、唯一 token、实际上采样曝光和关键切片。
  • [ ] 评测禁止库已冻结，污染候选有人工处置记录，旧评估是否可比已明确。
  • [ ] CPT 的 tokenizer、特殊 token 和模型配置与基座一致；长文档切块和 packing 可解码复核。
  • [ ] 小规模训练对照同时报告领域收益与通用回归，不仅报告训练 loss。
  • [ ] manifest、文件哈希、验收报告与已知限制齐全，快照不可变且能回滚到上一版。
