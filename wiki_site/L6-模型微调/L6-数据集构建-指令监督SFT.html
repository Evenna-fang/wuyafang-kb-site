SFT（Supervised Fine-Tuning，监督微调）用人工编写、规则生成或模型生成并审核的“输入—目标输出”样本，让预训练模型学习任务格式、对话行为、领域表达和工具调用方式。它仍然做 next-token prediction，但训练目标从“预测通用文本”收窄为“在给定上下文中生成期望回答”。

SFT 适合解决三类问题：

  1. 行为不稳定：输出结构、语气、拒答边界或多轮跟随不符合要求。
  2. 任务有明确示范：抽取、改写、分类、工具参数生成等有可审核目标答案。
  3. 领域表达方式不足：模型已有基础能力，但不会按业务术语和流程组织回答。

SFT 不是知识数据库。需要频繁更新、可追溯引用的知识，优先检索增强；只有少量 bad case 时，先检查提示词、解码参数和检索，而不是设一个“满多少条才能微调”的门槛。是否值得训练，应由固定评测集上的基线、错误类型和训练小实验共同决定。

SFT 最常见的失败不是模型太小，而是数据与目标错位：答案错误、模板泄漏、评测集污染、chat template 不一致，或把用户输入也计入损失。数据版本、模板版本和模型版本必须一起管理。

2. 统一源格式：messages

3

建议把人工审核后的源数据保存为 JSONL，每行一个样本；框架所需 alpaca/sharegpt 格式由转换层生成，而不是维护多份手工副本。

{"id":"case-0001","source":"human-reviewed-v3","messages":[{"role":"system","content":"你是严谨的运维助手。"},{"role":"user","content":"把“磁盘写满导致任务失败”改写成一句告警。"},{"role":"assistant","content":"磁盘空间耗尽，任务写入失败；请清理空间并检查写入权限。"}],"meta":{"topic":"rewrite","review":"passed"}}

字段约定：

字段 必要性 作用
id 必需 去重、回流、审计与删除请求定位
source 必需 记录来源批次、许可与审核版本
messages 必需 保留 system/user/assistant 等角色及顺序
meta 建议 主题、难度、审核状态等，不默认送进模型

工具调用样本需要按目标模型官方模板表示工具声明、调用和工具返回。工具返回不是 assistant 答案，不能用普通文本拼接后让模型学习伪造返回。

TRL 还接受 text、prompt/completion 等形式。单轮且边界清晰时，prompt/completion 很容易正确设置 completion-only loss；多轮对话优先使用模型自带 chat template，而不是自行猜特殊 token。

3. loss mask：决定模型学什么3 个重点▾ 点开看本节重点
本节重点
  • 因果语言模型通常用交叉熵训练
  • labels 为 「-100」 的位置被 PyTorch 交叉熵默认忽略
  • language modeling：整段文本计算损失，适合连续语料，不等于 assistant-only SFT
3

因果语言模型通常用交叉熵训练。labels 为 -100 的位置被 PyTorch 交叉熵默认忽略。SFT 常见目标设置：

  • language modeling：整段文本计算损失，适合连续语料，不等于 assistant-only SFT。
  • prompt-completion：只让 completion 参与损失；TRL 对该格式默认采用 completion-only loss。
  • 多轮 messages：只让 assistant 生成段参与损失，system、user、工具返回被 mask。

assistant_only_loss=True 不是无条件开关：TRL 要求 chat template 含 {% generation %} 标记，才能识别 assistant 生成范围；部分已知模板由 TRL 自动处理。模板不支持时，应改用 prompt-completion、转换模板或使用框架支持的掩码方案，不能忽略警告继续跑。

还要区分：

  • assistant-only：每轮 assistant 都可能成为监督目标。
  • 最后一轮-only：只监督最后回答，会丢弃前面 assistant 段的监督。
  • packing：把多样本拼进定长序列提高利用率，不等于改变 mask；拼接后仍须验证样本边界和标签。

4. 数据生产与质量控制

3

来源可以是人工精标、历史业务记录、规则转换、强模型蒸馏或 Self-Instruct/Evol-Instruct 类扩展。来源没有固定“性价比排行榜”，取决于任务可验证性、许可和审核成本。

一条可审计流水线是：

需求与错误分类 → 许可/隐私检查 → 样本生成 → 规则过滤
→ 去重与近重复聚类 → 人工/程序审核 → 独立切分
→ 模板渲染与标签检查 → 数据快照 → 小实验 → bad case 回流

关键原则：

  • 正确性先于数量：代码可跑测试、抽取可对字段、数学可验答案；开放写作用明确 rubric 和抽检。
  • 保留必要多样性：精确去重之外，还要检查近重复是否让某个模板或主题占满训练集。
  • 独立评测：先按业务场景建立保留集，再做训练数据增强；同主题变体按组切分，不能随机散落到 train/eval 两边。
  • 防止污染：比较训练与评测的规范化文本、n-gram 和近重复簇；发现重叠应移除训练侧并记录。
  • 合规可撤回：保留来源、许可、审核和删除状态，不把真实密钥、个人信息或无权使用内容写入样本。

不存在适用于所有模型的数据配比和扩量阈值。先用覆盖主要错误类型的小规模高质量快照训练，只有当保留集证明某类能力不足且该分类有足够好样本时再扩量。

HOW

2
1. 先建立基线与不可变数据快照3 个重点▾ 点开看本节重点
本节重点
  • 1. 固定基座模型 revision、tokenizer/chat template、解码参数和评测脚本
  • 2. 用未训练基座跑保留集，按正确性、格式、遗漏、幻觉、拒答等错误类型分桶
  • 3. 仅纳入有来源和审核记录的数据；规范化空白后检查空消息、非法 role、重复 「id」、相同对话和近重复
3
  1. 固定基座模型 revision、tokenizer/chat template、解码参数和评测脚本。
  2. 用未训练基座跑保留集，按正确性、格式、遗漏、幻觉、拒答等错误类型分桶。
  3. 仅纳入有来源和审核记录的数据；规范化空白后检查空消息、非法 role、重复 id、相同对话和近重复。
  4. 按 group_id 或近重复簇切分 train/eval；同组只能在一侧。
  5. 保存只读数据快照和 manifest，后续训练不得原地修改。

最小校验脚本（示例，未实跑）：

import json
from collections import Counter
from pathlib import Path

path = Path("train.jsonl")
ids = []
for line_no, line in enumerate(path.open(encoding="utf-8"), 1):
    row = json.loads(line)
    assert row["id"] and row["source"], (line_no, "缺少id/source")
    assert row["meta"]["review"] == "passed", (line_no, "未审核")
    messages = row["messages"]
    assert messages and messages[-1]["role"] == "assistant", (line_no, "缺少目标回答")
    assert all(m.get("content", "").strip() for m in messages), (line_no, "空消息")
    assert all(m["role"] in {"system", "user", "assistant", "tool"} for m in messages)
    ids.append(row["id"])
assert not [x for x, n in Counter(ids).items() if n > 1], "id重复"
print(f"schema ok: {len(ids)} rows; 仍需另做语义正确性、去重与污染审核")

这段脚本只验证结构，不代表答案正确、无泄漏或可安全使用。

2. 渲染一条样本并检查标签

3

在启动完整训练前，输出以下内容：

  • 完全渲染后的文本和特殊 token；
  • input_ids/attention_mask/labels 的长度与对齐；
  • 将 labels 中 -100 剔除后解码，确认只留下目标 assistant 内容；
  • 最长样本和截断比例，确认回答末尾/EOS 没被意外截掉。

如果使用 assistant_only_loss=True，先检查模板是否支持 {% generation %}；若框架自动补丁模板，则保存补丁后的版本。不要只凭“loss 有下降”判断 mask 正确。

以下使用文档当前接口 SFTConfig(max_length=...)。旧稿中将 max_seq_length 直接传给 SFTTrainer 的写法不要照搬。安装时锁定 TRL、Transformers、PEFT、PyTorch 版本并保存解析后的配置。

训练代码（示例，未实跑）：

from datasets import load_dataset
from trl import SFTConfig, SFTTrainer

MODEL = "Qwen/Qwen3-0.6B"  # 示例标识；正式实验固定revision并核对许可
train = load_dataset("json", data_files="train.jsonl", split="train")
eval_set = load_dataset("json", data_files="eval.jsonl", split="train")

args = SFTConfig(
    output_dir="runs/sft-smoke",
    max_length=1024,
    packing=False,
    assistant_only_loss=True,  # 前提是模板支持generation标记
    report_to=[],
)
trainer = SFTTrainer(
    model=MODEL,
    args=args,
    train_dataset=train,
    eval_dataset=eval_set,
)
trainer.train()
trainer.save_model("runs/sft-smoke/final")

先用少量 batch 做 smoke test，确认数据、模板、显存、保存和恢复链路，再扩大步数。max_length、batch、学习率和 epoch 不是通用常数，应结合样本长度、有效 batch、验证曲线与任务指标做小实验。

4. 验收而不是只看训练 loss

3
层级 检查 通过依据
数据 schema、来源、去重、污染、切分 有报告与可复查样本，不是仅有脚本退出码
标签 assistant-only 边界、EOS、截断 解码 labels 与目标段一致
优化 train/eval loss、梯度、NaN 曲线可解释，无未处理异常
任务 固定保留集与基座对照 主要错误类型改善，其他场景未不可接受回退
产物 重新加载、固定输入推理 config/tokenizer/权重齐全，结果可复现
回退 保留上一版及数据/配置 能明确回滚到哪个模型和数据快照

如果业务指标下降而 eval loss 变好，先相信任务评估，再检查评测是否与训练分布过于相似、模板是否一致以及数据是否优化错了目标。

5. 常见坑与有序回退3 个重点▾ 点开看本节重点
本节重点
  • 模型复述用户问题：解码 labels；若 user/system/tool 段未置 「-100」，修复 mask 后重跑
  • 输出突然截断：检查长度分布、「max_length」、EOS/PAD 和生成参数；不要先加 epoch
  • 训练集很好、真实请求很差：查近重复泄漏、主题分布偏移和线上模板差异
3
  • 模型复述用户问题：解码 labels；若 user/system/tool 段未置 -100，修复 mask 后重跑。
  • assistant-only 报模板错误：检查 {% generation %} 和 TRL 版本；改 prompt-completion 或采用受支持模板，不强行忽略。
  • 输出突然截断：检查长度分布、max_length、EOS/PAD 和生成参数；不要先加 epoch。
  • 训练集很好、真实请求很差：查近重复泄漏、主题分布偏移和线上模板差异。
  • 通用能力回退：缩小训练强度、重做数据配比，加入经审核的通用回放样本，并同时保留领域与通用评估。
  • 扩量后无收益：停止继续堆量，回到错误分桶，检查答案质量、任务覆盖和训练/评测是否错位。

本库真实落地（源码核对，2026-11-04）

  • "指令数据清洗"在本库的真实版本：入库前的低信息/噪声过滤（rag/ingest.py L539 _is_low_info()，grep 可验）：
    python def _is_low_info(chunk: str) -> bool: raw = (chunk or "").strip() t = re.sub(r"\s+", "", raw) if not t: return True if t in LOW_INFO_EXACT: return True # 纯标点/符号（无任何中英文） if not re.search(r"[\u4e00-\u9fa5A-Za-z]", t): return True # 极短：含数字（限额/版本/价格等关键事实）则保留，否则判为低信息 if len(t) < MIN_CHUNK_CHARS: return not bool(re.search(r"\d", t))
    对应 SFT 数据清洗四条中的"占位/空样本剔除"，且加了"极短但含数字则保留"的例外——限额/版本号这类短事实不该因短被丢。
  • 长度与结构约束（rag/ingest.py L613 split_parent_chunks + L128 SEPARATORS）：父块 800 字符/重叠 100，子块按中文句读切（["\n\n", "\n", "。", "；", "！", "？", ". ", " ", ""]）——指令样本"按语义边界截断"的同一思路。
  • 和课件讲法的差异：课件用 datasets.load_dataset("json") + apply_chat_template(tokenize=True, max_length=2048) + DataCollatorForSeq2Seq(label_pad_token_id=-100)；本库没有对话模板和 label mask，因为语料是"知识文本"不是"指令-回答对"。本库暂无 SFT 数据集构造代码，上述两步可直接套课件写法。
