ModelScope SWIFT 微调框架实操

本文以 ms-swift 3.5.3 为固定基线，使用该版本官方文档、依赖声明和训练脚本核对参数；这不是对当前最新版接口的承诺。示例面向 Linux、Python 3.10 和 NVIDIA CUDA 环境，默认从 ModelScope 下载公开模型。先用小模型打通数据、保存和推理，再扩大模型及数据规模。本文命令是供读者在训练机执行的操作说明，编写本文时没有实际启动 GPU 训练，也没有据此宣称训练效果。

版本纪律：正文主要使用三代接口。用户经常搜索的 --sft_type lora/qlora、--quantization_bit 4 属于需要辨析的旧教程用语：二代可以使用 --sft_type lora，但核对的二代和三代接口都没有 qlora 这个训练类型枚举；QLoRA 通过 LoRA 加低位量化实现。不要直接复制混合版本的参数。涉及安装、数据生成和训练的命令应按所在小节顺序执行；不同训练方案互为替代，不需要全部运行。

SWIFT 全称为 Scalable lightWeight Infrastructure for Fine-Tuning，是 ModelScope 社区的模型训练与应用框架；modelscope/ms-swift 是官方代码仓库，ms-swift 是安装时使用的 Python 发行包名，swift 是安装后出现的命令行入口，也是 Python 导入名称。它与苹果的 Swift 编程语言无关，安装前应确认命令来自当前虚拟环境。

在本文固定的 v3.5.3 README 中，官方声明支持 500 多个文本大模型和 200 多个多模态大模型。这属于该版本的模型适配统计，不能解读为每个模型都支持每一种训练、量化和推理后端。多模态覆盖图像、视频、音频，以及视觉问答、图像描述、OCR 和定位任务。选模型时，需要同时确认训练模板、模型专属依赖、视觉模块冻结策略和部署引擎支持。

比较维度 ModelScope SWIFT LLaMA-Factory
典型入口 swift sft/rlhf/infer/deploy/eval，同一套工具衔接训练到部署 llamafactory-cli train 和 WebUI，配置驱动的训练流程成熟
国内模型获取 默认接入 ModelScope，也可切换 Hugging Face 支持多种模型来源，需要按其版本配置下载渠道
数据组织 本地路径直传、自动预处理、外部注册文件 常见方式为数据文件配合 dataset_info.json 注册
多模态实操 统一 messages 与 images/videos/audios，模型专属模板负责编码 同样支持多模态，格式和模型能力按其文档核对
适合团队 希望用 CLI 串联训练、评测、推理服务，并扩展预处理逻辑 已有配置模板、偏好可视化训练和统一实验管理

两者都能做全参、LoRA 和偏好对齐。真正影响选择的是团队已有脚本、目标模型适配程度、数据预处理成本和部署路径，不应仅用支持模型总数作决定。下面通过包元数据确认装到的是哪个发行包及导入路径。

CUDA 自检除了检查是否可见，还应执行一次小张量运算。只有设备枚举成功但首次矩阵乘法失败，仍然说明环境没有准备好。BF16 要求硬件支持；以下主训练示例采用 BF16，在不支持的卡上需要重新选择精度和框架支持的训练策略，不应只把所有参数盲改为 FP16，尤其是全参训练。

import torch
print('torch:', torch.__version__)
print('wheel CUDA:', torch.version.cuda)
print('CUDA available:', torch.cuda.is_available())
assert torch.cuda.is_available(), '本示例需要可用 NVIDIA CUDA 设备'
print('GPU:', torch.cuda.get_device_name(0))
print('BF16 supported:', torch.cuda.is_bf16_supported())
x = torch.randn(256, 256, device='cuda')
print('matmul mean:', (x @ x).mean().item())

常用参数的关系是：--model 指向权重，--model_type 指向框架适配类型，--dataset 指向数据，--train_type 决定更新哪些参数。--max_length 约束编码后序列长度，不能用它代替图像分辨率限制。有效批量约等于单卡微批量乘梯度累积步数再乘数据并行进程数；扩大卡数时，需要重新核对学习率和有效批量。

4.1 messages 多轮与 query/response3 个重点▾ 点开看本节重点
本节重点
  • 推荐把业务数据统一转换为 messages
  • 早期 3.0 发行说明曾写过不再支持该格式，但本文核对的 3.5.3 自定义数据文档与 ResponsePreprocessor 已明确支持，因此应按具体版本确认，不能仅根据迁移公告下结论
  • 每条记录是一段完整对话，角色按照 system、user、assistant 表示，不要提前手工拼接模型的聊天模板特殊标记
3

推荐把业务数据统一转换为 messages。每条记录是一段完整对话，角色按照 system、user、assistant 表示，不要提前手工拼接模型的聊天模板特殊标记。训练样本通常应以 assistant 回复结束；样本中已经包含 system 时，它优先于训练命令中的默认系统提示。JSONL 每行必须是一条完整 JSON，不能把漂亮打印后的多行对象当作一行样本。

{"messages":[{"role":"system","content":"你是运维知识助手，回答应简洁且可操作。"},{"role":"user","content":"训练前要检查什么？"},{"role":"assistant","content":"先检查显卡驱动、PyTorch CUDA 可用性、模型路径和数据格式。"},{"role":"user","content":"数据检查重点是什么？"},{"role":"assistant","content":"检查角色顺序、空回复、样本长度和验证集是否与训练集重复。"}]}

query/response 是另一种输入格式，history 保存前序轮次，框架预处理后转为 messages。早期 3.0 发行说明曾写过不再支持该格式，但本文核对的 3.5.3 自定义数据文档与 ResponsePreprocessor 已明确支持，因此应按具体版本确认，不能仅根据迁移公告下结论。

{"system":"你是运维知识助手。","history":[["什么是 LoRA？","LoRA 通过训练低秩增量矩阵适配基础模型。"]],"query":"它会修改全部基础权重吗？","response":"通常不会，基础权重保持冻结，主要更新适配器参数。"}

下面生成一个真正可加载的小数据集，后续命令直接引用。它只用于管线冒烟，重复扩充的样本不能证明模型学到知识，也不适合用于正式效果评估。正式项目应准备独立来源的验证集，按文档、用户或时间切分，避免同一问题的近似改写跨越训练与验证两侧。

# 创建后续命令使用的数据文件；共 40 条，用于验证加载和保存链路。
mkdir -p data output models
python - <<'PY'
import json
from pathlib import Path
pairs = [
    ('什么是梯度累积？', '梯度累积在多次微批次反向传播后执行一次优化器更新。'),
    ('验证集有什么作用？', '验证集用于监控未参与训练样本上的表现和过拟合。'),
    ('LoRA 的 rank 是什么？', 'rank 是低秩矩阵的秩，决定适配器容量并影响可训练参数量。'),
    ('全参微调保存什么？', '全参微调通常保存完整模型权重、配置及分词器相关文件。'),
]
with Path('data/train.jsonl').open('w', encoding='utf-8') as f:
    for _ in range(10):
        for question, answer in pairs:
            row = {'messages': [{'role': 'user', 'content': question},
                                {'role': 'assistant', 'content': answer}]}
            f.write(json.dumps(row, ensure_ascii=False) + '\n')
PY

4.2 dataset.json 注册与本地文件直传

3

本地文件可以直接通过 --dataset data/train.jsonl 加载，并不要求注册。需要复用别名或转换列名时，可以使用外部元数据文件。下面内容保存为实验目录的 dataset.json；这个名字是人为选择的文件名，真正让它生效的是 --custom_dataset_info 参数，SWIFT 不会自动扫描任意一个叫 dataset.json 的文件。

[
  {
    "dataset_name": "local_ops",
    "dataset_path": "data/train.jsonl"
  }
]

dataset_name 定义本地别名，dataset_path 指向实际数据文件，相对路径以启动命令时的工作目录为准。跨机器运行建议改用绝对路径。以下是实际可训练的别名加载命令；若不需要注册，删掉 --custom_dataset_info dataset.json 并把 --dataset 改成文件路径即可。

# 需要先按上面的 JSON 内容创建 dataset.json；本段执行一次最小训练。
CUDA_VISIBLE_DEVICES=0 swift sft \
  --model models/Qwen2.5-0.5B-Instruct \
  --custom_dataset_info dataset.json \
  --dataset local_ops \
  --train_type lora --torch_dtype bfloat16 \
  --max_steps 2 --max_length 512 \
  --per_device_train_batch_size 1 \
  --split_dataset_ratio 0 --eval_strategy no \
  --output_dir output/data-smoke

更复杂的字段变换可调用真实注册 API。把下面代码保存为实验目录的 register_ops.py，再用 --custom_register_path register_ops.py --dataset registered_ops 加到完整训练命令中。注册代码只描述数据集，不应在导入时启动训练或下载大型模型，否则每个分布式进程都可能重复执行副作用。这里使用自动预处理器，兼容本文的 messages 与 query/response；需要自定义字段转换时，再选择对应专用预处理器。

# register_ops.py 的推荐完整内容：适用于本文生成的 messages 数据。
from pathlib import Path
from swift.llm import AutoPreprocessor, DatasetMeta, register_dataset

register_dataset(DatasetMeta(
    dataset_name='registered_ops',
    dataset_path=str(Path('data/train.jsonl').resolve()),
    preprocess_func=AutoPreprocessor(),
))

5. SFT 全参微调与 DeepSpeed ZeRO-3

2

全参微调会更新模型的全部可训练权重，适合数据较充足、领域分布变化明显且算力预算允许的任务。下面选择小模型，方便先检查端到端流程。--model_type qwen2_5 显式指定模型适配类别；三代通常能从模型配置自动推断，常规模型可省略此参数。不要把二代的具体模型别名复制为三代的 model_type。

# 小模型单卡全参基线；默认从 ModelScope 获取模型。
CUDA_VISIBLE_DEVICES=0 swift sft \
  --model Qwen/Qwen2.5-0.5B-Instruct \
  --model_type qwen2_5 --use_hf false \
  --train_type full --dataset data/train.jsonl \
  --torch_dtype bfloat16 --num_train_epochs 1 \
  --per_device_train_batch_size 1 \
  --gradient_accumulation_steps 4 \
  --learning_rate 1e-5 --max_length 1024 \
  --gradient_checkpointing true \
  --split_dataset_ratio 0 --eval_strategy no \
  --save_strategy epoch --logging_steps 1 \
  --output_dir output/full --add_version false

--num_train_epochs 是遍历训练集的轮数，--learning_rate 是优化器步长，--gradient_checkpointing 通过重算激活降低显存。保存策略使用 epoch，适合本文小样本，避免设置很大的 save_steps 后误以为没有产物。实际业务中应设验证集、验证频率和保存上限；当前明确关闭验证是为了避免把重复的冒烟样本当成效果证据。

DeepSpeed ZeRO-3 会分片优化器状态、梯度和模型参数。它缓解单卡状态占用，但也增加通信、CPU 内存及保存过程的开销。以下内容保存为实验目录的 zero3.json，是 DeepSpeed 真正读取的 JSON 配置；不要随意把 JSON 改为 YAML 后仍传给 DeepSpeed。

{
  "bf16": {"enabled": "auto"},
  "train_micro_batch_size_per_gpu": "auto",
  "gradient_accumulation_steps": "auto",
  "train_batch_size": "auto",
  "zero_optimization": {
    "stage": 3,
    "overlap_comm": true,
    "contiguous_gradients": true,
    "stage3_gather_16bit_weights_on_model_save": true
  }
}

配置说明：stage 选择第三阶段分片，overlap_comm 尝试重叠通信与计算，contiguous_gradients 减少梯度碎片，stage3_gather_16bit_weights_on_model_save 允许保存时收集可独立加载的权重；三个批量相关的 auto 由训练参数推导。保存时的权重聚合也可能产生额外显存峰值，需要为它预留空间。

# 两卡全参示例：先安装与当前 torch/CUDA 相容的 DeepSpeed。
python -m pip install 'deepspeed==0.16.9'
CUDA_VISIBLE_DEVICES=0,1 NPROC_PER_NODE=2 swift sft \
  --model Qwen/Qwen2.5-0.5B-Instruct \
  --train_type full --dataset data/train.jsonl \
  --torch_dtype bfloat16 --deepspeed zero3.json \
  --num_train_epochs 1 --learning_rate 1e-5 \
  --per_device_train_batch_size 1 --gradient_accumulation_steps 4 \
  --max_length 1024 --gradient_checkpointing true \
  --split_dataset_ratio 0 --eval_strategy no \
  --save_strategy epoch --output_dir output/full-zero3

6.1 LoRA 命令行和 YAML 配置

3

LoRA 冻结基础模型，仅训练指定线性层的低秩增量。--lora_rank 决定低秩空间容量，--lora_alpha 控制缩放，--target_modules all-linear 自动选取适合注入的线性层。rank 越大通常意味着更多可训练参数和更大适配器，但不保证业务指标更好，应在相同数据切分下比较。

# 这是后续导出及推理使用的主训练产物。
CUDA_VISIBLE_DEVICES=0 swift sft \
  --model Qwen/Qwen2.5-0.5B-Instruct \
  --dataset data/train.jsonl --train_type lora \
  --torch_dtype bfloat16 --lora_rank 8 --lora_alpha 32 \
  --target_modules all-linear --learning_rate 1e-4 \
  --num_train_epochs 1 --max_length 1024 \
  --per_device_train_batch_size 1 --gradient_accumulation_steps 4 \

显存只能在相同模型、长度、批量和内核设置下公平比较。以七十亿参数 BF16 模型为量级参考：仅基础权重约十四 GB；全参 AdamW 训练叠加梯度和优化器后，常见混合精度状态预算约每参数十二至十六字节，尚未包含激活；LoRA 仍须加载基础权重，QLoRA 则显著减少这一部分。v3.5.3 官方七十亿参数示例分别标注 LoRA 约二十二 GB、BNB QLoRA 约十 GB，属于特定脚本参考值，不是所有 GPU 的容量保证。

方法 基础权重 额外训练状态 使用判断
全参 BF16 等浮点权重 覆盖全部可训练参数 优先评估多卡分片和完整训练预算
LoRA 通常保留浮点基础权重 主要覆盖适配器 单卡领域适配的常用起点
QLoRA 四位权重加量化元数据 主要覆盖适配器，另有反量化开销 显存紧张时优先试验，速度未必更快

9.1 原生推理和真实 Python API

适配器推理使用 --adapters，全参或合并权重使用 --model。适配器目录中的训练参数可帮助恢复基础模型和模板，但应检查模型权重是否仍能下载，尤其是迁移到另一台机器之后。先用原生 PyTorch 后端验证一组固定输入，再切换加速引擎，便于定位模板、权重或引擎差异。

vLLM 通常更适合并发和批量推理，安装时可能调整 PyTorch 等核心依赖。建议在单独的服务环境中安装，而非直接改动已经训练成功的环境。下例使用官方 v3.5.3 README 推荐的 vLLM 版本；安装后重新检查依赖及 CUDA，实际可用性还取决于 GPU 和模型支持情况。

# 建立服务环境；从原实验根目录执行，output/merged 路径保持有效。

source .venv-serve/bin/activate
python -m pip install --upgrade pip

CUDA_VISIBLE_DEVICES=0 swift infer \
  --model output/merged --infer_backend vllm \
  --max_model_len 2048 --temperature 0 --max_new_tokens 256

CUDA_VISIBLE_DEVICES=0 swift deploy \
  --model output/merged --infer_backend vllm \
  --served_model_name swift-ops \
  --host 127.0.0.1 --port 8000 --max_model_len 2048

# 先查模型清单，再发起完整聊天请求；仅访问本机服务。
curl -fsS http://127.0.0.1:8000/v1/models
curl -fsS http://127.0.0.1:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \

# 检查图像数量、路径可读性、像素面积和标记数量。
import json
from pathlib import Path
from PIL import Image

for number, line in enumerate(Path('data/vision.jsonl').read_text(encoding='utf-8').splitlines(), 1):
    row = json.loads(line)
    markers = sum(m['content'].count('<image>') for m in row['messages'])
    assert markers == len(row['images']), f'第 {number} 行图像标记不匹配'
    for filename in row['images']:
        with Image.open(filename) as image:
            width, height = image.size
            print(number, filename, width, height, 'pixels=', width * height)

12.4 LoRA merge 后推理报错

3

优先检查是否把 adapter 目录当成完整模型加载，基础模型 revision 是否相同，以及 tokenizer、config、视觉处理器文件是否齐全。只复制 safetensors 文件不是完整模型交付。训练期间新增 token 或改动 embedding 时，适配器保存范围也必须包含相应改动，否则合并成功仍可能出现维度不匹配或输出异常。

# 对本文导出目录检查完整模型配置及权重，再用 pt 隔离引擎问题。
python - <<'PY'
from pathlib import Path
root = Path('output/merged')
assert (root / 'config.json').is_file(), '缺少模型 config.json'
weights = list(root.glob('*.safetensors')) + list(root.glob('pytorch_model*.bin'))
assert weights, '没有找到完整模型权重'
assert (root / 'tokenizer_config.json').is_file(), '缺少 tokenizer_config.json'
print('weight files:', len(weights))
PY
CUDA_VISIBLE_DEVICES=0 swift infer \
  --model output/merged --infer_backend pt \
  --temperature 0 --max_new_tokens 128

若合并前后回答差别明显，用相同模板、相同生成参数和同一批输入比较，并检查是否仍在推理时加载训练量化配置。仅通过“服务能启动”不能认定模型正确；至少需要固定输入的输出回归，再检查领域测试集。本文中的文件存在性检查只能排除一部分包装错误，不能替代权重正确性和模型质量验证。
