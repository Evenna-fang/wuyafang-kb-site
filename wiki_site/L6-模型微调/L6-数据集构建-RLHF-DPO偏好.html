DPO 偏好对齐：数据、训练、监控与验收

← 返回总入口

前置：SFT 数据构建与训练；原理衔接：训练与微调总览。

WHY3 个重点▾ 点开看本章重点
本章重点
  • SFT 教会模型“怎样给出一个合格答案”，但同一问题常有多个都合格、质量却不同的回答
  • 偏好对齐利用“同一上下文下 A 比 B 更符合目标”的比较信号，调整模型对回答风格、帮助性、安全边界、事实可靠性等维度的相对倾向
  • 经典 RLHF 通常包含奖励模型训练和基于奖励的强化学习
2

SFT 教会模型“怎样给出一个合格答案”，但同一问题常有多个都合格、质量却不同的回答。偏好对齐利用“同一上下文下 A 比 B 更符合目标”的比较信号，调整模型对回答风格、帮助性、安全边界、事实可靠性等维度的相对倾向。

经典 RLHF 通常包含奖励模型训练和基于奖励的强化学习。DPO（Direct Preference Optimization）在特定假设下把偏好优化写成直接监督式目标，省去显式奖励模型与 PPO 在线采样管线，因此工程路径更短；它并没有取消偏好数据、参考策略、分布偏移、裁判偏差和独立评估。

适合先做 DPO 的情形：

  • 已有可正常完成任务的 SFT 模型；
  • 主要错误表现为“两个回答中哪个更好”，而不是模型完全不会任务；
  • 能构造并审核同 prompt 的 chosen/rejected；
  • 有未参与构造数据的保留集，能比较 DPO 前后胜率、质量和副作用。

若 chosen 本身错误、SFT 基座不会基本格式、或评估只看 DPO loss，继续训练往往只会放大错误。偏好维度也应有优先级：事实与安全不能被“更礼貌”“更长”抵消。

WHAT

2
1. DPO 在优化什么3 个重点▾ 点开看本节重点
本节重点
  • 对同一输入 \(x\)，偏好对为 \((y_w,y_l)\)，分别表示 chosen 与 rejected
  • 它不是“越小越保守”，也不是跨模型可照搬的最优常数
  • 变体改变优化目标，不能只替换名字后沿用原结论
3

对同一输入 (x)，偏好对为 ((y_w,y_l))，分别表示 chosen 与 rejected。当前策略为 (\pi_\theta)，参考策略为 (\pi_{ref})。DPO 的典型 sigmoid 损失可写为：

[
\mathcal{L}{DPO}=-\mathbb{E}\left[\log\sigma\left(\beta\left(
\log\frac{\pi\theta(y_w|x)}{\pi_{ref}(y_w|x)}
-\log\frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}
\right)\right)\right]
]

直观上，它希望 chosen 相对 reference 的对数概率变化优于 rejected。beta 控制偏好信号与偏离 reference 的尺度；TRL 文档默认值为 0.1，且越大越限制偏离 reference。它不是“越小越保守”，也不是跨模型可照搬的最优常数。

TRL 当前还支持 ipo、robust、sigmoid_norm 等损失变体，默认 sigmoid。变体改变优化目标，不能只替换名字后沿用原结论。

2. 数据格式与语义边界

3

TRL 的 conversational 显式偏好格式：

{"prompt":[{"role":"user","content":"用一句话解释过拟合。"}],"chosen":[{"role":"assistant","content":"过拟合是模型记住训练集中的噪声，导致在新数据上表现变差。"}],"rejected":[{"role":"assistant","content":"过拟合就是模型越复杂越好，所以训练集越准就越好。"}]}

每个样本必须具备：

  • 完全相同的 prompt 前缀；
  • 非空且语义不同的 chosen/rejected；
  • 明确、可复核的偏好方向；
  • 与部署一致的 system、历史和 chat template；
  • 来源、裁判/标注、审核和版本元数据。

多轮样本把公共历史放在 prompt，只让最后 assistant 回复分支。不要把 chosen 和 rejected 各自不同的历史拼成一对，否则模型会混淆上下文差异与回答质量差异。

“偏好对差距很大就没有信息”不是普适结论。容易 pair 可能很快饱和，困难 pair 更可能提供持续学习信号，但也可能带来噪声；应通过 pair 来源、基线 margin、标注一致性和消融实验判断，而不是按主观分差机械删除。

3. 数据来源与裁判偏差3 个重点▾ 点开看本节重点
本节重点
  • 1. 人工比较：适合高风险、安全、复杂业务和裁判校准
  • 2. 当前模型多路采样 + 排序：rejected 更接近当前策略可能产生的错误
  • 3. 强模型/规则提供 chosen：适合有可靠教师或可程序验证的任务
3

常见生产方式：

  1. 人工比较：适合高风险、安全、复杂业务和裁判校准。
  2. 当前模型多路采样 + 排序：rejected 更接近当前策略可能产生的错误。
  3. 强模型/规则提供 chosen：适合有可靠教师或可程序验证的任务。
  4. best-of-n/拒绝采样：代码用测试、数学用答案验证、结构化任务用 schema 和字段规则筛选。

使用 LLM-as-judge 时至少处理：

  • 位置偏差：随机交换 A/B，必要时双向复核；
  • 长度偏差：rubric 明确“长不等于好”，并按长度分桶抽检；
  • 自我/家族偏好：不要只依赖与候选生成器相同的裁判；
  • 不可判定样本：允许弃标或送人工，不强迫所有 pair 都有方向；
  • 提示注入：候选回答是不可信内容，裁判不能执行其中指令。

一致性比例、Cohen's κ 或 Krippendorff's α 可用于审核流程，但阈值应依据任务风险和标注设计预先约定，不能套旧稿的单一通用分数线。

4. 必须监控的训练信号

3

DPO loss 下降并不足以证明模型更好。TRL 文档列出的关键指标包括：

指标 含义 异常提示
logps/chosen 当前策略对chosen的log概率 持续大幅下降可能说明偏好改善以压低chosen为代价
logps/rejected 当前策略对rejected的log概率 只降rejected不一定带来更好生成
rewards/margins chosen与rejected隐式奖励差 应结合保留集胜率，而非单独追大
rewards/accuracies 训练对中chosen奖励高于rejected的比例 高值也可能来自容易pair、记忆或过拟合

还要记录输出长度、拒答率、格式正确率、事实/任务指标和通用回归。margin 增大但业务评估下降时，应停止，不得把 margin 当最终目标。

5. DPO 与 RM/PPO 的边界2 个重点▾ 点开看本节重点
本节重点
  • 两者都不是 SFT 的默认前置或必然后继
  • 根据目标与证据选择，不以“流程更先进”作为理由
3
维度 DPO 显式RM + PPO
主要输入 离线偏好对 偏好训练RM，策略在线采样优化
额外模型 reference policy；不显式训练RM 奖励模型、reference及RL所需组件
工程链路 较短 较复杂，在线系统与稳定性要求高
数据更新 可离线迭代补充 可在线探索，也需防奖励攻击与分布偏移
适用判断 已有明确偏好对，先建立对齐基线 确有在线优化需求且具备评估与运维能力

两者都不是 SFT 的默认前置或必然后继。根据目标与证据选择，不以“流程更先进”作为理由。

HOW

2
1. 构造可审计偏好数据3 个重点▾ 点开看本节重点
本节重点
  • 1. 从 SFT 保留集之外收集真实失败类型和代表性 prompt
  • 2. 用相同上下文生成候选，记录生成模型、revision、温度与系统提示
  • 3. 按 rubric 比较；正确性/安全性优先，格式与风格不得掩盖事实错误
3

建议源数据 JSONL 保留元数据，训练前再投影成 TRL 字段：

{"id":"pref-0001","prompt":[{"role":"user","content":"把这段故障描述改写得更清楚。"}],"chosen":[{"role":"assistant","content":"服务在写入磁盘时失败，原因是可用空间不足。"}],"rejected":[{"role":"assistant","content":"服务出问题了，可能是很多原因，请全面检查。"}],"meta":{"rubric":"clarity-v2","judge":"human-reviewed","group_id":"incident-42"}}

操作顺序：

  1. 从 SFT 保留集之外收集真实失败类型和代表性 prompt。
  2. 用相同上下文生成候选，记录生成模型、revision、温度与系统提示。
  3. 按 rubric 比较；正确性/安全性优先，格式与风格不得掩盖事实错误。
  4. 删除空答案、相同答案、方向不明或无法审核的 pair；保留弃标原因。
  5. 按近重复簇或业务实体分组切分 train/calibration/test；test 不参与 prompt 设计、裁判调参和模型选择。
  6. 分别统计 chosen/rejected 的长度、来源、裁判、主题与胜率，防止模型只学到“选长答案”或“选某模型风格”。
  7. 冻结数据快照与 manifest，保存裁判提示和审核版本。

结构校验（示例，未实跑）：

import json

for line_no, line in enumerate(open("dpo-train.jsonl", encoding="utf-8"), 1):
    row = json.loads(line)
    assert set(("prompt", "chosen", "rejected")) <= row.keys()
    assert row["prompt"] and row["chosen"] and row["rejected"]
    assert row["chosen"] != row["rejected"], (line_no, "相同回答")
    assert row["chosen"][-1]["role"] == "assistant"
    assert row["rejected"][-1]["role"] == "assistant"
    assert row["meta"]["judge"] == "human-reviewed"

脚本只检查结构，不能证明 chosen 更好。应对抽样 pair 做盲审，并检查同一 prompt 是否在 train/test 两侧出现。

2. 固定 SFT 起点并跑基线

3
  1. 固定 SFT 模型、tokenizer/template、数据快照和依赖。
  2. 在独立 test 上运行 SFT 模型，保存逐样本输出，不只保存平均分。
  3. 记录长度、拒答、格式和关键错误类型，作为 DPO 副作用基线。
  4. 先跑短训练验证保存、日志和评估，再决定训练规模。

如果 chosen 与 SFT 输出来自不同聊天模板，先统一模板，否则 DPO 可能学到模板差异。

3. TRL 最小训练主路径3 个重点▾ 点开看本节重点
本节重点
  • 以下采用官方当前显式偏好数据格式
  • 代码为示例，未实跑，执行前锁定 TRL/Transformers/PEFT 版本并保存解析配置
  • trainer.save_model("runs/dpo-smoke/final")
3

以下采用官方当前显式偏好数据格式。ref_model=None 时使用训练前初始 policy 作为参考；加载已有 adapter 时还应核对 PEFT 参考模型处理。代码为示例，未实跑，执行前锁定 TRL/Transformers/PEFT 版本并保存解析配置。

from datasets import load_dataset
from trl import DPOConfig, DPOTrainer

SFT_MODEL = "runs/sft/final"
train = load_dataset("json", data_files="dpo-train.jsonl", split="train")
eval_pairs = load_dataset("json", data_files="dpo-calibration.jsonl", split="train")

args = DPOConfig(
    output_dir="runs/dpo-smoke",
    beta=0.1,
    report_to=[],
)
trainer = DPOTrainer(
    model=SFT_MODEL,
    ref_model=None,
    args=args,
    train_dataset=train,
    eval_dataset=eval_pairs,
)
trainer.train()
trainer.save_model("runs/dpo-smoke/final")

beta=0.1 是文档默认值，不是本文推荐的最优超参。改变 beta、损失类型、参考模型或训练数据任一因素后，都应重新做对照。不要只看 loss 自动选 checkpoint；选择应结合校准集、独立任务评测和通用回归。

4. 用盲评验收，而不是用训练 pair 自证

3

至少保留四组结果：SFT 基线、DPO 候选、必要时上一线上版本、以及通用回归集。

评估流程：

  1. 使用相同 prompt、解码参数和生成预算分别生成回答。
  2. 对输出匿名并随机左右位置，避免裁判知道模型身份。
  3. 对可程序验证任务运行测试/schema/事实规则；开放任务使用预先固定的 rubric。
  4. 报告总体和分主题胜率，同时报告平局、无法判定、长度、拒答和格式。
  5. 抽检“DPO 胜”和“DPO 负”的样本，确认裁判没有只偏好更长或更模板化答案。
  6. 若总体胜但高风险场景回退，按场景门禁拒绝上线，不用平均分抵消。

通过标准应在训练前按业务风险设定。验收产物包括逐样本输出、裁判版本、统计表、失败案例、训练指标截图/日志、最终配置和回退模型。

5. 故障定位与回退1 个重点▾ 点开看本节重点
本节重点
  • 回退单位应是一个完整可复现版本：SFT 起点、DPO 权重、数据快照、依赖与评估报告，而不是只保留最后一个 checkpoint
3
现象 优先定位 处理方向
reward accuracy很高但盲评不变好 pair过易、泄漏、裁判同源偏差 换独立测试与裁判，重做困难样本和来源审计
chosen logp与rejected一起下降 策略整体退化、训练过强或数据问题 早停/回退，检查beta、LR、数据与reference
输出明显变长 chosen长度偏置、裁判长度偏好 长度分桶审计、重写rubric、重采样pair
拒答增多 chosen安全/拒答样本过集中 按场景统计，补正常可回答样本并重训
训练pair提升、真实请求变差 prompt分布偏移、模板不一致 对齐线上分布与模板，扩充真实失败类型
margin持续增大但质量下降 优化目标与业务目标错位 停止追margin，按独立评估选早 checkpoint
保存后行为不同 reference/adapter/模板保存不完整 另起进程加载，核对配置、权重与tokenizer

回退单位应是一个完整可复现版本：SFT 起点、DPO 权重、数据快照、依赖与评估报告，而不是只保留最后一个 checkpoint。
