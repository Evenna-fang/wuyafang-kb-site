大模型预训练、继续预训练与 SFT：数据到验收的唯一闭环

本篇统一回答：什么时候不该训练，预训练/CPT/SFT 分别学什么，连续语料和指令数据怎样制作，以及怎样完成一次可归因、可回退的微调实验。LoRA/QLoRA 见参数高效微调，偏好对齐见RLHF/DPO，训练数值稳定性见深度学习与 Transformer。

运行边界：本文训练代码和命令均为示例，未实跑；没有下载模型、安装依赖或启动 GPU 训练。静态语法检查不等于 API、硬件兼容或业务效果通过。

WHY：先证明需要参数更新，再选择训练阶段

2

大模型项目常见浪费，是把“知识缺失、检索失败、提示词不清、输出格式不稳、偏好不一致”都当成微调问题。训练会引入数据权利、隐私、模板、算力、评估污染、通用能力回退和版本维护成本；如果 RAG 或提示词已经解决，就没有理由承担这些成本。反过来，若模型长期不会遵循稳定的业务格式、术语表达或工具调用约束，仅靠不断堆提示词也会难以维护。

先按失败类型选手段：

观察到的差距 首选手段 什么时候才进入训练
最新政策、内部文档、商品状态不知道 RAG、搜索、业务工具 检索已正确但回答格式或证据使用仍不稳定时，再叠加 SFT
输出 JSON、分类、改写、工具参数不稳定 提示词、schema、少样本、执行器校验 固定测试集证明行为差距稳定存在，再做 SFT
稳定领域连续文本的术语和语言分布不熟 先做基线与领域小实验 有合法连续语料且 CPT 对照有收益时做 CPT；需要问答行为再接 SFT
多个回答都合格，但详略、风格或安全偏好不稳 先写评价 rubric 有可审核 chosen/rejected 后做 DPO/RLHF，不用偏好训练补基础格式
少数 bad case 或知识需要频繁更新 修提示词、检索或工具 不设“满 500/1000 条才可微调”的伪门槛，以错误覆盖和小实验决定

预训练、CPT、SFT 与偏好对齐不是可以互相替换的四份数据。预训练主要学连续文本的下一 token；CPT 在既有基座上继续语言建模；SFT 学给定上下文中的目标回答；偏好训练学同一提示下哪个回答更好。把文档强行改成问答不等于 CPT，把偏好对当 SFT 答案也不能替代基础任务示范。

不做数据治理会怎样：网页导航、转载、评测题、个人信息和错误答案会进入训练；文件数与 token 数看似增长，有效信息却可能没有增长。测试集若与训练集共享同一文档、用户或近重复样本，分数会虚高。最终可能出现“loss 下降、评测很好、真实请求变差”，还无法定位是哪版数据和代码造成的。

WHAT / WHYT：阶段、数据契约与适用边界

2

1. 四个阶段分别改变什么

3
阶段 典型输入 优化对象 直接产物 不能自动保证
从零预训练 大规模连续文本、代码 通常预测下一 token 基座语言与知识表示 指令遵循、事实实时性、业务安全
继续预训练 CPT/DAP 通用与领域连续文档 在既有权重上继续语言建模 领域适配基座 自动学会问答；通用能力不退化
SFT messages 或 prompt/completion 模仿目标回答，常只计算回答区 loss 会按示例完成任务的模型 答案必然真实；未见场景零失败
DPO/RLHF 偏好对、奖励信号 调整多个可行回答的相对倾向 偏好调整后的策略 偏好覆盖之外的价值与事实正确

Base 与 Instruct 的选择也应由对照实验决定。直接做业务 SFT 时，Instruct 往往已有通用指令行为；重度 CPT 通常从 Base 起步，但最终仍需跑同一领域集和通用回归集。模型许可证、分词器、上下文、工具生态和部署格式与训练效果同样重要。

2. 预训练/CPT：连续文档的九道数据门禁

3

（1）来源与许可。 每个来源登记 source_id、获取版本、授权依据、允许用途、撤回方式和责任人。“公开可访问”不自动等于“允许训练与再分发”；未确认的来源进入隔离区。隐私处理是检测、处置、复核和审计的闭环，不能用几个正则替换就宣称匿名化。

（2）正文抽取与规范化。 保留标题、段落、代码、公式、文档边界、原文哈希与页码；导航、页眉页脚和 OCR 低置信页分开处置。NFKC、简繁转换、空白归一可能改变代码、数学符号和语言变体，必须按内容类型抽检，而不是全量一键执行。

（3）质量过滤。 可读性、信息性、来源信誉和学习型质量是不同信号。规则可解释但容易误杀中英混排、代码与表格；质量分类器会继承正负例偏差，且“质量高”不等于“事实正确”。每条规则都看来源/语言切片的保留率和误杀样本。

（4）精确与近重复去重。 文档哈希处理完全重复，文档内规则处理异常重复段落，shingles 与 MinHash/LSH 等用于候选近重复，再由确认规则和人工抽样决定。不要误删同一法规的不同版本或同模板的不同实体。去重族不能跨 train/eval。

（5）有效 token 配比。 按进入训练的有效 token 报告来源、语言、领域与质量层分布，同时报告唯一 token 和实际上采样曝光。CPT 候选配比使用相同模型和训练预算比较，同时监测领域收益与通用遗忘，不照抄固定 Web/Code/领域百分比。

（6）分词器与文档边界。 CPT 通常复用基座 tokenizer、特殊 token 和词表。检查各语言压缩率、异常 byte、代码和数字表现。文档末尾是否加 EOS、packing 是否跨文档、position id 与 attention mask 如何处理，必须和框架约定一致。

（7）长文档与 packing。 切块保留 parent_doc_id 和片段序号，不为凑长度跨 split 拼接。Packing 提高填充利用率，但不等于可以忽略文档边界；从编码分片解码少量样本，验证没有错串和答案截断。

（8）评测污染。 训练前冻结测试集，对题面、答案、参考文档和近重复变体建立禁止匹配库。发现污染后旧评估作废，不能继续与清理后的模型直接比较。过强过滤也可能删掉正常知识，需要抽检误删。

（9）不可变快照与血缘。 每次训练引用只读快照，保存分片、采样索引、tokenizer、packing、规则、代码版本、统计报告和 SHA-256。任何规则或配比变化生成新版本；来源撤回时能定位派生分片与训练 run。

课件落点：day01 将原始文本、指令、对话和反馈数据区分，并给出获取、清洗、脱敏、去重、抽样与小规模测试的教学主线；day06 提醒版权、隐私、基座模型卡与评估。本文据此搭骨架，但不沿用课件中的固定数据量分档。

书籍落点：《从零构建大模型》的目录与公开划线支持“无标注文本上的下一 token 预测、自监督、BPE、滑动窗口和指令微调”；《大语言模型：原理、应用与优化》的目录/划线支持预训练、指令、反馈数据与归一化的分类；《Happy-LLM》目录/划线支持 CLM、input_ids、attention_mask 与 SFT 数据处理。这里只使用目录和公开划线，不声称阅读书籍全文。

3. 本地论文：预训练架构与 SFT 数据研究怎样转化为实践

3

Cola2（arXiv:2610.31305）研究连续语义压缩与离散生成的联合预训练：动态语义分段、重建与生成监督、连续—离散协同。摘要报告约 2100 亿训练 token 的核心设计实验，另有一个使用 3460.3 亿 source token 的未收敛 checkpoint。我们怎么用：它提醒预训练目标、表示学习和生成器设计可以分别消融，不能把预训练简化成“堆文本”；做架构研究时记录训练 token、source token、收敛状态和评估范围。不能怎么用：它不是普通 CPT/SFT 配方，不能据摘要外推小数据微调收益或全面优于其他模型。

AutoSFT（arXiv:2610.22194）把 SFT 数据研究扩展为调比例、剪枝、修复、替换和合成，多智能体分离执行与分析；比较中固定模型、训练器和预算，每轮从基座重新训练。摘要报告分析模块和合成模块在 IFEval/IFBench、MBPP+ 上的增益。我们怎么用：数据迭代不要只会“从固定池多选一点”，每次实验明确一种数据动作；固定训练栈并保留逐版快照，用消融判断数据动作是否有效。边界：这些数值只属于摘要中的任务和系统，不证明多智能体必然胜过人工数据工程。

4. SFT：messages、模板与 loss mask 是同一份契约

3

建议人工审核后的源数据统一保存为 JSONL，每行一段对话；框架所需 alpaca/sharegpt 由转换层生成，不维护多份手工副本。

{"id":"case-0001","source":"human-reviewed-v3","group_id":"incident-42","messages":[{"role":"system","content":"你是严谨的运维助手。"},{"role":"user","content":"把磁盘写满导致任务失败改写成一句告警。"},{"role":"assistant","content":"磁盘空间耗尽，任务写入失败；请清理空间并检查写入权限。"}],"meta":{"review":"passed"}}
  • id/source/group_id 用于去重、审计与按实体切分；meta 默认不送进模型。
  • 工具声明、调用和工具返回必须按目标模型模板表示。工具返回不是 assistant 答案，不能拼成普通回答让模型伪造。
  • 因果语言模型仍用下一 token 交叉熵。只学回答时，system/user/tool/padding 位置通常设为 -100，assistant 和需要学习的 EOS 保留监督。
  • PAD 与 EOS 即使复用同一个 token id，也必须按位置决定掩码，不能把所有等于 pad id 的标签一并屏蔽。
  • TRL 的 assistant_only_loss=True 需要模板含 {% generation %} 标记，或由当前版本明确支持的自动处理。模板不支持时改用 prompt/completion 或受支持掩码方案，不能忽略警告。
  • Packing 只改变样本排列，不改变标签契约；仍需检查样本边界、有效监督 token 和 EOS。

SFT 数据生产遵循“错误分桶 → 权利/隐私检查 → 生成 → 规则过滤 → 去重 → 人工或程序审核 → 分组切分 → 模板与标签检查 → 快照 → 小实验 → bad case 回流”。代码可跑测试、抽取可对字段、数学可验答案；开放写作使用固定 rubric 和人工抽检。合成数据是生产手段，不是质量证明。

5. 评估分四层，训练 loss 只是第一层

3
  1. 训练健康：有效监督 token、loss、梯度、学习率、吞吐和异常样本。
  2. 冻结任务集：基座与候选使用相同提示、解码和工具环境，比较正确性、格式、指令遵循与安全。
  3. 通用回归：覆盖通用对话、工具调用、长输入、多语言和拒答边界；CPT 尤其要监测遗忘。
  4. 灰度与回退：观察真实输入漂移、延迟、失败率与人工接管，保留切回上一稳定模型或 adapter 的路径。

测试集在数据制作前冻结，按文档、用户、业务实体或近重复簇切分。LLM-as-a-Judge 要固定裁判、提示与顺序并抽查人机一致性；高风险任务仍需领域人员审核。

HOW：从数据校验到 SFT 冒烟与发布回退

2

1. 准备两个最小数据文件

3

连续语料保存为 corpus.jsonl，一行一篇文档：

{"doc_id":"doc-0001","source_id":"manual-v1","rights":"approved","group_id":"manual-1","text":"这是已经获得处理授权的连续正文，不含指令答案或偏好字段。"}

SFT 数据使用上一节 messages 格式保存为 train.jsonl。另建不参与制作的 eval.jsonl 和通用回归集；同一 group_id 只能出现在一个 split。

2. 运行结构与快照校验

3

把下面保存为 validate_data.py。它只验证结构、空文本和重复 ID，不证明语义正确、无 PII、无近重复或无评测污染。

import argparse
import hashlib
import json
from collections import Counter
from pathlib import Path

parser = argparse.ArgumentParser()
parser.add_argument("kind", choices=["corpus", "sft"])
parser.add_argument("path", type=Path)
args = parser.parse_args()

rows = []
with args.path.open(encoding="utf-8") as handle:
    for line_no, line in enumerate(handle, 1):
        row = json.loads(line)
        assert row.get("group_id"), (line_no, "缺少分组切分键")
        if args.kind == "corpus":
            assert row.get("doc_id"), (line_no, "缺少doc_id")
            assert row.get("text", "").strip(), (line_no, "空正文")
            assert row.get("rights") == "approved", (line_no, "来源未批准")
            assert "instruction" not in row and "chosen" not in row
            rows.append(row["doc_id"])
        else:
            assert row.get("id") and row.get("source"), (line_no, "缺少id/source")
            assert row.get("meta", {}).get("review") == "passed"
            messages = row.get("messages", [])
            assert messages and messages[-1].get("role") == "assistant"
            assert all(m.get("content", "").strip() for m in messages)
            assert all(m.get("role") in {"system", "user", "assistant", "tool"} for m in messages)
            rows.append(row["id"])

assert not [key for key, count in Counter(rows).items() if count > 1], "ID重复"
digest = hashlib.sha256(args.path.read_bytes()).hexdigest()
print(f"schema ok: {len(rows)} rows; sha256={digest}")

以下命令语法可执行，但本次未实跑：

python validate_data.py corpus corpus.jsonl
python validate_data.py sft train.jsonl
python validate_data.py sft eval.jsonl
sha256sum corpus.jsonl train.jsonl eval.jsonl > data-manifest.sha256

随后人工完成结构校验无法替代的工作：按来源/语言/长度分层抽检，检查权利与隐私，运行精确/近重复去重，按 group_id 或去重族切分，渲染一条真实模板，剔除 labels 中 -100 后解码，确认只留下目标回答且 EOS 未被截掉。

3. 跑一条最小 SFT 主路径

3

安装与训练命令均为示例，未实跑；正式实验应锁定依赖和模型 revision，并保存解析后的完整配置。

python -m pip install torch transformers datasets trl peft accelerate
python train_sft.py

将下面保存为 train_sft.py。assistant_only_loss=True 只有在模型模板支持生成区标记时才保留；否则按当前 TRL 文档改为 prompt/completion 或受支持模板。

from datasets import load_dataset
from trl import SFTConfig, SFTTrainer

MODEL = "Qwen/Qwen3-0.6B"  # 示例标识；正式实验固定revision并核对许可
train = load_dataset("json", data_files="train.jsonl", split="train")
eval_set = load_dataset("json", data_files="eval.jsonl", split="train")

args = SFTConfig(
    output_dir="runs/sft-smoke",
    max_length=1024,
    packing=False,
    assistant_only_loss=True,
    report_to=[],
)
trainer = SFTTrainer(
    model=MODEL,
    args=args,
    train_dataset=train,
    eval_dataset=eval_set,
)
trainer.train()
trainer.save_model("runs/sft-smoke/final")

执行顺序不是直接扩大 epoch：

  1. 基线：固定基座、tokenizer/template、解码参数，在冻结集保存逐样本输出和失败分类。
  2. 单 batch 冒烟：确认输入、标签、有效监督 token、有限 loss、可训练参数、保存和重载。
  3. 小样本可学习性：能记住少量干净样本只证明链路可学习，不证明泛化。
  4. 单变量对照：每次只改数据版本、学习率、训练步数或 LoRA 秩之一；AutoSFT 的“固定 model/trainer/budget、从 base 重训”用于保证归因，而不是每次从上次候选继续叠加。
  5. 独立盲测：最佳 checkpoint 冻结后才评测试集；报告总体和关键切片，包含正例、边界例、对抗例和不应回答的负例。
  6. 打包与回退：保存权重或 adapter、基座修订、tokenizer/template、数据哈希、环境、配置、评估和已知限制；另起进程重载后再灰度。

4. 发布门槛与故障回退

3
检查 通过口径 失败时回退
数据可复现 快照只读、哈希与血缘齐全，分组/近重复未跨 split 作废旧评估，回到上一合规快照
模板与标签 解码有效 labels 与目标回答一致，无全 -100 batch 修模板/掩码后从基座重跑，不在错标签上追加训练
主任务有效 基座/候选同集同解码达到预定义改善 回到基线，修数据和错误定义，不盲目加 epoch
通用能力保留 对话、工具、安全和长上下文不越过降级预算 回滚基座或较早 checkpoint，重做配比和训练强度
产物可加载 基座、adapter/权重、tokenizer、template 和配置绑定 恢复上一完整产物，不用缺文件目录上线
服务可回退 灰度期间能切回旧版并复测 出现安全/隐私问题立即隔离新版并保存最小复现

  • 判分规则是确定性的（/home/wuyafang/.hermes/scripts/eval_smoke.py 的 judge()）：missing = [kw for kw in case["expected_keywords"] if kw not in response]，关键词全中才算过；不引入 LLM 当裁判，避免"裁判漂移"混淆结论。
  • 和课件讲法的差异：课件微调选型常用 lm-evaluation-harness / C-Eval 跑通用基准；本库没有跑基准任务，只有自建短用例冒烟（成本低、可天天跑）。本库暂无微调前后对照评测管线（微调本身未做），上述模板可直接当"微调后回归"的骨架：把基座和微调产物各配一个 MODELS 条目即可。
  • 另一处：/home/wuyafang/.hermes/scripts/batch_audit.py 用"分段字数/代码块数/三段齐全/来源行数"做文档质量机械审计——同一思路可用于检查微调数据集的字段完整性，而不只看 loss。
