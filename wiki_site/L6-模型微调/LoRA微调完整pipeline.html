WHY3 个重点▾ 点开看本章重点
本章重点
  • 全参数微调会更新全部模型权重，并为大范围的参数保存梯度和优化器状态
  • LoRA 并不会自动消除以下成本：基座权重仍要加载，激活仍随序列长度、batch 和网络结构增长，反向传播仍要穿过冻结层，训练吞吐也不保证高于全参训练
  • QLoRA 在 LoRA 思路上进一步把冻结基座以 4-bit 量化形式加载，使用 NF4、双重量化和分页优化器降低训练内存压力
2

全参数微调会更新全部模型权重，并为大范围的参数保存梯度和优化器状态。LoRA（Low-Rank Adaptation）冻结原权重，只为选中的线性层学习低秩增量，从而显著减少可训练参数及其梯度、优化器状态，并让不同任务可以共享同一基座、分别保存小型 adapter。

LoRA 并不会自动消除以下成本：基座权重仍要加载，激活仍随序列长度、batch 和网络结构增长，反向传播仍要穿过冻结层，训练吞吐也不保证高于全参训练。它更不是把基座模型本身压缩成小模型。

QLoRA 在 LoRA 思路上进一步把冻结基座以 4-bit 量化形式加载，使用 NF4、双重量化和分页优化器降低训练内存压力。它适合基座权重精度加载放不下或需要降低内存占用的场景，但是否更快、是否保住任务效果，必须在同一模型、数据、序列长度、batch 与硬件上测量，不能套用一个通用百分比。

决策顺序：

  1. 先确认微调确有必要，并已有独立评测集；见训练总览。
  2. 基座精度和 LoRA 训练能稳定放下，优先跑普通 LoRA 建立质量基线。
  3. 基座加载或训练内存成为瓶颈，再试 QLoRA，并重新评估质量与速度。
  4. 多卡内存仍不足时，再组合梯度检查点、ZeRO/FSDP 等；这些技术解决的是不同维度的问题。

WHAT

1. LoRA 的数学与缩放3 个重点▾ 点开看本节重点
本节重点
  • LoRA 冻结 \(W\)，学习
  • 两者不能混用同一套“alpha 必须是 rank 两倍”的经验公式
  • rank、alpha、dropout 与学习率都应由任务验证集选择，而非固定最佳值
3

对原线性层

[
y = Wx,\qquad W\in\mathbb{R}^{d_{out}\times d_{in}}
]

LoRA 冻结 (W)，学习

[
W' = W + \Delta W,\qquad \Delta W = \frac{\alpha}{r}BA
]

其中 (A\in\mathbb{R}^{r\times d_{in}})、(B\in\mathbb{R}^{d_{out}\times r})，秩 (r\ll\min(d_{in},d_{out}))。PEFT 默认以 Kaiming-uniform 初始化 A、以零初始化 B，因此训练开始时 (BA=0)，adapter 不改变原层输出。

普通 LoRA 的缩放是 lora_alpha / r；rsLoRA 使用 lora_alpha / sqrt(r)，PEFT 通过 use_rslora=True 启用。两者不能混用同一套“alpha 必须是 rank 两倍”的经验公式。rank、alpha、dropout 与学习率都应由任务验证集选择，而非固定最佳值。

3. 关键配置的真实含义3 个重点▾ 点开看本节重点
本节重点
  • 「r」：低秩增量容量，影响 adapter 参数和计算，不是“越大越好”
  • 「lora_alpha」：与缩放公式共同决定增量幅度
  • 「target_modules」：决定挂接层
3
  • r：低秩增量容量，影响 adapter 参数和计算，不是“越大越好”。
  • lora_alpha：与缩放公式共同决定增量幅度。
  • target_modules：决定挂接层。all-linear 是 PEFT 文档给出的 QLoRA 常用配置，但会排除部分特殊层；是否适合某模型必须打印已挂模块确认。
  • lora_dropout：adapter 分支正则化，不控制基座其他 dropout。
  • bias：是否训练偏置，会改变可训练参数与保存内容。
  • 学习率/有效 batch：优化超参，不能从 rank 推导固定答案。
  • 梯度检查点：用额外重算换激活内存，和 LoRA 可组合但不是同一机制。

4. 产物与合并方式

3

LoRA/QLoRA 默认训练产物是 adapter，不包含一份新的完整基座。部署有两条路径：

  1. 运行时挂 adapter：共享基座、多任务切换方便；要求推理服务支持对应 PEFT/LoRA 格式。
  2. 离线合并：以所需原始精度重新加载基座，执行 merge_and_unload() 并接收返回模型，再保存完整权重与 tokenizer。

PEFT 的 merge_and_unload() 不是原地操作：应写 merged = model.merge_and_unload()。量化模型反复 merge/unmerge 可能积累舍入误差；要得到高质量完整模型，不要简单把 4-bit 基座合并结果当成 bf16 全参模型。

3. QLoRA + SFT 主路径

3

以下展示当前 Transformers/PEFT/TRL 的组合方式。assistant_only_loss=True 的模板前提与标签检查见 SFT 篇。代码仅为接口示例，未实跑；实际运行须锁定版本、模型 revision，并按官方文档处理模型特定要求。

import torch
from datasets import load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig
from trl import SFTConfig, SFTTrainer

MODEL = "your/instruct-base-model"
quant = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_use_double_quant=True,
    bnb_4bit_compute_dtype=torch.bfloat16,
)
model = AutoModelForCausalLM.from_pretrained(
    MODEL,
    quantization_config=quant,
    device_map="auto",
)
tokenizer = AutoTokenizer.from_pretrained(MODEL)
train = load_dataset("json", data_files="train.jsonl", split="train")

peft_config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules="all-linear",
    lora_dropout=0.0,
    task_type="CAUSAL_LM",
)
args = SFTConfig(
    output_dir="runs/qlora-smoke",
    max_length=1024,
    packing=False,
    assistant_only_loss=True,
    report_to=[],
)
trainer = SFTTrainer(
    model=model,
    processing_class=tokenizer,
    args=args,
    train_dataset=train,
    peft_config=peft_config,
)
trainer.train()
trainer.save_model("runs/qlora-smoke/adapter")
tokenizer.save_pretrained("runs/qlora-smoke/adapter")

普通 LoRA 对照实验去掉 4-bit quantization_config，以训练所需精度加载基座，其余条件保持一致。显存不足时按顺序检查：样本长度是否异常、micro-batch、梯度检查点、目标模块、基座量化、分布式切分。梯度累积能降低 micro-batch 的激活压力，但不会消除基座权重成本，也不等于减小总有效 batch。

4. 合并并保存完整模型3 个重点▾ 点开看本节重点
本节重点
  • merged.save_pretrained(OUT)
  • AutoTokenizer.from_pretrained(BASE).save_pretrained(OUT)
  • 合并前确认基座 revision 与训练完全相同；合并所需内存与训练不同，必要时在更大内存环境执行
3

合并代码（示例，未实跑）：

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel

BASE = "your/instruct-base-model"
ADAPTER = "runs/qlora-smoke/adapter"
OUT = "runs/qlora-smoke/merged-bf16"

base = AutoModelForCausalLM.from_pretrained(BASE, dtype=torch.bfloat16)
model = PeftModel.from_pretrained(base, ADAPTER)
merged = model.merge_and_unload()  # 必须接收返回模型
merged.save_pretrained(OUT)
AutoTokenizer.from_pretrained(BASE).save_pretrained(OUT)

合并前确认基座 revision 与训练完全相同；合并所需内存与训练不同，必要时在更大内存环境执行。保存后另起进程重新加载，检查 config、权重、tokenizer、chat template 和生成配置。

5. 三层验收

3
  1. 训练层：loss/梯度无异常，可训练参数正确，adapter 能保存并重新加载。
  2. 模型层：与基座在独立保留集上做同条件对照；按场景报告任务指标、拒答、格式、长度及通用能力回退。
  3. 交付层：对最终部署形态评估——运行时 adapter 就测挂载后的服务，合并模型就测合并权重，部署前再量化就测量化后模型。

只有训练 loss 下降不构成通过。若 QLoRA 与 LoRA 有差异，先检查是否使用同一数据顺序、有效 batch、模板、训练步数与评估解码配置，再判断量化影响。
