Answer Correctness 回答的是评测体系里最终的问题：把答案和标准答案放在一起，对不对。它是三层评测里的端到端指标，也是 Faithfulness 的盲区补位：Faithfulness 看不到漏答和"忠于错误材料"，Answer Correctness 因为直接对比标准答案，两者都能扣分。

先澄清一个常见的引用错误：RAGAS 原论文（arXiv:2309.15217）没有定义 Answer Correctness。论文的结论段说得很明确，它提出的是三个"无需标准答案"的维度：faithfulness、answer relevance、context relevance。Answer Correctness 是 ragas 库后来加入的、需要 reference 的指标，它的定义来自官方文档和源码，不来自论文。所以引用时应写"RAGAS 论文提出了无参考评测框架，Answer Correctness 属于库在其后扩展的有参考指标"，不要写成"论文 Table 1 的指标"。

它的构成是两部分加权：事实重合的 F1（默认权重 0.75）加答案与标准答案的语义相似度（默认权重 0.25）。这个设计带来三个必须知道的性质：①答案说得更全也会扣分（多出的内容算 FP）；②语义相似度对"一个关键数字错了"几乎不敏感，会给错误答案抬分；③整个分数的上限由 reference 质量决定，本库 golden-q 56 条里有 1 条（Q001）标注了与实测冲突的待裁定标记，这样的题不能用来打分。

为什么需要端到端指标（动机与代价）

2

动机：检索层指标证明材料找到了，Faithfulness 证明答案没越界，但两者都不能证明用户拿到了正确答案。三层方法论篇记录的本库实测是：5 条 golden-q 上检索 Recall@5 = 100%，端到端 answer_correctness = 0.787，严格答对率 80%，同题内差约 20 个百分点。这就是"找到不等于答对"，需要一个以标准答案为锚的指标才能量化。动库门禁里 Answer Correctness 是最后一道关：检索没掉、Faithfulness 没掉，但答案变差了，只有它能抓住。

代价：①必须有 reference，每道题需要人工写（或审核）一份标准答案，这是三个指标里人力成本最高的；②每条样本要抽两遍 statement（答案与 reference）、一遍分类、一遍 embedding；③分数含义依赖 reference 的写法，换一批人写 reference，分数分布会整体移动。

不适合的场景：线上流量没有标准答案，跑不了；多种表述都正确的开放题，F1 会误扣；答案很长且包含大量合理的补充信息，会被 FP 扣分。这些场景用 Faithfulness、Answer Relevancy 或人工抽检。

官方定义：官方文档写"gauging the accuracy of the generated answer when compared to the ground truth"，分数 0 到 1，越高越好。它把两个方面合在一起：答案与标准答案的事实重合（factual correctness），以及两者的语义相似度（semantic similarity）。

边界：
- ✅ 管：答案相对标准答案的事实准确度和完整度。
- ❌ 不管：材料从哪来（检索）、说得有没有依据（Faithfulness）、答案是否切题（Answer Relevancy）、标准答案本身是否正确。
- ⚠️ 它是相对 reference 的相对指标。reference 错了，分数就是错的。

事实重合：TP / FP / FN 与 F1

3

官方 Factual Correctness 页的定义：先由 LLM 把答案和标准答案各拆成 claims，再用 NLI 判断每组里哪些 claim 出现在另一组中。

  • TP：答案里有、标准答案里也有的 claim
  • FP：答案里有、标准答案里没有的 claim（多说的）
  • FN：标准答案里有、答案里没有的 claim（漏说的）

Answer Correctness 页给出 F1 = TP / (TP + 0.5 × (FP + FN))。它和常见的 F1 = 2PR / (P + R) 是同一个量，代数上等价，所以下面两个官方示例可以互相验证。

官方示例一（Einstein）：标准答案"Einstein was born in 1879 in Germany."，低分答案"Einstein was born in Spain in 1879."。TP 是"出生于 1879"，FP 是"出生在西班牙"，FN 是"出生在德国"。F1 = 1 / (1 + 0.5 × 2) = 0.5。我在本机用纯 Python 复算得到 0.5，一致。

官方示例二（Eiffel，来自 Factual Correctness 页）：答案"The Eiffel Tower is located in Paris."（1 条 claim），标准答案多一句"It has a height of 1000ft."（2 条 claim）。TP=1，FP=0，FN=1，精确率 1，召回率 0.5，F1 = 0.667，文档输出 0.67，本机复算一致。

注意这个示例说明了漏答的代价：答案没有任何错误，只因为少说一半，事实分就掉到 0.67。

语义相似度3 个重点▾ 点开看本节重点
本节重点
  • 答案与标准答案各算一个 embedding，取余弦相似度
  • 代价是它对局部关键错误几乎没有区分力
  • 它的作用是兜底：同义改写、措辞不同但意思一致的情况，事实抽取可能漏判，相似度补一点分
3

答案与标准答案各算一个 embedding，取余弦相似度。它的作用是兜底：同义改写、措辞不同但意思一致的情况，事实抽取可能漏判，相似度补一点分。代价是它对局部关键错误几乎没有区分力。"出生在西班牙"和"出生在德国"两句话，embedding 之间非常接近。

加权合并与默认值

3

官方 Answer Correctness 页没有写默认权重，而且描述自相矛盾：概述说用"加权方案"合并，计算一节又说"是 factual correctness 与 semantic similarity 之和"，同一页还说是"加权平均"。默认权重只能从源码读到：collections/answer_correctness/metric.py 里 weights: List[float] = [0.75, 0.25]（顺序是事实、相似度），beta: float = 1.0，最终用 np.average([factuality, similarity], weights=weights) 合并。因此"0.75 加 0.25"是源码默认值，引用时应写明来源是源码而非文档，且按加权平均理解，不是求和。

源码里的其他行为（读自抓取的源码文件，未在本机运行）：
- 构造函数校验：权重必须是两个非负数且和不为零；相似度权重大于 0 时必须提供 embeddings；beta 必须是 float。
- 相似度权重为 0 时，跳过 embedding 计算。
- 任一 embedding 范数为零时，相似度记 0。
- 答案或标准答案的 statement 列表任一为空时，事实分直接设为 1.0。
- 没有阈值逻辑，分数是连续值。（旧版接口的文档提到过 threshold 参数，可以把分数舍入成二值，新版 collections 接口的源码里没有。）

最后一条需要特别警惕。按此行为，一个空答案或抽取失败的答案，事实分会是满分，只靠 0.25 权重的相似度把总分拉下来。这是需要在用到的版本里实测确认的风险（见下文"怎么用"）。

与 Faithfulness 的联合判读

2

两个指标正交，联合起来才能定位。

Faithfulness Answer Correctness 含义 处置方向
高 高 有据且答对 正常
高 低 忠于材料但答案不对：漏答，或材料本身缺失、过时 查 Context Recall；查材料里是否新旧值并存
低 高 答对了，但夹带了材料没有的说法（可能来自模型自身知识） 抽查无据说法；收紧提示词，但注意别误伤正确补充
低 低 既不忠实也不正确 先判断是检索没找到还是生成乱写，再对症

本库的 10-15 那轮 RAGAS 库评测（rag/eval_ragas_report.csv，5 题）就是"高、低"象限的典型。其中"总地图工作流有哪六个节点"一题，Faithfulness 1.0，Context Recall 0.0，答案自己说只找到 N3–N6 四个节点，标准答案列了 N1 到 N6 六个节点。这一轮没有跑 Answer Correctness，下面是我手工推演（不是实测）：若标准答案抽出 6 条 claim，答案命中其中 4 条且没有错误，则 TP=4，FP=0，FN=2，事实 F1=0.80，再加相似度项，总分大约在 0.8 上下。也就是说 Answer Correctness 会对这种半截答案给出明显低于 Faithfulness 的分数，但分数不会很低，因为它是按 claim 比例算的。这个推演的准确性取决于两点：标准答案怎么拆 claim，以及答案里"没有找到 N1、N2"这句话怎么被归类。

reference 建设：这个指标最容易出错的地方3 个重点▾ 点开看本章重点
本章重点
  • Answer Correctness 的可信度上限就是 reference 的质量
  • 数字本身自洽，但它和本库自己的消融实验结论冲突，所以这条题不应参与打分，否则答对和答错都说不清
  • 这条的 reference 写的是 hybrid-only 相对 dense-only 的 Recall@5 从 0.587 升到 0.695（相对提升 18.4%）、hybrid+rerank 达 0.816
2

Answer Correctness 的可信度上限就是 reference 的质量。以本库 rag/eval/golden-q.jsonl 为例：

  • 共 56 条：5 条负例（is_no_answer 为真，没有标准答案）；51 条有 reference_answer。
  • 其中 Q001 带有 TODO_conflict 字段，内容是"与 2026-10-16 E 消融实测 0 提升冲突，待人工裁定"。这条的 reference 写的是 hybrid-only 相对 dense-only 的 Recall@5 从 0.587 升到 0.695（相对提升 18.4%）、hybrid+rerank 达 0.816。我复算：0.695/0.587 − 1 = 18.4%，0.816/0.587 − 1 = 39.0%。数字本身自洽，但它和本库自己的消融实验结论冲突，所以这条题不应参与打分，否则答对和答错都说不清。
  • 去掉负例和冲突题，可用于 Answer Correctness 的是 50 条（我用脚本逐条核对得出）。

reference 的写法规范：

  1. 一句一事实，便于 LLM 拆成原子 claim；不要把三个事实塞进一个长句。
  2. 只写必要事实。标准答案里的每条 claim 都会成为答案必须覆盖的 FN 候选，写多了会让正确但简洁的答案被判漏答。
  3. 数字、单位、条件写全，例如"rerank 阈值 0.45，归一化得分"，别只写"0.45"。
  4. 有争议或待裁定的题单独标记并排除，如 Q001 的做法，这个习惯应保持。
  5. reference 与来源文档同步更新。知识库内容改了而 reference 没改，分数会无故下降，且很难归因。
  6. 每条 reference 写明出处文件，方便复核。

《RAGAS三层评测落地》§5.5 的 goldenq_to_ragas() 读取字段 g["answer"]，而 golden-q.jsonl 的实际字段是 reference_answer（另有 answer_keywords，没有 answer）。我用该函数的判断逻辑在真实文件上跑了一遍：保留 0 条，因为每一行 g.get("answer") 都是空，函数会静默返回一个空数据集。

正确的读取方式（已在本机运行，输出"可用 50 条；跳过 5 条无答案负例、1 条冲突题"）：

import json

def load_reference_set(path):
    usable, skipped = [], {"no_answer_q": 0, "no_reference": 0, "conflict_todo": 0}
    with open(path, encoding="utf-8") as f:
        for line in f:
            g = json.loads(line)
            if g.get("is_no_answer"):
                skipped["no_answer_q"] += 1; continue
            if not g.get("reference_answer"):
                skipped["no_reference"] += 1; continue
            if g.get("TODO_conflict"):
                skipped["conflict_todo"] += 1; continue
            usable.append({"id": g["id"], "user_input": g["question"],
                           "reference": g["reference_answer"]})
    return usable, skipped

之后需要用生产管线对每道题实际跑一遍，得到 response（和 Faithfulness 所需的 retrieved_contexts），再组装成评测样本。

用于把评测器返回的 TP/FP/FN 与相似度手工复核一遍，也用于审计时对照：

import math

def factual_f1(tp, fp, fn, strict=True):
    if tp + fp == 0 or tp + fn == 0:
        return math.nan if strict else 1.0   # 官方源码行为是 1.0，strict 让它显式暴露
    return tp / (tp + 0.5 * (fp + fn))

def answer_correctness(tp, fp, fn, sim, weights=(0.75, 0.25)):
    f = factual_f1(tp, fp, fn)
    if math.isnan(f):
        return math.nan
    return (weights[0] * f + weights[1] * sim) / sum(weights)

print(factual_f1(1, 1, 1))                         # 0.5  官方 Einstein 示例
print(round(factual_f1(1, 0, 1), 2))               # 0.67 官方 Eiffel 示例
print(round(answer_correctness(1, 1, 1, 0.90), 4)) # 0.6  相似度为假设值

必做的版本实测

3

在你实际使用的 ragas 版本上，用三条构造样本验证行为，再信任分数：

  1. 空字符串答案：分数是否被拉高（源码摘要显示事实分会取 1.0）。
  2. 答案与标准答案完全一致：应接近 1。
  3. 关键数字改错、其余全对：分数应明显下降，而不是只降一点点。

三条里任一不符合预期，就在评测脚本里加显式断言（如空答案直接记 ERROR，不送评测器）。

动库门禁怎么用它3 个重点▾ 点开看本章重点
本章重点
  • 门禁判据是三层联合不降：Recall@5、Faithfulness、Answer Correctness 在同一份 golden set上前后对比
  • 1. 只在同一批 reference 上比
  • 中途改了 reference，必须重跑基线
2

门禁判据是三层联合不降：Recall@5、Faithfulness、Answer Correctness 在同一份 golden set上前后对比。对 Answer Correctness 要补充几条规则：

  1. 只在同一批 reference 上比。中途改了 reference，必须重跑基线。
  2. 逐题配对比较，并给出降幅最大的几道题，不只给均值。50 条的均值，单题变化 0.3 就能让均值动 0.006，噪声和真实变化要靠逐题明细区分。
  3. 同时看 TP/FP/FN 分布，因为漏答和多答的总分可以一样，处置完全不同：漏答往往要查检索或提示词里的长度限制，多答往往要收紧"只回答问到的"。
  4. 本库没有为 Answer Correctness 标定过绝对阈值。三层评测落地篇的"低于某值需查"和生产级篇的"跌超 0.05 阻断"都是经验或规则设定，没有本库的校准数据支撑；0.787 这个数是 5 条样本的均值，不能当线。建议先在 50 条可用题上跑出基线，再用重复运行的波动（同一批跑 3 次的标准差）定出"噪声带"，降幅超过噪声带才算显著。
  5. 0.787 的原始报告（/tmp/ragas_answer_eval_report.md）已被清理，数据只在三层方法论篇里留有引用，无法复核计算细节。

局限

2
  1. 多种正确说法会被误扣：标准答案只写了一种表述，答案换了说法且正确，NLI 判定可能漏判。
  2. 多答被扣：答案补充了正确但标准答案没写的信息，会计入 FP。reference 写得越省，这类误扣越多。
  3. 语义相似度会抬高错误答案：见上文敏感性演算，关键数字错误时相似度项仍然偏高。如果业务上"数字对不对"是核心，可考虑把权重调向事实项（例如 weights=[0.9, 0.1]），或另加精确匹配类指标做兜底。调整权重要把新旧口径分开留档，不能与旧基线混比。
  4. 长答案的 claim 抽取不稳：抽取的粒度和数量会随裁判模型变化，同一答案在不同裁判下的 TP/FP/FN 不同，所以裁判模型必须固定。
  5. 英文提示词：官方判定提示词是英文，对中文语料，强模型一般够用，小模型要先用人工标注样本校准。
  6. 一个分数压缩了多种错误：漏答、多答、错答、措辞不同都落在同一个 0 到 1 的数里，所以每次报告必须附 TP/FP/FN 明细。
