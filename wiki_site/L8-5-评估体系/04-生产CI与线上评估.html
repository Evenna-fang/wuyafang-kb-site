生产 CI 与线上评估：同尺子门禁、影子评估和 badcase 闭环

本篇是本层“生产 CI 与线上评估”的唯一正文。所有流水线与部署示例均未实跑，不提供虚假的通过率。方案只允许读取本地数据、写本地评估产物；未经批准不把私有查询、上下文、日志或答案发送到外部端点。

WHY：为什么离线全绿仍可能上线失败

2

离线测试集是历史分布的压缩，不可能覆盖所有真实变化：新业务上线、文档更新、用户措辞迁移、检索延迟升高、工具部分失败，都会让“昨天的好系统”在今天退化。反过来，线上一点波动也不必然代表模型变差，可能是样本结构、裁判或数据管道变了。

没有生产评估闭环，常见后果是：

  • PR 只测少量“漂亮样例”，合并后夜间全量才暴露回归。
  • 候选与基线不在同一批请求上比较，把流量差异误当模型收益。
  • 裁判大面积故障，分数缺失被过滤，报告仍显示“质量上升”。
  • 线上只监控平均延迟，不看无答案率、检索空结果和关键业务分桶。
  • badcase 散落在聊天记录里，没有回到版本化数据集，同类问题重复出现。

生产评估的目标不是让所有请求都同步调用昂贵裁判，而是建立一条便宜检查及时阻断、昂贵评估异步补全、关键变化可复跑、异常样本能回流的链路。

WHAT / WHYT：四层反馈与同尺子比较

2

1. PR 冒烟、夜间全量、影子评估、线上实验各管一件事

3
层 样本与频率 适合阻断什么 不适合声称什么
PR 冒烟 小而稳定的确定性集，每次变更 接口破坏、格式错误、明显 badcase 回归 全业务质量提升
夜间全量 较大冻结集与分层集，定时运行 检索/生成/端到端配对回归、覆盖率下降 真实用户长期收益
异步影子评估 脱敏生产样本，异步而非阻塞主链路 分布漂移、未知失败、裁判与业务偏差 未完成样本上的确定结论
线上 A/B 随机或合理分流的实时流量 用户结果、业务指标、延迟与成本权衡 小样本短期噪声的普遍规律

Hamel 的三级评估在这里形成闭环：Level 1 的确定性断言优先进入 PR；Level 2 的人工/模型评估用于夜间和影子样本；Level 3 的线上 A/B 验证最终用户结果。级别不是“高级替代低级”，而是不同成本与证据强度的组合。

2. 同尺子 paired delta 是发布门禁的基本单位

3

候选与基线必须共享：同一组 query_id、同一数据 manifest、同一检索快照、同一裁判版本和同一有效样本集合。逐题比较后再汇总，才能避免样本构成改变带来的假收益。

以下情况应判为“门禁无效/需重跑”，不是“候选通过”：

  • 基线缺失或运行失败。
  • 候选 ID 集合与基线不一致。
  • 分数含 NaN、无穷或越界值。
  • 数据 manifest、裁判版本或指标实现不同。
  • 有效覆盖率下降超过事先约定的容忍值。

阻断阈值与观察阈值要分开。确定性关键错误可以直接阻断；模型裁判的小幅均值变化可能需要置信区间、人工复核或扩大样本，不能假装精确。

3. 线上监控必须能解释“没分”的原因

3

每个指标同时保留：请求总数、可评数、成功评分数、失败数及原因。按业务、语言、输入长度、检索空结果、拒答、延迟桶切片。裁判自身使用固定哨兵样本，防止把裁判漂移误判为产品漂移。

4. 论文怎么说，我们怎么用

3

评估意识（arXiv:2610.22333）。本地摘要显示测试提示会改变拒答行为，并对良性请求也产生影响。我们的用法：离线安全集之外增加生产分布采样，同时监控有害请求漏拒与良性请求误拒；不能用带测试标识的离线行为替代线上结论。

可复现性与分析稳健性（arXiv:2610.23845）。本地摘要报告：SEER-Repro 含 20 篇论文；agent 复现了 2190 条原子声明的 77.4%，并把 9.5% 完全复现发现中的潜在关键分析选择交给专家审查。该数字属于原研究设置，不是本库复现率。

我们的用法：保存可执行基线、环境/manifest 和逐样本产物；对关键结论扰动分析选择（样本过滤、尺度、阈值、聚合方式）后重跑。自动复跑不是免审凭证，影响发布的关键分歧仍需领域专家复核。

HOW：搭一条可阻断、可诊断、可回流的评估链路

2

第一步：冻结 manifest 与产物契约

3 
{
  "manifest_id": "rag-eval-2026-11-04-v1",
  "dataset_sha256": "<数据集文件哈希>",
  "retriever_version": "<本地版本或提交>",
  "generator_version": "<本地版本或提交>",
  "judge_version": "<裁判提示、模型与尺度>",
  "metric_version": "<指标实现版本>",
  "protocol": {"temperature": 0, "seed": 42}
}

每次运行输出逐样本 JSONL，而不是只输出汇总：

{"query_id":"q-001","manifest_id":"rag-eval-2026-11-04-v1","variant":"baseline","status":"scored","metrics":{"faithfulness":1.0},"latency_ms":820,"error":null}

私有输入和输出只保存在获准的本地目录；公开报告只放样本 ID、指标和经批准的摘要。临时产物在收口前清理，持久产物进入正式目录并登记。

第二步：在 PR 中优先跑确定性检查

3

PR 冒烟至少包括：

  1. 数据 schema 与 golden-q 的 reference_answer 字段检查。
  2. 输出可解析、必需字段、禁止模式和关键 badcase 断言。
  3. 检索 ID 非空、排序位置与最终送模上下文的一致性。
  4. 评分函数对空输入、NaN、异常和越界值的单元测试。
  5. 小样本上的基线/候选 ID、manifest 和覆盖率配对检查。

配对门禁核心逻辑：

import math


def paired_gate(baseline, candidate, max_mean_drop=0.0):
    base = {row["query_id"]: row for row in baseline}
    cand = {row["query_id"]: row for row in candidate}
    if set(base) != set(cand) or not base:
        return {"decision": "invalid", "reason": "样本ID不一致或为空"}
    if any(row.get("manifest_id") != base[qid]["manifest_id"]
           for qid, row in cand.items()):
        return {"decision": "invalid", "reason": "manifest不一致"}

    deltas = []
    for qid in sorted(base):
        left = base[qid].get("score")
        right = cand[qid].get("score")
        if left is None or right is None:
            return {"decision": "invalid", "reason": f"缺失分数: {qid}"}
        if not math.isfinite(left) or not math.isfinite(right):
            return {"decision": "invalid", "reason": f"非有限分数: {qid}"}
        deltas.append(right - left)

    mean_delta = sum(deltas) / len(deltas)
    return {
        "decision": "pass" if mean_delta >= -max_mean_drop else "fail",
        "mean_delta": mean_delta,
        "deltas": dict(zip(sorted(base), deltas)),
    }

这段代码只示范一致性门禁，没有把任意平均分差当作统计显著性，也没有处理多指标业务权衡。真实系统还应给每对样本的 metric_status、置信区间和关键分桶结果。

第四步：异步影子评估与裁判哨兵

3
  1. 从获准的本地生产日志按业务分层抽样，主链路只记录样本 ID，不等待裁判。
  2. 异步worker读取冻结的输入快照、最终上下文和输出，写入独立评估结果，避免后续文档更新改变历史样本。
  3. 每批混入人工已标的哨兵样本；哨兵分数漂移时暂停自动门禁并检查裁判。
  4. 报告覆盖率和缺失原因；裁判失败达到预算时结论标为无效，不用剩余样本假装全量通过。
  5. 监控检索空结果、合理/异常拒答、忠实度、正确性、延迟和成本，并按关键桶告警。

第五步：A/B、复核与 badcase 回流

3

线上实验先写假设、主要用户指标、护栏指标、样本量和停止规则。模型质量分只能作为解释变量之一，不能替代真实任务成功率、误拒、延迟和成本。

badcase 回流按以下字段进入开发集：

原始query_id / 版本化输入快照 / 故障层 / 人工期望 / 严重度 /
是否含敏感信息 / 修复提交 / 首次通过日期 / 是否晋级冻结回归集

同一问题修复后，先跑原 badcase，再跑同类扰动样本和全量回归，避免只记住一条字面表达。涉及关键分析选择时，改变过滤规则、评分尺度或聚合方式做稳健性重跑；分歧仍影响发布时交专家，而非让门禁替人做价值判断。

    ```python
    def should_rewrite(state: RAGState) -> str:
    """条件边: 判断是否需要查询重写"""
    if not CONFIG["crag"]["enabled"]:
    return "pass" # CRAG禁用, 直接过

    relevant_count = len(state.get("relevant_docs", []))
    min_relevant = CONFIG["crag"]["min_relevant_docs"]
    max_retries = CONFIG["crag"]["max_rewrite_retries"]

    if relevant_count < min_relevant and state.get("rewrite_count", 0) < max_retries:
    print(f"[crag] 相关片段仅{relevant_count}条 < {min_relevant}, 触发查询重写 (第{state['rewrite_count']+1}次)")
    return "rewrite"
    return "pass"
    `` 阈值在rag/config.yaml：min_relevant_docs: 2（少于此数触发重写）、max_rewrite_retries: 2（防死循环）。**线上"要不要重试"是配置项，不是玄学**。 - **不合格就拒答，而不是硬答（rag/query.pyL2245gate_node()→_build_refusal_answer()）**：gate不达标返回常量拒答文案，"""CRAG式拒答文案(负例必须命中此文案, 验收断言依赖此常量)。"""——**拒答率、命中率都可以按这个常量做线上断言**。 - **和课件讲法的差异**：课件生产 CI/线上评估讲"离线回归集进门禁 + 线上采样打分 + 人工抽检 + 漂移告警看板"；本库有离线评测（rag/eval_ragas.py）+ 机械门禁（gate_node`），但没有线上采样与漂移告警看板，也没有 CI 集成（评测靠手动跑）。这是本库与课件最大的差距项。
