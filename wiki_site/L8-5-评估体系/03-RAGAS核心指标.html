RAGAS 核心指标：Faithfulness、Answer Relevancy 与 Answer Correctness

本篇是本层“RAGAS 核心指标”的唯一正文。源码口径核对到 RAGAS v0.3.9，不把它冒充为以后所有版本的不变行为。文中教学数值用于验证公式，不是本库生产实测；官方库调用示例未实跑。

WHY：为什么一个“答案质量分”不够

2

RAG 回答可能“每句话都能在材料中找到依据，却完全没回答用户问题”，也可能“答到了主题，却遗漏了决定性条件”，还可能“整体语义接近参考答案，但把日期或否定词写反”。一个总分会掩盖这些相反故障。

三个常用指标分别回答：

  • Faithfulness：回答中的可核查陈述是否受给定上下文支持。
  • Answer Relevancy：回答是否对准原问题，而不是只追求形式上像答案。
  • Answer Correctness：相对 reference，答案在事实与语义上有多正确。

三者需要联合使用。Faithfulness 高不代表没有漏答；Relevancy 高不代表事实正确；Correctness 高也不自动证明答案只使用了给定材料。评估的目的不是追求“三个都接近 1”的展示图，而是定位具体故障、发现指标失效样本并推动修复。

如果裁判抽取失败返回空列表，再把空列表默认记成满分，最差的系统输出反而可能得到最高忠实度。如果裁判异常被静默记为 0，则基础设施故障会被误判成模型回归。因此，状态处理与公式本身同等重要。

WHAT / WHYT：指标口径、来源与不能回答的问题

2

1. Faithfulness：支持率，不是完整性和材料真理性

3

在 v0.3.9 的典型流程中，系统先把答案拆成可核查陈述，再让裁判逐条判断是否由上下文支持。教学化表达为：

[
Faithfulness = \frac{\text{受上下文支持的陈述数}}{\text{全部可核查陈述数}}
]

边界必须写清：

  • 看不到遗漏：回答只说了材料中的一半事实，也可能全部受支持。
  • 不验证材料本身：材料过时或错误时，“忠实于材料”不等于现实正确。
  • 不等于拒答质量：合理拒答、空答案和不可解析输出要按任务策略单独标注。
  • 受拆分与裁判影响：陈述粒度、上下文截断、裁判提示和尺度都会改变结果。

本库旧稿曾记录历史自写实现的缺陷：裁判抽取失败返回空列表后可能记为 1.0，以及上下文截断、空输出误判。历史出现的 28.1%、47.0% 等数字因此不能当成官方 RAGAS 可直接比较的基线，本篇也不复用它们证明当前质量。

2. Answer Relevancy：对题程度，不是事实正确性

3

v0.3.9 的实现思路是依据答案生成若干候选问题，再比较它们与原问题的语义相似度，并处理 noncommittal 等情况。它适合发现答非所问、绕开问题或空泛回答。

但它不能证明回答中的事实为真：一个错误答案也可能与原问题非常相关。向量模型、生成问题数量和裁判失败都要进入运行记录，不能只留最后的浮点数。

3. Answer Correctness：事实 F1 与语义相似度的组合

3

在 v0.3.9 源码中，该指标把事实部分与语义相似度组合，默认 weights=[0.75, 0.25]。教学化表达：

[
F1_{fact} = \frac{2TP}{2TP+FP+FN}
]

[
Correctness = 0.75 \times F1_{fact} + 0.25 \times Similarity
]

其中 TP/FP/FN 来自答案与 reference 的事实项比对，不是检索结果的 TP/FP/FN。默认权重来自该版本库源码，不是原始 RAGAS 论文规定的普适常数。

还要特别区分来源：Answer Correctness 是 RAGAS 库后续扩展指标，不是原始论文 arXiv:2309.15217 最初提出的三个无参考指标之一。它需要 reference，不能与无参考的 Faithfulness 混用数据契约。

4. 论文怎么说，我们怎么用

3

临床摘要语义对齐（arXiv:2610.31467）。本地摘要报告：研究涉及 4500 条摘要；grounding constraints 改善临床对齐，但对遗漏的影响依模型而变，且可读性存在代价。证据边界是本地摘要，不声称复现其临床实验。

我们的用法：Faithfulness 必须与遗漏率、不确定性保持和可读性联合评估。对高风险摘要增加“必需事实覆盖率”和人工复核，不因支持率提高就自动发布；把“更 grounded 但更难读”作为真实 trade-off 报告。

评分尺度敏感性（arXiv:2610.22187）。本地摘要提示归一化分和类别会随尺度设计变化。我们的用法是固定裁判提示与尺度，用人工标注的正负双端样本校准；换尺度时做配对敏感性分析，不能直接比较两种尺度下的绝对分。

HOW：先保证状态正确，再接入官方指标

2

第一步：用可测的确定性函数明确公式和空输入行为

3 
import math


def safe_ratio(numerator, denominator):
    return numerator / denominator if denominator else math.nan


def faithfulness_from_verdicts(verdicts):
    if not verdicts:
        return math.nan
    if any(v not in (0, 1) for v in verdicts):
        raise ValueError("verdict 只能是 0 或 1")
    return sum(verdicts) / len(verdicts)


def factual_f1(tp, fp, fn):
    if min(tp, fp, fn) < 0:
        raise ValueError("TP/FP/FN 不能为负")
    return safe_ratio(2 * tp, 2 * tp + fp + fn)


def correctness_from_counts(tp, fp, fn, similarity):
    if not 0.0 <= similarity <= 1.0:
        raise ValueError("similarity 必须位于 [0, 1]")
    fact_score = factual_f1(tp, fp, fn)
    if not math.isfinite(fact_score):
        return math.nan
    return 0.75 * fact_score + 0.25 * similarity

教学例：verdicts=[1,1,0] 得 Faithfulness=0.666666...；tp=3, fp=1, fn=1, similarity=0.8 时事实 F1=0.75，Correctness=0.7625。这些只是公式单元测试值，不是模型或本库生产结果。

空 verdicts 返回 NaN 是刻意设计：上层必须把它转成 metric_status=not_applicable 或 judge_error，不能在 JSON 汇总时静默变成 0 或 1。

第二步：为每条指标建立显式状态机

3 
input_valid?
  ├─ 否 → invalid_input，不进入评分分母
  └─ 是 → 答案可解析?
            ├─ 否 → invalid_output
            └─ 是 → 裁判/嵌入调用成功?
                      ├─ 否 → judge_error 或 embedding_error
                      └─ 是 → 输出有限且定义域合法?
                                ├─ 否 → invalid_metric
                                └─ 是 → scored

对空答案是否 not_applicable，要由任务卡决定：无答案问题上的规范拒答可以单独评“拒答正确”，但不能直接获得 Faithfulness=1。每批报告给出 scored / total、缺失原因和失败样本 ID。

第三步：正确映射 reference，保留可追溯字段

3

本库 golden-q 的正确字段是 reference_answer，不是 answer；answer 应保留给系统候选输出：

def to_ragas_row(row, candidate_answer, contexts):
    return {
        "question": row["query"],
        "answer": candidate_answer,
        "contexts": contexts,
        "reference": row["reference_answer"],
        "query_id": row["query_id"],
        "qrels_version": row["qrels_version"],
    }

冲突题、无答案题和多参考答案题先单独分桶。无 reference 的样本不能运行 Answer Correctness 后再把缺失值当 0；应标 not_applicable，或先补建 reference。

第四步：固定版本接入 RAGAS，并保存原始输出

3

以下是常见的高层调用形态，未实跑；实际使用前必须核对安装版本的 evaluate、数据集和本地模型适配接口：

# 未实跑：需要自行配置本地 LLM 与 embeddings，不在这里读取或写入任何凭据。
from datasets import Dataset
from ragas import evaluate
from ragas.metrics import answer_correctness, answer_relevancy, faithfulness


def run_ragas(rows, llm, embeddings):
    dataset = Dataset.from_list(rows)
    return evaluate(
        dataset=dataset,
        metrics=[faithfulness, answer_relevancy, answer_correctness],
        llm=llm,
        embeddings=embeddings,
    )

安装与版本核对命令：

python -m pip install 'ragas==0.3.9' datasets

本地回环适配器必须满足：输入与输出显式映射、异常向上传递、每次调用有 ID、原始响应落本地、失败不自动补分。不要用旧稿里的云端密钥、隐式外部数据流或未标定阈值替代这些约束。

第五步：用样本而非总分校准指标

3
  1. 正例：答案完整、受支持、对题，用于检查指标是否能识别好样本。
  2. 幻觉负例：添加材料外事实，观察 Faithfulness 是否下降。
  3. 遗漏负例：只保留部分受支持事实，检查 Faithfulness 为何可能仍高，并由 Correctness/必需事实覆盖补位。
  4. 答非所问负例：材料内真实但不回答问题的句子，用于检验 Relevancy。
  5. 拒答与空输出：分别标注合理拒答、异常空输出，禁止共享默认分。
  6. 裁判扰动：固定样本更换尺度或提示做敏感性检查，分歧样本送人工。

最终报告除均值外，还应给逐指标有效分母、分桶结果和原始 badcase 链接。只有这样，指标变化才能转化为修复动作。
