1. 检索成功是必要条件，不是最终交付

3

想象一条问题要求给出“当前过滤线及更新原因”。检索材料已经含有现行值 0.45、旧值 0.465 和变更说明。答案可能只抄旧值，可能给出正确数值却省略原因，也可能追加材料从未写过的“自动回滚机制”。这三种失败在来源命中率上都可能满分，但用户拿到的是错误、不完整或无据的回答。因此，检索评测结束以后，不能只检查答案非空，而要分别判断它是否有依据、是否切题、是否符合经过核对的参考答案。[D1]

三个生成侧指标承担不同任务。Faithfulness 用上下文审查答案里的声明；Answer Relevancy 用问题审查回答是否围绕请求；Answer Correctness 用 reference 审查事实正确性和完整性。它们不是互相替代关系。尤其是“忠于过期资料”的回答可以忠实但错误；“只答一半”的回答可以忠实且切题，但正确性里的召回部分低。三列分别保留，才能看到究竟缺哪种能力。[S2][S3][S4]

2. 为什么不能让一个裁判直接打一百分3 个重点▾ 点开看本节重点
本节重点
  • 整体印象分难以说明错误发生在哪里
  • 模型可以被流畅措辞影响，也可能给格式漂亮但事实不对的答案较高评价
  • RAGAS 把问题拆为更小的判定：从答案提取原子声明、逐条查证；从答案反推可能的问题；将答案和标准答案的声明分成 TP、FP、FN
3

整体印象分难以说明错误发生在哪里。模型可以被流畅措辞影响，也可能给格式漂亮但事实不对的答案较高评价。RAGAS 把问题拆为更小的判定：从答案提取原子声明、逐条查证；从答案反推可能的问题；将答案和标准答案的声明分成 TP、FP、FN。这样得到的数仍然依赖裁判，但可以回溯到具体判断，而不是停在一个无法解释的“82 分”。[S2][S3][S4]

代价是多步调用、解析失败和更复杂的统计。一次 Faithfulness 至少涉及声明提取与支持判定两阶段；Answer Correctness 还需要分别提取两侧声明、做对应分类和语义相似度；Answer Relevancy 要生成多个反推问题并编码向量。实际请求数会因批处理、重试和后端是否支持 n 而变化，不能固定宣称每题恰好几次或恰好多少钱。实验预算应按实际调用日志和输入规模测算，不凭指标数量估算。[S2][S3][S4][D1]

3. 本库历史说明：先校准裁判，再讨论分数

3

本库 2026-10-10 报告列有正例 Faithfulness=28.1%、Answer Relevancy=79.3%，但后续审计指出当时使用自写实现、存在截断上下文、异常回空及拒答记满分等问题。它们是历史运行记录，不是本次官方 RAGAS 的可复用基线。把历史数直接抄进新的验收线，会让不同实现看似在同一尺度上比较。[L1][L2]

4. 前置知识与术语对齐

3

本篇沿用 RAGAS v0.3.9 的 SingleTurnSample 字段：user_input 是原始问题，retrieved_contexts 是模型真正看见的文本片段，response 是实际生成答案，reference 是人工核对的答案。不是所有字段都要传给每个指标；按最小所需字段构造输入，能减少误用和不必要的数据暴露。无参考答案的线上流量可跑前两项，不能自动得到 Answer Correctness。[S2][S3][S4]

5. Faithfulness：被支持数除以答案声明数3 个重点▾ 点开看本节重点
本节重点
  • 固定实现先用 「StatementGeneratorPrompt」 把答案拆成不依赖代词的声明，再用 「NLIStatementPrompt」 对每条给出支持判定
  • 若 reference 要求四个要点，答案只说对一个，忠实度仍可为 1
  • 这是教学构造，不是重新复现历史 Q004
3

固定实现先用 StatementGeneratorPrompt 把答案拆成不依赖代词的声明，再用 NLIStatementPrompt 对每条给出支持判定。分数是支持数除以声明数。假设答案含“过滤线是 0.45”“旧值为 0.465”“系统每日自动回滚”三条，实际上下文只支持前两条，则手工判定下 Faithfulness=2/3=0.6667。这是教学构造，不是重新复现历史 Q004。[S2][D1]

Faithfulness 不检查漏答，因为没有出现的声明不会进分母。若 reference 要求四个要点，答案只说对一个，忠实度仍可为 1。它也不保证材料真实：资料明确写了旧值，模型忠实转述旧值，支持判定可以通过。若业务要求“截至某日的现行配置”，日期和版本必须进入问题与 reference，并用端到端正确性或专门规则核验。[S2][D1]

零声明时分数未定义，该标签官方实现返回 NaN。不要为了报表整齐把它改成 1，也不要一律改成 0。合法拒答、空白答案、裁判抽取失败，是三个不同的状态：合法拒答走拒答指标，空白答案走生成可用性，裁判失败走评测健康度。它们都不能通过简单 dropna 悄悄从总分母里消失。[S2][D1]

声明粒度同样影响分数。若裁判把“三个条件全部满足才支持”的长句当一条，单个错误就可能使整句失分；另一位裁判拆成三条，则分数变成 2/3。比较版本时必须固定声明拆分模板、模型和输入范围，并抽查数字、否定词、条件句和跨句指代的处理。若新旧答案风格差很多，分数变化中可能混有拆分方式的影响，不能全部解释成事实质量改变。[S2][D1]

6. Answer Relevancy：反推问题，而不是检查事实真伪

3

v0.3.9 的 ResponseRelevancy 默认 strictness=3，表示从答案生成三个可能的问题；AnswerRelevancy 是相关兼容类。反推阶段输入是 response，而非把原问题一起提供给它“照着出题”。随后用同一向量模型编码原问题与反推问题，计算余弦相似度的平均，并结合 noncommittal 标记。该标签在所有反推结果都标为模糊拒答时将结果乘为 0，不能把这个规则说成所有版本都完全一致。[S3]

比如问题问“过滤线是多少”，回答为“当前过滤线是 0.45”，三个反推问题的余弦值假设为 0.90、0.84、0.87，则基础平均为 0.87。若答案变成“检索增强生成是一种结合外部知识的方法”，它可能完全有据却不回答请求，相关性应降低。反过来，“当前过滤线是 0.99”仍可能强烈切题，因此 Answer Relevancy 高不能证明数字正确。[S3][D1]

向量相似度理论上可能为负，不能一概把任何越出 0—1 的值当解析错误；本篇统计器对该项仅要求有限值，阈值解释依赖实际模型。更换 embedding 模型会改变余弦尺度，应重新定标。数字型、布尔型与极短回答尤其容易使反推问题含糊，建议同时给出任务专用 Exact Match、数值容差或字段覆盖率；这属于补充验收，不是偷偷更改官方指标定义。[S3][D1]

strictness 从 3 提高到 5 可能增加采样和成本，但不是保证质量提升的万能参数。先看同一批人工样本的稳定性，再决定是否多生成问题。若反推结果大量重复或全为空，先审查模型结构化输出和输入长度，不要用提高 strictness 掩盖基本兼容性。没有保留下来的反推问题明细，就很难说明低相关性到底来自产品回答还是裁判故障。[S3][D1]

7. Answer Correctness：事实重合与语义相似度的组合3 个重点▾ 点开看本节重点
本节重点
  • 默认公式可写为 「0.75×F1+0.25×Similarity」
  • 但如果错误只是一个非常关键的数值，语义相似度仍可能给部分分；高风险关键字段还应通过确定性断言兜底
  • 因此 reference 建设应记录适用时间、必要要点、可接受别名和不应要求的扩展内容
3

固定版本默认 weights=[0.75,0.25]，beta=1.0：先从答案和 reference 各提取声明，分类为 TP、FP、FN，再计算事实 F1；另算两段文本的语义相似度，最后做加权平均。默认公式可写为 0.75×F1+0.25×Similarity。如果自定义权重不加起来等于 1，官方使用加权平均会再做归一化；本文参数总和为 1，避免含义不清。[S4]

手算例：TP=2、FP=1、FN=1，F1=2TP/(2TP+FP+FN)=4/6=0.6667；假设语义相似度=0.92，则 Answer Correctness=0.75×0.6667+0.25×0.92=0.73。0.92 很高却没有掩盖事实错误，这正是复合指标的用处。但如果错误只是一个非常关键的数值，语义相似度仍可能给部分分；高风险关键字段还应通过确定性断言兜底。[S4][D1]

beta 控制事实 F-score 对精确率或召回率的偏重，beta>1 更重漏答，beta<1 更重多说错误。调整它属于改变尺子，不能与旧默认分数直接连线。另一个边界是两侧声明都为空：该标签对事实部分可能给 1，因此集成层必须先识别空 response、空 reference，不能把“两个空字符串相似”误认成完美答题。[S4]

reference 不是天然真值。若参考答案把“旧配置”当“现行配置”，正确回答会被扣分；若参考答案含大量问题未要求的背景知识，简洁正确的答案也可能出现 FN。因此 reference 建设应记录适用时间、必要要点、可接受别名和不应要求的扩展内容。标准答案越长并不必然越好，关键是和用户真正的任务边界一致。[S4][D1]

9. 第一步：建立 reference 与实际轨迹的连接

3

问题集和运行轨迹分开管理：golden set 负责问题、reference、可回答性和必要证据；轨迹负责同一次运行的最终上下文、答案、路由、时延及状态。以稳定 ID 加入，而不是以问题文本做宽松匹配。重复问题、空 ID、缺失轨迹都应显式失败，不能挑选“恰好能评”的记录作为整套系统成绩。[D1]

参考答案至少经过一次按原始来源的核对：数值题写单位与有效日期，多跳题写必要的两段推理链，步骤题标出不可省略的动作，否定题区分“不支持”和“明确反对”。两名标注者有分歧时先记录分歧原因，不急着让一个模型替人决定真值。无法确认的题可以进入探索集，但不得用来给发布门禁定标。[D1]

将下列代码保存为 notes/benchmark/generation_math.py。它不提取声明、不假装实现完整 RAGAS，而是验证给定人工判定后的公式，确认缺失值处理和数值门禁没有基本错误。它与模型版本、网络及本机凭据完全无关，适合作为第一层烟雾检查。[D1]

import math

def faithfulness_from_verdicts(verdicts):
    if not verdicts:
        return math.nan
    if any(v not in (0, 1) for v in verdicts):
        raise ValueError("binary verdicts required")
    return sum(verdicts) / len(verdicts)

def factual_f1(tp, fp, fn):
    if min(tp, fp, fn) < 0 or tp + fp + fn == 0:
        raise ValueError("non-empty, non-negative claim counts required")
    return 2 * tp / (2 * tp + fp + fn)

def correctness_from_counts(tp, fp, fn, similarity):
    if not math.isfinite(similarity):
        raise ValueError("finite similarity required")
    return 0.75 * factual_f1(tp, fp, fn) + 0.25 * similarity

def relevancy_from_cosines(cosines, all_noncommittal=False):
    if not cosines or not all(math.isfinite(v) for v in cosines):
        return math.nan
    return 0.0 if all_noncommittal else sum(cosines) / len(cosines)

def main():
    faith = faithfulness_from_verdicts([1, 1, 0])
    relevance = relevancy_from_cosines([0.90, 0.84, 0.87])
    correct = correctness_from_counts(2, 1, 1, 0.92)
    print(f"teaching_faithfulness={faith:.4f}")
    print(f"teaching_answer_relevancy={relevance:.2f}")
    print(f"teaching_answer_correctness={correct:.2f}")
    assert math.isclose(faith, 2 / 3)
    assert math.isclose(relevance, 0.87)
    assert math.isclose(correct, 0.73)
    assert math.isnan(faithfulness_from_verdicts([]))
    assert relevancy_from_cosines([0.9], True) == 0
    assert math.isclose(factual_f1(1, 0, 2), 0.5)
    print("offline_generation_checks=passed")

if __name__ == "__main__":
    main()

import asyncio
import json
import math
import os
import sys
from pathlib import Path
from urllib.parse import urlparse

def local_url(name):
    value = os.environ[name]
    parsed = urlparse(value)
    if parsed.scheme not in {"http", "https"} or parsed.hostname not in {"localhost", "127.0.0.1", "::1"}:
        raise ValueError("loopback HTTP(S) endpoint required")
    if parsed.username or parsed.password or parsed.query or parsed.fragment:
        raise ValueError("credentials/query/fragment not allowed")
    return value

def validate_row(row):
    if not row.get("answerable", True):
        return "negative_separate"
    if row.get("status") != "ok":
        return "pipeline_error"
    if not isinstance(row.get("user_input"), str) or not row["user_input"].strip():
        return "schema_error"
    if not isinstance(row.get("reference"), str) or not row["reference"].strip():
        return "reference_missing"
    if not isinstance(row.get("response"), str) or not row["response"].strip():
        return "generation_empty"
    contexts = row.get("retrieved_contexts")
    if not isinstance(contexts, list) or not contexts or not all(isinstance(c, str) and c.strip() for c in contexts):
        return "retrieval_miss"
    return "scored"

async def main(input_path, output_path):
    from langchain_openai import ChatOpenAI, OpenAIEmbeddings
    from ragas import SingleTurnSample
    from ragas.llms import LangchainLLMWrapper
    from ragas.embeddings import LangchainEmbeddingsWrapper
    from ragas.metrics import Faithfulness, ResponseRelevancy, AnswerCorrectness
    from ragas.run_config import RunConfig

    chat = ChatOpenAI(
        base_url=local_url("RAGAS_LOCAL_CHAT_URL"),
        api_key="local-no-auth",
        model=os.environ["RAGAS_LOCAL_JUDGE_MODEL"],
        temperature=0, max_tokens=4096, timeout=120, max_retries=2,
    )
    embedding = OpenAIEmbeddings(
        base_url=local_url("RAGAS_LOCAL_EMBED_URL"),
        api_key="local-no-auth",
        model=os.environ["RAGAS_LOCAL_EMBED_MODEL"],
        check_embedding_ctx_length=False,
        request_timeout=120,
        max_retries=2,
    )
    llm = LangchainLLMWrapper(chat, bypass_n=True, bypass_temperature=True)
    emb = LangchainEmbeddingsWrapper(embedding)
    metrics = [
        Faithfulness(llm=llm),
        ResponseRelevancy(llm=llm, embeddings=emb, strictness=3),
        AnswerCorrectness(llm=llm, embeddings=emb, weights=[0.75, 0.25], beta=1.0),
    ]
    for metric in metrics:
        metric.init(RunConfig(timeout=120, max_retries=2, max_workers=1))
    rows = [json.loads(line) for line in Path(input_path).read_text(encoding="utf-8").splitlines() if line.strip()]
    ids = [row["id"] for row in rows]
    if not rows or len(ids) != len(set(ids)):
        raise ValueError("empty dataset or duplicate ids")
    results = []
    for row in rows:
        record = {"id": row["id"], "status": validate_row(row), "metrics": {}}
        if record["status"] == "scored":
            sample = SingleTurnSample(**{
                key: row[key] for key in
                ("user_input", "retrieved_contexts", "response", "reference")
            })
            for metric in metrics:
                try:
                    score = float(await metric.single_turn_ascore(sample))
                    record["metrics"][metric.name] = {
                        "value": score if math.isfinite(score) else None,
                        "status": "ok" if math.isfinite(score) else "undefined",
                    }
                except Exception as exc:
                    record["metrics"][metric.name] = {
                        "value": None, "status": "judge_error",
                        "error_type": type(exc).__name__,
                    }
        results.append(record)
    destination = Path(output_path)
    if destination.resolve() == Path(input_path).resolve():
        raise ValueError("refuse to overwrite source")
    destination.parent.mkdir(parents=True, exist_ok=True)
    with destination.open("x", encoding="utf-8") as handle:
        json.dump(results, handle, ensure_ascii=False, indent=2, allow_nan=False)
    print(f"rows={len(results)}; inspect every metric status")

if __name__ == "__main__":
    asyncio.run(main(*sys.argv[1:]))

13. 第五步：以评测单元为分母，计算覆盖率

3

假设 50 条可回答题跑 3 个指标，总共应有 150 个判分单元；若 Faithfulness 成功 50、相关性成功 48、正确性成功 47，则有效覆盖率=145/150=96.67%，缺失率=3.33%。不能只检查三个列均值都存在，就宣布成功率 100%；每列只剩一条有效值，也能算出均值。也不能将三列先整体 dropna，因为那会丢掉其他本来有效的指标单元。[D1]

下面统计器与上面的输出格式配套。它拒绝空输入、重复 ID、不完整指标集合，并把未进入 scored 状态的可回答题当作缺失单元计入覆盖率。实际执行前须将 negative_separate 样本另存或先分流，避免混入正例统计。保存为 notes/benchmark/summarize_generation.py。[D1]

import json
import math
import sys
from pathlib import Path

NAMES = ("faithfulness", "answer_relevancy", "answer_correctness")

def summarize(records):
    if not records:
        raise ValueError("empty evaluation is not a pass")
    ids = [row["id"] for row in records]
    if len(ids) != len(set(ids)):
        raise ValueError("duplicate ids")
    if any(row.get("status") == "negative_separate" for row in records):
        raise ValueError("separate negatives before positive summary")
    result = {}
    valid_total = 0
    for name in NAMES:
        values = []
        for row in records:
            cell = row.get("metrics", {}).get(name, {})
            value = cell.get("value")
            if row.get("status") == "scored" and cell.get("status") == "ok" and isinstance(value, (int, float)) and not isinstance(value, bool) and math.isfinite(value):
                values.append(value)
        valid_total += len(values)
        result[name] = {
            "mean": sum(values) / len(values) if values else None,
            "valid": len(values), "expected": len(records),
        }
    result["coverage"] = valid_total / (len(records) * len(NAMES))
    result["missing_rate"] = 1 - result["coverage"]
    return result

if __name__ == "__main__":
    rows = json.loads(Path(sys.argv[1]).read_text(encoding="utf-8"))
    print(json.dumps(summarize(rows), ensure_ascii=False, indent=2, allow_nan=False))

“缺失”不等于全是裁判错误。实际报告应进一步按 reference_missing、generation_empty、retrieval_miss、pipeline_error、judge_error、undefined 分类。完整性指标负责告诉你全量有多少没评到；质量均值负责告诉你有效部分怎么样。若只想用一个数表达保守下界，可将产品执行失败按零计算端到端成功率，但仍须保留错误类型，不能改写为官方 RAGAS 分数。[D1]

下面门禁函数使用同 ID、同 manifest、全量有限分数的严格教学策略。它选择“任何缺失先阻断比较”，比允许 5% 缺失的统计方案更保守；两种策略不能混用后仍叫同一个门禁。函数不写 baseline，也不自动更新任何生产配置。[D1]

import math

def paired_gate(baseline, candidate, tolerance=0.02):
    if tolerance < 0 or not math.isfinite(tolerance):
        raise ValueError("invalid tolerance")
    if not baseline.get("manifest") or baseline["manifest"] != candidate.get("manifest"):
        raise ValueError("incomparable manifests")
    before = baseline["scores"]
    after = candidate["scores"]
    if not before or set(before) != set(after):
        raise ValueError("empty or unmatched id sets")
    deltas = {}
    for metric in ("faithfulness", "answer_relevancy", "answer_correctness"):
        differences = []
        for sample_id in sorted(before):
            left = before[sample_id].get(metric)
            right = after[sample_id].get(metric)
            if not all(isinstance(value, (int, float)) and not isinstance(value, bool) and math.isfinite(value) for value in (left, right)):
                raise ValueError("missing or non-finite score")
            differences.append(right - left)
        deltas[metric] = sum(differences) / len(differences)
    return {
        "passed": all(delta >= -tolerance or math.isclose(delta, -tolerance, abs_tol=1e-12) for delta in deltas.values()),
        "paired_n": len(before),
        "deltas": deltas,
    }

这里 manifest 应只包含需完全相同的评测条件，候选与基线的生成版本号等实验变量另放 run metadata；否则把版本号也放进必须相等的 manifest，会使任何真实对照都被拒绝。反之，如果裁判模型或题集哈希从 manifest 漏掉，即使函数返回 passed，也不构成同尺子比较。机械函数只能执行已声明的契约，无法自动替用户发现未声明的实验变化。[D1]

16. 裁判校准：至少让错误样本真的扣分

3

首批可用 20 条公开或脱敏样本做人工校准，其中 10 条有据、10 条无据，再覆盖数字替换、否定翻转、日期冲突、漏答和错误拒答。20 和 10/10 是起始配置，不保证统计充分。需要看的是各类误判：无据声明被判支持，是真正危险的假阳性；有据声明被判不支持，会导致误报。只报整体准确率可能掩盖某一类完全失败。[D1]

至少检查五个端到端反例：把 0.45 改为 0.99，预期正确性下降；添加无据自动化承诺，预期忠实度下降；回答无关但真实背景，预期相关性下降；删掉 reference 关键要点，预期事实召回下降；制造裁判空输出，预期 judge_error 而不是零分或满分。如果这五种坏结果都不能触发对应异常，先修尺子，不要让它进入 CI 拦截别人的代码。[D1]

裁判与生成器选择不同模型有助于减少某些同源偏差，但不是绝对要求“裁判必须云端”或“必须比被评模型更大”。本机隐私约束优先：有能力的本地裁判经过校准可以使用，能力不足则用人工基线。若未来考虑云端，只能在取得单独授权、明确数据范围及脱敏策略之后执行；当前任务只做文档和本地验证，不触发这类外传。[D1]

17. 排错手册：先看状态，再看均值3 个重点▾ 点开看本节重点
本节重点
  • 第一种症状是 Faithfulness 全满分但用户说漏答
  • 先查 reference 必要要点与答案覆盖，不要只看支持比例；同时拉 Answer Correctness 的 FN
  • 第五种是正确性高但关键日期错
3

第一种症状是 Faithfulness 全满分但用户说漏答。先查 reference 必要要点与答案覆盖，不要只看支持比例；同时拉 Answer Correctness 的 FN。第二种是裁判输出空却出现满分。查自写包装层有没有把空声明默认视为忠实，或将异常当成无幻觉。第三种是分数忽高忽低。固定模型、模板、向量模型和文本范围，检查输出截断、重试及负例分布，不能靠把温度写成 0 就宣布消除随机性。[L2][L3][D1]

第四种是 numeric 答案相关性低但人工确认正确。查看反推问题是否因“0.45”这种短答案而缺少主语；保留官方分数，同时增加数值 Exact Match，不要为了好看而改 embedding。第五种是正确性高但关键日期错。把日期、单位、生效范围列入确定性规则，避免语义相似度掩盖重要错误。第六种是 NaN 大量增加。按题逐项定位 reference 缺失、无声明、超时和 JSON 失败，不要先 dropna 再报均值上升。[S2][S3][S4][D1]

第七种是检索评测很好但三指标都差。确认是否重新检索后拼接了不同轮次的上下文和答案，或裁判只看见前 2000 字；本库自写实现历史上存在截断疑点。第八种是同一道题修订 reference 后分数骤变。先审查旧 reference 是否有错，建立新题集版本并让基线和候选都重新评分；不能只重算候选，再把“标注修正”当作模型提升。[L2][D1]

18. 拒答、可用性与线上闭环

3

负例没有必需证据，不应混入正例 Recall 的分母；合法拒答也不应给 Faithfulness 人为加 1。单独统计应拒答题的正确拒答率、可回答题的误拒答率，以及生成空白和服务错误的比例。空字符串不是拒答承诺，更不是“安全无幻觉”；超时也不等于系统正确判断没有资料。把这些状态分开，才能避免“系统挂了所以拒答率 100%”的假绿。[D1]

线上没有 reference 时可旁路跑 Faithfulness 和 Relevancy，低分题经人工补标后再进端到端评测。采样要按路由与风险分桶，不只随机抽最短答案。评测不得阻塞用户请求，不把包含私有资料的轨迹默认发往外部监控平台；结果回流先形成脱敏 badcase 和人工裁决，再决定改文档、检索或生成提示词。是否改生产参数是独立授权动作，不由评分脚本自动执行。[D1]
