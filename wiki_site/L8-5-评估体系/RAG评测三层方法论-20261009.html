1. 找到文档、找到证据、把证据放在前面，是三件事

3

假设用户问“当前重排过滤线是多少”。系统前五条包含一份阈值文档，但命中的片段只是目录，没有真正写数值；或者同一文档同时含有现行值和历史值，重排把旧值放在第一。这两种情况都可能满足“文件名命中”，却不能保证生成模型获得了足够、准确、易利用的证据。检索评测必须把对象定到片段或证据单元，而不是只凭文件名宣布问题已经解决。本库旧脚本使用来源匹配，因此它能作为历史烟雾报警器，却不是证据完备性的充分证明。[L1][L3]

三个指标各管一个方向：Recall@k 看必须的证据找齐了多少；Context Precision 看被判有用的片段是否靠前；Context Relevance 看送入上下文的内容是否与问题有关。三者并列观察，才能区分漏召回、排序差和上下文污染。它们不是重复投票，也不应直接平均。把三个不同定义的数压成“检索综合分”，会丢掉排查入口，例如 Recall 很高而 Precision 很低，首先应该检查排序，而不是再扩候选池。[S2][S3]

2. 增大 k 有收益，也会把成本和错误一起放大3 个重点▾ 点开看本节重点
本节重点
  • 将 top-k 从 5 提到 10，可能补回一段缺失证据，也可能增加五段重复课件与过期说明
  • 对于固定标签集合，真正的 Recall 随 k 增大不应下降，但上下文 token、重排耗时、重复比例和生成干扰都可能上升
  • 如果 top-10 的召回明显增加，而生成层正确性下降，应先查看新增片段有没有冲突、噪声或截断效应，再决定保留数量
3

将 top-k 从 5 提到 10，可能补回一段缺失证据，也可能增加五段重复课件与过期说明。对于固定标签集合，真正的 Recall 随 k 增大不应下降，但上下文 token、重排耗时、重复比例和生成干扰都可能上升。因此本篇建议用 k=1、3、5、10 观察曲线，同时记录最终送给生成器的文本量，而不是默认“越多越好”。如果 top-10 的召回明显增加，而生成层正确性下降，应先查看新增片段有没有冲突、噪声或截断效应，再决定保留数量。[D1]

评测成本也要分两档。ID 比对可在每次本地变更后运行，不需要裁判；语义 Context Precision 和 Context Relevance 则需要读取文本并调用模型，适合抽样或冻结集。先用便宜的确定性检查拦住空结果、重复 ID、非法状态，再支付模型评测成本，能避免把网络失败当成算法问题。这里“便宜”指是否需要模型调用，不代表本地模型推理没有算力成本。[D1]

历史基线报告记载过 B010：检索返回 FastAPI 依赖注入课件，但标注要求命中一个没有对应章节的术语表，因此实际有用的结果被判成 miss。报告还记载过 B002 返回向量数组打印内容，以及 B005 把 G-Memory 问题检索成普通 LangChain Memory。三个失败分别涉及尺子、语料和语义检索，不能统一解释为“向量模型不够强”。本篇保留这些案例，但不把报告的阈值归因当成本次已复现结论。[L1]

更直接的问题在现有代码：rag/eval/eval_recall.py 以“存在任一匹配来源”为每题记分，再跨题求均值；当参考源有两份而只找到一份时，它仍记 1。这个量更接近来源级 HitRate，而不是多证据 Recall。它还先去重来源再取前 k，与生产 top-k 片段的口径不同。复用旧分数之前先读判定循环，往往比重跑一小时更有价值。[L3]

5. Recall@k：先写分母，再写百分比3 个重点▾ 点开看本节重点
本节重点
  • 跨问题做宏平均时，每题权重相同；微平均则让需要更多证据的问题占更大权重
  • 多跳问题只找到一跳时，HitRate 满分尤其容易产生误导，至少应同时报告证据 Recall 和全部证据命中率
  • 对于一条事实可由两份等价文档支持的情况，不要把两份都列为“必须找到”
3

对可回答问题 q，令 Gq 为人工认定的必需证据集合，Rq,k 为前 k 个真实检索位置覆盖的证据集合，则：

Recall(q,k)=|Gq ∩ Rq,k| / |Gq|，Hit(q,k)=1[|Gq ∩ Rq,k|>0]。

跨问题做宏平均时，每题权重相同；微平均则让需要更多证据的问题占更大权重。比如一题只有一条证据且命中，另一题需要三条而只找到一条：宏 Recall=(1+1/3)/2=66.67%，微 Recall=2/4=50%，HitRate=100%。三者可以同时成立。多跳问题只找到一跳时，HitRate 满分尤其容易产生误导，至少应同时报告证据 Recall 和全部证据命中率。[D1]

对于一条事实可由两份等价文档支持的情况，不要把两份都列为“必须找到”。更可靠的标注是建立证据组：同组多个片段任意命中即可；不同组分别代表不可缺少的事实。比如“阈值数值”和“生效日期”是两组，两份同内容阈值文档只是第一组的替代来源。本文代码采用一对一证据 ID 的简化格式，复杂场景应在导出时把等价片段映射到同一证据 ID。[D1]

6. Context Precision：不是简单的相关块比例

3

固定使用 RAGAS v0.3.9 的 LLMContextPrecisionWithReference：裁判读取问题、参考答案与每个片段，判断片段对得到参考答案是否有用，产生二值序列 v。实现计算相关位置上的精确率平均，分母是本次返回列表里被判有用的片段数量，而不是全库相关证据总量；源码另加极小量避免除零。[S2]

例如 v=[1,0,1,0,1]，普通 Precision@5=3/5=0.6，Context Precision=(1+2/3+3/5)/3=0.7556。若重排成 [1,1,1,0,0]，后者升到 1，但 Precision@5 仍是 0.6。如果只检索到唯一一段相关片段而漏掉其他必需证据，Context Precision 仍可为 1。因此它适合衡量排序，不适合代替 Recall。报告时写出完整类名与版本，避免把 AP、P@k、IDBasedContextPrecision 三种不同计算混称。[S2]

官方同标签还提供 LLMContextPrecisionWithoutReference，它用实际 response 替代 reference。这个变体虽不需要标准答案，却依赖模型答案：模型若已经答偏，裁判可能奖励“能帮助生成错误回答”的片段。本篇离线主基线选 WithReference；没有参考答案的线上样本，可以单独跑 WithoutReference，但列名和报表必须分开，不与主基线纵向连线。[S2]

7. Context Relevance：名字相近不代表算法相同3 个重点▾ 点开看本节重点
本节重点
  • RAGAS 原论文讨论过从上下文抽出相关句子、再与上下文句子数比较的 Context Relevance；本篇代码不冒充这一历史算法
  • 两次原始评分若为 2 和 1，最终是 0.75
  • 它不是“逐 chunk 二分类后取均值”
3

RAGAS 原论文讨论过从上下文抽出相关句子、再与上下文句子数比较的 Context Relevance；本篇代码不冒充这一历史算法。本文采用 v0.3.9 导出的 ContextRelevance，其内部名字是 nv_context_relevance：把全部片段按换行拼接为整体，两套提示词分别评 0、1、2，先除以 2 归一化，再合并两次评分。两次原始评分若为 2 和 1，最终是 0.75。它不是“逐 chunk 二分类后取均值”。[S1][S3]

这个区别直接影响结论。五段中只有一段包含答案，整体式评分可能因已经能回答而较高，但片段利用率仍然很低。要监测上下文冗余，额外保存每段有用性判定、重复率及 token 数；若自行实现逐块 0/1 相关率，请命名为 chunk_relevance_rate，不要覆盖 nv_context_relevance。新指标可以有价值，问题在于不能借相同名字假装历史成绩可比。[S3][D1]

该版本还在指标内部指定 temperature=0.1，外围把 ChatOpenAI 设成 0 不等于所有调用温度都必然为零。源码对异常的处理也存在降级分支，因此报告除了最终分数，还应统计裁判完成率、重复运行波动。不能用“温度设为 0”推导“完全确定”，也不能从一个有限数值反推两次判定均成功。[S3]

8. 本篇的三层指标契约

3
层 指标及输入 能支持的判断 不能支持的判断
检索 Recall@k：qrels、排名 ID 必需证据覆盖率 模型是否用对证据
检索 Context Precision：问题、片段、reference 相关片段排序质量 全库是否漏证据
检索 Context Relevance：问题、片段 整体上下文答题相关性 答案真实正确
生成 Faithfulness：问题、片段、response 回答是否被材料支持 材料本身是否过期
生成 Answer Relevancy：问题、response、向量模型 回答是否切题 数字与事实一定正确
端到端 Answer Correctness：问题、response、reference 相对标准答案的正确性 真实世界真值自动获得

这是一套教学与工程排障选集，不声称“六项是所有业务的最小充分集合”。代码执行、权限隔离、引用真实性、拒答与时效性可能还需其他测试。尤其是高风险业务，不能因为六项都有数字，就免除人工审查或业务级验收。[S1][D1]

为什么不能把历史 56 条的 87.5% 自动解释为 49/56？因为题集中可能含负例，分数也可能使用不同分母或平均方式。算术上 49/56 确实等于 87.5%，但这只说明一种可能的构造，不证明原报告实际如此。任何正式基线都应附可回答题数量、缺失条数、每题命中和运行状态，避免漂亮小数掩盖失败样本。[L2][D1]

以下是教学 JSONL 的单条格式，真实文件应放在 notes/benchmark/，不要放进 raw 或可被检索的 wiki 语料。本文展示的例子仅用于解释格式；生产测试集必须与教学例子隔离，不能把本文本身作为答题证据。[D1]

{"id":"ret-001","answerable":true,"status":"ok","question":"演示配置的过滤线是多少？","gold_ids":["policy-value"],"retrieved_ids":["policy-value","noise-1"],"reference":"演示配置过滤线是0.45。","contexts":["演示配置过滤线为0.45。","无关背景。"]}

这里 retrieved_ids 保留真实排名位置；不能先去重来源再补足五条。假如前五个位置全来自同一文档的五块重复内容，生成器实际上只有这一文档，评分器就不应伪造“第五个不同文档”进入 top-5。证据集合可以去重，但 k 的切片必须先做。重复 chunk 在 Precision 标签层仍占位置，另报重复率即可。[D1]

将下面代码保存为基准目录中的 retrieval_math.py。脚本只用标准库，不访问向量库、不调用模型、不写结果文件，适合首先验证计算语义。输入来自固定教学构造，输出不能当业务评测结论。[D1]

import math
from statistics import mean

def recall_at_k(gold_ids, retrieved_ids, k):
    if k <= 0:
        raise ValueError("k must be positive")
    gold = set(gold_ids)
    if not gold:
        raise ValueError("answerable query needs non-empty gold")
    return len(gold & set(retrieved_ids[:k])) / len(gold)

def hit_at_k(gold_ids, retrieved_ids, k):
    return float(recall_at_k(gold_ids, retrieved_ids, k) > 0)

def context_ap(verdicts):
    if not verdicts:
        return math.nan
    if any(v not in (0, 1) for v in verdicts):
        raise ValueError("binary verdicts required")
    positives = sum(verdicts)
    if positives == 0:
        return 0.0
    running = 0
    numerator = 0.0
    for rank, verdict in enumerate(verdicts, 1):
        running += verdict
        numerator += (running / rank) * verdict
    return numerator / positives

def main():
    rows = [
        {"gold": [f"g{i}"], "ranked": [f"g{i}", "x", "y", "z", "w"]}
        for i in range(7)
    ] + [{"gold": ["g7"], "ranked": ["a", "b", "c", "d", "e"]}]
    r5 = mean(recall_at_k(r["gold"], r["ranked"], 5) for r in rows)
    print(f"teaching_recall@5={r5:.1%}")
    print(f"context_precision={context_ap([1, 0, 1, 0, 1]):.4f}")
    print(f"nv_context_relevance_demo={(2 / 2 + 1 / 2) / 2:.2f}")
    assert r5 == 0.875
    assert math.isclose(context_ap([1, 0, 1, 0, 1]), 34 / 45)
    assert context_ap([0, 0]) == 0
    assert math.isnan(context_ap([]))
    assert recall_at_k(["a", "b"], ["a", "x"], 5) == 0.5
    assert hit_at_k(["a", "b"], ["a", "x"], 5) == 1.0
    assert recall_at_k(["a", "b"], ["a", "a", "b"], 2) == 0.5
    for k in (1, 3, 5):
        assert recall_at_k(["a", "b"], ["x", "a", "b"], k) <= 1
    print("offline_math_checks=passed")

if __name__ == "__main__":
    main()

下面是一份完整的读取 JSONL、调用两个检索指标、保留每项失败状态的适配脚本。保存为 notes/benchmark/ragas_retrieval_lab.py。裁判端点通过环境变量显式给出，必须为 localhost 回环地址；代码不接收云端端点，也不读取凭据文件。模型名同样来自已有本地服务配置，文档不假定某个模型已经安装。[D1]

import asyncio
import json
import math
import os
import sys
from pathlib import Path
from urllib.parse import urlparse

def local_url(name):
    value = os.environ[name]
    parsed = urlparse(value)
    if parsed.scheme not in {"http", "https"}:
        raise ValueError("HTTP(S) endpoint required")
    if parsed.hostname not in {"127.0.0.1", "localhost", "::1"}:
        raise ValueError("private evaluation requires loopback endpoint")
    if parsed.username or parsed.password or parsed.query or parsed.fragment:
        raise ValueError("credentials/query/fragment not allowed in URL")
    return value

async def main(input_path, output_path):
    from langchain_openai import ChatOpenAI
    from ragas import SingleTurnSample
    from ragas.llms import LangchainLLMWrapper
    from ragas.metrics import LLMContextPrecisionWithReference, ContextRelevance
    from ragas.run_config import RunConfig

    chat = ChatOpenAI(
        base_url=local_url("RAGAS_LOCAL_CHAT_URL"),
        api_key="local-no-auth",
        model=os.environ["RAGAS_LOCAL_JUDGE_MODEL"],
        temperature=0,
        max_tokens=4096,
        timeout=120,
        max_retries=2,
    )
    llm = LangchainLLMWrapper(chat, bypass_n=True, bypass_temperature=True)
    metrics = [LLMContextPrecisionWithReference(llm=llm), ContextRelevance(llm=llm)]
    for metric in metrics:
        metric.init(RunConfig(timeout=120, max_retries=2, max_workers=1))

    rows = [json.loads(s) for s in Path(input_path).read_text(encoding="utf-8").splitlines() if s.strip()]
    ids = [row["id"] for row in rows]
    if not rows or len(ids) != len(set(ids)):
        raise ValueError("empty dataset or duplicate ids")
    output = []
    for row in rows:
        record = {"id": row["id"], "metrics": {}, "run_status": row.get("status")}
        if not row.get("answerable", True):
            record["status"] = "negative_separate"
        elif row.get("status") != "ok":
            record["status"] = "pipeline_error"
        elif not isinstance(row.get("contexts"), list) or not row["contexts"] or not all(isinstance(c, str) and c.strip() for c in row["contexts"]):
            record["status"] = "retrieval_miss"
        elif not isinstance(row.get("reference"), str) or not row["reference"].strip() or not row.get("question"):
            record["status"] = "schema_error"
        else:
            record["status"] = "scored"
            sample = SingleTurnSample(
                user_input=row["question"],
                retrieved_contexts=row["contexts"],
                reference=row["reference"],
            )
            for metric in metrics:
                try:
                    value = float(await metric.single_turn_ascore(sample))
                    record["metrics"][metric.name] = {
                        "value": value if math.isfinite(value) else None,
                        "status": "ok" if math.isfinite(value) else "undefined",
                    }
                except Exception as exc:
                    record["metrics"][metric.name] = {
                        "value": None, "status": "judge_error",
                        "error_type": type(exc).__name__,
                    }
        output.append(record)
    destination = Path(output_path)
    if destination.resolve() == Path(input_path).resolve():
        raise ValueError("refuse to overwrite input")
    destination.parent.mkdir(parents=True, exist_ok=True)
    with destination.open("x", encoding="utf-8") as handle:
        json.dump(output, handle, ensure_ascii=False, indent=2, allow_nan=False)
    print(f"rows={len(output)}; per-metric status retained")

if __name__ == "__main__":
    asyncio.run(main(*sys.argv[1:]))

本例 bypass_n=True 用于兼容不支持多候选参数的服务；bypass_temperature=True 让包装器不要改写 ChatOpenAI 的温度，但 NVIDIA 指标直接传入温度的行为仍须根据实际适配链核对。并发先设 1，超时 120 秒、最大输出 4096 是实验起点，不是对所有推理模型都足够的保证。使用推理型裁判时，必须查看是否发生截断；只看到 HTTP 成功或 finish_reason 为 stop，并不能保证结构化结果完整。[S3][S4][D1]

运行前由操作者按本地服务现状设置两个环境变量：一个是回环 /v1 地址，一个是实际存在的模型名。这里不提供云端密钥注入步骤，因为本机知识库材料禁止外传。即使端点在 localhost，也应确认后端不是把请求转发至外部供应商；网络地址校验只是第一层，不是数据出域审批的替代品。[D1]

每题至少保存原问题、路由、候选集、重排后排名、最终截断文本、状态和时延。Recall 可以同时在候选池、重排后 top-5、最终送模文本三处算，但列名必须分别标注。若候选池有金标而最终上下文没有，问题发生在排序、过滤或截断阶段；此时继续调 embedding 不会直接解决。若三处都没有，才优先查索引覆盖、查询改写或召回策略。[D1]

JSONL 中的 contexts 必须来自最终生成输入，不是用文档全文回填。尤其是 parent-child 检索、图谱追加与上下文压缩：原始 chunk 命中不代表经过处理后关键句仍在。证据 ID 应与最终文本逐项对齐，并保存文本哈希，避免两个脚本分别重新检索后把不同结果拼成假四元组。生成篇将用这份冻结轨迹检查“找到但没用对”的问题。[D1]

对于合法的检索空结果，可回答题的 Recall 必须记 0；对于超时、进程崩溃，质量分记缺失并单独计执行失败率，不能把失败条删掉以后继续宣布整体达标。一个实用输出是 eligible=50, retrieval_ok=48, zero_hit=4, pipeline_error=2，同时报告成功运行口径的 Recall 与全量覆盖率。若业务必须保守验收，还可计算“失败按零”的下界，但应显式标作下界。[D1]

16. 排错顺序：先证明尺子没有坏

3

第一类，Recall@10 比 Recall@5 低。若题集和金标固定，这不符合本篇集合 Recall 的单调性；先检查是不是把相关块数除以 k、是否不同 k 重新跑了随机检索，或者报告名称用错。第二类，Recall 很高但 Context Precision 低。查看每题标签序列与首条证据位置，确认是不是重复块或固定置顶槽挤占前排，不能直接据此断言检索算法失败。[D1]

第三类，Context Precision 全是 1。手工挑出至少五条明显无关片段作负例，检查裁判是否只判断了主题相似、reference 是否泄漏到 contexts。第四类，Context Relevance 永远是 0.5 或 1。核对是否用了粗粒度整体评分、是否两个提示词都完成，并与逐块标签分开观察。第五类，所有分数突然下降。优先查缺失率、超时和输入截断，随后才查召回质量；模型评测器失效与产品退化不能混合处理。[S2][S3][D1]

第六类，同一题换一种文件名就从命中变 miss。检查路径前缀匹配和旧目录别名，升级为稳定证据 ID；不要为了让分数恢复而把所有来源模糊匹配为同一主题。第七类，多跳题只找到一个源却满分。复核是否运行了 HitRate，或者标注把多个必需证据写成了任选关系。第八类，超时被当空结果。旧入口会返回空列表，必须从外围保留超时与退出状态，不能靠最终零分逆推出病因。[L3][D1]
