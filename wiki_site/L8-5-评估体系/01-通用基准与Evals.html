通用基准与 Evals：从排行榜分数到可执行产品评估

本篇是本层“通用基准与 Evals”的唯一正文。公共基准用于横向参照，自有 Evals 用于回答具体产品问题；两者不能互相替代。文中模型评测命令均未实跑，确定性评分代码的验证记录见本层融合清单。

WHY：为什么不能只看一个排行榜分数

2

通用模型上线前，团队很容易问：“MMLU 多少分，能不能直接换？”这个问题把三种不同决策混在了一起：

  1. 能力参照：模型在一组标准化题上的相对表现如何。
  2. 产品适配：它能否遵守本产品的提示词、输出格式、领域约束和安全边界。
  3. 发布决策：新版本相对当前版本是否在自己的流量分布上更好，代价是否可接受。

公共基准主要回答第一问。它不自动包含企业私有任务、真实上下文长度、工具调用链、拒答策略和用户偏好的分布。即使两个模型的总分相同，也可能一个擅长知识选择题、另一个更擅长按约束生成；把它们视为可互换，会把回归推迟到上线后才发现。

不做可执行 Evals，还会出现四类反复发生的问题：

  • 换提示词就换结论：shot 数、选项排列、答案提取规则变了，分数差异却全归因于模型。
  • 平均分掩盖关键人群：总体上涨，低资源语言或高风险场景却大幅退化。
  • 参考答案过窄：把字符串不完全一致的正确答案判错，或把流畅但错误的答案判对。
  • 测试行为代替线上行为：模型识别出“这是测试”后更谨慎，离线分数无法代表日常请求。

Hamel Hussain 的评估分级把确定性检查、人工/模型评估、线上 A/B 放在不同层级，价值就在于先便宜地排除明确错误，再把昂贵评估用于真正需要判断的地方，最后回到真实用户结果，而不是期待某一个分数包办所有决策。

WHAT / WHYT：基准、Evals 与“最佳答案”的边界

2

1. MMLU、CMMLU、C-Eval 分别是什么

3
基准 核心形态 主要用途 不能直接推出
MMLU（arXiv:2009.03300） 57 个学科的多项选择题 比较英文世界知识与推理的广覆盖表现 中文业务、开放式生成、工具调用能力
CMMLU（arXiv:2306.09213） 67 个中文学科主题的多项选择题 检查中文知识与本土语境覆盖 企业私有知识检索是否正确
C-Eval（arXiv:2305.08322） 面向中文模型的分学科选择题套件 中文知识与推理的分层比较 任意中文产品任务上的用户满意度

比较时必须同时固定：模型与解码参数、提示模板、few-shot 数量、选项顺序、答案提取方式、题目子集、学科聚合方式及实现版本。只写“跑了 MMLU”不足以复现。macro 是先算各学科再平均，micro 是把题目放到同一分母；学科题量不均时，两者回答的问题不同。

公共基准还可能被训练数据污染，且选择题上的相对排序不保证开放生成上的排序。因此它适合作为候选模型的初筛和回归哨兵，不适合作为唯一发布门禁。

2. 自有 Evals 是什么

3

一个可执行的 Eval 至少包含六件东西：

任务卡 + 版本化数据 + 固定运行协议 + 明确评分器 + 失败状态 + 分桶报告
  • 任务卡：用户是谁、输入是什么、什么结果算好、允许什么拒答。
  • 数据：覆盖高频、长尾、对抗、边界与历史 badcase，保留来源和隐私级别。
  • 运行协议：模型、提示词、上下文、工具、温度、随机种子、并发和超时。
  • 评分器：确定性断言、人工 rubric 或模型裁判；不能把解析异常当普通低分。
  • 失败状态：scored / invalid_output / timeout / judge_error / not_applicable 分开记录。
  • 报告：除均值外，按业务、语言、难度、输入长度和风险级别分桶。

“最佳答案”也不等于唯一字符串。封闭题可以有唯一正确选项；开放题的 reference 应包含必须命中事实、可接受变体、禁止事实和需要保留的不确定性。字符串完全匹配适合选项 ID，不适合评价自然语言答案的全部质量。

3. 论文怎么说，我们怎么用

3

评分尺度敏感性（arXiv:2610.22187）。本地摘要报告：改变评分尺度设计会使归一化分平均移动约 0.10，约 20% 的文本类别发生变化，使用 rubric 并没有消除这种敏感性。这里的证据边界是本地摘要，不是全文复现实验。

我们的用法：

  • 在 manifest 中固定裁判模型、提示、rubric、尺度端点和归一化公式，禁止候选版与基线各用一把尺子。
  • 裁判上线前用同一批评分样本做跨尺度稳健性检查；结论翻转的样本送人工，不把“多了 rubric”当成偏差已经消失。
  • 报告保留原始类别和尺度，不只保存归一化后的一个小数。

评估意识（arXiv:2610.22333）。本地摘要报告：测试提示会提高有害请求拒答，Indic 语言平均增加 14.4 个百分点，良性请求拒答也从 6.9% 增至 11.3%。这说明“更安全”可能伴随“更爱误拒”，而且测试场景行为未必等于线上行为。

我们的用法：安全 Evals 必须同时含有害与良性对照，并按语言分桶；发布结论再结合脱敏后的生产采样，不能只用带明显测试标记的请求推断日常表现。

HOW：建立同尺子、可复跑的通用评估

2

第一步：先写任务卡，再选指标

3

每张任务卡至少回答：

task_id: product_grounded_qa
user_goal: 根据给定材料回答并保留不确定性
input_schema: [question, context]
required_behavior: [结论正确, 不添加材料外事实, 格式可解析]
acceptable_refusal: 材料不足时明确说明缺少什么
blocking_failures: [编造关键事实, 泄漏受限内容]
slice_keys: [language, domain, difficulty, context_length]
reference_policy: 必需事实 + 可接受变体 + 禁止事实

选择题优先用确定性答案提取；开放题把格式、事实完整性和偏好评价拆开。不要把所有维度塞进一个不可解释的总分。

第二步：保存逐题输入、输出和评分状态

3

建议一行一个 JSON 对象：

{"id":"zh-law-001","slice":"zh/legal","input":{"question":"……"},"reference":{"required":["要件A"],"forbidden":["虚构条款B"]},"candidate_output":"……","status":"scored","score":1.0,"protocol_id":"mcq-v3"}

status != scored 的样本不能悄悄从分母删除，也不能默认记 0 分或满分。报告同时给出覆盖率、失败率和分数；裁判故障时整批结论应是“评估无效”，而非“候选更差”。

第三步：用确定性代码处理封闭答案与有限分数

3 
import math
import re


def extract_choice(text):
    """只接受唯一的 A-D 选项；歧义与空输出都返回 None。"""
    matches = re.findall(r"(?<![A-Z])([A-D])(?![A-Z])", text.strip().upper())
    return matches[0] if len(set(matches)) == 1 else None


def score_mcq(records):
    rows = []
    for row in records:
        predicted = extract_choice(row["output"])
        valid = predicted is not None
        rows.append({
            "id": row["id"],
            "status": "scored" if valid else "invalid_output",
            "score": float(predicted == row["gold"]) if valid else math.nan,
        })
    scored = [r["score"] for r in rows if r["status"] == "scored"]
    return {
        "rows": rows,
        "accuracy": sum(scored) / len(scored) if scored else math.nan,
        "coverage": len(scored) / len(rows) if rows else 0.0,
    }

这里的 coverage 用全部输入作分母，准确率只覆盖可评分样本，两者必须一起报告。真实数据还要按 slice 分组，不能只用总覆盖率。

第五步：裁判校准与发布解释

3
  1. 用人工双标的一批正例、负例和边界例校准裁判，记录一致率与分歧类型。
  2. 固定主评分尺度，另选一种合理尺度做敏感性分析；若发布结论翻转，标记为不确定并人工复核。
  3. 对有害/良性、语言、领域、难度分别给出 delta；总体均分不能覆盖关键桶退化。
  4. 报告“公共基准变化 + 自有任务变化 + 线上待验证项”，不要合并成没有口径的总排名。
