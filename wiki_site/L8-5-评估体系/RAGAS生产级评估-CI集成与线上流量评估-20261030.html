跑通 RAGAS 只是起点，生产级评估要解决的是"评测什么时候跑、跑哪部分、分数怎么变成门禁和告警"。落地骨架是三层节奏（Hamel 分级）：断言级每次提交跑（秒级、零成本）、RAGAS 模型评测按 PR/夜间跑（分钟级、控成本）、线上流量评估持续跑（采样、异步、回流）。三个最容易做错的点：①门禁看同尺子 delta 不看绝对分——绝对分会随题集演进漂移，跨轮比较是假数；②线上评估必须异步旁路（影子评测），绝不进请求主链路；③评测失败题必须回流 golden set（badcase.jsonl → 人工裁决 → 进题集），否则评测系统只报警不进化。本文给 CI 集成与线上评估的完整设计 + 可直接跑的代码。

一、生产级评估全景与节奏

2
层级 触发 内容 时延 成本 失败处置
断言级 每次提交/每次请求 代码单测、schema 校验、chunks>0、答案非空、含来源标注 秒级 零 直接红灯，禁止合并
模型评测（离线） PR 冒烟 + 夜间全量 RAGAS 5 指标（PR 跑 10~15 条子集，夜间跑全量 golden set） 分钟级 低~中 delta 超阈值 → 阻断合并/告警
线上评估（在线） 持续采样 Faithfulness + Answer Relevancy（无 reference 两件套）+ 用户反馈 准实时 可控 漂移告警 → 回流 badcase

三条节奏对应 Hamel Husain 的三级：单元断言→人工+模型评测→线上 A/B。不要在 PR 里跑全量 RAGAS——50 条 × 5 指标 ≈ 300~500 次裁判调用，既慢又烧钱，PR 只需要"没变坏"的快速信号。

据[一手源]：raw/sources/RAG优化-外部调研-20260929.md（方向 4）：业内的工具分工口诀是 "DeepEval catches regressions at PR time, RAGAS monitors drift over time"。DeepEval 是 pytest-based CI runner，拦 PR 回归（golden-question 套件）；RAGAS 以定时任务采样生产流量算 faithfulness / context precision / answer relevance，在 Grafana 看 7 天滚动平均。生产 pattern 是 CronJob 每小时采样 1–5% traces，faithfulness < 0.80 触发告警（本文 §3.3 地板 0.75 比该业界线更松，上线初期可先用 0.80 收紧一轮看误报率）。

2.1 门禁设计原则

3
  1. 比 delta 不比绝对分：基线文件 eval/baseline.json 存上一轮同尺子分数，当前轮与基线逐指标比差值。绝对分（如 faithfulness=0.83）随题集增删天然漂移，"高于阈值就放行"会把退化放过去——本库评测纪律明确"基线必须每轮实测，别引用旧数"。
  2. 同尺子才可比：题集变了（golden set 加题）必须先重跑基线，否则 delta 是两把尺子的差，无意义。
  3. 失败分档：关键指标（faithfulness / answer_correctness）跌 >0.05 阻断；次要指标跌只告警。阈值来自 RAG管线现状与阈值标定 的实测标定，不是拍脑袋。
  4. 统计噪声意识：20 条以内的题集单指标抖动 ±0.03 正常（裁判 temperature=0 也仍有网络/解析抖动）。判"真退化"要求 delta 超阈值且低分题明细能对上具体病因，两者齐了才回滚。

    K -->|"否"| M{"次要指标下跌"}

2.2 门禁脚本 eval/ci_eval.py（可直接跑）2 个重点▾ 点开看本节重点

#!/usr/bin/env python3
"""RAGAS CI 门禁：跑指定题集子集 → 与基线比 delta → 超阈值退出非 0。"""
import json, os, sys, argparse
from datetime import datetime, timezone

from ragas import evaluate, EvaluationDataset, SingleTurnSample
from ragas.metrics import Faithfulness, AnswerRelevancy, AnswerCorrectness
from ragas.llms import LangchainLLMWrapper
from ragas.run_config import RunConfig
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from ragas.embeddings import LangchainEmbeddingsWrapper

# 关键指标阈值：跌超此值阻断（经基线标定，勿拍脑袋）
BLOCK_METRICS = {"faithfulness": 0.05, "answer_correctness": 0.05, "answer_relevancy": 0.08}

def build_judge():
    llm = LangchainLLMWrapper(ChatOpenAI(
        model="qwen-plus",
        api_key=os.environ["DASHSCOPE_API_KEY"],
        base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
        temperature=0.0, max_tokens=2048, timeout=60,
    ))
    emb = LangchainEmbeddingsWrapper(OpenAIEmbeddings(
        model="text-embedding-v3",
        api_key=os.environ["DASHSCOPE_API_KEY"],
        base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
    ))
    return llm, emb

def load_samples(path, limit=None):
    """golden-q.jsonl → EvaluationDataset；contexts 为空的题 SKIP 不污染均值。"""
    samples, skipped = [], 0
    with open(path, encoding="utf-8") as f:
        for line in f:
            g = json.loads(line)
            if not g.get("answer") or not g.get("contexts"):
                skipped += 1
                continue
            samples.append(SingleTurnSample(
                user_input=g["question"],
                retrieved_contexts=g["contexts"],
                response=g.get("actual_answer", ""),
                reference=g["answer"],
            ))
            if limit and len(samples) >= limit:
                break
    print(f"[load] usable={len(samples)} skipped={skipped}")
    if not samples:
        print("[FATAL] 无可用样本（全空）——大概率检索超时/chunks=0，禁止静默 0 分通过")
        sys.exit(2)
    return EvaluationDataset(samples=samples)

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--golden", default="rag/eval/golden-q.jsonl")
    ap.add_argument("--limit", type=int, default=15, help="PR 冒烟子集条数")
    ap.add_argument("--baseline", default="eval/baseline.json")
    ap.add_argument("--json-out", default="eval/ci_result.json")
    args = ap.parse_args()

    llm, emb = build_judge()
    dataset = load_samples(args.golden, limit=args.limit)
    metrics = [
        Faithfulness(llm=llm),
        AnswerRelevancy(llm=llm, embeddings=emb),
        AnswerCorrectness(llm=llm, embeddings=emb),
    ]
    result = evaluate(dataset, metrics=metrics,
                      run_config=RunConfig(timeout=120, max_retries=3, max_workers=4),
                      raise_exceptions=False)
    scores = {k: float(v) for k, v in result.items() if v == v}   # 滤 nan
    fail_rate = 1 - len(scores) / max(len(metrics), 1)
    if fail_rate > 0.05:
        print(f"[FATAL] 裁判失败率 {fail_rate:.0%} > 5%（超时/上下文过长），不判门禁")
        sys.exit(2)

    baseline = {}
    if os.path.exists(args.baseline):
        baseline = json.load(open(args.baseline, encoding="utf-8"))

    out_dir = os.path.dirname(args.json_out)
    if out_dir:
        os.makedirs(out_dir, exist_ok=True)   # dirname 为空会 FileNotFoundError，必须判
    json.dump({"scores": scores, "ts": datetime.now(timezone.utc).isoformat()},
              open(args.json_out, "w", encoding="utf-8"), ensure_ascii=False, indent=2)

    blocked = []
    for m, thresh in BLOCK_METRICS.items():
        cur, base = scores.get(m), baseline.get(m)
        if base is None:
            print(f"[warn] {m}: 无基线（首轮），仅记录 {cur:.3f}")
            continue
        delta = cur - base
        flag = "BLOCK" if delta < -thresh else "ok"
        print(f"[{flag}] {m}: {base:.3f} -> {cur:.3f} (delta {delta:+.3f}, 阈值 -{thresh})")
        if flag == "BLOCK":
            blocked.append(m)

    if blocked:
        print(f"[FAIL] 阻断合并：{blocked} 跌幅超阈值。先看 eval/ci_result.json 低分题明细归因，"
              f"别直接调阈值。")
        sys.exit(1)
    print("[PASS] 三层关键指标未显著退化")

if __name__ == "__main__":
    main()

坑已在脚本里内置规避：①os.makedirs(dirname) 前判空（纯文件名时 dirname 为空会 FileNotFoundError，本库所有 --json-out 脚本都踩过）；②无可用样本直接 exit(2)，不静默出 0 分；③裁判失败率单独设卡——失败率本身超阈说明基础设施坏了，此时任何分数都不可信。

3.1 原则3 个重点▾ 点开看本节重点
本节重点
  • 1. 旁路异步，绝不进主链路：线上请求先把四元组（question / retrieved_contexts / response / metadata）落日志，影子评测 worker 异步消费打分
  • 3. 采样而非全量：默认 2%~5% 采样 + 100% 采集日志
  • 采样率按预算反推：裁判单次 ≈ 千 token 级，日活 1 万问 × 3% × 2 指标 ≈ 600 次调用/天，免费档可覆盖
3
  1. 旁路异步，绝不进主链路：线上请求先把四元组（question / retrieved_contexts / response / metadata）落日志，影子评测 worker 异步消费打分。进主链路 = 每请求加 3~6 次裁判调用的延迟和成本，用户直接感知。
  2. 无 reference 两件套：线上流量没有标准答案，能跑的是 Faithfulness + Answer Relevancy（都不依赖 reference）；Answer Correctness 只对回流后人工补了 reference 的题跑。
  3. 采样而非全量：默认 2%~5% 采样 + 100% 采集日志。采样率按预算反推：裁判单次 ≈ 千 token 级，日活 1 万问 × 3% × 2 指标 ≈ 600 次调用/天，免费档可覆盖。
  4. 分群看分数：按业务线/问题类型（简单事实/多跳/全局）分桶看均值，总均值会被题型分布漂移带偏。

3.3 影子评测 worker（可直接跑）2 个重点▾ 点开看本节重点

#!/usr/bin/env python3
"""影子评测：采样消费生产日志 → Faithfulness+AnswerRelevancy → 落分数流。"""
import json, os, random, time
from ragas import evaluate, EvaluationDataset, SingleTurnSample
from ragas.metrics import Faithfulness, AnswerRelevancy
# build_judge 同 ci_eval.py

SAMPLE_RATE = float(os.environ.get("EVAL_SAMPLE_RATE", "0.03"))
ALERT_BELOW = {"faithfulness": 0.75, "answer_relevancy": 0.70}

def should_sample(rec: dict) -> bool:
    # 低置信检索 / 用户点过踩的必采，其余随机采
    if rec.get("feedback") == "down" or rec.get("top1_dist", 0) > 0.75:
        return True
    return random.random() < SAMPLE_RATE

def run(log_path="logs/rag_requests.jsonl"):
    llm, emb = build_judge()
    rows = [json.loads(l) for l in open(log_path, encoding="utf-8")]
    picked = [r for r in rows if should_sample(r)]
    dataset = EvaluationDataset(samples=[SingleTurnSample(
        user_input=r["question"],
        retrieved_contexts=r["retrieved_contexts"],
        response=r["response"],
    ) for r in picked])                       # 线上无 reference，只跑两件套
    result = evaluate(dataset,
                      metrics=[Faithfulness(llm=llm), AnswerRelevancy(llm=llm, embeddings=emb)],
                      run_config=RunConfig(timeout=120, max_retries=2, max_workers=2),
                      raise_exceptions=False)
    with open("logs/eval_scores.jsonl", "a", encoding="utf-8") as f:
        for rec, row in zip(picked, result.to_pandas().to_dict("records")):
            f.write(json.dumps({"req_id": rec["req_id"],
                                "faithfulness": row.get("faithfulness"),
                                "answer_relevancy": row.get("answer_relevancy"),
                                "route": rec.get("route")}, ensure_ascii=False) + "\n")
            for m, floor in ALERT_BELOW.items():
                if row.get(m) is not None and row[m] < floor:
                    print(f"[ALERT] req_id={rec['req_id']} {m}={row[m]:.2f} < {floor}")

if __name__ == "__main__":
    run()

生产部署形态：cron 每小时消费上一小时日志（本库同类同步任务的既有姿势），或消息队列消费者常驻；由常驻服务/主会话托管，不由会退出的执行者进程托管（本库踩过：执行者退出把它起的后台任务一起带走）。

3.4 漂移监控与告警

3

监控四个信号，全部按天/周滚动窗口：

  1. 分数趋势：Faithfulness / Answer Relevancy 7 日滚动均值跌 >0.05 或单日跌破地板（0.75/0.70）→ 告警。分数下跌先分桶定位（哪个 route、哪个业务线跌），再查根因。据[一手源]：raw/rag-arch/外部调研-雷点知识学习-20260925.md（主题 1，渠道健康哨兵）：同构的阈值做法是"错误率 >20%/2 min 停止路由、用量漂移 >15% 告警"，即告警要同时给窗口和比例两个量，不要只写"明显下降"。本文的 0.05 与 7 日窗口属于这一类，落地时把窗口、阈值、触发后动作三项写进告警配置。
  2. 检索置信度分布：top1_dist 分布右移（越来越不确定）→ 知识库过期/新问题类型涌入，早于分数下跌暴露。
  3. 词/主题漂移：问题 embedding 与 golden set 的分布距离变大 → 题型漂移，提示补题。
  4. 裁判自身漂移：裁判模型被供应商静默升级会让分数整体跳变——每轮评测固定带 5 条"金标哨兵样本"（人工已知分数），哨兵分数跳变 = 裁判变了，不是产品变了。

3.6 线上 A/B（重大变更才用）

3

换 prompt/换模型/换检索策略时：双跑分流（5%/5%）→ RAGAS 两件套 + 用户侧指标（点赞率、追问率、人工转接率）联合判胜。RAGAS 分数只代表质量维度，不替代业务指标——答案更"忠实"但更啰嗦，用户追问率可能反而升。判胜规则要事前写死：质量指标不降且至少一项业务指标显著提升才算赢；只有分数涨、业务不动的改动不值得付双跑成本。分流期间两组都要跑影子评测，防止"实验组分数涨是因为题目分布碰巧简单"。

  1. 绝对分门禁必失灵：题集一变基线就废，delta 门禁 + 同尺子是唯一可持续做法。
  2. PR 跑全量 = 没人跑：又慢又贵，团队会绕过它。冒烟子集 15 条 3~5 分钟出结果才有人看。
  3. 线上评测进主链路：延迟 +300%、成本爆炸，一次事故后整个评测系统会被砍掉——旁路是底线。
  4. 均值掩盖分桶退化：某 route 跌 0.2、其他涨 0.05，总均值几乎不动。分桶监控是必须项。
  5. nan 混进均值：裁判超时的条目是 nan，pandas.mean() 默认跳过——失败率必须单独报，否则"分数没掉"可能是"掉的题都没跑出来"。
  6. 基线被 PR 顺手更新：门禁自我放水，基线更新权收归夜间主分支任务。
  7. 哨兵样本缺失：裁判模型被供应商静默升级，分数整体跳变被误判为产品退化，白查一周。
  8. 回流只进不出：badcase.jsonl 积压不裁决、不进题集，评测系统只报警不进化，三个月后题集与线上严重脱节。
  9. 门禁里的断言必须可重放，失败先智能重跑再定性：据[一手源]：raw/rag-arch/外部调研-雷点知识学习-20260925.md（主题 5，Google Testing Blog 与 flaky 论文）：断言不依赖墙钟、上一轮残留计数器、共享可变状态（assertEquals(4, timer.count()) 第二次运行变 8 就红）；失败后先重跑一次判可复现，可复现直接红，盲目自动重跑会把红洗成绿（调研引用 47% 重启即过的失败 job 掩盖了真问题）；不稳定的检查进 quarantine，必须写 owner 和 deadline（一个 sprint），是队列不是坟场。
  10. baseline.json 并发写要原子：据[一手源]：raw/rag-arch/外部调研-雷点知识学习-20260925.md（主题 6）：flock 是 advisory 锁，官方 man 明说进程可以无视它，且锁不保证原子与落盘；写入要配"临时文件 + fsync + rename"原子替换，读-改-写型更新加版本号/内容 hash 乐观校验，冲突则重读重试而非盲写。基线文件属于这一类。对应上面"基线更新归夜间主分支任务"，同一时刻只许一个写者。
  11. 评测报告不采信自报：据[一手源]：raw/rag-arch/反面教材-踩坑Top10-20260928.md（Top3 自报不采信/只测正例）：门禁要用故意退化（改坏 prompt）验证真能红灯，并带负例；本文路线图第 2 周验收就是这条。据[一手源]：raw/rag-arch/RAG基线评测-20261013.md：golden 标注自身会错（B010 的 top1 score 0.7572 却被判 miss），所以 CI 开跑前先过 --check-golden 尺子守卫，exit=0 才谈分数。
