L12 AWQ 量化实操：激活感知缩放，以及 AutoAWQ 退役之后怎么做

TL;DR：AWQ 不做误差补偿，也不反向传播。它只做一件事：按激活幅值给权重通道乘一个缩放因子 s，再量化，使"重要通道"的相对量化误差变小。论文（MLSys 2024 最佳论文）报告 Llama-2 的 INT4-g128 困惑度与 FP16 只差 0.09–0.13，校准数据只需 16 条序列，对校准集的分布变化比 GPTQ 稳。但 2025-05-11 起 AutoAWQ 已归档弃用，新项目用 llm-compressor（面向 vLLM）或 GPTQModel（多后端）。本篇给出：算法拆解、本机实跑的玩具 AWQ（验证"按激活选通道"和"α 搜索"）、工具链迁移路径、GPTQ/AWQ 选型证据。

验证边界：算法部分的数字来自本机 numpy 实跑；论文数字引自一手源；各库命令引自官方文档，本机无 GPU，这些命令未实跑，文中逐处标注。

WHYT：激活感知量化的观察与算法

1. 一个反直觉的起点：重要的是激活，不是权重

2

量化会引入误差。AWQ 的第一个观察是：权重通道的重要性由对应的输入激活幅值决定，而不是权重自己的大小。道理很直接：输出 y = Σ wᵢ·xᵢ，通道 i 的激活 xᵢ 很大时，wᵢ 的任何微小误差都会被放大成输出误差。

论文（arXiv:2306.00978）在 OPT-6.7B、INT3-g128 上做了一个对照：保留一小部分通道为 FP16，其余 RTN 量化，看选哪些通道最有效。结果（WikiText 困惑度，FP16 基线 10.86，纯 RTN 23.54）：

选哪些通道保留 FP16 0.1% 1% 3%
按激活幅值选 11.58 11.39 11.36
按权重范数选 23.41 22.37 22.45
随机选 约 23.5–24.2（抽取结果的列对应不清，仅作量级参考）

只保留 1% 的通道，按激活选的困惑度从 23.54 降到 11.39（增量从 +12.68 降到 +0.53），按权重选几乎没有改善（+11.51），随机选等同于没做。论文据此提出：约 0.1%–1% 的通道是"显著通道"，要按激活而不是按权重来识别。

但"保留 1% 为 FP16"在硬件上不友好（混合精度，访存不规整）。AWQ 的第二步是找一个不需要混精度的等价办法。

2.1 缩放的数学

3

量化一个权重 w：Q(w) = Δ·Round(w/Δ)，Δ = max|w| / 2^(N−1)。给 w 乘 s > 1，再让激活除以 s，乘积不变：

y = w·x = (w·s) · (x/s)
量化后：Q(w·s) · (x/s)

当 s > 1 且这个通道没有改变该组的 max|w| 时，Δ 基本不变，而 w·s 变大，相对误差变成原来的 1/s。论文的 Table 2（同一模型）验证了这一点：

方案（OPT-6.7B，INT3-g128） 困惑度
RTN 23.54
显著通道保留 FP16 11.39
显著通道乘 s=2 再量化 11.92
AWQ（搜索得到的 s） 11.39

s=2 的"只缩放"就把 23.54 降到 11.92，不需要任何混合精度。

2.2 s 不能无限大3 个重点▾ 点开看本节重点
本节重点
  • 放大一个通道会改变整个 group 的取值范围
  • s 太大时，这个通道的权重成了组内最大值，Δ 变大，其余通道的误差被放大
  • α 在 [0, 1] 上做 20 格网格搜索（论文原话：grid size of 20）
3

放大一个通道会改变整个 group 的取值范围。s 太大时，这个通道的权重成了组内最大值，Δ 变大，其余通道的误差被放大。所以 s 要取折中。论文的做法：

s = s_X ^ α        （s_X：校准数据上每个通道的平均激活幅值）
α* = argmin_α  ‖ Q(W·diag(s))·diag(s)⁻¹·X − W·X ‖

α 在 [0, 1] 上做 20 格网格搜索（论文原话：grid size of 20）。α=0 表示不缩放（等价 RTN），α=1 表示完全按激活幅值缩放。没有反向传播、没有逐列补偿，只有前向与量化，这就是 AWQ 快且对校准集不敏感的原因。

2.3 权重裁剪

3

缩放之后，论文还对每个 group 做一次权重裁剪的搜索（最小化量化后输出误差），进一步减小 Δ。这一步在多数库里是默认开启的，参数名各库不同，见 §7。

HOW：玩具验证、工具链实操与部署验收

3. 本机实跑：玩具 AWQ

2

和《L12-GPTQ量化实操》§3 同一套思路：用合成数据验证机理方向，不换算成真实模型的掉点幅度。设置：d_out=256、d_in=512，激活里有 1% 的通道（5 个）幅值是其余的 20 倍，权重是高斯随机数，量化为 4bit、g128 对称 RTN。

import numpy as np

def rtn_sym(W, bits=4, group=128):                 # 对称 RTN：Δ = max|w| / (2^(N-1)-1)
    qm = 2 ** (bits - 1) - 1
    out = np.empty_like(W)
    for g in range(0, W.shape[1], group):
        b = W[:, g:g + group]
        d = np.abs(b).max(axis=1, keepdims=True) / qm
        d[d == 0] = 1.0
        out[:, g:g + group] = np.clip(np.round(b / d), -qm - 1, qm) * d
    return out

def awq_search(W, X, err, bits=4, group=128, grid=20):
    sx = np.abs(X).mean(axis=1)                     # s_X：每通道平均激活幅值
    best = (None, np.inf, None)
    for k in range(grid):                           # α 取 0, 0.05, ..., 0.95
        a = k / grid
        s = sx ** a
        s = s / np.sqrt(s.max() * s.min())          # 归一化
        Wq = rtn_sym(W * s[None, :], bits, group) / s[None, :]   # Q(W·diag(s))·diag(s)^-1
        e = err(W, Wq, X)                           # err = ‖(W−Wq)X‖²/n
        if e < best[1]:
            best = (a, e, s)
    return best

3.4 实验四：校准分布偏移（AWQ vs GPTQ）

3

设置：A 域校准、B 域评估。两个域的"离群通道幅值"相同，但通道之间的相关结构不同（相当于相同模型换了文本领域）。三个随机种子：

seed=0  同域: AWQ=2.359e+00 GPTQ=1.642e+00 | 换域(B): AWQ=2.365e+00 GPTQ=6.279e+00 RTN=5.924e+00 | AWQ换域/同域=1.00x GPTQ换域/同域=3.82x
seed=1  同域: AWQ=2.069e+00 GPTQ=1.842e+00 | 换域(B): AWQ=2.157e+00 GPTQ=5.724e+00 RTN=5.725e+00 | AWQ换域/同域=1.04x GPTQ换域/同域=3.11x
seed=2  同域: AWQ=2.295e+00 GPTQ=1.544e+00 | 换域(B): AWQ=2.314e+00 GPTQ=6.131e+00 RTN=6.165e+00 | AWQ换域/同域=1.01x GPTQ换域/同域=3.97x

读数：①同域内，GPTQ 的层误差更低（1.54–1.84 vs 2.07–2.36），因为 GPTQ 用了更多信息。②换域后，AWQ 的误差几乎不变（1.00–1.04 倍），GPTQ 放大到 3.11–3.97 倍，几乎退化到和 RTN 一样（5.72–6.28 vs 5.72–6.17）。③原因：AWQ 只依赖"每通道平均激活幅值"，而这个量在两个域里一致；GPTQ 依赖通道之间的协方差，两个域不同。

限制：这是构造出来的最有利于这个结论的场景（幅值不变、相关结构全变）。真实换域时幅值也会变，AWQ 也会退化，只是幅度更小。论文给出的真实数字见 §4.3。

  1. 没有特别理由时，4bit 用哪个都行。论文数字里 4bit-g128 的 GPTQ 与 AWQ 差 0.00–0.09 PPL，7B 上 AWQ 比 GPTQ 低 0.09（约 1.6%），13B 上只差 0.01（约 0.2%）。《L12-模型量化》里"AWQ 比 GPTQ 好 1–3%"的说法（该篇已标注为二手）与论文只在 7B 附近吻合，其他规模偏乐观，建议在该篇里改成上表的来源与数值（我未改动，见交付说明）。
  2. 校准数据拿不到业务代表样本，或业务领域多变 → 优先 AWQ。
  3. 有业务代表性校准集，且追求同域极致精度 → GPTQ（可用 act-order）有机会更好，但要自己测。
  4. 要压到 3bit → AWQ 论文证据更好，但必须完整回归。
  5. 别忽略引擎支持：不是所有引擎都支持两种格式的所有 kernel。先看目标引擎，再选方法。vLLM 页面表格我没法可靠抽取，请直接查 https://docs.vllm.ai/en/stable/features/quantization/ 。
  6. 不要用单一指标定论：困惑度、任务指标、业务回归集三者都要看（《L12-GPTQ量化实操》§9）。同一模型在不同来源里的 FP16 困惑度不同（AWQ 论文 Llama-2-7B 为 5.47，Marlin README 为 5.12），说明评测口径（如上下文长度）不一致，不同来源的困惑度绝对值不能直接比较。

7.1 路径 A：llm-compressor AWQ（推荐，面向 vLLM）

3

官方 AWQ 示例的配方（examples/awq/README.md，本次复核确认的部分）：

recipe = [
    AWQModifier(),
    QuantizationModifier(
        ignore=["lm_head"],
        scheme="W4A16_ASYM",       # 4bit 权重、16bit 激活、非对称
        targets=["Linear"],
    ),
]

README 同时说明：AWQModifier 决定哪些层被"平滑"（也就是做缩放），QuantizationModifier 的 targets 与 ignore 决定哪些层被量化。需要自定义时，通过 mappings 参数传入 AWQMapping，例如 AWQMapping("re:.*v_proj", ["re:.*o_proj"]) 表示 v_proj 的输出缩放需要吸收进 o_proj。mappings 的核心约束：缩放因子必须能被相邻层吸收（如前一层的 LayerNorm 或线性层），否则等价变换不成立；标准的 Llama 类结构库里有内置映射，一般不用自己写。

完整脚本的流程与 GPTQ 版相同（《L12-GPTQ量化实操》§6.3）：加载模型 → 准备校准数据 → oneshot(model=..., dataset=..., recipe=recipe, ...) → model.save_pretrained(dir, save_compressed=True)。我此前抽取到的示例脚本使用 256 条校准样本、序列长度 512、duo_scaling="both"，本次复核 README 页面没有重现这些值，请以仓库里 examples/awq/ 下的脚本为准。

量化与推理建议分环境，原因同《L12-GPTQ量化实操》§10.5。

本节重点

GPTQModel README 的矩阵列出了 AWQ 的格式（FORMAT.GEMM、GEMV、GEMV_FAST、LLM_AWQ、MARLIN、BITBLAS）和后端（AWQ_TORCH_ATEN、AWQ_MACHETE、AWQ_MARLIN、AWQ_EXLLAMA_V2、AWQ_GEMM、AWQ_GEMM_TRITON、AWQ_TORCH_FUSED 等）。迁移说明里与 AutoAWQ 相关的两条：version 属性现在叫 format；zero_point 现在叫 sym，sym=True 等价于 zero_point=False。这是旧脚本迁移时最容易写反的地方。具体量化入口以所装版本的 README 为准，本次抽取只确认了 GPTQ 路线的 GPTQConfig(bits=4, group_size=128)，没有确认 AWQ 路线的完整调用代码，本篇不编造。

7.3 路径 C：AutoAWQ（仅为读懂旧教程，不建议新项目）

3

vLLM 文档保留的旧写法，可帮助你读懂网上的老教程：

from awq import AutoAWQForCausalLM
from transformers import AutoTokenizer

quant_config = {"zero_point": True, "q_group_size": 128, "w_bit": 4, "version": "GEMM"}
# ... 加载 model、tokenizer 后：
model.quantize(tokenizer, quant_config=quant_config)

version 的两个取值（来自 AutoAWQ README）：

  • GEMM：batch size 小于 8 时比 FP16 快很多，长上下文友好。
  • GEMV：只适用 batch size 为 1，比 GEMM 快约 20%，但长上下文表现不好。

AutoAWQ 的 fuse_layers=True 启用融合模块，加速主要来自 FasterTransformer，仅 Linux。README 还写明：NVIDIA 需要算力 7.5（Turing）以上、CUDA 11.8 以上。

7.4 在 transformers 里使用已有的 AWQ 模型1 个重点▾ 点开看本节重点
本节重点
  • 识别一个模型是否 AWQ：看 config.json 的 「quantization_config.quant_method」 是否为 「"awq"」，并带 「bits」、「group_size」、「zero_point」、「version」
3

识别一个模型是否 AWQ：看 config.json 的 quantization_config.quant_method 是否为 "awq"，并带 bits、group_size、zero_point、version。加载与普通模型一样：

model = AutoModelForCausalLM.from_pretrained("TheBloke/zephyr-7B-alpha-AWQ", device_map="auto")

融合模块（AwqConfig(bits=4, fuse_max_seq_len=512, do_fuse=True)）对 Llama、Mistral 开箱支持，其他结构要写 modules_to_fuse。文档给出 Mistral-7B-OpenOrca-AWQ 在 batch size 1 下的对比：解码速度（tokens/s）未融合 31.6–38.5，融合后 80.3–106.3，显存也略降（序列 32 时 4.50 GB → 4.00 GB）。同时有两个限制：①fuse_max_seq_len 必须覆盖"上下文长度 + 预期生成长度"，设小了会出错，设大了浪费显存；②融合模块不能与 FlashAttention-2 同时使用。另可用 AwqConfig(version="exllama") 启用 ExLlamaV2 kernel，AMD GPU 也支持。

8. 部署：vLLM 加载

2

vLLM 文档对 AutoAWQ 产物的旧写法是：

llm = LLM(model="TheBloke/Llama-2-7b-Chat-AWQ", quantization="auto_awq")

注意这里参数值是 "auto_awq"。同一个文档页给出了弃用警告。llm-compressor 产物是 compressed-tensors 格式，加载方式与《L12-GPTQ量化实操》§8.1 相同，一般不用显式传 quantization。参数取值名随 vLLM 版本变化，到新环境先看 vllm serve --help 与启动日志里识别到的量化方法。

GPTQModel README 的后端矩阵里有 AWQ_MARLIN、AWQ_MACHETE，说明 AWQ 权重也可以走 Marlin 一类 kernel。是否实际走了、速度多少，必须在你的 GPU 上压测，并对照 FP16 基线，不要直接引用论文的 3× 数字。

评测方式与 GPTQ 版相同：lm_eval --model vllm --model_args pretrained=...,add_bos_token=true --tasks ...，量化模型对 BOS 敏感。

9. 翻车排查（AWQ 特有）3 个重点▾ 点开看本章重点
本章重点
  • 9.1 照着旧教程装 autoawq，环境被降级
  • 9.7 把"论文里 4bit 几乎无损"当成结论
  • 现象：transformers、torch 被改动，其他项目起不来
2

9.1 照着旧教程装 autoawq，环境被降级。 现象：transformers、torch 被改动，其他项目起不来。依据：transformers 文档警告 autoawq 会把 transformers 降到 4.47.1。改法：新建 venv；或改用 llm-compressor。

9.2 版本命名对不上。 现象：旧配置里 zero_point=True、version="GEMM"，新库里找不到这两个键。依据：GPTQModel 迁移说明（version→format，zero_point→sym，二者含义取反关系见 §7.2）。改法：逐项对照，别凭感觉改。

9.3 融合模块出错或显存不降。 现象：打开 do_fuse 后生成中途报错，或同时开了 FlashAttention-2。依据：transformers 文档（融合不能与 FlashAttention2 合用；fuse_max_seq_len 要包含上下文与生成长度）。改法：二选一；fuse_max_seq_len 取"最大上下文 + 最大生成"并留余量。

9.4 GEMV 版本在多并发下很慢。 依据：AutoAWQ README：GEMV 只适合 batch 1。改法：服务场景用 GEMM 或 Marlin 类 kernel。

9.5 缩放不被吸收的结构。 现象：自定义结构的模型 AWQ 后输出明显变差。机理：§7.1 的映射约束，缩放因子没有被相邻层正确吸收就不再等价。改法：先在小样本上对比量化前后同一批 prompt 的输出，再看完整评测；自写 AWQMapping 时优先从官方 Llama 示例改。

9.6 评测口径混用。 现象：把博客里的困惑度和自己的对比，得出"我的量化更差"。依据：§5 第 6 点。改法：只比较同一脚本、同一数据、同一上下文长度下的 FP16 与量化。

9.7 把"论文里 4bit 几乎无损"当成结论。 论文数字来自 WikiText2 困惑度，指标本身对长尾能力（推理、代码、多语言）不敏感。改法：任务级评测 + 业务回归集。
