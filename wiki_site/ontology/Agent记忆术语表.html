conflict_status 字段说明

2
取值 含义 用法
active 现行有效, 作为标准答案使用 默认值
superseded 被另一术语取代/覆盖, 保留作历史对比 标注取代关系: A superseded-by B
complementary 与另一术语互补, 二者不冲突但关注点不同 标注互补关系: A complement B
conflict 与另一术语矛盾, 需要人审 标注: A conflicts-with B, 提交周复盘

作用: RAG 检索时若 top-k 同时命中 superseded 和 active, 优先取 active; 命中 complementary 应同时返回两条避免单边答案; 命中 conflict 直接给 LLM 标记待仲裁。

System-1 / System-2

2
  • 定义: 双进程记忆/推理架构。System-1 = 轻量快系统(向量近邻检索、小分类器、规则路由), 日常 85% 查询直接出答案, 成本低; System-2 = 慢系统(重读原始会话历史、多跳推理、慢思考 Agent), 只在 System-1 不确定时被门控唤起, 成本高但质量高。
  • 来源论文: D-Mem(arXiv:2603.18631) 查询期双进程; Jev-Mem(arXiv:2609.23986) 写入期 System-One 控制面; PRIME(arXiv:2509.22315) 推理期慢思考触发。
  • conflict_status: active
  • 关系标注:
  • Jev-Mem(写入期 System-One 控制面) vs D-Mem(查询期双进程) — complementary: 一个管"写时选什么进记忆", 一个管"查时怎么用记忆", 阶段不同不冲突。两者都叫"System-1/2"但作用域不同, RAG 检索命中时必须同时给两条, 标注 写入期 vs 查询期 以免混淆。

Insight Graph

2
  • 定义: G-Memory 三层图记忆的最上层(泛化经验层), 存从多次任务抽象出的教训/模式(如"flaky 测试不要盲目重跑"), 短摘要、低成本, 供编排层和其他 Agent 复用。下层是 Query Graph(任务指纹→派谁→结果) 和 Interaction Graph(原始轨迹归档)。
  • 来源论文: G-Memory(arXiv:2506.07398)。
  • conflict_status: active
  • 关系标注: 与 BudgetMem(预算分级路由) — complementary: G-Memory 讲"经验怎么沉淀复用", BudgetMem 讲"每次查询给多少检索预算", 一个是记忆组织, 一个是查询路由, 不冲突。

Quality Gating

2
  • 定义: D-Mem 里介于 System-1 和 System-2 之间的元认知路由判定器。输入三个标量特征: ①置信度(top-k 向量相似度分布, top-1/top-2 分差小=低置信) ②证据稀疏度(字面关键词命中数) ③查询复杂度(是否含时序/因果/比较信号词), 加权求和输出升级概率, 超过阈值 τ 才唤起 System-2 重读原始历史。门控本身不调 LLM。
  • 来源论文: D-Mem(arXiv:2603.18631, LoCoMo F1=53.5, 35.8% token 恢复 96.7% 上限)。
  • conflict_status: active

自适应停止 (Adaptive Stopping)

2
  • 定义: Jev-Mem 图检索时的停止策略。每轮图扩展后评估四个标量: 证据充分性 s_d / 继续效用 u_d / 缺失 m_d / 矛盾 c_d, 达标即停; 外加 node/edge/depth/controller/latency 五重硬上限防失控。不等预算耗尽, 证据够了就停。
  • 来源论文: Jev-Mem(arXiv:2609.23986)。
  • conflict_status: active

预算分级路由 (Budget-Tiered Routing)

2
  • 定义: BudgetMem 的 query-aware 三档路由: Low / Mid / High, 按查询复杂度自动选检索预算, 不是固定 top-k。用 RL 路由器学习"什么 query 该给多少预算", λ 参数化调检索深度(服务器端高预算/边缘设备低预算的思想)。六员角色可天然对应三档: 编排=Low, 执行=Mid, 工程深度=High。
  • 来源论文: BudgetMem(arXiv:2602.06025, ICML 2026)。
  • conflict_status: active
  • 关系标注: 与 G-Memory(Insight Graph) — complementary (见上条)。与 D-Mem Quality Gating — complementary: 两者都用"查询复杂度"做输入, 但 BudgetMem 决定"给多少预算", D-Mem 决定"要不要升级到 System-2", 一个是容量决策, 一个是路径决策, 可以串联使用。

历时指针 (Diachronic Pointer)

2
  • 定义: DCPM 里给每条记忆/信念加的版本时间戳指针, 追踪一个 Agent(或多个 Agent) 对同一需求/架构决策的观点随时间的漂移(Draft→Review→Locked), 跨 Agent 对比时能看到"谁在什么时候改了主意", 支撑多 Agent 共识演化与分歧溯源。
  • 来源论文: DCPM(arXiv:2606.09483, 待精读, 本批只立项)。
  • conflict_status: active (待精读后复核)
