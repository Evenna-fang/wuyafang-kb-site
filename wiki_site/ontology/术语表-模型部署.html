模型部署术语表 (ontology)

入库: 2026-09-29 | 项目: wuyafang-l
每个术语 = 定义 + 适用场景 + conflict_status
conflict_status 取值含义见 ontology/Agent记忆术语表.md

vLLM

2
  • 定义: 高吞吐 LLM 推理引擎，核心是 PagedAttention（分页式 KV cache 管理）+ 连续批处理（continuous batching），主打高并发生产部署。OpenAI 兼容 API server。
  • 适用场景: 服务端高并发、要开 API 给多请求同时推理、追求吞吐。本地单任务/桌面端不划算。
  • conflict_status: active
  • 关系标注: 与 Ollama — complementary: vLLM 偏"服务端高并发"，Ollama 偏"本地单机一键跑"，按部署规模二选一。

Ollama

2
  • 定义: 本地一键跑开源大模型的工具/运行时，封装模型下载、格式转换、本地 API（默认 :11434）。支持 GGUF 量化模型，适合桌面/个人开发机。
  • 我们的口径: RAG 管线的 LLM 生成端用 Ollama 本地 doubao-seed-2.1-lite（零 API 费）。
  • 适用场景: 本地开发、零成本生成、单用户。不追求高并发。
  • conflict_status: active
  • 关系标注: 与 vLLM — complementary（见上）。

llama.cpp

2
  • 定义: C++ 实现的纯 CPU/低资源 LLM 推理引擎，GGUF 格式的原生载体，极致轻量，可在笔记本/边缘设备跑量化模型。是 Ollama 等上层工具的底层依赖之一。
  • 适用场景: 无 GPU、边缘/嵌入式、极简依赖环境。
  • conflict_status: active
  • 关系标注: 与 Ollama — complementary: llama.cpp 是底层引擎，Ollama 是它的易用封装。

GGUF

2
  • 定义: llama.cpp 生态的模型量化文件格式（替代旧的 GGML），单文件打包权重 + 元数据，支持多种量化位宽（Q4_K_M / Q5_K_M / Q8 等）。Ollama 直接加载 GGUF。
  • 适用场景: 本地量化部署、跨工具便携分发。
  • conflict_status: active
  • 关系标注: 与量化 — complementary: GGUF 是"载体格式"，量化是"压缩方法"，量化后的模型以 GGUF 落盘。

量化 (Quantization)

2
  • 定义: 把模型权重从 FP16/BF16 压到更低比特（INT8/INT4 等）以省显存、提速、降成本，代价是轻微精度损失。常见方案：GGUF 量化（Q4_K_M 等）、AWQ、GPTQ。
  • 我们的口径: 本地跑量化模型省资源；云端 API 模型（doubao 等）由服务商管，我们不自己量化。
  • conflict_status: active
  • 关系标注: 与 GGUF / AWQ — complementary: 量化是方法，GGUF/AWQ 是不同体系的落地格式。

AWQ (Activation-aware Weight Quantization)

2
  • 定义: 一种 INT4 权重量化方法，按"激活幅度"识别重要权重通道、保留其精度，比朴素 INT4 精度损失小，适合 GPU 上的高效推理（常配 vLLM / Text Generation Inference）。
  • 适用场景: GPU 服务端、要在可控精度损失下省显存。与 GGUF（CPU 生态）分属两大量化路线。
  • conflict_status: active
  • 关系标注: 与 GGUF — complementary: AWQ 偏 GPU/服务端，GGUF 偏 CPU/本地，按硬件选。

Step-level Model Routing (步级模型路由)

2
  • 定义: 不是整个任务锁一个模型，而是按推理"步"动态选档位：planning/复杂推理走强模型，formatting/摘要走轻量模型。来源论文 AgentRouter(arXiv:2609.22951)。
  • 我们的口径: 已落地为"模型能力矩阵"（AFP 系数 0.5/1/5/9），按任务类型选档位（notes/config/模型能力矩阵）。
  • conflict_status: active
  • 关系标注: 与 Budget-Tiered Routing — complementary: 步级路由决定"用哪个模型"，预算三档决定"给多少 token 上限"，二者正交可叠加。
