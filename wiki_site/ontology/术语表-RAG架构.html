Hybrid Retrieval (混合检索)

2
  • 定义: 同时用 dense（语义向量近邻，bge-m3 dense）和 sparse（关键词/稀疏向量，bge-m3 sparse / BM25）两路召回，再融合排序。dense 抓"语义相近但字面不同"，sparse 抓"专有名词/术语精确命中"。
  • 我们的口径: bge-m3 同时出 dense+sparse。当前管线两路均已启用 —— dense 召回 top-1000（DENSE_TOP_N=1000，2026-10-14 B005-fix 从20扩大）+ sparse 召回 top-100（SPARSE_TOP_N=100，从20扩大），经 RRF 融合。向量库实测 14510 条 chunks（2026-10-14）。基准实测（2026-10-14）：dense-only Recall@5=0.587 / MRR@3=0.433；hybrid-only Recall@5=0.695（+18.4%）；hybrid+rerank Recall@5=0.816 / MRR@3=0.605（+39%）。cosine 距离阈值 dist_threshold=0.60（2026-10-14 B005-fix-2 从0.75放宽，让 G-Memory 等中文短 query 过门）。
  • conflict_status: active
  • 关系标注: 与 RRF — complementary: hybrid 是"两路召回"，RRF 是"两路结果怎么融合"，二者配套使用。

RRF (Reciprocal Rank Fusion)

2
  • 定义: 一种免权重的多路结果融合算法：对每路召回的排名 r，给每条文档打分 Σ 1/(k+r)（k 通常=60），按融合分重排。不需要预先标定各路分数权重，对分数尺度差异鲁棒。
  • 适用场景: dense 和 sparse 两路分数不可比时，用 RRF 融合而非加权求和。
  • conflict_status: active
  • 关系标注: 与 Hybrid Retrieval — complementary（见上）。

Hierarchical Chunking (分层分块)

2
  • 定义: 不按固定字数一刀切，而是按文档结构（标题→章节→段落）切块，保留父子层级：小块进向量库做精确召回，命中后带上其所属的大块/父块上下文喂给 LLM，平衡"检索精确"与"上下文完整"。
  • 我们的口径: CHUNK_SIZE=384、CHUNK_OVERLAP=80（可被 RAG_CHUNK_SIZE / RAG_CHUNK_OVERLAP 环境变量覆盖）。生产环境最优解是父子分块：小 chunk（256–384 token）做检索找位置，父 chunk（≤1024 token）喂给 LLM 做生成。metadata 已有 parent_text 字段 —— ingest.py 写入、query.py 读取并用于 rerank 与生成上下文（见 rag/query.py 第 440-446、484、536-538 行），代码链路已通；分层收益已端到端量化（2026-10-14）：hybrid+rerank 后 Recall@5=0.816。
  • conflict_status: active

Reranker (精排/重排器)

2
  • 定义: 对初筛召回的 top-N（如 top-30）候选，用交叉编码器（cross-encoder）逐对"query-document"打分精排，取 top-k 进上下文。比纯向量近邻准，但贵、慢，所以只对小候选集用。
  • 我们的口径: bge-reranker-v2-m3 本地跑，对初筛 top-10 精排（RERANK_TOP_N=10，可被 RAG_RERANK_TOP_N 覆盖）；过滤阈值 RERANK_THRESHOLD=0.45（见 notes/benchmark/阈值标定记录）。
  • conflict_status: active

HyDE (Hypothetical Document Embeddings)

2
  • 定义: 让 LLM 先"假想"写出一个可能的答案段落（hypothetical document），用这个假段落而非原始 query 去做向量检索——因为假段落更接近真实文档的分布形态，提升小 query 的召回率。
  • 我们的口径: 基准题 Q8 验证过 HyDE 在低置信 query 下触发；当前 query 改写/HyDE 阶段（P3）仍禁用 —— query.py 的 rewrite_query() 直接 return None 直通原始 query（见 rag/query.py 第 236-245 行），常量 REWRITE_TIMEOUT / REWRITE_DAILY_LIMIT / REWRITE_CACHE_DIR 仍在但开关未开启，等异步预改写方案。
  • conflict_status: active
  • 关系标注: 与 Quality Gating / 质量门控 — complementary: 低置信（confidence<τ）时才触发 HyDE 或升级 System-2，不是每 query 都改写。

Contextual Retrieval (上下文检索)

2
  • 定义: 给每个 chunk 注入它在原文档中的上下文（标题、摘要、前后文）后再 embedding，解决"孤立 chunk 语义漂移"（chunk 脱离上下文后向量含义变了）。Microsoft 2024 提出，实测显著降检索失败率。
  • 适用场景: chunk 较短、容易脱离语境时。常与 hierarchical chunking 叠加。
  • conflict_status: active

Source Tier (来源分级)

2
  • 定义: 给语料标重要等级（tier=1 一手决策 / tier=2 二手调研 / tier=3 转述），检索时按 tier 降权或加权，避免"二手转述"压过"一手裁决"。
  • 我们的口径: raw 文件头标 source_tier；source_tier 字段在 metadata 里存在，但当前填充率 0%（chroma 库 6033 条 embedding 的 source_tier 值全为空），降权系数未落地。基准 Q9 暴露"source_tier 降权系数"未落地（MISS）。
  • conflict_status: active

Quality Gating (质量门控) — RAG 侧

2
  • 定义: RAG 查询期的元认知路由器（见 Agent记忆术语表）：按置信度/证据稀疏度/查询复杂度判定"这次够不够直接答"，低于阈值 τ 才升级到重排/HyDE/System-2 深推理。我们的落地：85% 走 System-1 快检索，15% 走深推理，τ=0.5 起步（notes/benchmark/记忆查询质量门控）。
  • conflict_status: active
  • 关系标注: 与 HyDE — complementary（见上）；与 Budget-Tiered Routing — complementary（门控决定"走哪条路"，预算档决定"给多少检索预算"，可串联）。

评测闭环 (Evaluation Loop)

2
  • 定义: RAG 上线后持续量化检索/生成质量的闭环，三件套分工：DeepEval = pytest-based CI gate 拦 PR 回归（golden-question 套件）；RAGAS = scheduled job 采样生产流量算 RAG 专属指标（faithfulness / answer relevancy / context precision / context recall / context utilization / noise sensitivity / answer correctness / answer similarity）；Langfuse = 捕获生产 trace（question/retrieved context/answer/metadata）。
  • 关键指标: faithfulness = reference-free（claim-decomposition，不需 ground-truth），适合个人库冷启动；生产阈值 faithfulness < 0.80 触发告警。
  • 我们的口径: 当前从 0 到 1 的最大缺口——无 golden-question 套件（计划 20 条）、无 faithfulness/context precision baseline、无 trace 记录。来源: raw/sources/RAG优化-外部调研-20260929.md 方向 4（genai.qa 2026 / Langfuse guides）。
  • conflict_status: active

Graph RAG / Agentic RAG（检索范式选型）

2
  • 定义: 两种进阶检索范式。Graph RAG = 把知识抽成图（节点=实体/决策，边=dependency/cause/reference），适合"追关系"类问题（法律/合规/生物医学）；LazyGraphRAG（Microsoft 2025）把全图索引成本降到 vector RAG 的 0.1%。Agentic RAG = 让 Agent 多步推理、自我纠错、判断"何时该检索/查哪个文件"，代价慢、贵、难调试。
  • 选型决策树: 答案在文档里+速度重要 → 标准 RAG；结构化知识追关系 → Graph RAG；多步推理+自我纠错 → Agentic RAG。
  • 我们的口径: 162 chunks 个人库明确暂不做（ADR），直到 chunk > 5000 或出现"追关系"类 query。来源: raw/sources/RAG优化-外部调研-20260929.md 方向 5（ByteByteGo / k-ai.ai 2026）。
  • conflict_status: active
