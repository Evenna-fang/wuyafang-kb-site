Agent 框架术语表 (ontology)

入库: 2026-09-29 | 项目: wuyafang-l
每个术语 = 定义 + 适用场景 + conflict_status
conflict_status 取值含义见 ontology/Agent记忆术语表.md（active / superseded / complementary / conflict）

LangGraph

2
  • 定义: 基于有向图（节点=函数/Agent，边=条件路由）的 Agent 编排框架，由 LangChain 团队推出。显式状态对象（StateGraph）在节点间流转，支持循环、分支、human-in-the-loop、持久化 checkpoint。
  • 适用场景: 需要可控多步推理流程、状态机式工作流、可回溯的 Agent 链（如 RAG 问答、工具调用循环、审批流）。不适合一次性单步任务。
  • conflict_status: active
  • 关系标注: 与 OpenAI Agents SDK — complementary: LangGraph 偏"图/状态机"显式编排，OpenAI Agents SDK 偏"轻量式 + handoff"高层抽象，可按流程复杂度二选一。

CrewAI

2
  • 定义: 以"角色（Role）+ 任务（Task）+ 团队（Crew）"为核心的多 Agent 协作框架。Agent 带 system prompt 式角色定义，按顺序或层级（hierarchical）执行任务，内置工具/记忆/输出解析。
  • 适用场景: 角色扮演式多 Agent（研究员→写手→审校）、流程固定的 pipeline、快速原型。不适合需要精细状态机或动态条件路由的场景。
  • conflict_status: active
  • 关系标注: 与 LangGraph — complementary: CrewAI 更"开箱即用、角色驱动"，LangGraph 更"底层、图驱动"；同一个多 Agent 流程两种都能实现，CrewAI 起步快，LangGraph 控制力强。

AutoGen (Microsoft)

2
  • 定义: 微软的多 Agent 对话框架，核心是可对话的 Agent（UserProxyAgent / AssistantAgent）互相对话直至任务完成；新版 AutoGen v0.4+ 引入事件驱动的 Actor 架构和团队模式。支持人类介入、代码执行容器。
  • 适用场景: 对话式协作、代码生成-执行-反馈闭环（写代码→跑代码→看报错→改）、研究实验。生产级强状态编排不如 LangGraph。
  • conflict_status: active

OpenAI Agents SDK

2
  • 定义: OpenAI 官方轻量 Agent 框架，核心抽象 = Agent（带 instructions + tools）+ Runner（执行循环）+ handoff（Agent 间交接）+ guardrails（输入/输出校验）。内置 tracing，与 OpenAI 模型生态深度绑定。
  • 适用场景: 用 OpenAI 系模型、需要快速搭工具调用型 Agent、需要内建 handoff 与 guardrails 的产品。非 OpenAI 模型需自行适配。
  • conflict_status: active
  • 关系标注: 与 LangGraph — complementary（见上）。

Claude Agent SDK

2
  • 定义: Anthropic 官方 Agent 开发套件（前身 Claude Code 的 SDK 化），围绕 Claude 模型构建工具使用型 Agent，支持 MCP（Model Context Protocol）接外部工具/数据源，沙箱化执行。
  • 适用场景: 以 Claude 为主模型、需要 MCP 生态工具接入、长程代码/文件操作型 Agent。
  • conflict_status: active
  • 关系标注: 与 OpenAI Agents SDK — complementary: 两家各自绑定自家模型与工具生态，跨模型统一编排时用六员路由层而非 SDK 本身。

MCP (Model Context Protocol)

2
  • 定义: Anthropic 提出的开放协议，标准化"Agent ↔ 外部工具/数据源"的接入方式（server/client 模型，JSON-RPC 风格）。一个 MCP server 暴露一组工具/资源，任意兼容客户端（Claude Desktop / Cursor / 各家 Agent）即插即用。
  • 适用场景: 想让同一套工具（DB、API、文件、浏览器）被多个 Agent/客户端复用，避免每个 Agent 手写一遍集成。
  • conflict_status: active
  • 关系标注: 与 A2A — complementary: MCP 解决"Agent→工具"，A2A（Agent2Agent）解决"Agent→Agent"，两者不互斥。

A2A (Agent2Agent Protocol)

2
  • 定义: Google 2025-04 提出的 Agent 间互操作协议：JSON-RPC over HTTP + SSE，用 Agent Card 声明能力做发现。解决"不同厂商/组织的 Agent 互相调用"。
  • 适用场景: 跨组织 Agent 互操作。对单一六员体系，当前不引入真协议，只借其"能力显式声明（agent_card）+ 任务结构化交接（task envelope）"两个设计习惯（见 notes/config/六员配置优化建议）。
  • conflict_status: active
  • 关系标注: 与 MCP — complementary（见上）。

Orchestrator-Walker 模式（编排者-执行者）

2
  • 定义: 业界主流多 Agent 骨架：一个编排者（orchestrator）拆任务/派单/汇总，多个执行者（worker）并行或串行干活，步骤间自动校验，外加独立 LLM 评审层和确定性终门，人工只在规划边界与冲突升级处出现。
  • 适用场景: 绝大多数六员协作任务。Hermes=编排者，DSH/Claude/Codex=执行者，OpenClaw=评审层。
  • conflict_status: active
  • 关系标注: 与 Kanban Swarm（并行工作者→验证者→合成者）— complementary: Swarm 是编排者-执行者的一种具体并行落地形态。

Agent Card（能力声明）

2
  • 定义: 借鉴 A2A 协议的静态能力声明文件（对应协议里的 /.well-known/agent.json）：给每个 agent 一个 markdown/JSON 文件，显式声明能力边界、输入契约、输出契约、典型任务类型。让编排者（Hermes）不用人脑记"谁擅长什么"，而是读 card 路由派单。
  • 适用场景: 六员（Hermes/DSH/Claude Code/Codex/OpenClaw/QwenCode）各自写一份 agent_card.md。短期不实现 A2A JSON-RPC server（本机 CLI 够用），但先落这个产物。
  • 我们的口径: 待建。来源: raw/multi-agent/A2A协议调研-20260928.md 第 3.3 节。
  • conflict_status: active

Task Envelope（结构化任务交接）

2
  • 定义: 借鉴 A2A Task Lifecycle 的交接信封：一个 JSON 文件含 task_id / status(submitted→working→input-required→completed/failed) / input / artifacts，落在固定目录（如 ~/.hermes/tasks/），替代散在 prompt 里的派单信息。让任务交接可观测、可异步、不暴露内部 memory。
  • 适用场景: 六员派单时用 task envelope 落盘，Hermes 能看到"DSH 正在 working / 需补充输入 / 已完成"，失败不靠人盯。
  • 我们的口径: 当前是硬编码 delegate_task + prompt 模板，待引入 envelope 文件。来源: raw/multi-agent/A2A协议调研-20260928.md。
  • conflict_status: active
  • 关系标注: 与 Agent Card — complementary: Card 解决"派给谁"，Envelope 解决"派出去后怎么追踪状态"。
