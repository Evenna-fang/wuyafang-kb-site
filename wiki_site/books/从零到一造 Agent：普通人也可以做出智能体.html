第1章 AI不只是聊天的对象

3
  • 问一句答一句 vs 自己把事情做完：Agent 与聊天 AI 的本质区别在于能否自主完成多步任务。
  • Agent 的最小定义：一个能自主决策、调用工具、循环推进直到完成目标的系统。
  • Agent 不是自动化脚本：脚本按固定路径执行，Agent 需要根据中间结果动态决策。
  • 20 行代码的魔法与之后的问题：最小 Agent 很容易跑起来，但跑起来之后暴露的失控问题才是工程的全部。

第3章 工具：Agent的手和脚

3
  • 工具不是给人看的按钮：工具是给 LLM 读的接口，设计对象是模型而非人类用户。
  • description 比 execute 更重要：工具描述直接决定模型是否会正确调用、何时调用。
  • 工具描述的四个原则：清晰说明用途、边界、输入输出与失败情形。
  • 分层加载：少给选择反而更好，避免模型在过多工具中迷失。
  • 并行执行需区分纯与不纯：纯工具可并行，有副作用的工具必须谨慎。
  • 工具输出太大是隐患：需要溢出处理，否则一次大输出就能炸掉上下文。

  • 四层错误防护：覆盖输出过大、工具不存在、格式错误等常见故障

第5章 并行：让Agent同时做几件事

3
  • Agent 可以同时做好几件事：借鉴餐厅厨房的分工逻辑，纯工具调用可批处理并行。
  • 纯工具与不纯工具的边界：有副作用、有顺序依赖的调用不能并行。
  • 批处理逻辑约三十行代码：并行调度的核心实现并不复杂，难在边界判断。
  • 细粒度锁被删掉：过度同步设计得不偿失，粗粒度边界更实用。
  • 并行不是万能的：需要模型具备并行意识，且并非所有场景都适合并行。

第7章 长期记忆：跨越会话的智能

3
  • 上下文窗口不是答案：跨会话的“认识你”需要独立的长期记忆系统。
  • 五类值得记住的记忆：需要明确什么值得记、什么不值得。
  • 选 SQLite 的理由：轻量、本地、够用。
  • 四个信号一个分数：检索不是简单按时间或重要性排序，而是多信号综合打分。
  • 自动提取：不需要用户说“记住这个”，系统应主动识别值得记忆的内容。
  • 记忆是攻击面：恶意记忆跨会话持续生效，如同埋在记忆里的特洛伊木马。
  • 命名空间隔离：一个大脑服务多个用户，必须做隔离。

    “如果这条指令被写入了长期记忆，它会跨越会话持续生效——就像一个特洛伊木马，埋在Agent的记忆里，每次新对话都会激活。”

第9章 LLM会犯错，而且经常犯

3
  • 先分类，再反应：七种错误对应七种反应，不能一概而论。
  • 200 OK 的谎言：HTTP 成功不代表任务成功，需要语义层面的成功判断。
  • 卡住了但没报错：最危险的错误是静默失败。
  • 格式错误回滚：坏 JSON 不该永远留在上下文里。
  • 降级链：首选模型不行就换一个，保证可用性。
  • 不能让 LLM 自己处理所有错误：依赖模型自觉的设计必定失败，系统层必须有兜底。

    “卡住了，但没报错”——最危险的错误是静默失败。

第11章 浏览器：Agent的眼睛

3
  • 三种看网页的方式：截图、原始 HTML、无障碍快照，各有取舍。
  • 无障碍快照是为机器设计的页面摘要：信息密度高、噪声低，是核心判断。
  • 截图看得见摸不着：原始 HTML 信息完整但噪声爆炸。
  • 登录态管理：让 Agent 不用每次都登录。
  • 无头部署与连接可靠性：服务器没有屏幕，浏览器也会“死”，需要重连机制。
  • 两条路径：自己开浏览器 vs 用用户的浏览器，场景不同选择不同。

第13章 从“能跑”到“能用”

3
  • 七件无聊的事决定生产可用性：容器化、自动备份、优雅关闭、数据库迁移、健康检查、日志监控、安全加固。
  • 容器化：别让环境跟着代码走；容器轻但隔离不如虚拟机。
  • 数据库迁移：加列容易改列要命，值合法性应在应用代码层校验。
  • 日志与监控分工：日志是“出了问题你去找原因”，Sentry 是“出了问题它来找你”。
  • 上线检查清单：做到 12 项以上才算生产系统。

    “你不需要主动去看日志——日志是‘出了问题你去找原因’，Sentry是‘出了问题它来找你’。”
