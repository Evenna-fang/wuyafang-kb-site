第1章 何谓Agent，为何Agent3 个重点▾ 点开看本节重点
本节重点
  • Agent的定义：Agent是能够感知环境、做出决策并采取行动的系统，具备自主性而非被动响应外界刺激
  • AI作为新生命形态的愿景：AI需要存储、计算和自我学习三种核心能力，才可能从工具演进为拥有独立思想的伙伴
  • Agent三大能力支柱：大模型提供推理“大脑”，语言交互与多模态构成“感知力”，语言输出与工具调用构成“行动力”
3
  • Agent的定义：Agent是能够感知环境、做出决策并采取行动的系统，具备自主性而非被动响应外界刺激。
  • Agent三大能力支柱：大模型提供推理“大脑”，语言交互与多模态构成“感知力”，语言输出与工具调用构成“行动力”。
  • Agent的行业价值：Agent不仅提升各行业效能，还催生“工具即服务”等新商业模式，创业者应聚焦特定小规模场景深入解决问题。
  • AI作为新生命形态的愿景：AI需要存储、计算和自我学习三种核心能力，才可能从工具演进为拥有独立思想的伙伴。
  • 落地边界：Agent的自主性必须建立在权限、预算、数据范围和人工确认之上，复杂并不等于可靠，能解释和能回退同样重要。评估一个Agent至少要同时看任务成功率、工具调用正确率、失败恢复能力、平均成本和人工接管比例。

    “Agent是一个能够感知环境、做出决策并采取行动的系统。”
    “他们建议创业者在创业初期专注特定的、小规模的业务场景，深入解决具体问题，而不是追求建立大型平台。”

第2章 基于大模型的Agent技术框架

3
  • 四大要素：Agent由大模型（推理引擎）、规划决策、记忆机制、工具调用四大要素构成完整技术框架。
  • 规划与决策：Agent通过任务分解、反思与调整实现自主规划，操作序列由大模型动态选择而非硬编码。
  • 记忆机制：短期记忆与长期记忆共同支撑Agent的上下文理解与经验积累；记忆写入必须考虑相关性、时效性和隐私。短期记忆服务当前任务，长期记忆则应经过筛选、摘要和检索，不能把全部历史对话无差别塞入上下文。
  • ReAct框架：核心设计哲学是“观察—思考—行动—再观察”的循环，强调持续学习与快速将推理转化为行动。
  • 分层Agent组织：高层次Agent负责决策与协调，低层次Agent执行具体任务，形成层级化协作体系。
  • 工程实现：应把状态、工具结果、错误信息和停止条件显式记录，避免Agent在失败时无限循环或重复调用。调试时要能按任务ID重放关键轨迹，并区分模型决策错误、工具执行错误和外部环境错误。这样才能针对性修复，而不是盲目更换模型。

    “操作的序列并非硬编码在代码中，而是使用大模型来选择执行的操作序列。这凸显了大模型作为AI自主决定应用程序逻辑这个编程新范式的价值。”
    “ReAct框架的设计哲学是：在动态和不确定的环境中，有效的决策需要持续的学习和适应，以及快速将推理转化为行动的能力。”

第4章 Agent 1：自动化办公的实现——通过Assistants API和DALL·E 3模型创作PPT

3
  • Assistants API定位：OpenAI提供的高层封装，支持不写代码在Playground中快速构建Agent。
  • 多工具协同：Assistants可调用代码解释器与DALL·E 3等工具，实现从内容生成到图像创作的自动化办公流程。
  • 实操路径：从Playground体验入手，再通过API代码化，完成虚构PPT的端到端创作。
  • 任务拆解：PPT创作可分为主题理解、页面结构、文字内容、图像生成和文件组装，每一步都应有中间产物和检查点。
  • 质量边界：自动生成的文案、图片和版式需要人工审核，尤其要检查事实、版权、品牌规范和最终文件可打开性。文件生成还应保存中间版本和失败日志，便于发现某一步工具调用异常后只重跑局部，而不是从头重复全部流程。对外发送前要再做一次格式、链接、敏感信息和收件人检查。

  • Function Calling的本质：让大模型根据用户意图选择并调用预定义函数，实现与外部系统的对接。
  • 两种实现路径：可通过Assistants API或ChatCompletion API（Tool Calls）实现函数调用。

  • 安全执行：模型只能提出调用请求，应用侧负责鉴权、参数校验、超时、重试和敏感操作确认，不能直接把自然语言当成命令执行。生产环境还要按工具划分最小权限，区分只读查询、可逆写入和不可逆操作，并在日志中记录调用者、参数摘要、结果与审批状态。

第6章 Agent 3：推理与行动的协同——通过LangChain中的ReAct框架实现自动定价

3
  • ReAct在LangChain中的落地：通过create_react_agent将推理与工具调用结合，构建自动定价Agent。
  • 工具与工具包：LangChain提供标准化工具接口，工具包可批量注册相关工具供Agent选用。
  • AgentExecutor运行机制：深入理解AgentExecutor的循环调度逻辑，是调试和优化Agent行为的关键。
  • 自动定价流程：Agent先理解商品和约束，再调用库存、成本或市场工具，最后生成价格建议；每一步都应保留依据。
  • 调试方法：检查工具选择是否正确、参数是否完整、观察结果是否被正确读回，以及停止条件是否触发，不能只看最后一句答案。

3
  • Plan-and-Solve策略：将“制定计划”与“执行步骤”解耦，先规划后执行，提升复杂任务的可靠性。
  • Plan-and-Execute Agent：LangChain中该模式适合多步骤、需全局规划的场景，如物流库存调度。
  • 从单Agent到多Agent：单Agent能力有限时，引入多Agent分工协作是自然演进方向。
  • 计划的价值：先列出目标、依赖和顺序，可减少执行过程中的方向漂移；但环境变化时仍需允许重新规划。计划还应标注每一步的完成判据，让执行器知道何时可以交接，避免只产生日志却没有可验证产物。
  • 执行验收：每个步骤都要有输入、输出和失败分支，库存、订单等真实业务动作应支持幂等与人工审批。

第8章 Agent 5：知识的提取与整合——通过LlamaIndex实现检索增强生成

3
  • RAG核心思想：检索增强生成通过外部知识检索弥补大模型知识时效性与准确性不足。
  • RAG与Agent结合：ReAct RAG Agent将检索作为工具纳入推理循环，实现知识驱动的自主问答。
  • 实操案例：通过LlamaIndex构建财报检索Agent，展示知识提取与整合的完整链路。
  • 检索工具设计：Agent需要知道何时检索、检索什么以及证据不足时如何继续查找或拒答，不能把搜索工具当成万能函数。
  • 回答验收：财报类回答应区分原文事实、计算结果和模型推断，并给出可追溯的文档片段或来源信息。

第10章 Agent 7：多Agent框架——AutoGen和MetaGPT

3
  • AutoGen：微软开源的多Agent对话框架，支持多角色协作完成复杂任务。
  • MetaGPT：将软件公司角色分工引入多Agent，按SOP编排Agent协作流程。
  • 多Agent价值：通过角色分工与层级协作，突破单Agent在复杂任务上的能力边界。
  • 协作机制：多Agent系统需要定义角色职责、消息协议、交接条件和终止规则，否则角色越多，沟通噪声和成本越高。
  • 工程取舍：只有当任务确实需要专业分工、并行处理或相互审查时才引入多Agent；能由一个确定性流程完成的任务不应复杂化。多Agent上线前应先用单Agent基线对照，比较准确率、延迟、调用次数和人工介入率，确认协作收益能够覆盖额外成本。
